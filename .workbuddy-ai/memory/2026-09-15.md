## 跨容器自动施肥「拉取方向」失效修复（活漏斗 × 活耕地）

**用户报告**：跨容器施肥只在一个方向生效——输出槽是跨容器活耕地 + 输入槽是同容器骨粉
→ 正常；反过来输入槽是跨容器骨粉、输出槽是同容器活耕地 → 完全不施肥（移走活耕地后
骨粉能正常跨容器传输，说明拉取链路本身没坏）。

**根因**：施肥分支只内嵌在推送方向（`CrossContainerTransfer.tryPushToNeighbor`）与
容器内管道（`TransferPipeline.executeInContainer`），拉取方向 `pullFromNeighbor` 走的是
通用路径（`tryPullFromNeighbor` + `SlotAccessor.transfer`）。而
`SlotAccessorFactory.create` 开头对**非箱类活物品**直接 `return null` →
`pullFromNeighbor` 里 `target == null` 立即 `return false`。活耕地正是「活物品 + 非存储
容器」，通用拉取对它必然失败，施肥分支永远不会被考虑。

推送方向之所以「自然涌现」：邻居槽位走 `createForNeighbor`（**不查活物品**），内嵌的
施肥 if 有执行机会；拉取方向目标槽走 `create`（查活物品 → null），连循环都进不去。

**修复**（`CrossContainerTransfer.java`）：
- `pullFromNeighbor` 增加前置分支：目标槽 = FARMLAND + IS_LIVING → 调
  `tryFertilizeFromNeighbor`（新增辅助方法，包级可见供单测直接驱动）：遍历邻居找骨粉 →
  `simulateExtract(1)` 试粉 → `tryFertilize` 生效 → `extract(1)` 扣粉（模拟优先协议），
  与推送/容器内两处同语义；生效时 `containerCtx.syncSlotToClients(targetSlot, farmland)`
  主动推（耕地在本容器，且其自身 tick 因 equals 守卫不会写回）。
- 顺手把 `tryPushToNeighbor` 里的 `Items`/`ServerLevel`/`LivingFarmlandFunction` 全限定名
  改为 import。

**测试**：新增 `CrossContainerTransferFertilizeTest`（5 项，包
`com.qiqi.li.living.domain.hopper`，用内存 `IItemHandlerModifiable` + mock ServerLevel）：
拉取方向 age+1 且扣邻居 1 粉、空槽跳过命中后面的粉堆、邻居无粉不误伤、冻结耕地零空转
不烧粉、非活/未种植拒绝。全量 `./gradlew test` 通过（仅存已知遗留
`WaxedGeneratorFeedChainTest.chiseled_configMatchesSamplingSide`）。

**文档**：`living-farmland-tech.md` → v1.8（§7.1 两方向入口、§10.3 测试表、§11.15 新踩坑、
§12.2 验证清单拆成方向 ①②）；`living-hopper-tech.md` §6.2 表格 + §6.2.1 重写（两方向对照表
+ 为什么拉取侧不能自然涌现）。

**教训（已写进 MEMORY.md）**：涉及方向/分支枚举的能力，必须逐条点名验证；「路径 A 实现了 X」
≠「X 覆盖所有路径」。`pushToNeighbor` 与 `pullFromNeighbor` 是两份独立实现。

## 追加：跨容器能力覆盖矩阵全量审计（同类漏项排查）

顺着同一类风险把 `CrossContainerTransfer` 四个方向格扫了一遍，结论（已固化进
`living-hopper-tech.md` §6.2.2）：

- **结构规则**：特殊槽位识别只在 `containerCtx` 一侧生效——本容器侧走
  `SlotAccessorFactory.create`（注册式 Provider 认活箱子/活末影箱，且先拦其它活物品）；
  邻居侧走 `createForNeighbor`（只认裸 IItemHandler）。**邻居侧没有访问器工厂**，
  这就是施肥在推送侧「自然涌现」（靠 `neighborStack.is(FARMLAND)` 自己认）、
  拉取侧必须显式补分支的根本原因。
- 覆盖矩阵：本容器侧特殊槽位（不论当源还是目标）都有支持；邻居侧特殊槽位默认全不支持。
  活箱子/活末影箱作源或作目标在「邻居侧」的 4 个 ✗ 格子是既有的、未被需求触发的设计边界
  （活箱子虚拟存储只对同容器展开），不是本次 bug 的同型漏项——**本次施肥是唯一一处
  「声称覆盖跨容器、实际只覆盖单向」的能力**。
- 新增面向邻居侧特殊槽位的能力（浇水/喂养等）时的三处点名清单已写进 §6.2.2。

## 追加：重构自引入的回归——「活骨粉施肥失效」（自查发现并修复）

**现象**（重构后自查，用户尚未实测）：容器内路径「活骨粉 → 活耕地」不再施肥。

**根因**：交互分发用 `SlotAccessorFactory.create` 拿源槽 Accessor，而该工厂开头就拦掉
**非箱类活物品**（`return null`）——活骨粉正是活物品 → `tryInteract(null, ...)` 恒 false。
普通骨粉不受影响，所以只测普通骨粉的用例全绿，掩盖了这条路径（
`FertilizeTransferTest.fertilize_livingBonemeal_alsoWorks` 测的是 `tryFertilize` 本身，
不经过工厂，也盖不住）。

**修复**：新增 `SlotAccessorFactory.createForInteraction(ctx, slot, filter, transferred)`
（PlainSlotAccessor + FilteredSlotAccessor，**不拦活物品**；只读源槽自身物品，不展开
活箱子虚拟存储），容器内交互改用它；同时把 `server`/通用 accessor 的创建还原到原来的
守卫之后（减小 diff）。**活物品隔离规则本身未动**（`create` 行为不变）。

**测试**：新增 `SlotInteractionFactoryTest`（4 项）——`create` 仍拦活物品（隔离不被破坏）、
`createForInteraction` 放行活骨粉、容器内活骨粉施肥端到端、普通骨粉无回归。
全量 **280 项全绿**。

**附带统一**：三处交互源槽现在都带 `FilterData`（黑白名单是漏斗货物筛选口径，交互同样是
消耗货物）；容器内路径原先在过滤检查之前，属代码位置产物，收编时统一。

**发现的既有边界（未修，已写进文档）**：跨容器**推送**方向源槽装活物品货物（含活骨粉）时，
`pushToNeighbor` 的活物品隔离守卫会先行 return false → 该方向不施肥。要统一得把守卫挪到
「交互分发之后 + 通用插入之前」，会同时放开活物品被推送的风险，故暂不动，只在
hopper §6.2.1 + farmland §7.1 标注边界。

**教训**：重构「提取公共入口」时，**要逐个检查原调用点的隐式前提是否被新入口继承**——
本例的隐式前提是「交互货物不经过 `SlotAccessorFactory` 的活物品守卫」。测试只覆盖
公共逻辑（`tryFertilize`）而没覆盖调用点装配（工厂选型），就会全绿而回归。

## 追加：活骨粉四方向统一（用户追问「输入槽是活骨粉会给活耕地施肥吗」）

**原先行为**（分方向）：容器内 ✓、跨容器拉取 ✓、跨容器推送 ✗、邻居间直传 ✗。
后两者在**进入交互分发之前**就被活物品隔离规则挡掉——`pushToNeighbor` 顶部
`if (!chest && !enderChest && isLivingItem(sourceStack)) return false;`，
`transferBetweenNeighbors` 源邻居循环 `if (... || isLivingItem(sourceStack)) continue;`。
与文档口径「普通/活骨粉统一放行」不符。

**统一做法**：把「隔离」与「交互」两件事分开——**隔离管运输，交互管消耗**。

- `tryPushToNeighbor` 新增 `interactionOnly = isLivingItem(cargo) && !活箱子 && !活末影箱`
  分支：交互未命中即 `continue`，**活物品永不进入 `SlotAccessor.transfer`**（连同种
  普通堆也不合并）。方法改包级可见以便单测直接驱动。
- `pushToNeighbor`：删掉顶部提前 `return false`，活物品货物改用
  `createForInteraction` 拿源槽访问器（工厂会拦活物品）。
- `transferBetweenNeighbors`：源邻居循环删掉 `isLivingItem` 跳过（隔离由上面的分支保证）。
- 测试 +5（推送方向：活骨粉施肥生效 / 普通骨粉照常插入 / 不入空槽 / 不与同种普通堆合并 /
  活熔炉全拒）。全量 **286 项全绿**。
- 文档：hopper §6.2.1 换成「活物品货物：交互放行、传输照旧隔离」方向表 + 红线说明；
  §6.2.2 矩阵加两行（活物品货物交互 / 活物品作普通货物被传输）；farmland §7.1 边界提示
  改为 ✅ 四方向可用；§10.3 测试行 14 项。

**口径沉淀**：活物品的「不可传输」是运输层规则，不应成为交互层的准入条件；
新增交互时若货物可能是活物品，必须确认调用点没有在分发之前粗判活物品。
