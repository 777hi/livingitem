## 新增：放置活耕地回世界 → 自动种下自带作物

**需求（用户原话）**：「放置有种子的活耕地，会自动种下该种子。」澄清后 = 把一块**已种植**的
活耕地物品**放置到世界中**，放置出的耕地上直接长出那株作物。

### 设计演进（用户三轮定调，最终形态比初版简单得多）

1. **初版（已否决）**：`CropClassifier.getBlockFromSeed` + `stateForAge` + `level.setBlock`
   —— 硬塞方块。
2. **用户指出致命问题**：这会**绕过模组自己的种植校验**（如「水稻只能在水下种」）。
   → 改为**模拟玩家右键**：构造 `UseOnContext` 调 `ItemStack.useOn`。
3. **用户要求做减法**：「简单、鲁棒、兼容优先，只做最核心的逻辑」「不管成熟度」。
   → 砍掉多格作物上部件/柱段、`canSurvive`、`displayStateFor`、主格被占的种子掉落兜底、
   纯函数拆分；`age` 整块消失（原版种下天然 age 0）。
4. **用户定性为「软逻辑」**：「能种上就好，种不上不出 bug 就好」
   → 整段兜 try/catch + WARN 日志；失败静默不补偿。

**连锁收益**：用 `useOn` 后连 `CropClassifier`、`canBeReplaced` 检查、`is(Blocks.FARMLAND)`
检查**都不需要了**（种子自己的 `canSurvive` 校验下方是耕地）—— 方案同时变简单和变兼容。

### 三个坑（都实际踩到/拦到，已写进 farmland §11.16）

1. **不能注入 `@At("RETURN")`**：`place` 末尾才 `consume(1)`，而空栈的 `getComponents()`

   → 锚在 `consume` 之前（已核对 `BlockItem.java` 全文仅 1 处 `consume`，无需 `ordinal`）。
2. **`Level.isClientSide` 是 `public final` 字段**，不是方法（方法只是读它）。Mockito
   只 mock 方法 ⇒ 我最初写字段式导致**单测里客户端守卫永远不触发**（测试红但代码看着对）。
   → 改用方法式 `level.isClientSide()`（语义等价，项目里 `EnderRouteManager` 已是此风格）。
3. **别自己 `setBlock`**（见设计演进 2）。

## 修复：活耕地种子图标在 HUD 快捷栏不渲染

**用户报告**：「活耕地的种子图标渲染在玩家快捷栏里，当玩家不打开背包的时候不渲染」。

**根因**：种子图标画在 `client/mixin/AbstractContainerScreenMixin.java` 的
`living_item$renderFarmlandCrops`（`@Inject(render, at=TAIL)`），这段代码**硬依赖
`leftPos`/`topPos`**——只有 `AbstractContainerScreen` 才有。而 **HUD 快捷栏**走
`Gui.renderHotbar` → `Gui.renderSlot` → `GuiGraphics.renderItemDecorations`
→ `ItemDecoratorHandler`，**从不经过 `AbstractContainerScreen`** ⇒ 永远不画。

**修复**：迁到 `IItemDecorator`（`client/render/LivingFarmlandSeedDecorator`，自抬 z=200）。
支点（已核源码）：`GuiGraphics.renderItemDecorations` 的**最后一行**就是
`ItemDecoratorHandler.of(stack).render(...)`，且容器 GUI 的 `renderSlotContents:307`
也调它 ⇒ **一份装饰器代码覆盖快捷栏 / 容器 GUI / 创造物品栏 / 副手槽，只画一次**。
容器 Mixin 里那段重复 blit 已删（`-24/+11`）；**生长槽大图保留**——它需要「同容器正上方
一格槽位」的邻居关系（`living_item$findSlotAbove`），装饰器只拿得到 `xOffset/yOffset`。

**三处易错契约**（都写进了 icon-system.md「种子图标改走装饰器路径」）：

1. 装饰器坐标 = **「在当前 pose 内 `translate(xOffset, yOffset, z)`」**。容器传的是
   `slot.x/slot.y`（**未加** `leftPos`——`renderSlot` 已 `translate(leftPos, topPos, 0)`）；
   快捷栏传绝对坐标（pose 为 identity）。**装饰器绝不能自己再加 `leftPos`**。
2. z 基准：容器 `renderSlot` 有 `translate(0,0,100)` ⇒ z=200 → **净 300**
   （正是旧注释里「z=300 才可见」的那个值）；快捷栏 pose 为 identity ⇒ 净 200。
3. `ItemDecoratorHandler` 每次调用前 `resetRenderState()`（**开**深度测试 + 开 blend），
   返回后 `restoreGlState` ⇒ **装饰器里不要写 `RenderSystem`**，旧 TAIL 版的
   `disableDepthTest()` 无法照搬。

**测试**：新增 `client/render/LivingFarmlandSeedDecoratorTest`（4 项，把 `shouldRenderSeed`
抽成包级静态供单测——装饰器按 `Item` 注册，会对**所有** FARMLAND 调用，守卫必须完整）。
全量 **297 用例全绿**（293 + 4）。客户端包下的单测在 FML 测试环境可正常编译运行。

**文档**：`icon-system.md`（三层架构 Layer 3 示例 + §5 表格**补上缺失的活耕地行** +
新增「种子图标改走装饰器路径」小节 + 关键文件表）；`living-farmland-tech.md` v1.11
（§1.2 决策表 / §8.2 / §10.1 / §10.2 / §10.3 / §12.3）；`AGENTS.md`（文件树 client/render 段 +
特性行 + 进展 + 用例总数 293→297）；`CropTextureResolver` javadoc。
