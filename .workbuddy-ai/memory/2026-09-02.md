## 红电系统「网络级共振」设计定稿（讨论完成，尚未实现）
- 背景：电力层锈蚟原本只有「同氧化级连通、异级不互通」的二值网络隔离，功能上无意义（电力可互换，不需要 4 个独立电网）。
- 定稿方案：**锈蚟 = 共振「声部」，共振发生在网络之间而非铜块之上**（把块级感应机制原样升维）。
  - 声部单位 = **锈蚟级**（不是 BFS 连通块）；同锈蚟级的多个连通块出力**直接相加**。
  - 这点不只是简化，而是 `R ≤ 4` 封顶的**结构性前提**——否则玩家把同一锈蚟级拆成多个小簇即可刷 N，退化为 N×(N-1) 膨胀。
- 公式（各锈蚟级基础出力 `ema[k]`，k=0..3）：
  - `N = |{k : ema[k] > 0}| ∈ [1,4]`
  - `s = (Π Aₖ)^(1/N) ÷ (Σ Aₖ / N)`（几何平均 ÷ 算术平均，全部相等时=1）
  - `R = 1 + (N − 1) × s`，`R ∈ [1,4]`
  - **容器本 tick 总发电 = (Σ baseRe[k]) × R^exp，`exp` 先取 2（满共振 ×16），留作常量待实测调整**
- 铁律（安全性的核心）：
  - **共振只读「共振前」基础值，单遍前馈，绝不回代**——A 出力变大不得再回灌影响 A。
  - **每锈蚟级 EMA 只跟踪基础出力**，若吃乘过 R 的值会形成 `R↑→EMA↑→s变→R变` 回代环。
  - R 用平滑 EMA 计算（避免逐 tick 跳变导致闪烁），作用于本 tick 实际基础出力。
- 强度校准：满共振 ×16 看似激进，但**真正的成本大头是材料获取**——集齐 4 种锈蚀的涂蜡铜块需养蜂取蜜脾 + 逐级风化（时间门槛，逐级变慢）+ 逐级涂蜡收集，是递进式养成门槛而非重复建造成本；且「各网出力须平衡」意味着**共鸣上限被最稀有的氧化级卡住**，与 GM/AM 的短板效应一致。故超线性奖励（R²）对应超线性成本，合理。
- 待修文档问题：`docs/红电系统.md` §3.2（约第 600 行）表格仍写电力层锈蚟 =「耦合强度 强→弱（1.0/0.7/0.5/0.35）」，属 v17.1 过期文字。实际实现为二值网络隔离（代码 `LivingWaxedCopperFunction:278` `getOxidationLevel != genOxidation → continue`，`PowerMath` 无任何氧化级系数）。实现共振时需一并改写为新语义。

- 机制：`runBfs` 从发电机 slot 扫描整个同锈蚀级铜块网络，每条 `(slot,dir)` 边一个独立 `SignalTracker`（edgeKey = slot<<2|dir）；红石传播延迟 + 网络拓扑让不同边在不同 tick 上升 → 不同相位 → 去重后 n 可远大于 4。

- 边界：若网络中多边同步上升（同 tick 相位相同），`deltaByOffset.merge` 合并 → n 塌成 1，无增益；真正增益需拓扑制造相位差。n=7 说明拓扑确实制造了 7 个不同相位。
- 可作活铜块网络玩法亮点（被动多相，玩家无需专门设计，搭够大网络自然多相）。

## 信号层 bug 修复：比较器/中继器输出只能传一格
- 症状：某些情况下活红石比较器（及同类中继器）的输出信号只能传播一格（紧邻下一格亮，再往后全 0）。
- 根因：`ContainerRedstoneData.calculate` 多阶段传播。phase1 把比较器当源收集（`phase1CollectSources` 行 412），但 `if (output <= 0) continue`——比较器输出依赖后方输入（粉链），而粉链要到 phase2 才传播，故 phase1 误判输出 0 并跳过入队。phase3/phase4 重算输出但 `powerConductiveNeighbor`（行 811）早退掩码 `MASK_REDSTONE` 含 `BIT_DUST|BIT_COPPER`，把比较器输出进 dust/copper 网络的路掐掉，且其后 `if (is(n2, BIT_DUST)) secondQueue.add(n2)` 是死代码（到不了）。结果：输出只写到比较器自身共享边 → 紧邻一格亮（共享边被显示读到），但下游不入队 → 不续传。

## 信号层边模型重构：共享边 → 每槽自有出边（v15，本轮）
- 决策（用户已批）：增量抽象层策略 + 本次一并删除 phase3 比较器 `!=` 兜底。
- Step A（input 抽象层）：`ContainerRedstoneData` 新增 `inputAt/maxInputOfSlot/anyInputOfSlot/oppositeDir` 助手，把所有「读某槽某方向受到的信号」调用点（phase2 粉/铜/雕刻/切制、phase3 格栅/铜灯、phase4 粉/铜、phase5 粉显示/红石灯/铜信号、比较器侧输入 `edgeGrid.get(slot,sideDir)`）全部迁移到 `inputAt`。抽象层内部 `inputAt(slot,dir)=edgeGrid.get(neighbor,oppositeDir(dir))`。Step A 合入后 `ContainerRedstoneDataTest` 全绿（16 例），证明行为等价。
- Step B（翻 EdgeGrid 存储）：`EdgeGrid` 内 `hEdges[height*(W+1)] + vEdges[(H+1)*W]` → `edges[slotCount*4]`，`get/set/maxOfSlot/anyOfSlot/zero` 改为返回本槽出边 `edges[slot*4+dir]`。写方（phase1 源、propagateDir、powerConductiveNeighbor）本就写「自己朝 dir 发出的出边」，无需改动；`computeFaceOutput` 改为读边界槽位出边（顶行 E_UP / 底行 E_DOWN / 左列 E_LEFT / 右列 E_RIGHT）。同步删掉 EdgeGrid 上过时的共享边 doc 注释。
- 配套清理（phase3 比较器 `!=` 兜底删除）：比较器出边写值从 phase3 `if(output!=edgeGrid.get(slot,outDir)) set(...)` 移到 phase4 `powerConductiveNeighbor` 前 `edgeGrid.set(slot,outDir,output)`（可抬可压）。原因：共享边下 `!=` 会误压下游粉 -1 衰减信号；每槽出边下该出边只归比较器自己所有无污染，且关闭时出边归零→下游粉下一 tick 经 maxInput 自然衰减（避免「卡在高电平」回归）。注：phase4 在 calculate 流程里早于 phase3 执行，故放 phase4 正确。

## 信号层稳态跳过优化（steady-state skip，本轮落地）
- 目标：物品修订计数 + 外部输入签名（Arrays.hashCode(faceInput)）+ 无在途倒计时定时器（中继器 delayTimer/按钮 pulseTimer）三者都不变时，复用 edgeGrid 跳过整段 calculate（含 BFS），省开销。
- 状态字段：`everCalculated/lastRev/lastExternalSig/lastHadActiveTimers/steadySkipCount`（`ContainerRedstoneData` 跨 tick 持久）。跳过判定放 calculate 最前，早退省开销。faceInput 清零已移入 `injectExternalInputs` 开头（因需提前采样外部输入算签名）。
- **关键坑（已修）**：`recordSteadyState` 原先记录方法开头采样的 `rev`，但传播过程中 phase5/phase3 经 `syncSlotToClients` 会 bump 修订计数（生产契约：就地变更走 syncSlotToClients(bump)）→ `lastRev` 落后一拍，下一拍开头采到的 rev 永远与之不等，稳态跳过几乎无法触发（测试表现为：期望跳 2 次只跳 1 次 / 期望归零后跳 1 次实际 0 次）。**修复：`recordSteadyState(context,...)` 改为重采样重算后的 `getContainerRevision(context)`，与下一拍开头采样对齐**。
- 安全性不变量：物品变更 bump rev（跳过被打破）、邻居/原版红石变化改变 externalSig（打破）、唯一不受两者驱动的逐 tick 演化是定时器倒计时（用 lastHadActiveTimers 保险，倒计时在跑就强制重算，绝不冻结时序）。跳过时不调 syncSlotToClients → rev 稳定，故可连续多 tick 跳过。
- 测试：`ContainerRedstoneDataTest` 新增 `steadyState_skipsWhenUnchanged`（红石块+粉链，物品不变连跳 2 tick、移除末端 rev 变强制重算）、`steadyState_noSkipWhileRepeaterCountingDown`（倒计时期间恒 0 跳过、归零后稳态才跳 1）。
- 验证：`./gradlew test --offline` 全量 **135 例，0 失败 0 错误**，BUILD SUCCESSFUL。
