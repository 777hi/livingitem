# 2026-09-07

## 相位波形图 → 相位圆盘重构（v19.2）

**背景**：用户反馈涂蜡发电机高级 tooltip 的相位波形图"除了样子是个波以外没有信息量"，
相数一多波形拥挤。诊断后发现比预期更严重——旧 `renderScope` 画的 n 条正弦
**三个自由度全是写死的**：相位 `2π·ph/n`（均匀错开，非真实 offset）、
振幅恒为面板半高（非 √|Δ|）、横轴固定 2 个周期（非真实 P）。纯装饰。

**更硬的根因**：真实 offset **根本没传到客户端**。
`collectDomains` 取 `d.deltaByOffset().values()` —— HashMap 值视图，
顺序是哈希序，且 offset 本身被丢弃只留 δ 值。
`DomainSnapshot` 注释写的"按偏移升序"是错的。

### 改动

1. `ChannelState.PhaseDomain.phasesSorted()`：新增，返回按 offset 升序的
   `(offset, maxDelta)` 列表。**凡要求顺序/offset 的消费者一律走这里**，
   不要用 `deltaByOffset()`（已在 tooltip-system.md 坑清单 §7.11 记录）。
2. `DomainSnapshot` 增加 `offsets`（与 `deltas` 一一对应、升序），
   CODEC / STREAM_CODEC 同步；新增派生读数 `minPhaseGap()`（环形最小相位间隔，
   含跨周期回绕，<2 路返回 -1）。
3. `LivingWaxedGeneratorData.bestDomain()`：按 `period == detectedPeriod` 定位最佳域。
   **唯一性由构造保证**——`domains` 来自 `period → PhaseDomain` 映射，period 在域集合内
   唯一，因此不需要额外的 best 标记字段。
4. `LivingWaxedCopperTooltipComponent` 增加 `unlockPermille / phaseOffsets / phaseDeltas / minPhaseGap`。
5. 渲染器重写：左半区**相位圆盘**（一周=P，辐条角度=φᵢ、长度=√|Δᵢ|、外弧=解锁度 u、
   12 点小方点=φ=0），下半区**相位展开条**（柱高之和 = Σ√|Δᵢ| = 合因子底数）。
   面板 172×62 → **172×112**。GuiGraphics 只有矩形 fill，圆/弧/斜线自己写了
   中点画圆 + Bresenham + 参数化圆弧三个逐像素 helper。
6. 文本层域快照行改显示 `φ=3:16` 配对 + `Δφ=2t`。

### 设计约束（改动前必须理解，否则会画错）

- **辐条不是箭头**：合因子用**标量求和** `Σ√|Δᵢ|`，相位只通过 n（去重计数）与
  调谐效率参与，**不做矢量相加**。画成箭头会暗示不存在的物理。
- **相位分布不影响收益**：n 路均匀分布 vs 挤成一坨，`u = eff×n/pref` 完全相同，
  每周期总跳变数也相同。圆盘的价值是**诊断**（为什么 n 没涨）不是优化目标。
- 拥挤行为：辐条各自占用独立角度扇区，n=16（r=28）相邻间隔约 11px 仍可分辨；
  更大靠 `Δφ` 数字兜底。两路相位极近时辐条真实贴合——这是特性不是缺陷。

### 复查时发现的第二个真 bug：标签行碰撞

`renderImage` 原来把「锈级 N/4」写死在 `x + BAR_X - 2`。长周期时左侧
`P=1200t n=64 Δφ=1200t` 会变长到 ~120px，从 x=5 起画会顶到右侧标签。
修法：右侧标签改为**右对齐**（`PANEL_W - 5 - font.width(...)`），
仍然撞上就**丢弃 Δφ 后缀**（它在 F3+H 域快照文本行里同样有，不是唯一出口）。

### 验证

`gradlew test`（全量）→ **201 项全绿，0 失败 0 错误 0 跳过**（改前基线 199）。
新增 6 项，全在 `ChannelStateTest`（5 → 10 项）：

1. `phasesSorted` 升序 + (offset, |Δ|) 同序配对 —— 特意选 HashMap 桶序 ≠ 数值序的
   offset 集合 {37,5,61,20}（桶序 20→37→5→61），忘了排序会立刻被抓。
2. `minPhaseGap` 环形回绕（P=10、φ={0,7} → 3）。
3. `minPhaseGap` <2 路 → -1。
4. `DomainSnapshot` codec 往返保留 offsets/deltas —— 守住「忘了把新字段接进
   RecordCodecBuilder」这个静默失败（不编译报错，只静默变空列表）。
   STREAM_CODEC 共用同一份字段清单，一并被覆盖。
5. `bestDomain()` 按 period 唯一定位 —— **故意把最佳域（P=20）放在列表第二位**，
   「取首项」的偷懒实现会立刻失败；同时锁住「圆盘画的域 = 顶层数字读数的域」。

**遗留**：`DomainSnapshot.STREAM_CODEC` 本身没有往返单测——
构造 `RegistryFriendlyByteBuf` 需要 RegistryAccess，测试里不好拿。
若以后要动 STREAM_CODEC 字段顺序，手工核对它与 record 声明顺序一致
（当前：period, n, maxDelta, effDeltaSum, offsets, deltas）。

**已知边界（未修，接受）**：极端大周期（P ≳ 160）时展开条 slotW < 1px，
相邻 tick 的相位会画到同一像素；圆盘同理（角度分辨率 2π/P 在 r=28 下不足 1px）。
两者都是「分辨率所限的诚实合并」，精确值由 `Δφ` 数字兜底，故不做特殊处理。

`build/libs/living_item-1.21.1-1.3.2.jar`（821 KB）。
