## 许可合规审查：原版纹理再分发风险（LICENSE.txt）

**背景**：用户问 `LICENSE.txt`（ARR）下的资源文件会不会有问题。用户已确认：纹理是**直接复制粘贴的原版游戏纹理**。

**实测结论**（`assets/living_item/textures/` 共 72 张 PNG，对照本机 fabric-loom 的 1.21.1 client jar 3070 张原版纹理）：

- 合计 **约 33 张（46%）是原版副本**。
- 其余为改动版/自绘：`waxed_*` 系列、`waxed_*_bulb_lit`、`living_map`、`chest`、`ender`、`redstone_torch(_off)`、`hopper_base/arrow_*`、`chiseled_copper_input/output` 等。
- `assets/minecraft/` 下**没有**任何实际文件（只有一个空目录 `models/item/`）⇒ 本项目**没有覆盖原版资源**，只是**打包了原版纹理的副本**。

**合规要点**（Minecraft Usage Guidelines 官方原文）：
- assets 定义 = "the code, software, graphics, textures, images, models, sounds and other audio from any of our games"。
- "Do not redistribute our games or any alterations of our games or game files"。
- Mod 定义要求 "an original plug-in ... that doesn't contain a substantial part of our copyrightable code or content"。
- "All rights ... in the name, brand, assets, and any derivatives are and will remain owned by Mojang and Microsoft" ⇒ **改动版（如 waxed_* 改色）也仍是 Mojang 的衍生物**。
- 对外分享（**即便免费**）即算 commercial use，须遵守 Commercial Use 准则。

**风险判读**：Mojang 实际起诉 mod 作者的概率极低；真正的硬伤是 **ARR 协议对这批纹理无效**（不能许可自己不拥有的东西）——第 1/3/6/7 条主张的权利在纹理上站不住脚。

**建议方案（按性价比）**：
1. **首选**：模型 JSON 把 `"layer0": "living_item:item/copper_block"` 改成 `"layer0": "minecraft:block/copper_block"`，然后删掉对应 PNG。零再分发、画面不变、体积变小。副作用：会跟随资源包（玩家改铜块材质，活铜块跟着变）。
2. 衍生物（`waxed_*` 等）要么彻底自绘，要么运行时从原版纹理 tint 生成。
3. 兜底：`LICENSE.txt` 加 NOTICE，声明 Minecraft 纹理版权归 Mojang/Microsoft、本许可不覆盖。

**工具侧方法论**：纹理来源比对用「raw MD5 + RGBA 像素 MD5」两级；**不要用 `ImageChops.difference().getbbox()` 判同**（曾误报：多张不同原版纹理同时被判 IDENTICAL，实际是 Pillow 惰性加载 + 缓存导致的假阳）。

## 许可证方向讨论（未决，用户诉求已明确）

**用户诉求原话**：「我其实想要 mit 的开放，但又想保护一下代码喵。毕竟是我想了很久的喵」

**关键澄清（要反复强调）**：**版权不保护「想法/架构/玩法设计」，只保护表达**。用户「想了好久」的

structures」**无法举证，等于没有**。

**已给建议（推荐 MPL-2.0）**：
- MIT 唯一放弃的是「允许别人闭源拿走、改完不还、甚至卖钱」；**署名义务所有主流协议都有**，
  「想被记住是谁写的」MIT 就已满足。
- ⚠️ **MC 生态特殊约束**：GPL 链接闭源 Minecraft 存在合规争议（FSF 视角），社区普遍避开 GPL，
  折中一般用 **MPL-2.0**（文件级 copyleft）或 **LGPL-3.0**。
- **分层授权**是更贴合的做法：代码 MPL/MIT + **美术资源单独许可**（ARR / CC BY-NC-ND）+
  API 层 MIT + 译文无限制。理由：抄纹理的概率远高于抄代码。
- 若要「现在保护、将来开放」⇒ BUSL（Business Source License，到期自动转 MIT/Apache）。
- 若核心是不许商用 ⇒ PolyForm Noncommercial（源码可见，非 OSI 开源）。
- **自定义协议的三宗罪**：平台不认、别人不敢依赖、整合包作者犹豫；且条款模糊时无法执行。

## MIT 对照与 Commons Clause（2026-09-21，用户回退到「先看 MIT」）

用户原话：「算了喵，不管这么多了喵，看看 mit 协议怎么说的喵」—— 从 §8 细节退回，重新评估 MIT。

**MIT 官方原文（opensource.org，已逐字核对）只有三段**：
1. 授权：`use, copy, modify, merge, publish, distribute, sublicense, and/or sell` + `deal in the Software without restriction`
2. **唯一义务**：`The above copyright notice and this permission notice shall be included in all copies or substantial portions of the Software.`
3. 免责：`AS IS`。

**结论：MIT 满足「开放可读 + 必须署名」，明确放弃「禁止商用 + 防闭源白嫖」** ——
`sublicense` 允许换协议（放进闭源项目），`sell` 明文允许售卖。与用户诉求冲突。
（另注：MIT **无专利授权、无商标授权**，这是它相对 Apache-2.0 的短板。）

**⭐ 中间方案：MIT + Commons Clause v1.0**（已拉取 commonsclause.com 原文）：
- Commons Clause 是在既有开源协议上叠加的**窄幅商业限制**，只禁 **"Sell"** 一种行为。
- `"Sell"` 定义 = 向第三方**收费**提供「其价值**完全或实质**来自本软件功能」的产品/服务
  （含托管费、咨询/支持费）。
- **关键：只禁「卖这个软件本身」**；在其上做产品、嵌入再分发、SaaS 售卖**都允许**，
  只要加了实质价值。改个名就卖 = 不允许。
- Commons Clause 官方明确声明 **"Is this Open Source? — No."**（不满足 OSD 全部条款）。
- ⇒ 对用户的诉求**只覆盖一部分**：挡住「改名转卖」，挡不住「闭源白嫖」，也挡不住
  「付费服务器拿它当卖点」以外的商业利用。

**三方案对照（开放可读 / 必须署名 / 禁止商用 / 防闭源白嫖）**：
- 纯 MIT：✅ ✅ ❌ ❌
- MIT + Commons Clause：✅ ✅ ⚠️部分（只禁卖）❌
- 当前自定义协议（已落地）：✅ ✅ ✅ ✅

**结论与建议**：若坚持「禁商用 + 防白嫖」，**当前这份自定义协议仍是最优解，不必换成 MIT**；
MIT 的价值只在「生态最友好、零解释成本」。用户尚未决定是否切换。

## MC 生态自定义协议先例（2026-09-21 查证，供日后参考）

用户问「有没有其它模组的协议是类似本模组的」。已联网查证并逐字读取原文：

| 模组 | 协议 | 禁售 | 衍生须开源 |
|---|---|---|---|
| **Create 机械动力** | MIT 代码 + 美术 ARR（`LICENSE.md` 分节式） | ✗ | ✗ |
| **Botania 植物魔法** | **Botania License**（自定义，`botaniamod.net/license.html`） | ✓ | ✓（Copyleft 条款） |
| **Immersive Engineering** | **Blu's License of Common Sense** | ✓ | ✓ |
| **Thermal 系列 / 龙之进化** | **CoFH "Don't Be A Jerk" v2** | ✓ | ✓ |
| **Sodium / Sable** | PolyForm Shield 1.0.0（现成标准文本） | 禁竞品 | ✗ |

**⭐ 结论：自定义 source-available 协议在 MC 生态是主流做法**，有体量的模组大量在用
⇒ 用户的路线完全在生态惯例内，不必有心理负担。

**Botania License 结构（最讲究，值得借鉴）**：按使用场景**三分法** ——
`Distribute`（再分发）/ `Feature`（展示，如实况视频）/ `Use Code or Assets`（使用代码或素材），
每个场景下挂不同条款。含：
- **Non-Monetary 条款**：不得对分发本身收费、不得靠它赚钱（含 adf.ly 短链、广告减速、paywall）；
  但**服务器内售卖游戏内物品不算**（归 Mojang ToS 管）。
- **Copyleft 条款**：用了代码/素材 ⇒ 你的项目必须开源且含类似条款。
- **API 条款**：`src/main/java/vazkii/botania/api` 下的 API 代码豁免上述条款，但必须原样包含。
- ⭐ **Informal 条款**（很有意思）：*"This license will not hold up in court. I have no intention of
  suing anyone for breaking it"* —— 作者直白承认协议在法庭上站不住脚、也不打算起诉。
  **这种坦诚反而让协议更好用**（靠社区舆论 + 平台下架机制而非诉讼）。

**Immersive Engineering（Blu's License of Common Sense）**：
- 可：看代码、借鉴、抄片段、fork 改、提 PR、**做附属模组**。
- 不可：声称是自己的、未经许可再分发、抄大段不署名、**monetize**（原文明确点名
  *"selling the code, compiled projects and also forbids the use of paywalls or 'donations' to
  restrict access"*，但**豁免 CurseForge Points 系统**）。
- 必须：用了它的代码（API 类除外）⇒ 你的项目必须**源码可见**；抄了要署名。
- 素材：必须给原作者署名、复制素材前须获许可；**附属模组可为附属目的 remix 美术素材**。
- 末尾同样有 Wheaton's Law（"别当混蛋"）式的撤销权保留。

**CoFH "Don't Be A Jerk" v2**：ARR 底子（仓库无 LICENSE 文件，靠 README 声明）。
- CAN：fork 改 / 提 PR / 抄部分代码 / 写依赖它的附属。
- CANNOT：**整体再分发**（源码或编译物）/ 复制 ≥50% "Functionally Equivalent Statements"。
- MUST：用了就得**保持源码可见**；不得声称所有权；不得未经许可再分发。

⚠️ **用户明确要求：协议里不要提 paywall / 付费整合包 / 付费服务器 / 商用这类灰色字眼**
⇒ 所以**不能建议照搬 IE 的 paywall 措辞**，尽管它很精准。用户现版协议比上表所有先例都**宽松**
（唯一放行闭源的一条）。
