# 2026-09-01

## 活末影箱「玩家绑定频道」需求 —— 架构分析（未实现）

需求（TODO.MD 活末影箱 #1）：绑定玩家的活末影箱，堆叠数=1 时直连玩家末影箱；堆叠数≥2 时变为该玩家专属频道。
用户已确认阈值：**≥2 变专属频道**（非 >2）。

### 核心结论
本质是**频道键从 `int` 升维为复合键** `EnderChannelKey(@Nullable UUID owner, int count)`，`owner == null` 表示公共频道。
牵连约 8 个文件：`EnderChannelRegistry`（`channels` / `entryToChannel` / `dirtyChannels` 三个 Map/Set 的键 + 全部方法签名）、
`EnderChannelSyncPacket`、`EnderChannelClientCache`、`EnderRouteManager`、`LivingEnderChestAccessor`、`LivingEnderChestFunction`、`zh_cn.json`/`en_us.json`。

### 已定位的坑（读代码确认，非推测）
1. **`filterData` 在绑定分支被丢弃** —— `LivingEnderChestAccessor.tryCreate()` 绑定分支走的构造器把 `filterData` 硬设为 null（旧逻辑：绑定=直连，过滤交给 `FilteredSlotAccessor`）。专属频道是路由模式，过滤要靠 `registry.peek(channel, filterData, ...)`，不修则黑白名单在专属频道完全失效。
2. **路由泄漏** —— `EnderChannelRegistry.shouldRemoveRoute()` 检查 2 只问"槽位上还有没有末影箱"，不问"是不是同一个频道键"。末影箱 count 变化（如 (A,3)→(A,1)）后旧频道路由三条检查全通过，永久残留。修法：`validateRoutes` 第三参数从 `Set<Integer> activeTargetSlots` 升级为 `Map<Integer, EnderChannelKey> targetKeysBySlot`。
3. **同步无登录补偿** —— `LivingItem` 只有 `onServerStarting`/`onServerStopped`/`onChunkUnload`，**没有 `PlayerLoggedIn` 钩子**。改成定向投递后，owner 离线期间的频道清空包发不出去，重连后客户端缓存陈旧。需新增全量快照推送。
4. **客户端缓存零淘汰** —— `EnderChannelClientCache.clear()` / `removeChannel()` 全项目无调用者（grep 只有定义处）。登出时只清了 `LivingMapClientCache`（`LivingItemInputHandler.onClientLoggingOut`）。
5. **`totalRoutes` 语义将被污染** —— 现在是全服所有频道总和，加了专属频道后对玩家是噪音且泄漏私有频道规模。

### 顺带发现（有利）
`EnderChannelRegistry.getChannels()` / `getActiveChannelCount()` / `getChannelSnapshot()` / `getEntries()` / `getChannelSize()` 全项目无外部调用者 → 改签名零成本，可直接删掉前两个。

### 已验证的边界情况
- target 末影箱**永远**在注册者容器内（`CrossContainerTransfer.pullFromNeighbor()` L163 从 `containerCtx` 取 targetStack）→ 改法覆盖全部路径。
- 拆堆一半去别的容器：反向索引按源/注册者容器索引，只会在原容器被检查到 → 被覆盖。
- 跨容器 pull 端断供是共享黑板架构固有特性（push 端末影箱消失即断供），非新引入，不需处理。

### 用户已拍板（三轮问答结论）
1. **阈值**：堆叠数 **≥ 2** 变专属频道（count == 1 直连）。
2. **totalRoutes**：确认它是全服所有频道的总和，**砍掉**。Tooltip 只显示本频道条数。
3. **行为跳变**：允许跳变，Tooltip 明确标注当前是「直连」还是「专属频道 N」。理由：本 mod 一贯哲学是「堆叠数 = 配置旋钮」。
4. **隔离语义（重大澄清）**：**专属频道是命名空间隔离，不是权限隔离。**
   用户原话：「公共频道是一块黑板，专属频道就是另一块黑板，其实并不需要防着其它玩家。
   玩家a有玩家b的专属活末影箱，也是可以使用的。」
   → 绑定信息在 DataComponent 里跟着物品走，**谁持有物品谁就能接入那个频道**，不做持有者鉴权。

### 由结论 4 带来的简化（重要）
- **同步层几乎不用改**：无隐私需求 → `flushDirtyChannels()` 保持广播给所有玩家，
  仍是「构造 1 包 + 发 N 次」，零额外开销。
- **之前论证的「定向投递 + PlayerLoggedIn 全量补偿 + 离线黑洞」全部作废**，不需要了。
- 客户端缓存 key 空间 = 64 × (玩家数+1)，靠 `channelSize == 0` 时 `removeChannel` 回收即可。

### 最终改动清单
1. 新增 `EnderChannelKey(@Nullable UUID owner, int count)` record + `of(ItemStack)` 工厂
2. `EnderChannelRegistry`：3 个容器键类型改 `EnderChannelKey`，约 15 个方法签名；
   删 `getTotalRouteCount()`；删 5 个零调用者查询方法（getChannels/getActiveChannelCount/
   getChannelSnapshot/getEntries/getChannelSize）；`validateRoutes` 第三参数改
   `Map<Integer, EnderChannelKey> targetKeysBySlot`
3. `EnderChannelSyncPacket`：`int channel` → `EnderChannelKey`（编码 boolean+UUID+VarInt）；去 totalRoutes
4. `EnderChannelClientCache`：key 改 `EnderChannelKey`；去 totalRoutes；channelSize==0 时 remove
5. `LivingEnderChestAccessor`：`directMode = boundUuid != null && count == 1`；
   **修绑定分支 filterData 被丢成 null 的 bug**（专属频道是路由模式，过滤靠 registry.peek）
6. `EnderRouteManager`：`isSameChannelGuard` 用 equals；`resolveCrossContainerTarget` 按新三态判定
7. `LivingEnderChestFunction`：tick 构造 targetKeysBySlot；Tooltip 三分支
8. lang `zh_cn.json`/`en_us.json`：改 routes 文案、新增专属频道/直连模式提示
9. 文档 `docs/tech/living-ender-chest-tech.md` 升 v12；`docs/TODO.MD` 划掉活末影箱 #1
