# 修复 φ 相位重进漂移：把相位基准从「容器本地 tickCounter」换成「世界游戏时钟」

## 真正的根因（这次钉死了）

φ 的定义是 `lastRisingTick mod P`，而 `lastRisingTick` 锚定在 `ContainerPowerData.tickCounter` 上——**容器本地计数器，重进后从 0 重新起步**。中继器振荡器的物理相位（delayTimer 落盘，重进续跑）与新的 tickCounter 原点**互不相关**：重进的耗时、区块加载顺序、tick 对齐误差让两个原点错开几 tick。第一个真实上升沿落到新时间轴的位置就变了 → φ 重锚 → tooltip 显示的 φ 变了 → 雕文/切制/格栅基于 φ 派生的额外相位全变。

前两轮修复（warmup / PhaseSnapshot / 首拍无沿）都是真修复——防住了假沿污染，但没发现**坐标系本身重进就换**了。快照存的 φ 是旧坐标系里的值，回填到新坐标系，首个真实跳变一到立刻重锚，快照的 φ 自然作废——这就是「修了和没修一样」的原因。

## 治本方案：相位基准换成世界游戏时钟

`level.getGameTime()` 是**跨会话连续**的（存档里持久化，重进继续递增，单机/多人/区块卸载全场景统一）。振荡器的物理相位本来就由世界 tick 驱动（中继器每 game tick 递减），把 φ 锚到世界时钟上，重进前后就是**同一个坐标系**——同一物理布局算出的 φ 跨会话恒定。

```
改动前：φ = lastRisingTick(容器本地) mod P   → 重进换轴 → φ 变
改动后：φ = lastRisingTick(世界 game time) mod P → 跨会话同轴 → φ 稳定
```

## 实施步骤

### 1. 时间源接入：`TickContext.getOrCreatePowerData` 或 `LivingWaxedCopperFunction.tickContainerData` 取世界 game time
- 容器 Context 已可达 `Level`（`SimpleContainerContext` 持有关联 BE，`be.getLevel()` 现成）；
- `tickContainerData` 开头取 `now = level.getGameTime()`（Level 为 null 的测试环境回退 `powerData.currentTick()`——保持纯 Java 单测可驱动）；
- `powerData.tickCounter` 保留（LRU 心跳等仍用），仅相位链路换轴。

### 2. `ContainerPowerData` 换轴适配
- `endTick()` 保留；新增 `worldTickMode` 无需——`now` 由 glue 层传入，`onRisingEdge(now)`/`PhaseEvent(tick)`/`pruneRegistry(now)` 全部吃同一个传入值，内部零改动即可换轴；
- `aliveWindow` 判定语义不变（世界 tick 同样每容器 tick +1，窗口大小不变）。

### 3. `PhaseSnapshot` 平移基准修正
- `restoreInto` 的 `base = power.currentTick()` 改为 glue 传入的当前世界 tick；快照 `tickCounter` 字段直接存世界 tick；
- 回填后 φ = 世界 tick 下的恒定值，**首个真实跳变到来时 `interval = P` 且 `offset()` 与快照一致**——快照不再作废，真正无缝。

### 4. 测试适配（受影响面已确认）
- 纯 Java 单测（PhaseSnapshotWarmupTest 等）驱动用的 `currentTick()` 语义不变（回退路径），预计零改动或极少；
- E2E 测试（PhaseInterpretation/NetworkTraversal/FeedChain）在无 Level 环境跑——走回退轴，断言不变；
- 新增回归：**「世界轴快照往返」测试**——capture(world tick W) → restore(world tick W+1000) → 断言 φ 不变（这是玩家场景的直接守卫）。

## 为什么这个方案是对的（对比另外两个候选）

- **候选①「快照延续 tickCounter」**：快照存 tickCounter、回填不归零——治标，依赖快照存活；快照缺失（新容器/跨存档拷贝/二次退出窗口）时 φ 仍重锚。且两套计数并存，语义更乱；
- **候选②「中继器状态推算 φ₀」**：理论上最物理，但要从 delayTimer 链反推周期内位置，多形态振荡器（火把环/混合）各有推法，改动大、易错；
- **世界时钟（推荐）**：一处换轴、全部路径（快照/无快照/区块卸载/跨存档）统一修复，物理上就是振荡器的驱动时钟，语义最正。
