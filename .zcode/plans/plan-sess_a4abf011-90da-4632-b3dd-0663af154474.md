# 修复 KC 水稻中/上段不渲染（三段柱状作物通用机制）

## 根因（KC 源码已核实）

KC 水稻与 FD 水稻结构完全不同：**单方块** `kaleidoscope_cookery:rice_crop`（CropBlock 子类）+ `age`(0~7) + **`location`(0=下/1=中/2=上，IntegerProperty)** + `waterlogged`。种下时三格同时放置（`setPlacedBy`）、age 三段同步生长（`updateShape` 从下方邻居拷贝）；每段每 age 各有独立 cross 模型（stage{N}_{down|middle|up}，blockstate 已确认全 24 个变体都映射真实模型）。

我方渲染只有两种上部件模式：原版 `DOUBLE_BLOCK_HALF`（LOWER/UPPER 两值）和 FD `UPPER_CROPS`（两个独立方块）——KC 的「同方块 + IntegerProperty 分段」两者都不命中。`stateForAge` 用默认态 location=DOWN → 第一格正常显示；中/上段 `getUpperCompanion` 返回 null → 不渲染。

**产出侧无恙**（用户确认正常）：`getDrops` 只有 location=DOWN 滚战利品表，我方 `matureStateFor` 默认态恰好就是 DOWN；种子→方块解析走 CropBlock 白名单也通。

## 修复（渲染专用，tick/产出零改动）

### 1. `CropClassifier` 新增 `COLUMN_PARTS` 注册表
- 作物注册名 → 各段「属性覆盖」列表（属性名 → 值字符串）：`kaleidoscope_cookery:rice_crop → [{location:"1"}, {location:"2"}]`
- `getColumnParts(block, age)` 返回 List<BlockState>：`stateForAge` 基础上逐段应用属性覆盖（`Property.getValue(String)` 解析），属性缺失的段静默跳过；未注册返回空表
- `registerColumnParts` 公开扩展点（第三种上部件模式：同方块属性分段，注册名延迟解析软依赖安全——与 UPPER_CROPS 同款）

### 2. mixin `renderCropInGrowthSlot` 渲染柱状段
在既有两格上部件逻辑之后追加：COLUMN_PARTS 各段从生长槽正上方**逐格向上**渲染（findSlotAbove 循环推进，空槽才画、到顶/被占自动截断）。三种模式并存各管各的注册集合，互不干扰。

### 3. 回归测试 CropClassifierTest 补 3 项
- 未注册作物（小麦）getColumnParts 返回空表
- 注册属性覆盖正确应用（用原版方块注册测试条目验证 setValue 生效）
- 属性不存在的段静默跳过不抛异常
