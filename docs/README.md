# 文档系统 —— 维护规约与地图

> **本文是项目级文档系统的唯一规约来源。** 所有 AI 工具（WorkBuddy / Cursor / Trae / Claude Code …）
> 与人都**以本文为准**。工具侧技能只是**适配层**（怎么在这个工具里执行），**不得成为规约的事实来源** ——
> 否则换个工具就看不到、多份规约会各自漂移。
>
> 入口文档是 [AGENTS.md](../AGENTS.md)；本文管「文档系统本身怎么维护」。

---

## 1. 分层与职责

| 层 | 位置 | 职责 | 体量约束 |
|---|---|---|---|
| **入口** | `AGENTS.md` | 项目是什么 + 铁律 + 模块地图 + 文档路由 | **≤20KB**（超出就归档/降级） |
| **术语** | `docs/glossary.md` | 专有名词速查（**新会话先扫这一页**） | 索引与速记；口径以实现层文档为准 |
| **决策** | `docs/decisions.md` | 跨领域决策索引 + **翻转留痕**（supersedes 链） | 索引式：一句话 + 指针，正文留领域文档 |
| 契约 | `docs/system-design/*` | 不变量 · 协议 · 口径（**违反即 bug**） | 不限（不进加载路径） |
| 实现 | `docs/tech/*` | 每子系统：链路 · 数据流 · 踩坑 · 实测清单 | 不限 |
| 指南 | `docs/guides/*` | 通用做法（如何写测试、如何做槽位设计…） | 不限 |
| 参考 | `docs/reference/*` | 详单快照（如 `file-map.md` 文件树、`completed-features.md` 能力清单） | **必须标注「快照、以 X 为准」** |
| 归档 | `docs/archive/*` | 冻结历史（`changelog.md`） | 不限 |
| 工具侧 | AI 工具技能 / `MEMORY.md` | **适配层**：只放「怎么在这个工具里执行」+ 指向仓库的指针 | 见铁律 5 |

**铁律**：
0. **文档的主要读者是 AI**（用户 2026-09-16 明确：「文档基本上都是给 ai 看的」）——
   由此推出下面全部：**写约束不写叙述**、**只写代码里推不出来的**、**断言必须可复算**、
   **索引与正文分离**、**翻转必须留痕**。判断一篇内容该怎么写时，先问「AI 读它会不会被误导」。
1. **入口层只写「路由 + 不可违反的约束」。** 凡能从代码反推的（文件清单 / 方法签名 / 调用链）
   **不进入口** —— 会漂移，且挤占新会话的加载预算。
2. **文档写成约束（不可违反的断言），不要写成描述（可自由解读的叙述）。** AI 会重新诠释描述，
   但绕不过约束。
3. **只写「代码里推不出来的」**：为什么这样决策、踩过什么坑、口径/语义约定、不变量。
4. **数字与路径类断言必须能复算**（给出命令或判据）。不能复算的断言迟早变假。
5. **每份知识都必须在仓库里有归宿**（用户 2026-09-16 明确：用多个 AI 工具开发，
   技能只对当前工具生效）。**发现某个知识点只写在技能或 `MEMORY.md` 里，就迁进 `docs/`** ——
   否则它对其它工具不可见，且随时可能因记忆超限被截断而丢失。
   工具侧只保留「怎么在这个工具里执行」+ 指向仓库的指针。

## 2. 入口文档（AGENTS.md）的规矩

- 体量 **≤20KB**；超出就把历史搬 archive、把详单搬 reference（见 §4/§5）
- 每个章节回答一个「新会话需要知道的问题」：项目是什么 / 架构 / 模块地图 / 已完成功能 / 最近进展 / 去哪读
- 文档路由写成**触发条件**（「改 hopper 传输时读它」），不是文件名罗列

## 3. 新增内容该放哪

```
不可违反的约束 / 不变量 / 协议 / 口径   → docs/system-design/
某子系统的链路 / 数据流 / 踩坑 / 实测清单 → docs/tech/
通用做法（可复用的步骤）                 → docs/guides/
详单快照（文件树、清单）                 → docs/reference/  + 标注「以 X 为准」
冻结的历史                               → docs/archive/changelog.md
决策 + 理由 + 被谁取代                   → docs/decisions/（规划中）
```

**改代码必须同步文档**（本项目铁律「文档即规范」）。新能力至少要有：技术文档小节 + AGENTS.md 进展条目。

## 4. 开发进展归档（周期性任务）

**触发**：入口体量超 **20,000 字符**，或「开发进展」超过 3 个批次。

> ⚠️ **先查冗余，再动历史。** 体量超标的常见真因是**章节重复**而非历史过多 ——
> 2026-09-16 实测：「子系统索引」与「文档导航」内容高度重合（都是「子系统/主题 → 一句话 → 文档」），
> 合并后入口 **20,631 → 18,548 字符，历史一个字没动**。
> 2026-09-18 又一次：「已完成功能」77 项与「子系统索引」**100% 重合**（14/14 关键词两边都有）
> ⇒ 降级搬 `docs/reference/`，入口 **19,756 → 15,896**。**两次都是历史没动、只清冗余。**
> **历史是最有价值的资产，冗余才是负债**：先删重复，再考虑归档。
> **不要靠上调预算来解决体量问题** —— 那等于用余量数字去容纳违反铁律 1（"能反推的不进入口"）
> 的冗余，而入口体量直接就是每个新会话的加载成本。

**步骤**（顺序固定，每步都要校验）：

1. **保留最近 3 个 `**最近更新** (日期):` 批次**，其余迁出
2. **从最旧的批次开始连续迁出** —— 不许跳过中间批次（跳一个 = 那批永久丢失）
3. 迁出内容转成 changelog 体例：`## 日期` + 正文（**同日期多批次要合并**）
4. 插入 `docs/archive/changelog.md` **顶部**（该文件按日期倒序）
5. **守恒校验**（防丢历史的**主**手段）：每段迁出的正文必须能在新 changelog 里**原样找到**
6. **边界单调性校验**：`changelog 最新日期` 必须**早于** `AGENTS 最早日期`
7. 同步更新 AGENTS.md 节首指针（含「更早的记录」日期）

> ⚠️ **不校验日期间隔**（2026-09-22 修订）。**开发是间歇性的 —— 日期间隔本身不含信息**：
> 「隔了 2 天」既可能是没开发、也可能是漏记，从日期上分辨不出来。
> 旧规则要求「跨文件空档 ≤1 天」，两个毛病：① 批次间隔 >1 天时**必然误报**；
> ② 与步骤 1 **互相矛盾** —— 批次相隔 2 天时，迁出最旧一个就必然产生 2 天空档 ⇒ **永远无法归档**。
> 真正会丢历史的只有三件事，已分别由步骤 2 / 5 / 6 覆盖：
> **迁移时跳过批次**、**正文没搬全**、**边界切错**。
> ⇒ **不要再把「空档 ≤N 天」加回来**（`doc_check.py` 里同理）。

> ℹ️ 可选提示（**警告级，不阻断**）：边界相隔 > **30 天**时提醒一句「确认这段没有只在
> `.workbuddy-ai/memory/` 日志里、而没进过 AGENTS/changelog 的工作」。
> 只是提示 —— **一个月没开发完全正常**，别把它读成失败。

**历史教训**：`2026-09-01 ~ 09-04` 曾**断档** —— 那段工作只写在 `.workbuddy-ai/memory/` 日工作日志里
（而日志按策略定期删除），`AGENTS.md` 与 `changelog.md` 都无记录。**归档漏做 = 永久丢历史。**
⇒ 防它的正确手段是**步骤 2（连续迁出）+ 步骤 5（守恒校验）**，**不是**拿日期间隔当证据。

## 5. 降级而非删除

入口瘦身时**搬走，不删掉**：

- **核心文件索引 → 模块地图**：入口只留目录级 + 根级文件；逐文件详单搬 `docs/reference/file-map.md`，
  两处都标注「快照、会漂移，准确清单用 `find src/main -name "*.java"`」
- **大段历史 → `docs/archive/changelog.md`**
- **能力清单 → `docs/reference/completed-features.md`**（2026-09-18）：入口的「已完成功能」
  77 项与「子系统索引」**100% 重合**、且塞满实现细节（违反铁律 1）与过时数字（如"146 项测试"，
  当时实际已 319）⇒ 整章搬 reference，入口只留一句路由「**下方全部子系统均已实现**，
  没列的就是没做」。**入口 19,756 → 15,896 字符，余量 244 → 4,104。**

每一步都做**守恒校验**（搬走的内容能在新家原样找到）。

## 6. 新条目体例（只对新条目生效，不回改历史）

- 一条 = **一行结论 + 指针**：写「做了什么 + 关键约束/坑」，细节写进 `docs/tech/*` 或 `docs/system-design/*`
- **别在入口铺正文** —— 入口是索引，不是档案

## 7. 改完必查

### 7.1 先跑校验脚本（覆盖机械检查）

```bash
python tools/doc_check.py        # 退出码 0 = 通过
```

| 检查 | 说明 |
|---|---|
| 1. 路径真实性 | 文档里的相对链接 / `file://` 链接 / `docs/…`·`src/…` 提及是否真实存在（**归档层豁免**；含「未建 / 待建 / 已删除」的行豁免） |
| 2. 测试条数一致性 | AGENTS.md 声明的条数 vs `build/test-results/test/*.xml` 实测（先 `./gradlew test --rerun`） |
| 3. 测试树一致性 | `file-map.md` 的测试树 vs `src/test` 实际文件 |
| 4. 归档边界 | `changelog 最新日期` 必须**早于** `AGENTS 最早日期`（单调，防边界切错）；**不校验间隔天数**（相隔 >30 天仅提示） |
| 5. 入口体量 | AGENTS.md ≤ 20,000 字符（**警告级**，超了就该归档） |
| 6. 决策取代关系 | `decisions.md` 的 supersedes 链**双向一致**（A 说取代 B ⇒ B 必须说被 A 取代） |

前 4 项与第 6 项失败即退出码 1；第 5 项只警告。

> 该脚本**首次运行就抓出 8 处真实断链**（`红电系统.md` 曾从根目录迁到 `reference/`、后又升级到
> `system-design/`，链接都必须跟着改；
> `living/core/` 包早已重组、`LivingChestContentsPacket` 类名已改）+ 顺带暴露了
> P0 搬运时误删的测试树与测试基线声明 —— **别跳过它。**

### 7.2 脚本覆盖不到的（人工）

- [ ] **守恒**：搬走的内容能在新家原样找到（**逐段**判定，别只验第一块 —— P0 搬运时
      就因只验了第一个代码块，误删了同一章节里的测试树与测试基线声明）
- [ ] 章节结构完整（无断裂、无旧标题残留）
- [ ] **`grep` 扫一遍旧结论**：口径翻转 / 边界变更后，旧表述极易残留在别的文档里
      （常用关键词：`既有边界`、`仍被拦下`、`待复测`、`已知遗留`、`暂不支持`）
      —— 2026-09-16 一次终审修了 7 处这类漂移，其中 1 处 javadoc 与代码**完全相反**
- [ ] 测试条数复核要用 `--rerun`（`FROM-CACHE` 是**假绿**）—— 详见
      [guides/unit-testing.md](guides/unit-testing.md)「全量测试与复核口径」
- [ ] **入口路由抽样验证**：新增能力后，模拟一个新 AI 只从 `AGENTS.md` 出发完成
      「解释这个功能怎么实现 / 排查一个相关 bug」各一题；发现「功能已实现但子系统索引没提」
      就补路由（2026-09-16 活耕地「放置回世界」曾只在更新日志可见，已修）
- [ ] **知识归宿检查**：发现某个知识点**只写在工具侧技能或 `MEMORY.md`** → 迁进 `docs/`。
      判据：`grep -rl "<关键词>" docs/` 无命中 = 无归宿。
      （2026-09-16 迁了 3 项：纹理约定 → `icon-system.md`、相位圆盘渲染像素规约 →
      `tooltip-system.md`、性能判读覆盖盲区 → `living-item-infrastructure.md` §10.3）

**脚本踩坑**：别在 shell 里用 `python -c` 且字符串含**反引号** —— Bash 会把 `` ` `` 当**命令替换**执行掉
（曾把 `` `find ...` `` 直接替换成实际文件路径）。**把脚本写成文件再跑**（`build/xxx.py`），跑完删。
