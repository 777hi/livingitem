# 容器监控 —— 判定口径（契约层）

> *创建: 2026-09-27 · 从 `guides/container-monitor.md` 抽出的**契约部分***
>
> 📄 本文只放「**什么算异常**」的口径（违反即 bug）。
> 使用方式、命令、日志格式、性能影响见 [`../guides/container-monitor.md`](../guides/container-monitor.md)。

---

## 1. 异常类型

| 类型 | 判定 | 严重度 |
|---|---|---|
| `ITEM_DUPLICATION` | 某物品**总数量增加**，无对应来源 | 🔴 严重 |
| `ITEM_LOSS` | 某物品**总数量减少**，无对应去向 | 🔴 严重 |
| `ITEM_DUP_AND_LOSS` | 同时存在复制和丢失 | 🔴 严重 |
| `LIVING_OVERWRITTEN` | **活物品被非活物品覆盖** | 🔴 严重 |

## 2. 计数方式（不变量）

监控器按**物品类型**统计总数量，**不是**按 `物品@堆叠数` 分类
⇒ **堆叠合并不得触发误报**。

| 场景 | 之前 | 之后 | 总数量变化 | 应当报告？ |
|---|---|---|---|---|
| 堆叠合并 | `2x chest@x1` | `1x chest@x2` | 2 → 2 | ✅ **不报告** |
| 物品复制 | `1x chest@x1` | `2x chest@x1` | 1 → 2 | 🔴 `ITEM_DUPLICATION` |
| 物品丢失 | `1x water_bucket@x1` | (empty) | 1 → 0 | 🔴 `ITEM_LOSS` |

> ⭐ 这是最容易写错的一处：若改成按堆叠数比对，「两个 x1 合并成一个 x2」会被误判成
> 「丢失 1 + 复制 1」。任何改动都必须保住「按物品类型统计总量」这条。

## 3. 差异计算流程

```
1. 逐槽位对比，记录 MODIFIED / ADDED / LIVING_OVERWRITTEN
2. 按物品类型对比总数量，计算 gained / lost
3. 存在 gained / lost 或 LIVING_OVERWRITTEN ⇒ 生成异常报告
```

## 4. 快照要求

- 每个槽位取 `ItemStack.copy()`（**深拷贝**）—— 否则后续修改会污染快照，比对结果失真
- 同时记录按物品类型的总数量映射

## 5. 性能约束（契约）

| 场景 | 要求 |
|---|---|
| 监控关闭 | **零开销** —— `isEnabled()` 必须短路返回，不得进入快照逻辑 |
| 监控开启 | 每容器 2 次快照 + 1 次差异计算；仅在调试时开启 |

快照需 `ItemStack.copy()` 每个槽位，对 54 格大箱子有明显开销 —— 因此「关闭时零开销」是硬要求。
