## 0. 为什么（可复算）

```bash
python -c "import io;print(len(io.open('AGENTS.md',encoding='utf-8').read()))"   # 18116 字符
# ⚠️ 必须用 len()（字符），不能用 wc -c（字节）—— 中文一个字 3 字节，差 1.5 倍
python -c "import io;s=io.open('AGENTS.md',encoding='utf-8').read();print(len(s[s.index('## 子系统索引'):s.index('## 模块地图')]))"
```

| 项 | 值 |
|---|---|
| 入口 `AGENTS.md` | **18116 / 20000 ⇒ 余量仅 1884** |
| 其中「子系统索引」段 | **3957 字符（占入口 22%）** |
| 索引行数 | **27 行**，平均 **138 字符/行** |
| ↳ 其中「概述」列 | **1419 字符（38%）**，平均 **53 字符/行** |
| ↳ 其中「文档」列（链接） | **1869 字符（50%）** |

**⇒ 两项都在涨**：每加一个活物品 ⇒ 索引 +1 行（约 +138）；
进展表滚动不占增量。**按当前速度，再约 9 个活物品就撞 20000。**

> ⚠️ **2026-10-06 更正（单位错误）**：本节初稿写「5933 字符 / 33% / 平均 220 字符/行」——

## 1. 现状诊断：体积在「行数 × 链接」，不在「概述」

**初稿的结论是"概述写成了摘要"—— 更正后不成立**：

| 列 | 体量 | 判断 |
|---|---|---|
| 概述列 | 1419 字符（平均 **53/行**） | **整体已很精简** —— 只有少数几行偏长（活流体 ~160、活工具 ~120） |
| **文档列（链接）** | **1869 字符（50%）** | **最大块，且压不动** —— 它是 `[living-tnt-tech.md](docs/tech/living-tnt-tech.md)` 这种**必须保留的路由目标** |
| 名称 + 表格格式 | 431 字符 | 压不动 |

**⇒ 真正的体积来源是「27 行」本身**：每行 ~138 字符里，**链接占 69**。
**⇒ 只有减少行数（家族合并）才有效；压缩概述最多省 ~200 字符。**

## 2. 两条修法（更正后的数字）

| 方案 | 做法 | 省 | 判断 |
|---|---|---|---|
| **A 家族合并** | 27 行 → **~7 行**（族级），族内清单降级 `docs/reference/subsystem-index.md`（**待建**） | **~2669** | ✅ **唯一有效** |
| **B 压缩概述** | 27 行保留，概述压到 ≤45 字符 | **~204** | ❌ **不划算**（概述已 53/行，且压掉的是路由线索） |

**⇒ 只做 A。B 放弃。**（初稿说"A+B 都做"，那是基于错误数字的判断。）

## 3. 具体设计

### 3.1 家族怎么分（A）

| 族 | 含哪些子系统 | 详单 |
|---|---|---|
| **活物品功能**（14） | 活TNT / 活流体 / 活熔炉 / 活漏斗 / 活箱子 / 活末影箱 / 活水车 / 活地图传送 / 活耕地 / 活工具 / 活武器 / 活红石 / 活涂蜡铜块 / 活打火石 | `docs/tech/living-*.md`（**文件名 = 子系统名**） |
| **容器基础设施**（4） | 基础设施 / 多方块容器身份解析 / 数据模型 / 超大堆叠审计 | `docs/system-design/` |
| **红电·电力**（2） | 红电架构演进 / 红电不变量测试 | `docs/buffer/` + `docs/system-design/` |
| **跨域机制**（3） | GUI交互 / 图标系统 / Tooltip 系统 | `docs/system-design/` |
| **工程实践**（3） | 单元测试 / 活TNT测试说明 / 文档系统 | `docs/guides/` + `README.md` |
| **未定案**（1） | 框架层对标 | `docs/buffer/` |

🔑 **关键**：第一族的 14 篇**不逐个列**，因为
**「有哪些 `living-*-tech.md`」用 `ls docs/tech/living-*.md` 就能枚举** ——
**能从文件系统反推的清单，按铁律 1 不该进入口。**

### 3.2 族行放「子系统名 = 链接」—— 路由 100% 无损

⚠️ **文档系统的意义是「新会话只靠 `AGENTS.md` 就能走到正确的文档」** ⇒
**省字符不是目的，不断路由才是。**

**⇒ 最终形态（已实施）**：族行里放**「子系统名 → 文档」的直链列表**，**删掉「概述」列**：

```
| **活物品功能（14）** | [活TNT](docs/tech/living-tnt-tech.md) · [活流体](docs/tech/living-fluid-tech.md) · … · [活打火石](docs/tech/living-flint-and-steel-tech.md) |
```

**为什么不是「只列名字」**（初稿设计）：那样新 AI 得先 `ls` 再猜 ——
实例：`活地图传送` 对应的文件是 `living-map-ender-pearl-tech.md`、
`活涂蜡铜块（红电发电）` 对应 `living-power-tech.md`、`活打火石` 对应 `living-flint-and-steel-tech.md`
—— **14 个里有 3 个从名字根本推不出来**。

**⇒ 用链接列表则 26 个路由键全部可点直链**（实测命中 26/26），
省下来的是**「概述」列**（那是各文档 §1 的内容，按铁律 1 不该进入口）。

**判据**：新 AI 看到子系统名，**能不能一步点到它的文档**？能才合格。

### 3.3 ⚠️ 顺手发现：有一行本该删，不是合并
