## §0 玩法定义（已拍板定稿 2026-11-11）

**语义**：**活观测者 = 容器内容的「变化传感器」**。观测本容器的**内容**（物品进出 / 数量增减 /
槽位间移动），检测到变化时沿朝向发出一次红石脉冲。解锁的玩法语言：「箱子被动过」「漏斗送进东西了」
「耕地产出了」—— 这些事件从此有了红石表达。

**获取**：原版观测者 + 活化。

**核心循环**：
- 放进容器 → 首次观测即脉冲一次（对齐原版「放置即脉冲」）；
- 漏斗送进一组矿物 → ≤1t 检测 + 2gt 延迟 → 脉冲 2gt → 点亮红石灯 / 触发下游；
- 配活比较器可做事件计数，配活漏斗红石锁定可做单件节流。

**规则**（违反即 bug）：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **观测口径 = 内容签名**：本容器全部槽位的「物品 id + 数量 + 槽位排列」（复用 `computeContentSignature`，空槽参与混合）；进出 / 增减 / 槽间移动都算变化 | 容器级直读口径，零新增扫描（签名每 tick 已算，见 §2.1）；「槽位排列」入签 ⇒ 换位也算变化，对齐「世界被移动过」直觉 |
| 2 | **组件级状态不观测**：任何 DataComponent 变化（熔炉进度 / 火把亮灭 / 粉的信号强度 / 方向重配置）不触发 | 进度类组件逐 tick 刷新 ⇒ 按组件观测 = 脉冲风暴；且这条偏离**顺带切断「观测者→粉→观测者」反馈环**（§4 对齐清单） |
| 3 | **受理三重门对齐原版**：仅待机态受理；延迟中 / 脉冲中的变化**忽略**（原版观测者脉冲期间「盲」：`updateShape` 的 `!POWERED` 门 + `hasScheduledTick` 去重）；受理时即把 `lastSeenSig` 更新为当拍签名 | 盲区合并是原版语义（§1）；受理即同步签名 ⇒ 「盲区期间 N 次变化合并为恢复后 1 次脉冲」自然成立，无需额外挂起状态 |
| 4 | **脉冲时序**：受理 → 2 game tick 延迟 → 输出 2 game tick → 回待机（原版 `scheduleTick(2)` × 2） | 与中继器「1 红石刻 = 2 game tick」同一时间分辨率（红石引擎已是逐 game tick 传播） |
| 5 | **输出 = 朝向出边（单边）**：`direction` 即输出方向（对齐中继器/比较器惯例），强度 = `getSignalCap(count)`（n==1?15:n²，家族统一口径） | 原版从背面单面输出 15；朝向语义收敛为「输出向」（容器内观测无空间方向性，见 §4 对齐清单） |
| 6 | **首次观测必脉冲**：`lastSeenSig` 哨兵 `Integer.MIN_VALUE`（与 `syncContentRevision` 首见哨兵同款）≠ 任意真实签名 ⇒ 活化后首拍受理 | 对齐原版「放置即脉冲」，零额外代码自然涌现 |
| 7 | **换容器 = 变化**：移入新容器 / 从背包拿进拿出 ⇒ `lastSeenSig` 与新内容不符 ⇒ 首拍脉冲；观测者自身同容器换槽**同样触发**——签名含槽位排列（规则 1），它也是物品（「观察对象」始终是容器整体，无重定向概念）【2026-11-11 实施勘误：原稿「同容器换槽不触发」与规则 1 矛盾，机制上换槽必触发，以规则 1 为准】 | 原版活塞推动观测者会触发；容器版对应物 = 换观测对象 / 内容被移动 |
| 8 | **只读**：不修改任何槽位、不消耗任何物品；活物品照常被观测（进出触发） | 零槽位写入 ⇒ 槽位操作选型 / 活物品隔离全无涉（§3.2 / §3.5）；观测是读，隔离规则管的是消费与转化 |
| 9 | **不穿嵌套**：只观测所在容器直读槽位；活背包 / 活箱子**内部**（物品形态子容器）的变化不可见 | 嵌套观测归活潜影箱议题（buffer）；原版观测者本也看不见箱子内部内容，容器版已是超能力 |
| 10 | **无右键交互**：方向配置走活按钮 WASD 通道（`HasDirection`，火把/中继器先例自动集成） | 原版观测者右键无操作；零交互处理器注册 |

**能力清单（目标）**：⬜ 内容变化检测（签名 diff）· ⬜ 2gt 延迟 + 2gt 脉冲 ·
⬜ 朝向出边输出（cap 随堆叠）· ⬜ 首次观测脉冲 · ⬜ 与活红石全家桶互通（粉/灯/中继器/比较器/漏斗锁定/边界面输出）
· ⬜ 图标 + 朝向 tooltip（声明式注册）

**验证入口**：§5（规则已定稿；守卫类实施时新建，复用红石既有测试脚手架）。

**工作场景边界**：观测者在**任何被 tick 的容器**里都工作（方块容器 / 玩家背包 / 实体容器 / 掉落物）——
玩家背包里动东西也会触发，这是预期（「随身监测器」），不是 bug。

## 1. 原版事实存档（1.21.1 源码，2026-11-07 查证）

`ObserverBlock.java`（`libs/src/neoforge-21.1.219-merged/net/minecraft/world/level/block/ObserverBlock.java`）：

| 机制 | 源码事实 |
|---|---|
| 状态属性 | `FACING`（观测面朝向，脸）+ `POWERED` |
| **检测面** | `updateShape`：变化方向 == FACING（脸朝的那一格）才受理 |
| **受理三重门** | ① `FACING == facing` ② `!POWERED`（脉冲期间盲）③ `!hasScheduledTick`（延迟期间盲）⇒ 盲区内变化**直接丢失**，不挂起 |
| **脉冲时序** | 受理 → `scheduleTick(pos, this, 2)` → tick：POWERED=true + 再 `scheduleTick(2)` → tick：POWERED=false。**2gt 延迟 + 2gt 宽度** |
| **输出** | `getSignal` = `POWERED && FACING == side ? 15 : 0`；`getDirectSignal` = `getSignal`（同强度，强充能）。输出面 = FACING 反面（背面），`updateNeighborsInFront` 通知的正是 `FACING.getOpposite()` 邻居 |
| **放置即脉冲** | 放置引发的 shape 更新走 `updateShape` 首次受理 ⇒ 必脉冲一次 |
| **观测者 × 观测者** | 观测者脉冲翻转自身 POWERED 方块状态 ⇒ 对面观测者可检测 ⇒ 原版可做 4gt 时钟（容器版对应偏离见 §4） |

## 2. 容器映射

### 2.1 检测内核 —— 零新机制

设计铁律自查：「现有抽象里有对应物吗？」—— 全部有：

| 需要 | 现成对应物 | 增量 |
|---|---|---|
| 「内容变了」的判据 | `ContainerLivingItemHandler.computeContentSignature`（逐槽混入 id+count，空槽参与）——每 tick 已由 `syncContentRevision`（`processContext` 阶段 1 扫描后）重算并存 `ContainerEntry.contentSig` | **零**（复用，不重扫） |
| 「上次看到什么」 | 观测者自己的 DataComponent（家族通例） | 新组件 `LivingObserverData` |
| 脉冲计时 | 红石引擎 Phase 0 倒计时模式（按钮 `pulseTimer` / 中继器 `delayTimer` 先例） | 观测者处理段 |
| 输出 | Phase 1/4 写朝向出边（中继器「仅输出方向」同款） | 观测者处理段 |
| 元件身份 | `slotMask` 位图 + `BIT_*` 族 | 新增 `BIT_OBSERVER` |
| 朝向 | `HasDirection`（WASD 自动集成，零输入层改动） | 实现 `HasDirection` |
| 信号上限 | `getSignalCap(count)`（n==1?15:n²） | **零** |

**diff 口径**：观测者比对 `lastSeenSig != 容器当前 contentSig`，**不走 `revision`**
—— revision 会被 `syncSlotToClients`（组件级变化）bump，正是规则 2 要排除的口径。

**签名获取路径**（实现时定，不新造存储）：`contentSig` 住在 `ContainerEntry`，
`calculate()` 已持有 `context` ⇒ 计算出快照里随参数传入 `RedstonePropagation`（与 `faceInput` 同待遇）。

**哈希碰撞**：签名是 int 混合哈希，理论碰撞 ⇒ 极小概率漏报一次变化。与既有用途（稳态跳过兜底）
同风险，**接受**，不做第二重哈希。

### 2.2 状态机（对齐原版三重门）

```
IDLE ──(diff: lastSeenSig != 当拍 sig)──→ ON_DELAY（pendingTimer=2，受理即写 lastSeenSig=当拍 sig）
IDLE ──(diff 相等)───────────────────→ IDLE（每拍 diff，零成本：一次 int 比较）
ON_DELAY ──(每拍 pendingTimer--)──→ 归零 ⇒ PULSING（powered=true，写朝向出边 cap）
ON_DELAY 期间 diff 到新变化 ──→ 忽略（盲区，lastSeenSig 已同步）
PULSING ──(2 拍后)──→ powered=false ⇒ IDLE
PULSING 期间变化 ──→ 忽略（盲区）
```

- 连续流（漏斗逐拍送料）：每周期合并一次 ⇒ 4gt 周期脉冲列（近似连续，与原版观测者看传送带同观感）；
- 一次性变化（放一组东西）：恰好一次脉冲；
- 盲区不丢失「恢复后再变」的事件：恢复 IDLE 后每拍照常 diff。

组件形状草案（字段命名实现定）：`LivingObserverData(direction, powered, pendingTimer, lastSeenSig)`，
`implements TooltipProvider`（家族通例）。**幂等**：红石账本 `processedThisTick` 既有机制保证同拍只算一次。

### 2.3 元件接入（家族扩展模式，活活塞先例）

- `RedstoneRegistration.register()`：注册 `LivingObserverFunction`（不实现 `HasContainerData`
  —— 驱动权在 `LivingRedstoneFunction` 单点，观测者只是元件；同火把/拉杆）；
  无交互处理器、无新网络包；
- `ContainerRedstoneData`：`BIT_OBSERVER` 入 slotMask；`hasRedstoneElements` 纳入观测者
  （有观测者 ⇒ 账本必跑，否则无人检测）；
- `RedstonePropagation`：Phase 0 增加观测者倒计时段；Phase 1 增加观测者「检测 + 受理」段与
  输出写边（单边）；Phase 5 同步组件（powered 变化才 sync，家族通例）；
- 快照贡献者（`RedstoneSnapshotProvider` 同款）把观测者槽位纳入快照；
- 图标：`LivingIconRegistry` 声明式注册（icon-system：零 Java 渲染类）；
- 检测成本：每拍每枚观测者一次 int 比较 + 受理时一次组件写——**无新扫描、无新循环**。

### 2.4 组合玩法（设计动机）

| 组合 | 效果 |
|---|---|
| 观测者 → 红石灯 | 「容器被动过」的房间级提示 |
| 观测者 → 比较器（脉冲计数） | 自动化事件计数器 |
| 观测者 → 活漏斗（红石锁定现成） | 到货暂停 / 单件节流（漏斗连续供料 ⇒ 4gt 周期脉冲列，漏斗被间歇锁住 —— 原版「漏斗+观测者」节流同款怪癖，**待实测**） |
| 观测者 → 边界面输出（`faceOutput` 通路现成） | 容器内事件 → 世界红石（警报 / 铃钟） |
| 活活塞推物品 | 推 = 槽位变化 = 脉冲 ⇒ 「推一下响一下」节拍器 |
| `SensorPort`（红电演进路线） | 第一个「非红石事件 → 信号」传感器，为信号层⇄电力层解耦提供第二个用户 |

## 3. 横切检查表（[设计模板](../guides/living-item-design-template.md)）

### 3.1 生命周期表 + 状态粒度

| 状态 | 存在哪 | 物品移走 | 取消活化 | 换槽位 | 容器卸载 |
|---|---|---|---|---|---|
| lastSeenSig | DataComponent | **保留**（⇒ 换容器必触发，规则 7） | 清除 | 保留（换槽本身不改观测对象；槽位排列变化按规则 1 触发【实施勘误】） | 保留（重载后内容未变则不误触发） |
| powered / pendingTimer | DataComponent | 保留 | 清除 | 保留 | 保留（重载后待机态继续） |

**粒度（模板 §1.1-b）**：每枚观测者有自己的输出与脉冲时序 ⇒ **数据层 per-item**；
「信号输出」是容器级副作用，写在 `edgeGrid` 上（按容器键）—— 家族「数据 per-item、副作用按容器」
的既有分工，无需新结构。多枚观测者并存：各自独立检测同一签名 ⇒ 同拍齐触发，输出边取 max
（信号模型语义）⇒ 冗余摆放只提高 cap、不叠加放大（已拍板 ③，§6：max 不特殊化）。

### 3.2 准入表

观测者**无槽位** ⇒ 无材料 / 燃料 / 瓶子类准入面。活物品隔离检查：无（只读，规则 8）。
唯一注意点：观测者**自己**是物品，进出容器是内容变化（会被别的观测者观测到）—— 预期行为。

### 3.3 反馈层三问

① 脉冲 2gt，玩家读不到也不据此决策 ⇒ **不做激活态视觉**（原版观测者脸纹理闪烁在容器内无对应物）；
② 方向是玩家配置且需反馈 ⇒ 组件持有、图标方向指示 + tooltip 方向行（对齐火把朝向先例）；
③ 上次触发时刻：v1 不做（登记，若真机要再加 tooltip 行——组件里已有数据，加行是纯展示）。

### 3.4 容器能力横切检查表

① 不读相邻槽（观测全容器，走签名）② 无容器级持久数据（状态全 per-item；容器级只有既有红石账本）
③ 零资源收付 ④ **零写回**（只读，不碰任何槽位引用）⑤ 无宿主写入口要求 ⇒ **「安全不工作」面 = 空**
（只读观测在任何被 tick 的容器都成立）—— 观测者是红石家族接入成本最低的元件。

### 3.5 槽位操作选型

零数量操作、零 `consume/produce`；自身组件更新走家族既有组件提交通道。
`check_stack_ops.py` 无新增 `setItem(`。

## 4. 原版对齐清单（逐条）

| 原版检查 / 行为 | 本实现 | 处置 |
|---|---|---|
| 检测 front 相邻 1 格 blockstate | 观测全容器内容签名（id+count+排列） | ⚠️ **偏离**：容器 = 一个观测对象（容器级是活物品的本体论）；逐槽观测不做（无玩法需求，破坏「容器级」直觉） |
| 检测红石粉 POWER 等方块状态变化 | 不检测（组件不在签名） | ⚠️ **偏离（有意）**：切断「观测者→粉→观测者」反馈环——红石引擎逐 game tick 传播下，可见电路状态 = 脉冲风暴；时钟职能由火把环 / 中继器环承担（原版观测者时钟的容器内替代） |
| 检测熔炉 LIT 等 BE 状态 | 不检测（熔炉进度是组件） | ⚠️ 同上；「熔炉出炉事件」若真机有需求，另立专门传感器（登记 TODO），不扩观测口径 |
| 受理三重门（盲区合并） | 同（§2.2） | ✅ |
| 2gt 延迟 + 2gt 脉冲 | 同（game tick 分辨率，`TICKS_PER_REPEATER_STEP` 同源） | ✅ |
| 强度 15 | `getSignalCap(count)`（n==1?15:n²） | ⚠️ **家族统一偏离**（redstone tech §7，非本物品特有） |
| 背面单面输出 + 强充能 | 朝向出边单边输出；「强充能」概念不适用于容器（边模型无强弱之分） | ✅ 单边对齐 / ⚠️ 强弱边界为家族既有口径 |
| 放置即脉冲 | 活化后首拍哨兵 diff 必受理 | ✅ 自然涌现 |
| 活塞推动观测者触发 | 换容器触发（规则 7）；同容器内任何物品移动（含观测者自身）按规则 1 触发【实施勘误，原稿误写「不触发」】 | ⚠️ 部分对齐（容器内无「推动观测者自身」的对应物；活活塞推**别的**物品会触发它） |
| 观测者 × 观测者做时钟 | 不触发（组件不在签名）；但放入/移走观测者**物品**本身是内容变化 ⇒ 离散触发 | ⚠️ 偏离（§4 第二行的同一根因，接受） |
| 观测者只读、不可被充能穿透 | 同；作为非导体元件不被 Phase 4 强充能（火把/格栅同款处理） | ✅ |
| 世界侧方块形态 | 不做（活物品只活在容器里） | 通用边界（全家族） |

## 5. 规则 → 验证入口（规则已定稿；守卫类为实施时新建）

| 规则 | 守卫 |
|---|---|
| 检测口径：进出 / 增减 / 换位触发；组件变化不触发（规则 1/2） | `LivingObserverTest`：放物品跑 tick 断言受理；粉振荡 / 熔炉进度 N tick 断言零脉冲 |
| 受理三重门 + 盲区合并（规则 3） | `LivingObserverTest`：延迟中 / 脉冲中变化 ⇒ 恢复后恰一次脉冲 |
| 时序 2gt + 2gt（规则 4） | `LivingObserverTest`：逐 tick 断言 powered 边沿（对齐中继器延迟既有断言形状） |
| 输出朝向出边 + cap（规则 5） | `LivingObserverTest`：出边值 = getSignalCap(count)，非朝向边恒 0 |
