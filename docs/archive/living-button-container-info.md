# 活按钮：当前容器基本信息

> **状态：已实施，待游戏验收（2026-10-26）**。用户确认补信息，不做配置工具；校准继续用指令。
> 现状已沉淀 [GUI 交互 §6.2.2](../system-design/gui-interaction-system.md#622-活按钮当前容器基本信息2026-10-26)。
> 本轮不改变兼容资格、解析优先级或运行行为；本稿保留设计与验收边界，不作为现状唯一来源。

## 目标与边界

- 活按钮仍是通用活化入口；按钮出现不意味着当前界面是活物品运行宿主。
- 普通提示显示容器形态、实际上下文槽数、列数/向上取整行数；启发式明确提示「推测」。
- 高级提示补布局来源和可取得的类型 ID；不泄漏他人容器内容，不展示物品清单。
- 「服务端确认可解析上下文」「已知非运行界面」「信息暂不可用」分开，信息缺失不能当不支持。
- 方向 HUD 已接管按钮 tooltip 时，容器段合入同一 HUD，不另画重叠 tooltip。

## 现有对应物与最小增量

- 身份与内容：复用 `ContainerContexts.resolve`、`ContainerKind`、`MenuSlotOwners` 与物品形态来源；不新建容器扫描器。
- 列数来源：让现有列数链同时返回列数及来源，`getWidth` 继续消费同一个结果；不在 UI 重新猜来源。
- 现有物品遥测依赖功能 tick 且按槽存储，空箱无数据；本次新增菜单级只读请求/响应，不能借活漏斗记录。
- 请求只带当前菜单 ID 与请求编号，服务端只解析该玩家实际菜单、不接受任意位置或容器键。
- 首次显示请求一次，悬停时限频刷新；服务端也限频。各按钮实例持有会话，回包必须匹配菜单 ID 与最新请求编号。
  关闭/重开/换菜单/resize 后旧实例不再接收，不能用菜单 ID 单独辨认会话（原版可能复用）。
- 玩家按 E 服务端仍使用 inventoryMenu，因此由客户端可见按钮发起查询，不只靠 Open 事件。
- 已知工作台/铁砧/交易等非运行菜单明确标记；未知第三方菜单解析失败保留「暂不可用」。

## 验证要求

- 列数与来源同源，活对象/规则/学习/家族/启发式优先级保持；实体、物品形态、末影箱路径不变。
- 空容器仍有基本信息，普通玩家库存菜单可查询；菜单中玩家槽不能替代当前宿主。
- 已知工具界面与未知菜单分开；异常来源不崩服，降级可见。
- 请求错误菜单/过期会话不回填，回包重排/菜单 ID 复用/新界面不串；限频与重试有效。
- payload 编解码、普通/高级文案、启发式警示与未知状态均有回归；新增守卫做负向验证。
- 全量 `./gradlew test --rerun`；层纪律、Mixin、文档和 diff 校验通过，不提交。
