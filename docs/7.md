### 2. 🟡 逻辑问题

**2a. `LivingMapEventHandler.onRightClickItem` 传送失败时不取消事件**

跟展示框一样的问题——如果传送失败（比如 Sable 跨维度拒绝），右键事件没被取消，原版地图会执行默认行为（比如缩放地图）。

**2b. `TeleportHelper` 跨维度坐骑传送的时序问题**

```java
vehicle.teleportTo(targetLevel, ...);  // 坐骑先传
player.teleportTo(targetLevel, ...);   // 玩家后传
player.startRiding(vehicle);           // 重新骑乘
```

`vehicle.teleportTo(targetLevel, ...)` 会调用 `player.stopRiding()`（内部逻辑），但此时玩家还没传送到目标维度。`startRiding` 在玩家传送到目标维度后才执行，应该没问题。但如果 `vehicle.teleportTo` 失败（比如坐骑类型不允许跨维度），玩家就独自传送了，坐骑丢失。

**2c. `TeleportHelper.teleportToBanner` 不检查 Sable 飞艇**

`teleportToBanner` 直接调用 `executeTeleport`，而 `executeTeleport` 内部已经处理了 Sable。没问题，我之前看错了。

**2d. `MapCoordHelper.hitVecToMapPixel` 中 DOWN/UP 面的翻转逻辑**

```java
if (facing == Direction.DOWN || facing == Direction.UP) {
    v = 1 - v;  // 先翻转 v
} else {
    u = 1 - u;  // 再翻转 u
}
```

这个翻转逻辑看起来有点奇怪——DOWN/UP 面翻转 v 后，后续旋转又可能再翻转。不过展示框不太可能放在 DOWN/UP 面上，实际影响不大。

### 3. 🟡 性能问题

**3a. `LivingMapEventHandler.onPlayerTick` 每秒发一次元数据包**

即使地图元数据没变，也会每秒发一次。可以加一个脏标记，只在元数据变化时发送。不过包很小（4 个字段），影响不大。

**3b. `MapCoordHelper.findBannerHit` 和 `findTargetPointHit` 每次都遍历所有装饰**

对于装饰很多的地图，这是 O(n) 遍历。但地图装饰数量通常很少（<100），不需要优化。

**3c. `LivingMapTargetRenderer` 是死代码**

`register` 方法体为空，`renderOverlay` 永远不会被调用。整个类可以删除。

目前有 3 个传送入口：`LivingMapEventHandler`（手持右键）、`ItemFrameMapTeleportHandler`（展示框右键）、`MapTeleportHandler/CarriedHandler`（容器内交互）。它们的传送逻辑（检查珍珠→检查旗帜→检查目标点→传送→消息）高度相似，可以提取一个 `MapTeleportExecutor` 统一处理。
