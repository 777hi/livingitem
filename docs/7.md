## 阶段一：地基（对应 Step 7）

**目标：事件驱动账本跑起来，零 Minecraft 依赖、可单测。**

1. **新建 `domain/power/` 包**（电力层内聚，和 redstone 平级）：
   - `ContainerPowerData` —— 容器级数据（挂进 `ContainerLivingItemHandler` 的缓存，与红石数据并列）：每发电机的通道状态、电池池、EMA 总功率。**设计为纯 Java 类**，不 import MC 类型，波形数据以参数传入——这样 62 项测试的基建模式可以直接复制；
   - `ChannelState` / `PathState` 内部类 —— §3.8 算法的落地：周期 EMA、双周期事件表（≤8 条封顶）、r 结算、相位域分组（每路记自己的周期+相位偏移，n 按域去重）；
   - `PowerMath` 静态工具 —— 合因子 `n^(1+解锁度)`、cos 效率、c 管径表，纯函数。
2. **`LivingWaxedCopperFunction`** —— 实现 `LivingItemFunction` + `HasContainerData`（**priority = 3**，硬约束：必须晚于红石的 2）+ `canApply`（涂蜡铜块/雕文/切制/格栅/铜灯全家族）+ 静态判定 `isBulb` / `getOxidationLevel`（→ 耦合 c：1.0/0.7/0.5/0.35）。
3. **`LivingItemManager` 注册**功能与 DataComponent；活按钮 UI 是通用的，注册完涂蜡物品即可被活化。
4. **单元测试先行**：波形分析表的两个示例直接变成测试用例——三路 6t（效率 50%、r=1 → 合因子 3^1.5≈5.2）、五路 5t 满相（n=5 → 25）。**测试不过不动下一阶段**。

## 阶段二：发电核心（Step 8+9）

5. **直连检测接线**：priority 3 的 `tickContainerData` 里读红石已算完的 `edgeGrid`/`prevEdgeGrid`（复用 `getPrevSignal` 模式），逐通道比对 → 跳变事件 → |Δ|（RE 记账：`每跳 RE = |Δ| × 合因子 × P`）。
6. **解锁度**：调谐效率（P_pref = 读 `ItemStack` 的 count）× 规律度 r（阶段一的通道状态）。
7. **n 计数**：每路（直连边 + 后续阶段的共享路）记周期+相位偏移，同域合并去重——路标识定为 `(来源槽位, 方向)`，实现时若共享路身份太复杂，v1 先支持直连路、共享路作为单一复合路接入。

## 阶段三：拓扑与耦合（Step 10+11）

8. **线圈分组**：铜块 1 通道×4 向 / 雕文 2 通道（H/V）/ 切制 1 通道×1 向 / 格栅 1 通道×4 向——通道划分决定哪些边进入哪次合因子计算，各通道独立结算后相加。
9. **感应耦合两阶段**：先算完全部直连幅度 → `radiateAmplitude[slot]`，再统一按 `c_i/Σc_j` 分配给相邻发电机；下游的感应输入作为路径进入它的 n/解锁度；**分频转发**（周期 ×2）在此实现。单趟无环。

## 阶段四：储能与输出（Step 12+13）

10. **电池池**：涂蜡铜灯聚合容量（160/640/2560/10240）与放电率，跳变能量入池、用电侧按放电率抽。v1 简化为容器级池（铜灯挪走的边界情况后置）。
11. **IEnergyStorage 暴露** —— ⚠️ **技术验证点**：电力是容器级而非物品级，给原版容器方块挂能力需要验证 `RegisterCapabilitiesEvent` 的方块注册路径（文档早就标注过）。建议做一个独立 spike 验证，不通就先以“避雷针/内部消费”为出口。

## 阶段五：表现层

12. **Tooltip 仪表盘**：检测值写回小型 DataComponent（照 `LivingGrateData.sumSignal` 模式）→ `syncSlotToClients` → tooltip 渲染（检测周期/偏好周期/n/解锁度/功率/起振中）。
13. **图标装饰器**：发电机运行状态的可视化（后置，不阻塞）。

## 两个执行纪律

- **顺序硬约束**：阶段三必须在阶段二后（耦合链的价值依赖合因子，否则只是衰减器）；每个阶段测试绿了才进下一个；
