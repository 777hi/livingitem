# 槽位数量操作原语 —— 选型指南（新活物品怎么写槽位操作）

> **本文管「怎么选、还要拍板什么」**。签名与规则（契约）在
> [api-contract §1.7](../system-design/api-contract.md)；守恒不变量在
> [container-boundary I-C12~14](../system-design/container-boundary.md)；
> 裸写门禁是 `tools/check_stack_ops.py`。本文不复制契约内容 —— 冲突时以契约为准。
>
> **判据（为什么有这篇）**：原语的守恒机制（写后回读、只扣实际量、违约撤销）调了就自动继承；
> 但「用哪个原语、一次吃几件、堆叠数怎么参与倍率」是**玩法语义**，原语推不出来 ——
> 这部分不可重推，唯一载体就是本文与设计稿模板 §1.5。

## 1. 一句话

**数量增减 = 四原语之一（或其组合），不写裸 `setItem`。**
守恒（I-C12）的三维度核验与违约留痕全部在原语里；你只需要回答「源是什么、去哪里、吃几件」。

## 2. 四原语速览

| 原语 | 玩法语言（什么时候用它） | 返回 | 违约时自动发生什么 |
|---|---|---|---|
| `move(from, to, amount)` | 「把 A 搬到 B」—— 同容器槽→槽，允许合并与部分交付 | `MoveResult` 四态（`Success.moved ≤ amount`） | 源扣减不成立 ⇒ **整拍撤销目标写入**（防复制）；目标被重定向 ⇒ 恢复原状 |
| `produce(slot, prototype, n)` | 「生成 n 个放进槽」—— 熔炉产物 / 耕地掉落 / 残留物 | 实际放入量 | 差额只 WARN 不回滚（已放入的是真产物，无复制面）；被重定向 ⇒ 恢复按 0 |
| `consume(slot, maxUnit)` | 「吃掉槽里至多 n 件」—— 熔炉输入 / 酿造材料燃料 | 实际扣减量 | 写回不符 ⇒ 恢复原状返回 0（调用方按 0 = 本拍不推进） |
| `transform(slot, fn)` | 「把槽里的东西变身」—— 酿造瓶槽一类 I-C13 不可拆整槽变换 | 成败布尔 | 写入不符 ⇒ 还原返回 false |

活物品隔离（`isLivingItem` 检查）**由调用方把关** —— 原语不认「活物品」概念（与 SlotAccessor 入口同责）。

## 3. 为什么四种就到头（不要发明第五种）

按「**源在哪 × 去哪**」正交组合，2×2 恰好穷尽：

| 源 \ 目标 | 槽 | 虚空（消耗/销毁） |
|---|---|---|
| **槽** | `move` | `consume` |
| **虚空**（配方 / 掉落生成） | `produce` | —— 无意义 |
| 槽 → **同一个槽** | `transform`（原地替换） | |

两个「看似第五种」的去向：

- **跨容器搬运** → 已存在，住 `SlotAccessor` 体系（`transferAmount`）。那是传输引擎（漏斗）的入口，
  与同容器原语「**共享数量内核，不共享入口**」（`ContainerContext.java` 顶部注释）是既定分工 ——
  不是缺一种原语，是另一个入口。
- **一次产出撒多槽 / 批量搬多槽** → 调用方循环调原语（流体推动循环即此形状），不开新 API。

真出现第五种的前提是「源/目标」出现了**新的态**（如按类型存取的「物品池」，TODO 容器边界 §5
登记过）—— 那是加维度，不是加操作。

## 4. 设计稿要拍板的三件事（模板 §1.5 逐条过）

1. **原语选型**：按 §2 的玩法语言映射，一个功能可以组合多种（熔炉 = consume + produce）。
2. **变换单元 U**（I-C13）：一次操作吃几件 —— 熔炉按配方、酿造一槽一瓶、耕地整份。
   U 是功能声明的常量；「这次能不能只作用在槽内一部分上」决定拆分语义。
3. **堆叠倍率公式**：活物品 count 怎么参与产量/速率（耕地 `count × drop`、熔炉 `count ÷ 8` 加速）。
   ⚠️ 算术纪律（I-C14②）：**先 long 算预算、再按预算消费**；乘法不过 long ⇒ 大堆叠回绕吞物品。

另有一条**容量口径档位**要选：

- `STANDARD`（默认）：容量+准入问 `simulateInsertItem`（容器自答，含超堆叠口径）、抽取权限问
  `simulateExtractItem`。**不知道选什么就选它。**
- `PHYSICAL`（A3 特例）：容量只问 `getSlotLimit`，不问准入与抽取权限。判据：这个搬运在玩法上是
  **物理力**（水流推动），不是「容器同意的转移」。参照系 = 流体推动；不要照抄流体（A3 是特例不是通则）。

## 5. 组合规则

- **consume 先行、produce 后行**（熔炉型「输入→产物」功能）：产物量 = 实际扣减量 × 每单位产出。
  反过来（先写产物再扣输入）在产物写失败时留「扣了输入、产物凭空消失」；先写产物在 actual 非
  产出整数倍时凭空多产物 —— **丢 ≤ 复制**，契约见 [api-contract §1.7](../system-design/api-contract.md)。
- **非 1:1 替换**（吃 N 个 A 出 M 个 B，同槽）= `consume(slot, N)` + `produce(slot, B, M)`；
  1:1 整槽替换（酿造瓶槽）= `transform`。
- **多目标 / 多槽** = 循环调原语；「一份产出放不下就整份等下次」这类**部分交付要不要接受**是
  玩法拍板项（耕地选择了合并整份等待 + 空槽按已交付记账，见 [living-farmland-tech.md](../tech/living-farmland-tech.md)）。

## 6. 负面清单（踩过的坑）

- ⛔ **裸 `setItem` 拼数量操作** —— `setItem` 是覆盖语义（void，写失败无法表达），「先写再扣源」
  曾在 8~12 处各坏各的（A1 丢 436 / A2 合并丢数量 / R-13 复制 / 耕地静默截断）。
  现由 `check_stack_ops.py` 棘轮拦截：新增 ⇒ 门禁红。
- ⛔ **自己算容量公式**（`min(slotLimit, 64)` 一类）—— NeoForge 默认 `getSlotLimit` = 99 不是真容量，
  超堆叠容器一槽几百个，任何公式都猜错一侧（I-C14①）。容量永远问 `simulateInsertItem`。
- ⛔ **拿 `moveStack` 当通用搬运** —— 那是活塞的整栈纯位移（不拆、不合并、目标必须空、
  要求精确写）；通用搬运用 `move`。
- ⛔ **在原语里加活物品特判** —— 隔离由调用方把关；原语保持对「活物品」概念无知。
- ⚠️ 容器有前置非存储槽（马/驴鞍槽）时，逻辑槽≠物理槽 —— 对外交付的槽号过 `toPhysicalSlot`
  （见 [infrastructure.md](../system-design/living-item-infrastructure.md)）。

## 7. 守卫测试

原语行为由 `ContainerSlotOpsTest` 钉住（六场景 × 双容器实现 + 违约三态 + 负向验证）。
**新增容器上下文实现时去那里补参数化**（`newCtx` 的两个分支加一个）；
新增域内搬运点时，先想「这是四种里的哪一种」，答不出来 = 设计没想清，回设计稿。
