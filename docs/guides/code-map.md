# 代码关系图（`tools/gen_code_map.py`）

> **一句话**：从 `src/main/java` **派生**出可交互的代码关系图，回答「**改这个类会牵动谁**」。
>
> ⚠️ **它和文档系统不是一回事，别混**：文档回答「该读哪篇」，本图回答「改动沿哪条链传导」。
> 文档可以手写，图**必须派生** —— 手画的架构图三个月后就是一张撒谎的图。
> 所以**进版本控制的只有生成脚本，图本身不进**。

## 1. 什么时候跑它

| 场景 | 看什么 |
|---|---|
| 改一个核心类**之前** | 它的**上游**（红）= 爆炸半径 |
| 排查「改 A 为什么弄坏 B」 | 沿**下游**（蓝）追传导链 |
| 判断两个模块是否真解耦 | CLI 打印的**双向耦合模块对** |
| 规划框架演进 | **包视图** + CLI 打印的**模块级强连通分量** |

## 2. 命令

```bash
python tools/gen_code_map.py          # → build/code-map.html
python tools/gen_code_map.py --json   # 同时落 build/code-map.json（供二次处理）
```

🔴 **产物只落 `build/`（已 gitignore）—— 提交图等于把「过期风险」一起提交。**

## 3. 交互口径（**代码里推不出来的约定**）

| 元素 | 含义 |
|---|---|
| 实心节点 | 一个本项目 Java 类 |
| **空心节点** | `@Mixin` 注入目标（原版 / 第三方），只作锚点 |
| **红环 = 上游** | **谁依赖我** ⇒ 改我，它们全受影响 |
| **蓝环 = 下游** | **我依赖谁** ⇒ 改它们，我可能坏 |
| 橙线 `inherit` | `extends` / `implements` / `permits` / record 组件 |
| 蓝线 `use` | 文件正文出现该标识符（import / 字段类型 / 方法调用 / 静态引用） |
| 紫线 `mixin` | `@Mixin(X.class)` 或 `@Mixin(targets="…")` |

- 深度滑杆 = 上游 / 下游展开跳数（1~4）
- `?view=module` → 包视图（按包聚合，**边粗细 = 耦合强度**）
- `code-map.html#ContainerFluidData` → 直达某个类（可分享 / 可收藏）

## 4. 可信边界

⚠️ **读图前必看 —— 它是静态近似，不是调用图。** 以下情况它**看不见**：

| 看不见 | 后果 |
|---|---|
| 反射 / 字符串引用（`Class.forName`、`ResourceLocation("mod:…")`） | 无此边 ⇒ **别据此断言「没人用」** |
| `use` 边的强度 | 「只用到类型」与「真的调用了」**在图上一样** ⇒ 判传导必须回看代码 |
| Mixin 的方法级注入目标（`@Inject` / `@Redirect`） | 只到类级 |
| `src/test` | 测试类**不在图中** |
| 泛型推断出的实参类型 | 调用点靠推断的类型不产生边 |

**判据一句话**：图用来**发现线索**，不用来**下结论**；结论回代码验证。

## 5. 铁律

🔴 **图是派生的 ⇒ 一定会过期。** 改完代码**必须重新生成**才可信；
**唯一真相永远是 `src/`，不是这张图。**

> 与 `doc_check.py` 的分工：`doc_check` 管**文档**是否与代码一致（可执行断言）；
> 本图管**代码自身**的关系是否可读（可视化）。两者都**不产生新知识**，只暴露已有知识。
