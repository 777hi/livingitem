# 🎮 活漏斗WASD方向输入系统 - 创新设计方案

## 💡 **核心理念**

**"像画箭头一样定义传输方向"**

通过直观的WASD键位组合，让玩家用最自然的方式告诉活漏斗：
> "从哪里 → 把东西 → 传到哪里"

## 🔑 **WASD键位映射规则**

### 基础方向

| 按键 | 方向 | 符号 | 说明 |
|------|------|------|------|
| **W** | UP (上) | ↑ | 向上 |
| **S** | DOWN (下) | ↓ | 向下 |
| **A** | LEFT (左) | ← | 向左 |
| **D** | RIGHT (右) | → | 向右 |

### 组合方向

| 按键组合 | 方向 | 符号 | WASD提示 |
|---------|------|------|---------|
| **W+D** | UP_RIGHT (右上) | ↗ | WD |
| **W+A** | UP_LEFT (左上) | ↖ | WA |
| **S+D** | DOWN_RIGHT (右下) | ↘ | SD |
| **S+A** | DOWN_LEFT (左下) | ↙ | SA |

## 🧠 **智能解析算法详解**

### 核心挑战

如何区分以下情况？

```
情况A: 先按W，再按D → 这是"两个独立的点"(源=W, 目标=D)
情况B: 同时按W和D → 这是一个"组合点"(源=右上)

解决方案：基于时间窗口的分组算法
```

### 时间窗口分组算法

```java
/**
 * 分组规则：
 * - 如果两个按键的时间间隔 < 100ms → 视为同时按下（同一组）
 * - 如果时间间隔 ≥ 100ms → 视为不同组的开始
 */

// 示例：按键序列 [W, D, S]
// 
// T=0ms:  按下 W
// T=50ms: 按下 D  (与W间隔50ms < 100ms → 同组!)
//         → 当前组 = {W, D} → 解析为 UP_RIGHT (↗)
//
// T=200ms: 按下 S  (与D间隔150ms > 100ms → 新组!)
//         → 第一组完成: {W, D}
//         → 第二组开始: {S} → 解析为 DOWN (↓)
//
// 最终结果:
// 源点 = UP_RIGHT (↗)  来自第一组 {W, D}
// 目标点 = DOWN (↓)     来自第二组 {S}
// 传输方向 = UP_RIGHT → DOWN (右上→下)
```

### 解析流程图

```
原始按键序列: ['W', 'D', 'S']
       ↓
┌──────────────────┐
│  Step 1: 分组     │
│  时间窗口=100ms   │
└────────┬─────────┘
         ↓
  组1: {'W','D'}  (间隔50ms)
  组2: {'S'}      (间隔150ms)
         ↓
┌──────────────────┐
│  Step 2: 点转换   │
│  键位 → Direction2D│
└────────┬─────────┘
         ↓
  组1: {'W','D'} → UP_RIGHT (↗)
  组2: {'S'}     → DOWN (↓)
         ↓
┌──────────────────┐
│  Step 3: 组装向量 │
│  源 + 目标        │
└────────┬─────────┘
         ↓
  TransferDirection(
    source = UP_RIGHT,
    target = DOWN
  )
         ↓
✅ 完成！返回结果
```

## 🛡️ **安全性与边界处理**

### 输入验证规则

```java
✅ 允许的输入：
- 单个WASD键: W, A, S, D
- 两个键的组合: WA, WD, SA, SD, AW, DW, AS, DS
- 最多2组输入（源点 + 目标点）

❌ 拒绝的输入：
- 非WASD键（数字、字母、空格等）
- 3个或更多方向键同时按（如WAS三个一起按）
- 冲突的方向（如同时按W和S）
- 超过2组的输入序列
- 超时未完成的输入（2秒无操作）
```

### 超时机制

```
为什么需要超时？
→ 防止玩家忘记自己在设置模式
→ 避免WASD键被永久占用（无法正常移动）

超时行为：
T=0s:    开始记录
T=1.9s:  正常等待输入
T=2.0s:  ⏰ 超时触发!
         → 显示红色警告: "输入超时，请重新开始"
         → 清空已记录的按键
         → 退出输入模式
         → 恢复正常WASD控制
```

### 取消机制

```
取消方式：
1️⃣ 按 ESC 键 → 立即取消，不保存任何更改
2️⃣ 超时2秒 → 自动取消
3️⃣ 再次点击活按钮 → 取消当前并重新开始

取消反馈：
❌ 已取消活漏斗模式设置 (灰色文字)
```

## 🔄 **与传统方案对比**

### vs 方案A: 循环点击切换

| 维度 | WASD输入法 | 循环点击 |
|------|-----------|---------|
| **操作次数** | 2次按键直达 | 平均4-8次点击才能找到目标 |
| **直觉性** | ⭐⭐⭐⭐⭐ 画箭头般自然 | ⭐⭐⭐ 需要记忆顺序 |
| **学习曲线** | 5分钟掌握 | 需要熟悉所有模式 |
| **速度** | ~2秒完成任意方向 | 取决于当前位置距离 |
| **可扩展性** | 无限（任何两点间） | 受限于预设列表 |
| **酷炫程度** | ⭐⭐⭐⭐⭐ 黑客范儿 | ⭐⭐⭐ 功能性 |

### vs 方案B: Radial Menu

| 维度 | WASD输入法 | Radial Menu |
|------|-----------|-------------|
| **实现复杂度** | 中等（纯逻辑） | 高（GUI渲染） |
| **可视化** | 文字+符号反馈 | 图形化预览 |
| **精度** | 高（精确到8个方向） | 中等（受GUI大小限制） |
| **移动端适配** | ❌ 不适用 | 可触控优化 |
| **模组冲突风险** | 低（只拦截特定场景） | 高（自定义渲染层） |

## 🚀 **技术架构**

### 核心组件关系

```
┌─────────────────────────────────────────────┐
│         HopperModeController                │ ← 总控制器
│                                             │
│  ├─ startModeSetting()                      │ ← 入口：检测到悬停
│  ├─ handleKeyPress()                        │ ← 处理按键
│  ├─ completeModeSetting()                   │ ← 完成确认
│  └─ cancelModeSetting()                     │ ← 取消
│                                             │
├─────────────────────────────────────────────┤
│        WASDSequenceParser                   │ ← 解析引擎
│                                             │
│  ├─ onKeyDown(char key)                     │ ← 记录按键
│  ├─ groupIntoCombos()                       │ ← 时间窗口分组
│  ├─ keysToPoint(Set<char>)                  │ ← 键位→方向点
│  └─ parseCurrentSequence()                 │ ← 返回TransferDirection
│                                             │
├─────────────────────────────────────────────┤
│         TransferDirection                   │ ← 数据模型
│                                             │
│  ├─ source: Direction2D                    │ ← 源点
│  ├─ target: Direction2D                    │ ← 目标点
│  ├─ getDisplayName()                       │ ← "↑→↓"
│  ├─ getColoredDisplayName()                │ ← 带颜色的Component
│  └─ CODEC                                  │ ← NBT序列化
│                                             │
├─────────────────────────────────────────────┤
│         LivingHopperData                    │ ← 持久化层
│                                             │
│  ├─ direction: TransferDirection           │ ← 当前方向
│  ├─ transferCooldown: int                  │ ← 冷却计时
│  ├─ totalItemsTransferred: long            │ ← 统计
│  └─ appendTooltip()                        │ ← UI显示
│                                             │
└─────────────────────────────────────────────┘
```

### 数据流

```
Player Input (Keyboard Event)
    ↓
NeoForge KeyInputEvent
    ↓
HopperModeController.handleKeyPress(key)
    ↓
检查 parser.isRecording()
    ↓ YES ↓
parser.onKeyDown(key)
    ↓
记录到 keySequence List
    ↓
调用 tryCompleteSequence()
    ↓
groupIntoCombos() → [{keys}, {keys}]
    ↓
keysToPoint() → [Direction2D, Direction2D]
    ↓
new TransferDirection(source, target)
    ↓
completeModeSetting(player, direction)
    ↓
获取 player.mainHandItem
    ↓
读取 currentData = stack.get(LIVING_HOPPER_DATA)
    ↓
updatedData = currentData.withDirection(direction)
    ↓
stack.set(LIVING_HOPPER_DATA, updatedData)
    ↓
player.setItemInHand(MAIN_HAND, stack)
    ↓
sendConfirmationMessage(player, direction)
    ↓
[完成 - NBT已更新]
```

## 💡 **设计亮点总结**

### ✨ **创新点**

1. **直觉式输入**: 像画箭头一样自然，无需记忆模式名称
2. **无限可能性**: 支持8个源点 × 8个目标点 = 64种理论组合（当前实现16种常用）
3. **零UI依赖**: 纯键盘操作，不需要额外的菜单界面
4. **仪式感": 有明确的"开始-输入-确认"流程，增强代入感
5. **高效性**: 2次按键即可到达任意方向，比循环点击快4倍以上

### 🛡️ **安全性**

1. **非侵入式**: 只在特定条件下激活（手持活漏斗+悬停活按钮）
2. **易退出**: ESC随时取消，超时自动退出
3. **防误触**: 严格的输入验证，拒绝非法组合
4. **状态清晰**: 多层次的视觉反馈，始终知道当前状态

### 🚀 **扩展潜力**

- **未来可扩展到其他活物品**: 活工作台的方向选择？活药锅的模式切换？
- **可推广到其他模组**: 一个通用的"WASD配置API"
- **VR/手柄适配**: 未来可以映射到摇杆或手势输入
