## 0. 为什么（可复算）

```bash
python -c "import io;print(len(io.open('AGENTS.md',encoding='utf-8').read()))"   # 18116
sed -n '/^## 子系统索引/,/^## 模块地图/p' AGENTS.md | wc -c                      # 5933
```

| 项 | 值 |
|---|---|
| 入口 `AGENTS.md` | **18116 / 20000 ⇒ 余量仅 1884** |
| 其中「子系统索引」段 | **5933 字符（占入口 33%）** |
| 索引行数 | **27 行**，平均 **~220 字符/行** |

**⇒ 两项都在涨**：每加一个活物品 ⇒ 索引 +1 行（约 +200）；进展表滚动不占增量。
**按当前速度，再 3~5 个活物品就撞 20000。**

> 📌 **本方案的判据不是"省字符"，是"入口只写路由"**（[README.md](../README.md) §1 铁律 1）。
> 27 行 × 220 字符里，**大部分是「这个子系统做什么」的摘要** —— 那是**各子系统文档 §1 已有的内容**，
> 属于"能从代码/文档反推"的东西，**不该进入口**。

## 1. 现状诊断：问题不在行数，在「概述」列

看两行的实际体量：

| 行 | 概述长度 |
|---|---|
| 活流体 | **~200 字符**（把引擎、行为分档、转化表、活桶定位、活熔岩全写进去了） |
| 活工具 | ~150 字符 |
| 活TNT测试说明 | ~130 字符 |

**⇒ 这是"摘要"，不是"路由"。** 路由只需要回答一件事：**「要改 X，读哪篇」**。

## 2. 两条修法（数字对比）

| 方案 | 做法 | 改后体量 | 省 |
|---|---|---|---|
| **A 家族合并** | 27 行 → **~7 行**（族级），族内清单降级到 `docs/reference/subsystem-index.md` | ~1600 | **~4300** |
| **B 压缩概述** | 保留 27 行，概述压到 ≤40 字符（只留"这是什么"） | ~1900 | **~4000** |
| **A+B 都做** | 7 族 × 120 字符 | ~900 | **~5000** |

**⇒ 两者收益相当，但价值不同**：
- **B 立竿见影**（不动结构、不丢路由粒度）
- **A 买的是"未来空间"** —— 27 行会变成 35、40 行；**7 个族基本不涨**

**⇒ 推荐 A+B 都做，但顺序上先 B（便宜）再 A（结构）。**

## 3. 具体设计

### 3.1 家族怎么分（A）

| 族 | 含哪些子系统 | 详单 |
|---|---|---|
| **活物品功能**（14） | 活TNT / 活流体 / 活熔炉 / 活漏斗 / 活箱子 / 活末影箱 / 活水车 / 活地图传送 / 活耕地 / 活工具 / 活武器 / 活红石 / 活涂蜡铜块 / 活打火石 | `docs/tech/living-*.md`（**文件名 = 子系统名**） |
| **容器基础设施**（4） | 基础设施 / 多方块容器身份解析 / 数据模型 / 超大堆叠审计 | `docs/system-design/` |
| **红电·电力**（2） | 红电架构演进 / 红电不变量测试 | `docs/buffer/` + `docs/system-design/` |
| **跨域机制**（3） | GUI交互 / 图标系统 / Tooltip 系统 | `docs/system-design/` |
| **工程实践**（3） | 单元测试 / 活TNT测试说明 / 文档系统 | `docs/guides/` + `README.md` |
| **未定案**（1） | 框架层对标 | `docs/buffer/` |

🔑 **关键**：第一族的 14 篇**不逐个列**，因为
**「有哪些 `living-*-tech.md`」用 `ls docs/tech/living-*.md` 就能枚举** ——
**能从文件系统反推的清单，按铁律 1 不该进入口。**

### 3.2 概述怎么压（B）

**判据：这一行删掉之后，读者还能不能找到正确的文档？**

- ❌ 删掉就找不到 ⇒ 留（如"活流体"这个名字本身是必要的路由键）
- ✅ 删掉也能找到 ⇒ 删（如"引擎零改动""子系统关系见 §1"这类**细节**，是文档正文的事）

**目标形态**：`| **活流体**（原活水桶） | 容器级流体引擎 + 活桶（载体） | [living-fluid-tech.md](…) |`

### 3.3 ⚠️ 顺手发现：有一行本该删，不是合并

`| **框架重构** | … | docs/archive/framework-refactoring.md |`

**它指向 `archive/` 层。** 按 [README.md](../README.md) §1，**归档层"不进加载路径"** ⇒
**这行不该在入口**。⇒ **直接删**（不是合并），并在族级路由里体现"历史见 `docs/archive/`"。
