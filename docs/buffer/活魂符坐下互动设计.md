# 活魂符坐下互动设计

> **状态**：设计稿（已拍板未实施）—— 活魂符"坐下"互动与行动暂停，不是现状；实施前别当 §0 读。
>
> **定案来源**：2026-11-12 用户提议并确认：空光标右键活魂符让女仆坐下、停止随机走动；
> 行为定义、tooltip 提示行、组件存储均按 AI 建议拍板。查证依据：TLM `EntityMaid.setInSittingPose(boolean)`
> 为公开 setter，Gecko（`AnimationRegister` "sit"）与内置 Bedrock（`SpecialAnimation`）两条动画链
> 均按 `isMaidInSittingPose()` 标志自动切坐姿——预览复用原 renderer 即可，我方不造姿势。

## 零、玩法原点

| 问题 | 定案 |
|---|---|
| 作用对象 | 容器 GUI 中槽位里的**活魂符**（有女仆快照、IS_LIVING）；世界方块形态、手持、掉落物形态不参与 |
| 输入粒度 | 空光标右键 = 一次 toggle 事件；同拍重复事件只看最终状态 |
| 方向含义 | 无方向——纯开关语义 |
| 首次出现 | 活化后默认站立（无组件 = 未坐下）；不建基线 |
| 忙碌窗口 | 不适用——toggle 幂等，重复右键只会在两态间翻转 |

**正例与负例**：

```text
正例：空光标右键 [活魂符]  ⇒ 坐下，随机走位停止；再右键 ⇒ 起身恢复
正例：坐下的魂符被活活塞推到新槽 ⇒ 新槽仍保持坐姿（坐是"不动"不是"钉住"）
负例：手持任意物品右键活魂符 ⇒ 不触发（避免与其它交互冲突）
负例：右键未活化魂符 / 无女仆快照的魂符 ⇒ 不触发
```

## 定案行为

| 项 | 定案 |
|---|---|
| 触发 | **空光标**右键槽位中的活魂符（有女仆快照）；拿着物品不触发 |
| 效果 | toggle：坐下 ↔ 起身 |
| 坐下时 | 行动尝试**直接跳过**——不进整秒门、不抽 `1/I`、不抽方向、不写 clock；I 保持不变 |
| 被动位移 | **照常发生**——坐是"不动"不是"钉住"；活塞仍可推拉（D-maid-04 口径不变），被推到新槽保持坐姿 |
| 状态存储 | 我方 boolean 组件 `living_soul_slab_sitting`，随物品持久化并同步客户端；**owned 声明**（取消活化清理，回站） |
| 释放女仆 | sitting 标志**不进** `maid_info`、不影响释放出的真实女仆（纯我方容器内状态） |
| tooltip | 坐下时显示"休息中（右键起身）"；站立时不加行 |

## 技术要点

1. **组件**：`MaidComponents` 新增 `SITTING`（boolean record + Codec/StreamCodec，模式同 `LivingSoulSlabClock`）；`LivingSoulSlabFunction.getOwnedComponentTypes()` 增列。
2. **交互接入**：空光标右键走 GUI 交互系统声明式注册；接入点现状（活耕地/活箱子同类交互的规则形状）实施时查证，**不新增网络通道**。
3. **客户端预览**：`SoulSlabMaidPreview` 读组件，`maid.setInSittingPose(flag)` 一行；坐下时走路插值自然停止（无 `move` 事件），站/坐切换由渲染层响应。
4. **服务端跳过**：`tick` 循环在读 clock 前检查组件——坐下即 `continue`（先于整秒门，不消耗任何随机数）。
5. **tooltip**：复用现有 `addToTooltip`，坐下分支加一行。
