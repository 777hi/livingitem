## §0 玩法定义（愿景态，未实现）

**一句话**：把植物大战僵尸搬进活物品体系——僵尸进攻，活物品防线防守；战场在容器里呈现，
真实存在远处竞技场。

**核心循环**：资源投放（候选=红电）→ 摆防线（活发射器 / 活方块）→ 僵尸波次推进 →
啃 / 射 / 炸 → 消灭得战利品（插回容器）· 摸到第 0 列即战败。

**三方单位**：

| PvZ 原型 | 本玩法 | 状态 |
|---|---|---|
| 豌豆射手 | **活发射器**——发射各种弹药（原版发射器弹药图鉴） | ⏳ 未实现 |
| 坚果墙 | **活方块**——任意方块物品活化，挖掘硬度→HP 通用规则 | ⏳ 未实现 |
| 僵尸 | **活僵尸**——敌方单位，真实体跑真 AI | ⏳ 未实现 |
| —— | **活不祥之瓶**——玩法驱动器：所在容器=战场，交互"喝下"=开战，等级=难度（§4.1） | ⏳ 未实现 |

**已有对应物（半个 PvZ 已建成）**：阳光=红电发电（[living-power-tech](../tech/living-power-tech.md)）·
樱桃炸弹=活TNT（爆炸账本现成）· 补给线=活漏斗 · 伤害记账=FakePlayer（活工具）·
容器内叠加渲染先例=活地图扩展显示 · 声明式配置先例=图标系统。

## 1. 架构主路线：投影竞技场 ✅

**分层定案**：**逻辑记账在容器，演出在竞技场**——容器侧 DataComponent 是唯一真相源
（单位存在 / HP / 弹药 / 波次时钟），远处真实竞技场是演出层（真僵尸、真弹药、真 AI）。
两者经桥实体（§2）联动。不是二选一，是分层。

**映射范式（2026-10-31 升华，本设计的第一性原理）**：**容器界面 = GUI，映射层 = 操控，
竞技场 = 画布**——槽位内容/位置/变更经映射层投影为真实战场的一切（单位、皮、演出、
保洁），世界事件经同一层回传为容器记账；场地本身也是投影（§7 全屏障图纸）。
副产品 = **涌现式玩法发现**：容器侧每多一种状态跃迁，就自动问"它的竞技场投影是什么"，
玩法自行生长（§4.4 演出层即由此导出）。

**三阶段落地**（沿用 [sable-sublevel-projection.md](../reference/sable-sublevel-projection.md) §7.5）：

1. **阶段1**：远处固定竞技场（普通方块结构，**不依赖 Sable**）——真僵尸 + 真弹药跑通闭环；
2. **阶段2**：竞技场内容投影进容器 GUI（观察窗口）；
3. **阶段3**（可选）：集成 Sable SubLevel 做"移动竞技场"。

**为什么不是纯数据容器模拟**（前两轮头脑风暴的备选路线，已降级为记账底座）：

| 维度 | 纯容器模拟 | 投影竞技场 ✅ |
|---|---|---|
| 僵尸动画 | 本地实体手动喂四个相位（walk/attack/hurt/death） | 原版渲染器 + 真实体，自动 |
| 生物多样性 | 三层映射表手搓 | 真 AI 原生：骷髅真射箭、苦力怕真爆炸 |
| 掉落 / 音效 | 借战利品表 / 音效事件 | 原版全流程，零映射 |
| 代价 | — | 竞技场生命周期 + GUI 世界视口渲染（§6） |

## 2. 核心机制：桥实体 ✅（细节待实现验证）

### 2.1 定位：无状态化身，容器是唯一真相

战场容器的每个活物品（§4.2 全员参战）在竞技场对应格生成一个**桥实体**
（自定义无材质 LivingEntity），作为活物品与真怪物之间仇恨与伤害的中转：

- **无 AI、无脑、站桩**：1×1 可被仇恨 hitbox，`EntityType.Builder.sized(1.0F, 1.0F)`；
- **容器 DataComponent 是唯一真相源**；桥是**派生品**，带（战场 key，槽位）出生；
- **不持久化**：覆写 `shouldBeSaved() = false`（`Entity.java:3670`，区块保存/卸载均不写入）
  ⇒ 服务器崩溃 / 区块卸载后，下次扫描容器活物品**自愈重建**，零回滚逻辑
  （与 `ContainerChunkCache` 生命周期同款思路，竞技场卸载=战局自动暂停，
  符合"容器只在加载时 tick"既有模型）。⚠️ 桥非 Monster，不走 `removeWhenFarAway` despawn，
  不能拿它当"不持久化"的钩子（2026-10-31 审计修正）；
- **区块就绪门**：桥 spawn（`addFreshEntity`）打到未加载区块 = 强制加载，踩
  [infrastructure.md](../system-design/living-item-infrastructure.md) §3.2.1
  「能力查询即加载入口」红线 ⇒ reconcile 必须以**战区区块已加载**为前置，
  未加载=跳过（"战局随竞技场卸载暂停"由此自然成立）；平台生成走 §3.2.2 方案 A
  （`addRegionTicket` 异步限速 + 三安全阀，**禁同步 getChunk / setChunkForced**），
  `ExplosionLedger`（账本→flush）是项目内现成范本；ticket 须 **BLOCK_TICKING** 级
  （实体才会 tick）；
- **位置校准**：啃咬击退 / 推挤可能挪动桥 ⇒ reconcile 把桥拉回格心
  （桥位置由容器槽位唯一决定，漂移即修）；
- **只给开战中的战场建桥**（实体预算：桥+皮=每格 2 实体，大箱满编 ~100 个均无 AI）。

### 2.2 仇恨：一个自定义「推进 Goal」，不碰原版目标列表

原版僵尸的目标类是**硬编码**（玩家 / 村民 / 铁傀儡 / 小海龟），自定义实体进不了
`NearestAttackableTargetGoal`。正解：本就要写一个推进 Goal，**仇恨选择做在它里面**——

- 同行、前方最近桥 → `setTarget(bridge)` → **原版 `MeleeAttackGoal` 免费接手**
  （寻路、逼近、挥臂啃咬动画全原生）；
- 该行无桥 → 向第 0 列（脑子）推进；摸到第 0 列 ⇒ 战败判定（纯逻辑）；
- **必须常驻评估**（寻路不看实体，桥被玩家拖走 / 铲除时要立刻换目标）；
- 远程僵尸（`RangedAttackMob`，如骷髅）：Goal 内换 `setTarget(桥)` + Ranged 系 Goal；
- **AI 皮不随存档（2026-10-31 审计补）**：原版实体加载时 `registerGoals` 重建默认 Goal
  ⇒ "清空+注入"在存档重载后**丢失** ⇒ scoreboard tag 随实体存档持久化，
  `EntityJoinLevelEvent` 检测 tag 重新打皮（与桥自愈同款"扫描重建"哲学）。

### 2.3 伤害路由：两个方向都不自研伤害系统

```
容器（DataComponent 唯一真相）          竞技场（真实世界，演出层）
┌────────────────────┐               ┌──────────────────────────┐
│ 活圆石 count:3      │──化身/皮──→   │ 桥皮(物品模型) + 桥实体    │←── 僵尸啃这里
│ 活发射器 弹药:箭     │──开火指令──→  │ 桥位置生成真箭 ──→ 真僵尸  │
└────────────────────┘               └──────────────────────────┘
        ▲                                       │
        └── LivingIncomingDamageEvent / LivingDeathEvent 回传 ──┘
```

- **啃咬→回传**：僵尸啃桥 = `LivingIncomingDamageEvent`（NeoForge 官方伤害入口）
  **cancel 原版伤害** → 按桥映射在战局记账扣血（§4.2 统一模型）；
  攒满单件血量 ⇒ `stack.count--`（掉层：皮/hitbox 联动）+ `syncSlotToClients`；
  **count = 0 ⇒ 物品消失 + 桥 discard**（破坏粒子/音效原生）。
- **开火→伤害**：活发射器 tick 决定开火 → 在**桥的位置**生成真弹药 → 真僵尸吃真伤害
  （原版伤害/击退/无敌帧全免费）→ `LivingDeathEvent` → **原版战利品表 roll** → 插回容器。
- 与 FakePlayer 的对称：**FakePlayer = 物品→世界的桥**（活工具），**桥实体 = 世界→物品的桥**——
  同一思想（隐形实体作中间人）的两个方向。

### 2.4 碰撞：物理硬碰撞可行（船先例），寻路仍不看实体 ✅（2026-10-30 口径修正）

> 修正留痕：初版结论"实体做不到方块级硬碰撞"**只对了一半**——原版船就是反例
> （用户指出）。已对 1.21.1 源码逐点核实（路径见下）。

| 层 | 事实（1.21.1 源码核实） |
|---|---|
| **物理层硬碰撞** | ✅ **实体可以**：`canBeCollidedWith()=true` 的实体，其 bounding box 会进其它实体移动解算的静态 shape 集（`EntityGetter#getEntityCollisions` 只收这类实体；船 / 潜影盒即此机制，玩家能站船顶同理） |
| **寻路层** | ❌ **仍不看实体**（pathfinder 包零引用 `canBeCollidedWith`）——僵尸寻路把桥格当空地，走到跟前被硬碰撞挡住 |

**桥实体碰撞三件套**：

1. `canBeCollidedWith() = true`——硬墙身份（船先例）；
2. `isPushable()` 保持默认 `false`——不可被挤走（船重写为 true 是因为要能被玩家推，桥不要）；
3. hitbox 高度 = **max(1.8, count)**（堆叠数动态，见 §2.6）——被硬墙挡住的僵尸会跳
   （horizontalCollision），僵尸跳高 ~1.25，桥顶必须跳不上去，防"跳上坚果顶站桩"
   （船顶仅 0.5625 才会出这毛病）。

**弹道分离（挡僵尸不挡豌豆）**：`Entity#canCollideWith` 是**移动者自己**的判定（官方口子）——

- 僵尸保持默认 ⇒ 被桥硬挡（防线物理不可穿透 = 保险丝，寻路失误 / 推挤 / 目标丢失也漏不出去）；
- **己方箭会被桥硬挡**（`AbstractArrow` 未豁免实体硬碰撞）⇒ 违背 PvZ"豌豆飞过坚果头顶"⇒
  **活弹药 = 自定义弹射物**，重写 `canCollideWith` 返回 false（豌豆飞过桥），命中判定只认活僵尸；
- 敌方远程照打桥：`canBeHitByProjectile()` 默认 `isAlive() && isPickable()`，LivingEntity 默认可被命中——
  骷髅射坚果是合法目标，桥不用动这个钩子；
- ⚠️ **MVP 即需活弹药弹射物（2026-10-31 审计钉死）**：发射器与墙**同阵线**——
  原版 `Arrow` 无 `canCollideWith` 豁免，**会被己方墙（桥）硬挡**，够不到墙后的僵尸。
  "活弹药自定义弹射物"不是 v2 优化项，是 MVP 闭环的**必要件**
  （弹药物品=箭只决定伤害参数，弹射物实体必须自定义）。

**Goal 锚定仍然主导行为**（寻路不看实体的事实没变）：僵尸永远有目标（桥/第 0 列），
`MeleeAttackGoal` 进攻击距离即停；桥死→目标消失→继续推进→撞上下一格——PvZ 节奏；
多僵尸围啃靠硬碰撞+推挤成圈。硬碰撞是**保险丝**，不是寻路替代。

- **车道隔断墙**：车道之间的隔断 = **静态平台结构**（真方块、硬碰撞、永不落盘变更）；
  防线格仍不放真方块（见 2.5）；
- **无材质**：hitbox 与渲染正交——碰撞箱照配，渲染注册空 renderer
  （`shouldRender` 恒 false + 阴影半径 0），**别指望不注册 renderer**。

### 2.5 视觉皮：BlockDisplay 或桥内建渲染，保住单一伤害通道 ✅

**防线格不放真方块**：真方块会让苦力怕爆炸产生世界通道（方块破坏）与实体通道（桥受损）
双通道受损，需双向同步收敛。皮保证所有伤害走桥一条路（爆炸对桥是实体伤害，
爆炸强度对物品爆炸抗性自己算——复用 §4 防爆映射）。
原版先例：`Interaction` 实体（隐形实体当交互代理）的伤害向变体。

- ⚠️ **实现层二选一（2026-10-31 审计）**：BlockDisplay 是原版实体**会随区块保存**
  ⇒ 桥自愈重建后旧皮残留堆积，需 reconcile 清理（tag 标记）；
  **推荐：桥实体内建 renderer**（`BlockRenderDispatcher#renderSingleBlock` 画 count 层
  方块模型）——桥本身不落盘，皮随桥生灭，免持久化/同步/清理三件麻烦。两案都守住
  "不写世界方块、单一伤害通道"，实现时按此取桥内建。

### 2.6 堆叠数 → hitbox 高度与血量（史莱姆范式）✅（机制核实，玩法映射待拍板）

**桥实体高度随物品堆叠数（count）动态调整**——原版标准能力，照抄史莱姆范式
（`Slime.setSize`：`entityData.set(ID_SIZE)` + `refreshDimensions()` + 血量/速度/攻击按 size 缩放，
`Slime.java:89-97`）：

- **尺寸重算链**：重写 `getDimensions(Pose)` 按 count 算高（默认读 type 固定尺寸，
  `Entity.java:3432`）→ `refreshDimensions()` 重算 box（box 从脚底向上长，`Slime.java:174-180`
  保脚底锚定）；NeoForge 还会在 `refreshDimensions` 里发 **`EntityEvent.Size`**
  （`Entity.java:2967`）——拦截/修改尺寸的第二个官方挂点；
- **数值拍板（2026-10-31）**：默认高度 1 格（count=1），上限 64 格（= 原版最大堆叠）。
  含义：1 格矮墙僵尸可跳越（软防线）、高墙硬挡——**高度即防线强度梯度**；
  此前"≥1.8 防跳上顶"口径据此降级为参考值，不再约束；
- **跨端同步自动**：count 进 `SynchedEntityData`（同史莱姆 `ID_SIZE`）⇒ 服务端一改自动同步，
  客户端 `onSyncedDataUpdated` 里重跑 `refreshDimensions`（`Slime.java:183-185` 范式）；
- **血量同款缩放**：史莱姆 `MAX_HEALTH = size²`（`Slime.java:92`）就是"尺寸↔血量"的原版先例——
  本设计映射（§4.2 统一模型）：**单件血量 = max(1, round(硬度×10))，无硬度 20；总血 = 单件 × count**，
  hitbox 高 = count（1~64，数值拍板见上）；
- **皮所见即所得**：桥皮按 count 渲染层数（物品模型，§4.2）——掉层即减层；
- **宽不变**：width 固定 1.0（变宽会占邻格，破坏车道判定）；
- **战损不写组件**（2026-10-31 口径更新）：当前层已损记账在战局数据（per-container），
  count 即剩余完整层数——~~受伤组件 ≠ 满血 ⇒ 不能堆叠~~旧口径作废，堆叠自然；
- **变更链路**：容器 tick 发现活物品 count 变 → 桥三步刷新（data + dimensions + 皮）；
  竞技场开放格子 ⇒ 尺寸变大无嵌入卡死问题。

## 3. 生物多样性：三层映射 + 统一战场 AI 皮 ✅（准入扩展：兼容模组生物，2026-10-31 拍板）

**准入口径（2026-10-31 拍板：要兼容其它模组的生物）**——从"v1 只收僵尸族"放宽为 tag 驱动：

| 门槛 | 判据 | 说明 |
|---|---|---|
| 族属 | 原版 `EntityTypeTags.ZOMBIES` 自动进 + 自定义数据包 tag（如 `livingzombie:invaders`）扩容 | 模组生物加 tag 即准入，不写 Java；被动类（Animal）想当敌军也由 tag 决定 |
| 类型下限 | `instanceof PathfinderMob`（推进 Goal 挂载与寻路的前提） | 飞行单位走 `FlyingPathNavigation`，推进 Goal 同一套 `moveTo` 适配 |
| 体型上限 | `getDimensions().width` ≤ 车道阈值 | 巨型/boss 默认门外，tag 手动放行（接开放问题 #6） |

**三层映射对模组生物自动适用（投影竞技场路线的兼容红利）**：数值层全读 Entity API
（血/速/攻/护甲/掉落/音效，模组自定义值直接生效）；模型渲染原生（模组自带 renderer，
竞技场所见即所得）；覆盖层按 `modid:mob` id 配置。**要新写的只有准入 tag 与战场 AI 皮。**

**统一战场 AI 皮（兼容模组生物的关键决策）**：敌军 spawn 进竞技场时**清空
goalSelector / targetSelector**，统一注入战场 Goal 组（推进 + 按分类层的行为）；
`MoveControl` / navigation 保留：

| 方案 | 表现 |
|---|---|
| 只追加推进 Goal | 模组生物自有 AI（乱逛/恐慌/驯服/觅食）与战场行为打架 ⇒ 走位漂移、卡车道，战局不可设计 |
| **清空后注入 ✅** | 任何模组生物行为统一为"推进+攻击"；攻击动画/音效由攻击 Goal 触发，不依赖原 AI |

- 依据：竞技场是封闭车道，生物的"自由生活 AI"在战场上全是噪音——PvZ 僵尸行为本来就单一；
- 竞技场无玩家 ⇒ 依赖玩家的 AI（恐慌/索敌玩家）清掉后正好消失；
- 特殊能力（瞬移/召唤/治疗）：v1 **接受**——"瞬移僵尸""召唤僵尸"很 PvZ；破坏平衡的个案走覆盖层禁用；
- 代价：模组生物的 idle 小动作消失（战场里本来也不该有）。

**敌军生命周期（2026-10-31 审计补——三件不做就跑不起来）**：

| # | 问题 | 解法 |
|---|---|---|
| 1 | **spawn 即消失**：竞技场无玩家 ⇒ 原版 Monster `removeWhenFarAway`（离最近玩家 128 格）恒触发 | spawn 时 `setPersistenceRequired()`（官方口子）；代价=persistence 实体随存档残留 ⇒ 战败/清场 reconcile 必须**清理战区 tagged 实体** |

### 4.2 全活物品参战 + 血量统一模型 ✅（2026-10-31 用户拍板三规则）

**战场容器里的所有活物品都是可被攻击的单位**（不限 battle 族）：都有桥、都有皮，
真实战场一一对应——活熔炉/活漏斗/活箱子……**边干活边挨打**（活漏斗供弹 = 后勤
单位，会被啃 ⇒ 后勤线成为战术）。皮统一用**物品模型**渲染（`ItemRenderer`，
方块类物品模型即 3D 方块——比方块状态皮通用，非方块类也能画）。

**血量统一模型**（堆叠即血量）：

```
单件血量 = 硬度 > 0 ? max(1, round(硬度 × 10)) : 20     （BattleMath 常数）
例：圆石 2.0→20/件（与无硬度同级）· 黑曜石 50→500/件 · 玻璃 0.3→3/件 · 瓶/非方块→20/件
总血量 = 单件 × 堆叠数；每掉满单件血量 ⇒ 堆叠数 -1（掉一层）
```

- **count 即血量表示**：当前层已损记账在 per-container 战局数据（攒满单件血量才真减
  count）——**物品组件不写战损**，count = 剩余完整层数；⚠️ 旧口径作废（留痕）：
  ~~受伤组件 ≠ 满血 ⇒ 不能堆叠~~——原版堆叠机制自然工作；
- **掉层自动联动**（开放题 #8 就此拍板"进阶版"）：count-1 ⇒ 皮层数-1 ⇒ hitbox 高度-1
  （§2.6 公式随动），啃咬动画/音效原生；
- **count = 0** ⇒ 物品消失 + 桥 discard（破坏粒子/音效原生）；
- 伤害路由（§2.3）落地路径：僵尸啃桥 → 战局记账扣血 → 攒满单件血量 ⇒ `stack.count--`
  + `syncSlotToClients` + 皮/hitbox 联动。

**战败条件**（⏳ 细节待用户确认）：僵尸目标 = 同行前方最近活物品桥（**含瓶**），啃完推进；
到达瓶端（下端）：有瓶 → 啃瓶（啃光 = 战败）；无瓶 → 战败（该行失守）。推论：瓶放
瓶端 = 最优（等价 PvZ 脑子位），规则不强制；**替代旧口径**"摸到第 0 列即战败"
（避免瓶放瓶端时两条件打架）。

### 4.3 战场空间规则 ✅（2026-10-31 用户拍板四条）

**① 方向：怪从上往下（⏳ 解读待确认）**——推荐解读 A：**竞技场真实世界北→南**
（观察者南侧看，怪从远到近），容器槽位映射不变（行=车道并排、列=纵深），GUI 投影
视角"北在上"呈现从上往下；解读 B（GUI 字面上→下）会让防线浅成 3 格，不取。
技术面 = Goal 方向向量 + ArenaPlots 映射，两种都便宜。

**② 车道钳制（lane clamp）**——真实体不受格子约束（瞬移/击退/飞天出界）：
reconcile 每 tick 校验 tagged 敌军 x/z 超出本车道带（y 不限，飞行怪天上飞也算本车道）
⇒ `teleportTo` 拉回车道锚点。战局正确性优先于原版感（竞技场是演出层）。

**③ 攻击多样性 → 伤害换算 + 战区保洁**（兼容模组怪的容器侧守护）：

| 模组怪能力 | 对策 |
|---|---|
| 穿透 / 秒杀 | 伤害-堆叠换算天然支持：`掉层数 = damage ÷ 单件血量`（余数进当前层记账）——秒杀 = 一次掉多层，模型零分支 |
| 范围 AOE | 事件按实体分发，每桥独立记账 |
| 瞬移 / 飞天 | 车道钳制（②）拉回 |
| **留下方块 / 岩浆** | **战区方块保洁**：reconcile 每 20 tick 扫战区 AABB，非白名单方块（屏障平台 + 空气）一律清除——火伤仍走桥通道（单一伤害通道不破） |

**④ 战场大小 = 容器布局**：车道数/纵深随 `getLayout()`——小箱 3×9 → 3 车道×9 纵深，
大箱 6×9 → 6×9，"小容器小战场、大容器大战场"；plot 网格 256 格间距对最大容器也够裕。

**设计原则升华：容器侧定规则，世界侧容错**——兼容怪能力越离谱，容器侧的确定性守护
（钳制 / 保洁 / 单一伤害通道）越重要；世界侧一律容错处理，不让任何怪能力污染战局记账。

**演出三约束（防跑飞）**：
1. **演出不碰真相源**——演出品是只读投影，记账/胜负判定绝不读它；
2. **限时自灭**——残骸/特效不持久化、定时消失，崩溃后**不重建**（演出不背真相，
   与桥"必须自愈"相反）；
3. **性能预算**——演出品数量上限（同桥预算思路），超限丢弃。

**投影物分类学**（实现期再决定抽不抽基类，框架化时机判据见设计模板 §三）：
**桥 = 持久投影**（背真相、自愈重建）· **皮 = 桥的渲染** · **残骸/特效 = 限时投影**
（不背真相）· **战区保洁 = 清除非投影物**。

    （128² 地块网格，越界抛异常 `SubLevelContainer.java:251`、`:259` 正向铺开；

  - 世界边界：2074 万 < 3000 万（余量 900 万）；⚠️ 别学 Sable 注释里的"30M 意图"真贴边——
    边界是可变状态非固定锚（center/size 运行时可改 ⇒ 地块可能被甩出界外）、
    界外即伤害区（`damagePerBlock=0.2` + safeZone 缓冲，`WorldBorder.java:22`）、
    精度末端（float32 魔数 16,777,216 ≈ 1677 万格起分辨率 >1 格）也在贴边区；
  - 历史留痕：10 万（漏算下界高速）→ 500 万（判据改跨维度机动）→ 2048 万对角带
    （判据改 Sable 实测对齐）→ 判据改整合包生态（距离降级为误入概率，隔离改无害化兜底）；
  **y = 220** 基准（+64 格墙 = 284 < build limit 320）；
- **plot 定址**：battleKey hash → 256 格间距网格槽位（确定性、零记账）；碰撞概率低，
  alpha 阶段不做归属检测（接开放问题 #7 余项）；
- **平台图纸（2026-10-31 终版，用户拍板：全屏障）**——场地用**屏障（Barrier）**
  一种方块打全部（`Blocks.java:3445`）：
  - 物理面：`strength(-1, 3,600,000)` ⇒ 生存**不可破坏** + **绝对爆炸免疫**（场地完整性 =
    战局正确性前提：任何爆炸都改不了场地 ⇒ reconcile 零场地维护，"静态平台"口径
    物理成立）；全高实心碰撞 ⇒ 寻路 walkable、不修正移速（数值层映射前提）；
    `pushReaction(BLOCK)` 活塞不可推、`noLootTable`；
  - 隐身面：不可见 + `MapColor.NONE`（原版地图取色下探穿过屏障 ⇒ **地图上也不可见**）+
    `isValidSpawn(never)` 场上不刷怪 ⇒ 到达的玩家只看到僵尸和桥皮，"竞技场"无实体可发现；
  - 视觉归皮层：草坪/墙面/战败线的"PvZ 画面"全部由渲染层提供（桥皮同思路，阶段2
    GUI 投影画草坪格子）——**连场地都是演出**，场地方块零视觉职责，
    "逻辑记账在容器、演出在竞技场"分层贯彻到底；
  - 废弃备选：黑曜石/强化深板岩（1200）——生存可挖（到达者能拆场地）、可见（多一个发现面）；
  - 保留项：白天燃烧照旧（屏障透光，`canSeeSky` 不断）⇒ 敌军作战头盔方案不变；
  - **车道宽 2 格**：槽位→平台格沿纵深 `格距 × 2`（桥居中），多僵尸并排围啃更贴 PvZ；
    行距 = 车道 2 + 隔断 1 = 3 格；单层浮空；生成 = ArenaLedger flush 一次性 fill；
    推进方向见 §4.3（怪从上往下 / 北→南 ⏳）；
- **验收路径**：`/livingitem battle arena` 子命令直接传送到本战场地块（观战；**未建**，
  MVP 落地时随命令实现）；
- 平台生成会落盘（一次性写入，"不落盘变更"指建成后不再改）；容器搬家=新 containerKey=新地块，
  旧地块残留于无人区（alpha 不处理）。

## 8. 落地阶段与验证（按设计模板 §四）

| 段 | 内容 | 验证 |
|---|---|---|
| MVP（=阶段1） | 竞技场平台生成 + 桥实体（内建皮）+ 推进 Goal + 伤害路由 + **活弹药弹射物**（§2.4 审计钉死：原版箭被己方墙挡）+ 最小闭环。开放题的 MVP 解已定：战场载体=**任意容器**（#1）· 弹药=**吃箭**（#2 选 a 最小版）· 来源=**命令手动召唤**（#3）· 战败=**轻重置**（#4） | **第一段先纯框架接入跑 `check_layers.py` + 全量回归**；闭环逻辑补单测；游戏内破坏性实测 |
| 阶段2 | GUI 视口投影 + 波次机 / 经济 / 覆盖层 JSON | 单测 + 实测（见开放问题拍板结果） |

拿走物品=铲除原子性 · 中途退群再进战局恢复 · 苦力怕爆炸只走单一伤害通道。

## 9. 边界与风险清单（❌ 明确不做）

- ❌ **防线格放真方块**（双通道同步；硬碰撞由车道隔断静态平台承担，§2.4）；
- ❌ **口袋维度 / 后台世界跑 AI**（投影竞技场的"真"来自自家远处地块，不建新维度机制；
  Sable 不用新维度的四条理由同理适用——boarding 无缝 / 客户端单世界 / 环境连续 /
  注册存档兼容面，见 [sable-sublevel-projection.md §1](../reference/sable-sublevel-projection.md)）；
- ❌ v1 准入：boss（龙/凋灵）、带乘客实体（鸡骑士递归）、带箱驴骡
  （`entity_<uuid>` 容器键那条线在用，装进战场=套娃）、濒死实体、玩家；
- ❌ 依赖 Sable（阶段3 才可选，软依赖同 `living/compat/sable/` 先例）；
- ⚠️ 实体预算：桥+皮只建给开战中战场；闲置战场随竞技场卸载消失=暂停白拿；
- ⚠️ 推进 Goal 必须常驻重评估（§2.2），桥死亡/被拖走的同 tick 内换目标；
- ⚠️ **距离不是隔离（2026-10-31 整合包视角）**：活空地图链式开图（52.4 万/跳）+
  珍珠传送、下界高速、区块加载器、传送点模组都可到任意坐标——竞技场的真实防线是
  **到达无害**（敌军不索敌玩家 / 浮空平台不碰地形 / 静态平台无破坏），
  距离只压低误入概率；真要防人为干扰，后置"战区交互保护"（按战场归属校验），不进 MVP。
  发现概率定量（用户拍板：降到最低即可，被发现也无妨）：活地图 `scale=0` ⇒ 一张图
  只覆盖 1024² 格（8 格/像素），平台要被画进图需开图中心落在 ±512 格内 =
  **精确瞄准**；链式传送落点同理；下界高速/加载器在该带无"经过"常态
  ⇒ **误发现≈0，发现=刻意行为**；且场地全屏障（§7 平台图纸）——到达后
  场地不可见、地图取色下探 ⇒ 连"看到了发个坐标"的暴露面也没有。

## 10. 可行性审计（2026-10-31，源码 + 项目基建三路探索）

> **总评：全部核心机制可实行，无 ❌ 级阻断。** 审计发现 3 项「不做就跑不起来」的实现级缺口
> （敌军 spawn 即消失 / 己方箭被己方墙挡 / AI 皮不随存档），已全部补进正文对应小节；
> 其余为口径精化。逐项依据可复算：

| 设想 | 结论 | 依据（1.21.1 源码 / 项目基建） |
|---|---|---|
| 竞技场阶段1（远处平台生成） | ✅ 有既定合规路径 | infrastructure.md §3.2.2 方案 A（`addRegionTicket` 异步限速，禁同步 getChunk）；`ExplosionLedger` 账本→flush 范本；⚠️ ticket 须 BLOCK_TICKING 级实体才 tick |
| 桥实体（无材质/硬碰撞/不落盘） | ✅ 全官方 API | `canBeCollidedWith`（EntityGetter.java:63）· `shouldBeSaved`（Entity.java:3670）· ⚠️ `isPushable` LivingEntity 默认 true 须覆写 false（LivingEntity.java:3071） |
| 动态 hitbox（count→高度） | ✅ 史莱姆范式 | Slime.java:89-97（data+refreshDimensions+onSyncedDataUpdated）· EntityEvent.Size（Entity.java:2967） |
| 推进 Goal 仇恨控制 | ✅ 标准 API | goalSelector/targetSelector 清空+注入 + MeleeAttackGoal；⚠️ 存档重载丢皮 ⇒ `EntityJoinLevelEvent` 重注入（§2.2） |
| 伤害路由双通道 | ✅ 项目内先例 | `LivingIncomingDamageEvent` @ LivingWeaponAssist；⚠️ 事件监听不在 `processIsolated` 隔离内 ⇒ 自 try/catch + `FailureThrottle` 复用 |
| 掉落/音效/护甲 | ✅ 原版全流程 | `getLootTable()` roll / 实体音效事件 / 护甲减免公式 |
| 容器级战局编排（prio 4） | ✅ 有空档+范本 | HasContainerData prio 0-3 已占、4 空闲；LivingFluidFunction 自维持范本；⚠️ 须廉价 no-op 门（§5） |
| 槽位=战场格子网格 | ✅ 现成 | `ContainerContext.resolveNeighbor/getNeighbors`（ContainerContext.java:257-301） |
| 模组生物兼容 | ✅ 成本≈0 | 数值层全 Entity API；覆盖层按 `modid:mob`；⚠️ 准入三门槛（tag / PathfinderMob / width）+ 敌军生命周期三件（§3） |
| 桥皮渲染 | ✅ 二选一 | 桥内建 renderer（**推荐**，免持久化）vs BlockDisplay（随区块保存，需 reconcile 清理）——§2.5 |
| 单测可行性 | ✅ 范本齐 | `FakeContainerContext` + `ExplosionLedgerTest` 式 mock ServerLevel；Goal/路由逻辑抽纯函数 |
| **阶段2 GUI 视口投影** | ⚠️ **唯一高风险** | 客户端区块同步无现成机制（服务端 ticket 不推送远端客户端）——自研快照下发或 Sable 集成前移；**不阻断阶段1** |
