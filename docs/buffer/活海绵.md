## 0. 玩法定义（定稿）

**语义**：**活海绵 = 流体容器物品**（一级定位）。容器级水源的**移动式储液罐**：
吸进容器水网里任意已支持的活流体源，流体随物品走（丢地上、送人、塞末影箱都带着），
对外暴露物品流体能力、能被模组设备与管道充放。原版海绵机制作为**风味**保留：
贴身吸水（上下左右四邻，2026-11-01 拍板收窄）；下界**不自干**（存储态，2026-11-01
拍板——蒸发只属「放进世界」的原生路径，§1 / ⑬）。

**获取**：海绵 + 活按钮（活化无门槛，`activation_rules.json` default allow）。

**核心循环**：活桶倒水成源 → 水网蔓延 / 晋升 → **活海绵**按上下左右四邻直吸（任意已注册流体源）→
存量累积（每枚上限 64,000mB，堆总量 × count）→ 输出三选一：模组设备 / 储罐对物品充放（主通道）·
桶 GUI 汲（每桶 1000mB）· 滴水石锥滴回水网成源（**跨物品，随活滴水石锥另立项，不在海绵实施范围**）。

**规则（定稿，违反即 bug）**：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **吸收任意已注册流体的派生源**（水 / 岩浆 / 将来模组注册的流体） | 用户 2026-10-29 定调：流体容器方向优先；原版「海绵只吸水」记为**显式偏离**（§4）。「已注册」= `FluidFlowBehaviors` 认识的流体 |
| 2 | **只吸派生源，流动格不吸** | 流动格是每拍重算的产物，吸了下一拍就长回来（§2.2） |
| 3 | **吸收沿上下左右四邻**：每拍只看海绵槽的 4 个直接邻居，逐格独立判定——可吸源才吸，流动格 / 干槽 / 活物品格 / 异种源只是「该格跳过」，**不挡其他邻居**；斜对角与更远的水靠晋升回灌「爬」到嘴边 | 原版「穿水不穿空气」收窄为贴身制（2026-11-01 拍板：可控、语义清晰，§2.2） |
| 4 | **逐源原子吸收**：每拍按上下左右固定方向序（上→下→左→右）逐个查邻居，可吸源逐个吸（每源 1000mB 均分入堆）；**快满判据** = 每枚剩余 ≥ floor(1000mB / count) 才吸，第一个装不下的源出现即本拍停（后面同样装不下） | 贴近原版「碰到水就吸」的手感；原子判定保证损耗界不破——不吸半源、不丢大块（§2.2） |
| 5 | **单一流体**：非空时不吸收 / 不被充入异种流体 | 对齐引擎「已占格不被异种覆盖」（fluid tech §2.1）；换流体 = 先清空 |
| 6 | **守恒律扩展**：水的形态 = 桶里 / **海绵里** / 容器源里 / 世界里，互斥；**定点 mmB 计量**（1/1000 mB，总量 = mmB × count 精确） | 海绵 = 物品携带形态，与桶同类；定点细粒度是均分守恒的前提（§3 因果链） |
| 7 | **能力收口**：容器水网**不暴露流体能力**（`ContainerFluidHandler` 退役）；流体能力的唯一面 = 活海绵物品（mB 双向，§2.3） | 用户 2026-10-29 定调：网格源能力是无海绵时代的探索实现；海绵 = 活流体世界 ⇄ 模组流体世界的唯一适配器，逻辑单源 |
| 8 | **均分充放**：对堆的任何 ±D 都**按枚均分**（floor + 零头回收，残余 ≤ (count−1) × 0.001mB，不可感知）；充放只作用于被交互的那一个堆 | 原版堆叠 = 同栈共享同一份组件 ⇒ 任何写入天然 ×count，均分是守恒的**算术必然**（不是语义选择，§3）；残余处理照抄灯泡（回收优先、超轮次保守丢弃 = 损耗向） |
| 9 | **取消活化清空 {fluid, mmB}**（`getOwnedComponentTypes()` 声明组件） | 不存在「带流体的未活化海绵」——活化资产不外流（灯泡同款论证） |
| 10 | 吸收 / 泵删源 = **账本即时**（`removeGeneratedSource` 即时移出 `generatedSources`，同拍后 tick 的海绵不再看见），世界侧（CA / 渲染 / `pruneActual`）下一拍可见 | 与汲走同层（fluid tech §3.6）；账本若延迟 = 同拍多枚海绵双吃同一源（守恒规则 6 被破）。引擎实查：`ContainerFluidData.removeGeneratedSource` 即 `map.remove`（2026-11-01 核对） |
| 11 | **下界不自干**（2026-11-01 推翻 2026-10-29 ③，⑬）：存储态不查 `ultraWarm`——蒸发只属「放进世界」的**世界暴露事件**（原版湿海绵放置成方块 / 桶倒水，原生路径自处理），活海绵在容器里没有直接暴露；**倒水成源路径同样不查**（同日拍板接受，TODO 活流体 #11） | 原版对照：湿海绵**物品**在背包 / 箱子里过下界同样不自干，只有**放置**才变干；存储态自干 = 走偏原版 + 杀玩法（手提水箱、下界机器供水、水/岩浆双向贸易）——「下界容器有水」= 新语义下接受的新玩法（容器内活流体不与下界接触） |
| 12 | **对外充放返回值 ≥ 实充量**（理想相等），任何取整 / 偏差只许**损耗向**（实充 ≤ 报账） | 外部按返回值扣账——报账 < 实充 = 凭空造电（灯泡 2026-09-09 同族教训，`RoundTripConservationIT` 实测 1000t +2043 FE）；守卫 = `SpongeFluidRoundTripTest`（§8.3） |
| 13 | **湿态可堆叠**（灯泡同款堆叠语义）：同 fluid 同 mmB 可合并 / 异则不合并；总量 = mmB × count，拆堆复制组件天然守恒 | 用户 2026-10-29 定调：堆叠是需求（灯泡那场仗就是为它打的），不可堆叠方案作废 |

**能力清单（目标）**：✅ 吸收（上下左右四邻 / 每拍 ≤4 源 / 任意已注册流体 / 每枚 64,000mB，2026-11-02 第二段）·

| 机制 | 原版实现 | 容器版对应 |
|---|---|---|

## 2. 容器映射

### 2.1 数据

per-item DataComponent `LivingSpongeData`（**两个字段：`fluid: FluidType` + `mmB: long`**——
**定点 mmB = 1/1000 mB**，与灯泡 mFE 同款机制：均分守恒需要细于外部接口的量子，§3 因果链）。
容量 **64,000 mB / 枚 = 6.4×10⁷ mmB**（= 64 源 × 1000mB，锚原版实际吸入量 64，§1）；
**堆总量 = mmB × count**（≤ 6.4×10⁷ × 64 ≈ 4.1×10⁹ > int ⇒ **账本 long**，`mulDivFloor` 溢出防护随内核继承，§8.1）。
**mB 对外、mmB 对内**的换算层随堆叠定案回归（用户 2026-10-29：堆叠是需求）。
干 / 湿 = `mmB > 0` 的派生态，**不换物品形态**；流体种类 = `fluid` 字段。

**形状照抄活涂蜡铜灯的存电模型**（`LivingWaxedBulbData` / `BulbItemEnergyStorage` / `BulbBank`，§3）：
按「每枚」定点存（同栈共享同一份组件，每枚各带 mmB，总量 = mmB × count）、
**同 fluid 同 mmB 可合并 / 异则不合并**（原版组件堆叠语义，灯泡同款）、
存量 = 默认值时移除组件（干海绵正常堆叠）、
取消活化清空（不存在「带流体的未活化海绵」）。

**干 / 湿对照（2026-10-29 追记：同一件物品的两个派生态，不是两种物品）**：

| 维度 | 干海绵 | 湿海绵 |
|---|---|---|
| 组件 | 不存在（mmB = 0 即按默认值移除） | `{fluid, mmB}`，mmB > 0 |
| 吸收 | 任意已注册流体源 | 只吸**同种**流体（规则 5），未满时继续 |
| 排出 | 无 | GUI 汲（1000mB 入桶）· 物品能力 drain（任意 mB）· 泵（1000mB 成源，跨物品随活滴水石锥） |
| 换流体 | 直接吸别的 | 先清空（非空拒绝异种） |
| 堆叠 | 干 ↔ 干自由堆叠（64） | 同 fluid 同 mmB 可合并 / 异则不合并（灯泡同款，规则 13）；干湿之间不合并 |
| 图标 | 原版海绵纹理，无叠加 | 原版湿海绵纹理 + 流体渲染叠加（§7，只表种类；量在 tooltip） |
| 下界（ultraWarm） | 无感 | **无感**（2026-11-01 拍板：存储态不自干，⑬）——干 / 湿海绵在下界容器里都保持原样；蒸发只发生在把流体**放进世界**时（原生路径，§1） |

**为什么不学原版做两个物品形态（2026-11-01 复确认拍板：物品 id 不换）**：湿/干的「转化」=
**组件派生 + 图标变体**——mmB 0→正的第一笔写入（吸收第一口 / 外部灌入第一滴）当拍显湿，
归零写入（汲空 / 排空）当拍翻干，GUI 实时刷新走 2026-10-31 修好的「组件翻转」同步通道
（活水车转向同款，白拿）。**转化时机没有选择题**：写入边沿即转化，任何场景零成本。
若做真物品形态（吸满第一口 swap 成「活湿海绵」物品），代价不成比例：
① 湿态写入发生在四种场景（吸收 / 外部灌入 / 汲空 / 排空），只有吸收在我们自己的容器里——
**外部灌入发生在模组机器的物品槽（别人的地盘），无统一替换通道** ⇒ 必现「组件说湿、物品说干」混合态；
② **丢活标记风险面扩大**（活桶实证：替换不由我们执行时组件必丢；模组机器吞了又吐、掉落合并、
创造拿取全部暴露）；③ 附录守恒算术全建立在「同一物品」上，形态制要在每个转化点重证；
④ 外部 handler 缓存陷阱（§8.2 #1）失效面加重。收益仅「创造栏 / JEI 能直接拿湿条目」——不值。
原版湿海绵的滴水粒子风味可在客户端按组件本地画（锦上添花默认本地自演），v1 不做。

**为什么容量锚 64 源当量，而不是熔炼水值「1 桶」（2026-10-29 探讨，同日拍板 64）**：
原版海绵不是储水罐，它的三个数各有含义——**访问预算 65**（`MAX_COUNT`，含海绵自身 ⇒
**实际吸入上限 64**，§1）、**湿态二值**（无数量概念）、**熔炼兑现 1 桶**（销毁性兑现的配额）。
活海绵已定调为**储液罐**，容量应服务储水玩法：

1. **64 是自洽恒等式**：原版一次放置最多吸 64 格、吸了就真的含着 64 桶的水，只是拒绝还你；
   活海绵只是把「还」补上（能力 / GUI 汲 / 泵），存多少 = 吸多少，正好对齐；
2. **「1 桶」的粒度由 GUI 汲保留**：每次汲 1000mB（与原版熔炼每块 1 桶同粒度），
   差别只是可重复、不销毁海绵——粒度继承了，配额没有；
3. **阶梯**：桶 = 1,000mB 手提 < **海绵 = 64,000mB / 枚手提（堆叠再乘 count）** < 容器水网 = 27~120+ 源固定。
   容量 1000mB 的海绵退化为「能自动进水的次品桶」（桶还能放水），存储位就没了；
4. **经济杠杆是速率不是容量**：水近乎免费（晋升农场），稀缺性由「每拍 ≤4 源 + 晋升回灌限速」把守；
   容量只决定「一次能带走多少」，不决定产出速率。

### 2.2 吸收（每水节拍；**四邻直吸 + 逐源原子**，2026-11-01 拍板）

1. 定位容器流体数据（`ContainerContexts` 反查，同 GUI 汲路径）；无数据 ⇒ 跳过；
2. 每拍扫海绵槽**上下左右 4 个直接邻居**，按固定方向序（上 → 下 → 左 → 右；偏移与行边界
   用既有算子 `ContainerContext.resolveNeighbor`——活耕地湿润 BFS 同款，width 走
   `ContainerLayoutResolver` 统一链，越界返回 −1 视同干槽）逐格独立判定：
   可吸源 = 派生源 且（海绵为空 ∨ 与所存同流体）（规则 5）；流动格 / 干槽 / 活物品格 / 异种源
   = **该格跳过，不挡其他邻居**——没有「层」也没有「墙」，逐格独立（⑦ 的核心红利）；
3. **逐源原子判定**：每个可吸源先查快满判据「每枚剩余 ≥ floor(1000mB / count)」
   （均分份额装得下，不越每枚上限 64,000mB）——装不下 ⇒ 本拍停（每个源增量相同，
   后面必然同样装不下，无需再查）；装得下 ⇒ `removeGeneratedSource(slot)`（汲走同款 API，
   **账本即时删**，规则 10）⇒ 1000mB = 10⁶ mmB 按 count 均分（floor + 零头保守丢弃，规则 8）；
4. 空海绵遇混流体邻居：按方向序取**第一个可吸流体**，当拍只吸这一种（单 `{fluid}` 组件的必然）；
5. `count` 放大容量、**不放大速率**（每槽每拍 ≤4 源；提高并行度 = 拆开摆）。

**吞吐由晋升回灌决定**：吸掉邻居源 ⇒ 该格空 ⇒ 水 CA 回灌流动（1 拍）⇒ 背后 ≥2 邻源
晋升成源（fluid tech §3.2）⇒ 约第 3 拍再被吸。稳态 = **约 3 拍一轮、每轮 ≤4 源**
（大水池贴脸 ≈ 12s 装满 64,000mB）。节拍取水节拍（§2.4）时空转最少——海绵抢不过水自己的
回灌循环，稀疏水塘自然空拍「等水爬回来」。

**为什么不吸流动格**：流动格是目标层 / 实际层的**每拍重算产物**，不是资产——吸掉下一拍
从源重新长出来，白吸；且流动格没有独立的量（level 1~7 是几何衰减）。
原版吸流动格是因为它那里流动水 = 真方块；容器里**资产只有源**。⇒ 偏离要记进对齐表。

**图解（一拍 = 扫一次四邻，源 = 派生源格，流 = 流动格，海 = 海绵）**：

```
例 1 · 邻居即全部（无 BFS、无深度）
┌───┬───┬───┬───┬───┐
│源A│流 │源B│   │   │
├───┼───┼───┼───┼───┤
│流 │海 │源C│   │   │
└───┴───┴───┴───┴───┘

└───┴───┴───┘

晋升农场摆在距离 ≥2 处即安全 —— 攻防从「距离战（>6 步）」变成**贴身战（≥2 格）**。
```

**贴身战与晋升农场（2026-11-01 随四邻制改写）**：原版是放置瞬间全吸，活海绵取**贴身直吸**
（⑦）——玩法空间收敛到**摆放位置**：想吸谁就把谁贴在四邻。晋升农场的攻防随之从
「距离战（穿水 >6 步即安全）」变成**贴身战（距离 ≥2 即安全）**：海绵没有触达半径，
农场摆在 2 格开外就永远够不着；反过来「两源夹一格」贴着海绵 = 手动版无限水农场
（晋升循环限速，见例 2）。隔离的合法形态 = 中途回灌格凑不齐 ≥2 邻源
（单源细流停在流动格，晋升不了；活物品墙 / 干区均合法）。
落槽瞬间海绵占的格子若有源 ⇒ 先被**挤没**（引擎既有规则，非海绵所吸）。

**挤没自愈互动**：海绵吸走贴身源 ⇒ 邻域 ≥2 源 ⇒ 下一推进拍自动补回（fluid tech §3.2）
⇒ 补回的源就在嘴边 ⇒ 再被吸——自愈机制照常运转，结果 = 海绵与水源的**稳定拉锯**

## 3. 与活涂蜡铜灯存电的同构对照（用户 2026-10-29 定调：照抄灯泡模型）

活海绵之于活流体 ≈ 活涂蜡铜灯之于红电——**物品级缓冲体**。逐条对照：

| 灯泡（存电） | 海绵（存流体） | 处置 |
|---|---|---|
| `LivingWaxedBulbData(chargeMilliFe)` 按每盏存：拆堆复制组件、每盏各带 q，总量 = q×count 天然守恒（按每堆存则拆堆即刷电） | `LivingSpongeData(fluid, mmB)` 按**每枚**定点存：同栈共享组件、总量 = mmB × count 守恒 | ✅ 照抄（**拆分守恒**靠按单位存，不靠防刷逻辑） |
| 容量 = 每盏 C × count（线性；平方容量拆分时坍缩毁电，弃用） | 容量 = 每枚 64,000mB × count（线性） | ✅ 同构 |
| 同电量两堆可合并 / 异电量不合并（原版组件堆叠语义） | 同 fluid 同 mmB 可合并 / 异则不合并 | ✅ 照抄（免费获得） |
| 存量 = 默认值时移除组件（`LivingItemManager.setData`） | mmB = 0 移除组件 ⇒ **干海绵正常堆叠** | ✅ 照抄 |
| 取消活化清空电量（`clearLivingData` 按 `getOwnedComponentTypes()`）⇒ 不存在「带电的未活化灯」 | 取消活化清空 {fluid, mmB} ⇒ 不存在「带流体的未活化海绵」 | ✅ 照抄（活化资产不外流） |
| 对外 `Capabilities.EnergyStorage.ITEM`（`BulbItemEnergyStorage`），准入 = `isLivingItem`，未活化返回 null | 对外 `Capabilities.FluidHandler.ITEM`（`SpongeItemFluidHandler`），准入同 | ✅ 照抄——**唯一能力面**（模组管道 / 设备对接） |
| 「宁损勿造」零头回收（`BulbBank.FePolicy` / `MAX_LEFTOVER_PASSES`） | **继承内核、回收分支不可达**——灯泡的「回收优先」是**跨堆**机制（余量按整堆 count 步进派给容器里其它未满灯堆，实查 `BulbBank.deposit`，2026-11-01）；海绵无跨堆聚合（本表末行），单栈操作余量恒 < count ⇒ **恒走保守丢弃**；回收腿留在共享内核里作防御，不为海绵分叉 | ✅ 内核照抄（v1.5 随堆叠定案回归），措辞照实（2026-11-01 修订） |
| mFE 定点小数（1/1000 FE）| mmB 定点小数（1/1000 mB） | ✅ 照抄（均分守恒需要细于外部接口的量子——因果链见下） |
| `BulbBank` 聚合视图（容器级扫描 + 按剩余容量比例分配） | **不需要**——吸收是**逐槽**的（每堆吸自己的四邻），外部充放只作用于被交互的那一个堆 ⇒ 无跨堆分配场景 | ⬜ 仍简化掉（聚合扫描是「发电全局灌」特有的，海绵没有；共享的只是记账内核，见 §3.1） |

**一句话**：海绵 = 灯泡的**直系继承者**——「按枚定点存 + 组件堆叠语义 + 取消活化清空 +
capability 准入 + 均分 + 零头回收 + 报账口径」全盘照抄，砍掉的只有 `BulbBank` 的
**容器级聚合扫描**（海绵无跨堆分配场景），另加一条灯泡没有的**流体维度**（fluid 字段 + 单一流体规则）。

**灯泡与海绵真正结构性的差异（不是简化，是方向）**：灯泡充电是**全局分配**
（容器里发电灌给所有灯泡，空间无关）；海绵吸收是**局部作用**（从海绵槽的四邻出发，
够不着的水吸不到）。所以灯泡是「容器里所有的灯都是一块电池」，海绵是
「每块海绵是一个有触达半径的泵」——海绵的玩法空间在**摆放位置**，灯泡的玩法空间在**容量堆叠**。

### 3.1 架构红利：记账内核升格为共享框架（2026-10-29 随堆叠定案触发）

**「按枚定点均分记账」现在有两个消费者了**（灯泡 + 海绵）——按
[设计模板 §三](../guides/living-item-design-template.md) 的判据
（已知多个接入方 + 接入成本 = 填配置 ⇒ 抽框架），从 `BulbBank` 抽**纯函数内核**：

- **内核形状**（无 IO、无扫描、无域类型）：`(当前 q, count, 容量, ±D) → (新 q, 实充, 回收轮次)`——
  均分 floor + 零头回收 + 回收轮次防御（`MAX_LEFTOVER_PASSES` 同款）；
- **归属**：power / water 两域共享 ⇒ 基础层（`WaxedCopperFamily` 上移 L1 的同款判据，
  过 `check_layers.py` 门禁）；
- **不搬的**：`BulbBank` 的容器级聚合扫描 / `FePolicy` 双口径——那是「发电全局灌」特有的；
  海绵侧各调用点自己定口径（规则 12）；
- **落点**：第三段实施时先抽内核（灯泡侧改为调用内核 + `RoundTripConservationIT` 全量回归
  守住灯泡行为不变），再接海绵。

### 3.2 换算层（FE↔mFE / mB↔mmB）存在的因果链（为什么它必须回来）

1. 接口粗：NeoForge `IEnergyStorage` 全是 int FE、`IFluidHandler` 是 int mB——外部世界
   没有亚单位概念；
2. **均分是算术必然**（不是语义选择）：同栈共享同一份组件 ⇒ 任何 ±D 只能 q ± D/count；
3. 整数域除法必有残余：量子 = 外部单位（FE / mB）时，每操作最多丢 (count−1) 个外部单位
   （64 堆吸 1 源丢 40mB = 4%，肉眼可见）；
4. 定点细量子 = 残余压到不可感知（mmB：≤ (count−1) × 0.001mB），零头回收清尾；
   发电 / 吸收侧的小量连续流同理。

⇒ **换算层 = 「均一堆 + 粗接口」这对矛盾的必然产物**；它的每次换算都是取整点
（报账口径选边）、零头回收循环只因取整残余而存在、定点制抬量级直接催生
long 溢出风险（`PowerMath.mulDivFloor` javadoc：1e9/盏 × 1e12/容器 ⇒
1.1e23 ≫ 9.22e18，溢出 = 静默变质：份额变负 → 10 亿轮慢 tick，份额变巨 → 凭空造电）。
**v1.4 曾试图用「不可堆叠」绕开这层——被堆叠需求否决（2026-10-29）；既然堆叠是需求，
这层就是必需品，连同它的全部防线一起继承（§8）。**

### 3.3 表示法定理（2026-10-29 封印论证——为什么不存在「更数学的存法」）

> 用户问：能否用某种数学函数 / 更精确的表示来存，对齐 q（每枚值）· N（count）· D（增量）·
> T（总量）？答：**「可堆叠 + 拆堆安全」约束下，均一整数 + 有损残余是唯一解族**。候选全表：

| 表示 | 运算 | 死因 |
|---|---|---|
| 有理数（q = a/b 约分，BigInt ~90bit，分母整除 lcm(1..64)） | q += D/N **全精确** | **拆堆**：N=3 存 1000，拆 3+4 ⇒ 两侧总量 428.57 / 571.43 mB——外部 mB 世界无法表达非整数总量 |
| 大分母定点（num over M = lcm(1..64) ≈ 10²⁷） | 同上全精确（M 整除所有 N） | 同上——M 整除 N 救不了拆堆这一刀（T×k/N 非整） |
| 浮点 / 对数（double 等） | 1000/64 精确（2 的幂） | N=7 类二进制无限循环，误差照旧；组件判等需逐位相同 ⇒ 合并近乎失效 |
| 双字段余数（q + dust，dust < N） | 全精确 | 拆堆复制组件：10 枚存 10003 拆 5+5 ⇒ 各 10003 ⇒ **凭空 +9999**；vanilla 无拆堆钩子可重算两侧 |
| 每栈总量 T 直存 | 吸收 T += 1000 精确、零除法 | 拆堆 5+5 ⇒ 两侧各得 T ⇒ 直接翻倍；任何「每栈单值」表示都过不了拆堆关 |
| **连续实数**（q ∈ ℝ，2026-10-29 追加） | ℝ 对除法封闭，q += D/N 精确 | 可存储的必是离散集（有限 bit）⇒「连续」在存储边界变回选网格；且 ℝ 救不了拆堆（N=3 存 1000 拆 3+4 ⇒ 333.33 / 571.43 mB，接口世界无此单位） |
| **连续函数**（存 f，读写时求值 / 复合，2026-10-29 追加） | 想象中扰动即函数复合、无舍入 | ① 有限可存的 f 就是系数组 ⇒ 更新系数回到同一套 D/N 算术；② 任意外部扰动的符号复合无界 ⇒ 不可序列化进 CODEC；③ 组件判等要求逐位相同 ⇒ 浮点 / 函数的历史相关性让合并失效 |

**定理**：可堆叠（组件均一，堆叠的定义本身）⇒ 总量 = q × N ⇒ 任何 ±D 只能 q ± D/N
（**均分是算术必然**，不是语义选择）⇒ 整数域除法必有残余（N 含 2、5 以外因子时十进制
二进制都除不尽）⇒ 拆堆安全要求 q 为某单位的整数 ⇒ **残余只能丢弃**（有损，
上限 = 量子 × (N−1)，存下来即拆堆不安全）⇒ **量子越细损耗越不可见** ⇒
最优解 = 细定点 + 零头回收 = 灯泡机器（§3.2 因果链）。自由参数只剩量子粗细
（本项目选 mmB：每次操作损耗 ≤ (count−1) × 0.001mB，`SpongeFluidRoundTripTest`
钉死为有界）。

**更干净的解（有理数精确域）真实存在**——它死于「拆堆复制组件」这个 Minecraft 组件模型
事实，不是没想到，是世界规则排除了它。本节为封印论证：后人（含 AI）再提「更数学的表示」
时，先过这张表。

**⭐ 离散性的真正来源（2026-10-29 终版封印）**：不在存储，在**接口**——网络源是 1000mB
原子、管道说 int mB、桶是一次性 1000、tooltip 是文本；守恒在接口结算，内部存得再连续
也买不到接口守恒，只会把取整从存储挪到边界。真水量确实连续地「住在」ℝ 里
（mmB = 它 0.001 分辨率的采样，误差低于一切可感知阈值三个数量级——连续理想已按
「够用」方式逼近）；但世界接口是原子的，连续性进不了守恒等式。「存连续函数」的思路
在「世界本身连续」的系统里是对的（流体模拟、信号处理），这里不成立的原因是世界离散，
不是存储离散。

## 6. 坑登记簿 / 远期

- **残量语义**：池 <1000mB 的残量无法单独成源 / 灌桶，但继续累积即可——不是死账（规则 7）；
- **超大堆叠审计回归**（v1.5 堆叠定案）：堆总量 = mmB × count ≤ 6.4×10⁷ × 64 ≈ 4.1×10⁹ > int
  ⇒ **账本 long + `PowerMath.mulDivFloor` 同款溢出防护**（灯泡 2026-09-11 教训直接继承，§8.1）；
- **挤没不伤海绵池**：活物品阻挡水流，源被挤没 ≠ 海绵受损；海绵池在物品组件上，与容器级数据无关；
- **岩浆入海绵安全**：岩浆焚毁只烧**非活物品**（fluid tech §3.7 机制一），海绵是活物品 ⇒ 免疫；
- **混流体拒绝**：非空海绵遇异种源（吸收侧）= 该邻居跳过、不挡其他邻居（⑦）/ 异种充入（能力侧）一律拒绝，换流体先清空（规则 5）；
- **多枚海绵并行**：各堆各吸各的四邻（先 tick 的先吃，后 tick 的扫邻看到前者已吸走的——
  账本即时删（规则 10），同拍不双吃）；与「数据层 per-item、副作用按容器键」同构（设计模板 §1.1-b 正例结构）；
- **嵌套免费**：活潜影箱 / 活背包里的活海绵——物品形态 ctx 已打通，流体数据按容器键隔离；
- **性能**：吸收只在「容器里有活海绵」时跑（`scanAndGroupLivingItems` 分组），
  每拍固定扫 4 个邻居（无 BFS，⑦），微不足道；
- **列数错 ⇒ 跨行吸**（与熔炉燃料槽「列数错 ⇒ 不烧」同款已知风险）：width 由统一链解析
  （Tier 0~3 兜底 + 自动学习），解析错的容器会把视觉上不相邻的槽当邻居——既有风险水位，
  工具链兜底（`check_layers` / 规则表单测 / `gen_code_map --query`），不新增防线；
- **快满尘量**：每枚剩余 < floor(1000mB/count) 时吸收停拍（⑪）——该尘量只能被外部充入
  （任意 mB）填满或汲 / 排腾出，无害且有界（< floor(1000/count) mmB）；
- **放置丢数据（已接受）**：放置活海绵 = 活标记 + 流体一起没（⑨）；不拦截、不提示，
  对齐表留痕（§4）；
- **模组机器的耗材配方不在把守范围**：原版海绵无燃料值、无酿造用途 ⇒ 原版槽位天然安全；
  第三方把 `sponge` 当配方原料的机器（若有）会消耗活海绵并带走该枚份额（损耗向，附录口径）
  ——不专项把守；
- **退役留痕**：`ContainerFluidHandler`（fluid tech §10）2026-10-29 用户拍板退役——
  无海绵时代的探索实现；「整源单位」口径**不退役**（网络源永远整源，海绵 → 网络的入口
  泵 / GUI 汲仍是 ≥1000mB 整源）；**退役动作挪第三段**（⑫：与物品能力注册同拍，
  避免取水空窗）；退役时 `resolveContextAt` 反查保留（GUI 汲仍用）；
  2026-10-31 的 Create 连通性修复（§10.4）随退役一并删除（有心理预期）；
- **FluidType 组件序列化**：跟随 `ContainerFluidData` 的 FluidType CODEC 先例（registry codec），
  实现时对齐同款写法。

## 8. 与模组传输的守恒防线（灯泡前车之鉴，2026-10-29 用户预警）

> 活涂蜡铜灯在与外部电力 mod 的传输中踩过多轮电量不守恒（源码注释可查：
> `RoundTripConservationIT` 实测 1000t +2043 FE 凭空造电、零头记账 ×count 倍、
> 比例分配 long 溢出 → 1.17s/tick 慢 tick）。**v1.5 堆叠定案后，海绵完整继承同款机器，
> 这些坑全部重新适用**——本节从「防线清单」升级为「继承清单」，第三段实施时逐条对照。
> 收口后（规则 7）唯一能力面 = `SpongeItemFluidHandler`，出事只可能在这一处，
> 但也意味着所有模组流体 mod 的怪癖都落在它身上。

### 8.1 灯泡的坑 → 海绵继承的防线（机器照抄，防线同款）

| 灯泡的坑（源码注释可查） | 根因 | 海绵继承的防线 |
|---|---|---|
| 零头记账 × count 倍 ⇒ 每 tick 凭空造电（实测 1000t +2043 FE） | 比例分配的按盏取整：写入是 count mFE、账面记 1 mFE | 内核（§3.1）的记账与写入同源：每枚写入 = 每枚记账，账面按 count 计 |
| 报账 < 实充 ⇒ 往返造电 | 接口返回 ceil / 实充口径漂移 | 报账口径照抄（返回 ≥ 实充，规则 12） |
| 比例分配 long 溢出 ⇒ 分配静默失败 ⇒ 零头回收循环 ~10 亿轮 ⇒ 1.17s/tick | accept × remaining 超 long | **账本 long + `PowerMath.mulDivFloor` 同款溢出防护**（堆总量 ≤ 4.1×10⁹ mmB，§6） |
| FE ↔ mFE ×1000 换算层取整点 | 外部 FE / 内部 mFE 异单位 | mB ↔ mmB 同款换算层（§3.2）——**它是必需品**，连同取整纪律一起继承 |
| 三份分配算法口径漂移 | 复制粘贴 | 记账内核只此一份（§3.1 共享，两域同源） |

### 8.2 海绵仍要主动防的陷阱

| # | 陷阱 | 防线 |
|---|---|---|
| 1 | **handler 缓存旧 ItemStack**：外部 mod 缓存 `IFluidHandlerItem` 跨 tick 用，而槽内物品已换 ⇒ 写进幽灵栈 = 复制 / 丢失 | handler **不缓存栈**：每次操作解析活栈，`getContainer()` 如实返回当前栈；绝不 copy 后改副本 |
| 2 | **SIMULATE 与实做分叉**：模拟返回一套、实做写另一套 | 同一段代码路径跑两遍（simulate 只是不落账），严禁两套实现 |
| 3 | **返回值 ≠ 实充** | accept = min(请求, 余量)，报账口径照灯泡（规则 12） |
| 4 | **count 乘法悄悄进公式**：总账 = mmB × count，漏乘 / 多乘即不守恒 | 内核统一处理 count（§3.1）；审查公式时任何绕过内核的手写 `* count` / `/ count` 即违规 |
| 5 | 零 / 负请求 | `toExtract` / `toReceive` ≤ 0 ⇒ 返回 0（灯泡同款首行守卫） |
| 6 | **FluidStack 附加组件丢失**：模组「带组件的流体」充入，池只存 FluidType ⇒ 排出时退化为纯类型 | v1 已知限制（接受）：池 = 纯类型 + 量；特化组件流体不在保护范围，记 tooltip 口径即可 |
| 7 | 组件 equals / hashCode（TODO 3.3 前科：校验开启即抛异常） | `LivingSpongeData` 是 record（FluidType 恒等比较）⇒ 天然合规 |
| 8 | **floor 排出 ⇒ 三连炸（2026-11-02 实测：7 堆存 1 桶，机械动力管道抽不出）**：① 交付量随请求逐次缩水（999 请求实交 998、997…）② SIMULATE ≠ EXECUTE（§8.2#2 闭合被破）③ 尾差沉成「罐显示 1mB 却抽不出」的卡死尘，且一次空返回还销毁 994mmB | **排出侧唯一口径 = ceil**（`withdrawCeil`，GUI 汲同款）：交付 = 决定交付的整 mB 分毫不差，实扣 ≥ 交付（损耗向）；残余尘 <1mB 对 mB 世界隐身（罐报 0 = 干净停手）、留账继续累积（不是死账）。守卫 = `SpongeFluidRoundTripTest` ⑩（实测场景）+ ⑪（simulate/execute 同请求必同结果）。
  **充入侧对偶检查（同日）**：报账 ceil 封顶请求 ⇒ 无缩水；count ≤ 64 ⇒ per ≥ 15 ⇒ **无报 0 死区**；
  simulate/execute 同源确定。唯一残留毛刺：存量带尘时 content 恒差 1 mB 到 capacity（floor 报量
  的对偶效应，表示法定理固有）——以 fill 返回值为准的管道（Create / Mekanism）收到 0 即停 ✓，
  守卫 ⑬（全 count×请求量扫描无死区）+ ⑭（尘区反复 fill 有限步收敛、恒不越上限）钉死边界 |

### 8.3 守卫测试先行（灯泡的 `RoundTripConservationIT` 精神）

**`SpongeFluidRoundTripTest`——第三段的第一块代码，不是最后一块**：

- 随机量级序列 充入 → 排出 往返（部分充 / 部分排 / 跨容量溢出 / 空排 / 超容量拒收 /
  异种拒绝 / 零负请求），**穿插拆堆 / 合并**（堆叠语义的守恒主战场——每步断言两侧
  总量之和不变）；
- 断言**净迁移无凭空产生**：假储罐扣掉的 = 海绵现存 + 已排出的 + 有界损耗
  （损耗只许来自零头回收的保守丢弃，单次 ≤ count−1 mmB，损耗向）；
- 红线：**不许为了让它过而改它**（`BulbBank` javadoc 原话）——测试红 = 实现有 bug，
  不是测试太严。

## 附录：算例——6mB 存进 7 堆叠，再拆分（2026-10-29，数字即测试断言）

**存 6 mB（干 7 堆，储罐推入）**：6 mB = 6,000 mmB → 均分 floor(6000/7) = 857 mmB/枚
（857×7 = 5,999，余 1）→ 零头回收步长 = count = 7，余 1 < 7 ⇒ 完整步进保护、保守丢弃
→ 组件 `{水, 857}`，**7 枚全部变湿**（共享组件），堆总量 **5.999 mB**；
报账 ⌈5.999⌉ = **6 mB**（返回 5 = 凭空造 0.999，规则 12 禁止）——边界销毁 1 mmB。

**拆分（3 + 4）**：组件原样复制 ⇒ 3 枚侧 857×3 = 2.571 mB、4 枚侧 857×4 = 3.428 mB，
合计 5,999 mmB **精确守恒**——总量 = q×count 是恒等式，任意拆法零损益。
两堆 q 相同 ⇒ 可再合并复原（7 枚 5.999 mB）。

**损耗全景**：填充 / 排出 / 吸收各 ≤ (count−1) mmB（均分余量 / ceil 超额，损耗向）；
快满停拍不产生损耗（不吸就不算账，⑪）；**拆堆 / 合并 / 搬运 / 换容器 / 换维度恒等于零**（纯代数，无运算）。

**⚠️ 损耗归属与守恒分界（2026-10-29 术语钉死）**：
- 损耗的正名 = **均分损耗**（整除余量），**不叫「拆堆损耗」**——拆堆 / 合并是零损耗恒等式，
  叫错会让玩家与实现者防错方向（怕拆堆、不怕充放，全反了）；
- **守恒分界 = count 是否为 1，不是拆不拆堆**：单枚海绵（count=1）全生命周期**精确守恒**
  （一切 ÷1 整除）；count > 1 时每次跨边界写入损耗 ≤ (count−1) mmB——哪怕从不拆堆；
- **只损耗不增加**是规则 12 的不变量：存储侧 floor / 交付侧 ceil / 报账 ≥ 实充，
  外部合并路径（掉落物合并、insertItem）要求组件逐位相同 ⇒ 只合并同 q 堆 ⇒ 守恒；
  外部配方消耗走堆里 1 枚 ⇒ 该枚份额随物品离开 = 损耗向。
