# 目标层抢占：从「距离」改为「到达时间」

> **性质**：行为修正（用户 2026-10-07 拍板；起因是"刷石机接触格像一堵墙"）。
> 前置阅读：`living-fluid-tech.md` §3.6（统一时钟三分表）、§3.7 机制五；
> 上一批 `living-fluid-no-displace-fix.md`（蔓延不抢占异种实际占据的格）。

## §1 现象与定性

刷石机稳态下，接触格（岩浆前沿格）**永远不进水**，哪怕那格在活水源的流域内、水到得更快。
玩家把圆石拿走后，那格空着，水照样不蔓延过来 ⇒ **一堵看不见的墙**。

关键区分（用户指出后我才分清）：

| | 本质 | 是否可接受 |
|---|---|---|
| **不一致的墙** | 分配规则把格子判给了**到得更慢**的流体 ⇒ 分配与实际到达脱节 | ❌ 就是本次要消掉的 |
| 物理前沿 | 岩浆真的先到（或真的在那儿）⇒ 边界与到达一致 | ✅ 合理，玩家能理解 |

## §2 根因

1. **目标层按距离抢占**（纯 BFS + FIFO）⇒ 完全不看流速；
2. 等距时由**源的注册顺序**决定 ⇒ 任意；
3. 上一批加的「不驱逐」守卫：岩浆**已实际铺开**的格，水永远 claim 不到（哪怕更近）⇒ 直接造墙；
4. 反应后 `flows.remove()` 让那格空出来 ⇒ 下一拍又被岩浆按距离/顺序重新 claim ⇒ 墙永久化。

⇒ 统一时钟（2026-10-06）只让**蔓延**走流体节拍，**分配**仍用距离 ⇒ 两者时钟不同步。

## §3 定稿：按到达时间抢占（多源 Dijkstra）

- 每个流体的**每格成本** = 它自己的节拍：`flowSpeed < 0 ⇒ vanillaTickDelay`（水 5 / 岩浆 30，
  下界 10）；`0` = 瞬时 ⇒ 成本 0；`N` = N tick/格；
- 源格时间 0；松弛时 `t = 父时间 + 成本`；按时间升序定型；
- **源格永不被抢**（`existing.isSource()` ⇒ 跳过）—— 源格只能被**反应**湮灭，不能被蔓延抢占；
- 保留上一批的「**不驱逐**」守卫：实际层被异种占据的格，蔓延不抢（只由反应决定）；
- `maxLevel` / 活物品阻挡 / 挤没播种全部不变。

⇒ 分配与实际到达**用同一个时钟**：谁先到谁占格，不再出现"在水的流域内却进不去"。

## §4 边界位置（几何结论）

水赢一格的条件：`d_水 × 5 < d_岩浆 × 30` ⇒ `d_岩浆 > d_水 / 6`
⇒ 边界落在**距岩浆源约 D/7** 处（D = 两源间距）：

| D（两源间距） | 结果 |
|---|---|
| D ≤ ~6 | 岩浆守不住任何前沿格 ⇒ 水贴到岩浆源 ⇒ **源格反应 ⇒ 黑曜石 + 源湮灭**（刷石机自毁） |
| **D ≥ ~7** | 岩浆守住至少紧贴自己的一格 ⇒ **边界稳定 ⇒ 圆石照常累加** |

⚠️ 这与原版是**同一条约束**：原版刷石机也必须保证水碰不到岩浆源，否则出黑曜石。
区别只在门槛：原版是「水的 maxLevel」，我们是「时间竞争」。

## §5 为什么不再需要「产物挡路」

我上一轮曾断言"原版稳定靠产物是实体方块，A 必须配它才成立" ⇒ **错的**。
产物挡路解释的是"挖掉后岩浆能回流再凝固"这一半；"刷石机为什么不毁"靠的是**几何约束**（§4），
A 已经复现。产物挡路与我们自己定的「产物格不是墙 ⇒ 圆石累加」口径冲突 ⇒ **不引入**。

## §6 被否选项

| 选项 | 否掉的理由 |
|---|---|
| 维持距离分配 | 分配与实际到达不同步 ⇒ 就是那堵墙 |
| 只改"等距时给流速快的" | 治一半：非等距几何（岩浆更近但实际更慢）仍造墙 |
| 产物挡路（两侧都挡） | 与用户 10-06 定的「不是墙 / 要累加」口径冲突，且会让刷石机退回"挖一块出一块" |
| 按距离但把岩浆节拍算进 level | 概念更绕，等价于本方案但更难解释 |
