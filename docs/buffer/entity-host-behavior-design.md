# 实体宿主行为兼容设计（批次 A + B）

状态：已实施 —— 批次 A / B / A2 全部落地（2026-11-12），结论已归位稳定层；本稿留作拍板记录，按 [README.md](README.md) 维护判据可分流。

> **范围**：实体容器宿主（箱船 / 箱矿车 / 带箱驴骡 / 女仆背包 / 未来经 `EntityContainers.Provider` 接入的生物容器）下，把「需要世界位置」的活物品从保守静默跳过升级为正式行为。
> **关联决策**：`D-container-15`（锚点三型）· `D-container-16`（宿主锚点四开关默认关）—— D-container-16 **范围原样保留**（只门物品形态借宿主锚点）；实体宿主自身锚点的行为是本稿新增的「正常行为」，不设门（2026-11-12 用户拍板，见 §1）。
> **背景**：2026-11-12 全量审计结论见会话记录；女仆宿主现状 = 与船/矿车同桶（`AtEntity` ⇒ 工具不重放、信标不开光、水车注不进、TNT 炸原地）。

## §0 玩法原点

### 0.1 共同前提：实体宿主 = `AtEntity`

- 三条位置语义（`EntityContainerContext` 已定，不再改）：`getBlockPos()` 恒 null、`getOwnerPlayer()` null、`getAnchor()` = `AtEntity(实体)`（[container-boundary.md](../system-design/container-boundary.md) I-C1/I-C5）。**`AtEntity` 覆盖一切实体形态宿主**：箱船 / 箱矿车 / 带箱驴骡 / 女仆背包 / 掉落物。
- 宿主准入走 `EntityContainers`：原版三类白名单 + 能力面双闸；第三方生物容器注册 `Provider`（女仆先例 36 行）。**"这个宿主的背包是哪个视图"只有宿主模组自己知道** ⇒ 接入层的 Provider 是固有成本，行为层不承担。
- **写法纪律（未来宿主自动兼容的条件，评审硬检查项）**：
  1. `domain/` 行为层禁止 `instanceof` 具体宿主类（`EntityMaid` 等）——宿主差异走 Provider 扩展点（先例 `getLiveColumns()`）；`check_layers.py` R3 棘轮兜底。
  2. 配置开关只门「**借来的位置**」（物品形态借宿主锚点 = D-container-16 原范围，含活背包嵌套在女仆包里的情形）；**实体宿主自身锚点是容器的物理事实，功能直接用，不设门**——与方块容器（`getBlockPos()`）同判。口径一句话：**自己的位置直接用，借来的位置才要开关**。
  3. 实体差异（眼高 / 脚下方块 / 体转角）交给 Entity API（`getEyePosition()` / `blockPosition()` / `yHeadRot`），无宿主特判。

### 0.2 活工具 / 活武器 —— 主动模式回放（A 批）

| 问 | 定案提案 |
|---|---|
| 作用对象 | 从**宿主实体眼睛位置**出发、沿记忆射线（录制时的固定偏移向量）命中的世界方块 / 实体；宿主自身是实体非方块，无自挖问题（形状求交排除） |
| 输入粒度 | 每 tick 结算射线终点 = `origin.add(offset)`；同 tick 宿主移动 ⇒ 终点变 ⇒ **挖掘进度按目标方块记账、目标变即重置**（现状语义直接沿用） |
| 方向含义 | 输入 = 记忆组件（录制自玩家，不随宿主变）；输出 = 挖掘 / 交互 / 攻击；无观察 |
| 首次出现 | 带记忆的工具进入实体容器即生效，无基线建立；**无记忆的工具不重放**（辅助模式另属 C 批，见 §3） |
| 忙碌窗口 | 无新语义——沿用现有「目标变即重置」机制（`LivingToolReplay` L23，与原版逐格挖掘进度同模型，对一切宿主一致）。宿主移动时目标格随步速更换（约每 3~4 tick，几何相关），产出按挖掘时长自然分流——是该机制的既有表现，不是本批设计的规则 |

- 正例：女仆驻立在矿洞，包内带挖掘记忆的活镐从她眼睛位置向记忆方向挖。
- 负例：宿主移动 ⇒ 目标格随步速更换 ⇒ 换格即进度清零（原版式逐格进度的既有表现，非本批新增语义）。
- 抽象判据：`originOf` 的 AtEntity 分支从「只认 ItemEntity」扩为「返回 `entity.getEyePosition()`」——**既有分支填充，无新机制**；FakePlayer 钉起点、破坏归因记工具 owner（= 通常为宿主的主人），均与宿主种类无关。
- 既有注释翻转：`LivingToolFunction` originOf「船/矿车里的活工具本来就不重放 ⇒ 维持 null（不是遗漏）」⇒ 改为「实体宿主回放 = 正常行为（与方块容器同判，不设门）」。
- 开关判据：`effectiveAnchor` **无需改动**——它本来就只门 null 锚点回退（物品形态借用），实体锚点（`getAnchor()` 非 null）不受门。掉落物形态的射线回放是既有已实装行为（碰撞箱中心，L14=d），不因本批改变。

### 0.3 活水车 —— 实体脚下方块注应力（A 批）

| 问 | 定案提案 |
|---|---|
| 作用对象 | 实体 `blockPosition().below()` 那格的动能 BE（须过 Create 白名单，`StressOutputManager` 既有判据）；不是齿轮则静默无输出 |
| 输入粒度 | 每 tick 重算注入；宿主移动 ⇒ 旧位置应力 ≤1 tick 自过期（`StressStateMachine` 既有兜底，无残留无重复计入，2026-11-12 审计已核） |
| 方向含义 | 纯输出（应力），无输入 |
| 首次出现 | 开关开 + 宿主进入实体容器 ⇒ 首 tick 即注入；无需基线 |
| 忙碌窗口 | 无（tick 级数据）；「站上齿轮供能、走开即断」为自然涌现规则 |

- 抽象判据：`ContainerStressWriteback` 第三分支拆两条路径——`getAnchor()` 为 `AtEntity` ⇒ **无条件注入**（实体宿主自己的位置，含掉落物落在地上）；否则物品形态走 `getHostAnchor()` 且保持 `water_wheel` 开关门（D-container-16 原样）。无新机制。
- 注意：物品形态活背包**嵌在**实体宿主里时走既有 `getHostAnchor()` 路径（hostAnchor 透传 = `AtEntity`），行为不变。

### 0.4 活信标 —— 实体宿主开光（**建议拆 A2 批**）

| 问 | 定案提案 |
|---|---|
| 作用对象 | buff 以实体 `position()` 为中心（80 tick 节奏沿用）；光束以实体为锚 |
| 关键约束 | **不能只做 buff 不做光束**——「有 buff 没光」是 2026-10-25 修过的真机坏状态（`BeaconFunction.java` 类注释），刻意重造不可接受 |
| 忙碌窗口 | 无 |

- 工作量实质：buff 是服务端一行分支；**光束需要第三条宿主同步通道**（`BeaconChestHost` 按方块 / `BeaconPlayerHostSync` 按玩家 UUID 之外新增实体键变体）+ 客户端渲染器实体锚分支——与玩家光束（实体跟随）同构，但独立成片。
- **提案：A2 拆批**（buff + 光束 + 联机同步一起做，单独排期），A 批先落工具回放与水车。拍板记录见 §1。
- 开关判据：实体宿主开光**不设门**——与有盖箱宿主光束（已实装、无开关）同判。

### 0.5 活武器辅助 —— 实体宿主补刀（B 批）

| 问 | 定案提案 |
|---|---|
| 作用对象 | 宿主实体（已准入）近战命中的目标——可达性由宿主这一刀证明，**直连目标不造射线**（沿用 2026-11-06 直连判据） |
| 输入粒度 | 宿主每次近战命中 ⇒ 背包内无记忆活武器逐把补刀（收集序）；怪中途死亡即停（现状语义） |
| 方向含义 | 输出 = 伤害 / 附魔 / 击退；无输入 |
| 首次出现 | 无基线；per-weapon 冷却沿用 |
| 忙碌窗口 | 辅助循环期间 `active` 标志防递归（现状沿用）；FakePlayer 来源排除现状沿用 |

- 触发判据泛化：`LivingWeaponAssist` 来源从「`ServerPlayer` 且非 fake」扩为「**已准入实体宿主**（`EntityContainers.isContainerEntity`）且非 fake」——女仆近战走标准 `hurt` 链，NeoForge 事件照发，**不需要 TLM 的 `MaidHurtTarget` 专用事件**（通用挂点，未来宿主自动进名单）。
- 收集与写回：新增实体容器收集路径（`EntityContainers.createContext` 构造 ctx → 遍历槽位 → 无记忆武器过滤），写回走 `ctx.setItem` + `syncSlotToClients`（替代玩家侧 `inventoryMenu.broadcastChanges()`）。
- **不做环渲染**：背后环是玩家视觉概念，实体宿主无环；是否在辅助中不做联机可见性承诺（tooltip/实机观察兜底）。

## §1 拍板记录（2026-11-12 用户定）

1. **开关语义 = 用户案**：`host_anchor.*` 四开关**只约束物品形态借宿主锚点**（D-container-16 范围原样，含活背包嵌套在女仆包里的情形）；生物容器（船 / 矿车 / 驴 / 女仆 / 未来 Provider 接入者）实现活物品功能逻辑是正常行为，**不设门**。依据：① 与已实装行为完全一致（方块容器无门 + 实体宿主 TNT 无门）⇒ 原提案①的「TNT 例外不对称」在此口径下自动消失；② D-container-16 的立法理由（替玩家做玩法决定）只适用于「借位置」——实体容器真的在世界里。§2 相应缩减：`effectiveAnchor` 与 `GameplayConfig` 注释均无需改动。
2. **信标拆 A2 批**（采纳提案）：buff + 光束 + 联机同步一起做，单独排期。
3. **宿主范围 = 全量**（采纳提案）：一切 `isContainerEntity` 准入宿主同等生效，不写女仆特判。

> 「宿主移动 ⇒ 换格 ⇒ 进度重置」不构成拍板项：它是既有逐格进度机制的既有表现（原版同模型），不进文档规则（2026-11-12 用户定，类比「眨眼不是规则」）。

## §3 不做 / 缓办（C 批，理由已在审计中核实）

- **辅助挖掘（宿主侧）**：女仆挖方块是瞬时破坏（`destroyBlock` → `setBlock`），无 BreakSpeed/进度可加速——「加速挖掘」语义无对应物；唯一真实缝是女仆掉落判定 tool 传 EMPTY（正确工具方块丢掉落）⇒ 属宿主特有联动，通用化无锚点。
- **辅助环 / 记忆射线联机渲染（实体宿主）**：无环概念；K2 上报仅服务 F3+B 射线可见性（变更点 #3 已含）。
- **朝向跟随映射实体头转角**：默认回放不需要视线向量；followBody 对实体的映射等真实玩法需求出现再定。
- **红石世界互通实体化**：互通接口按「带 FACING 的方块」建模，实体宿主脚下是空气 ⇒ 双向静默失效；要「移动红石塔」须单独立项。
- **既有小毛病不随本批修**：红石粉对宿主旧站位的视觉连接怪象（`POS_TO_CACHE_KEY` 首建冻结，所有移动实体容器共有）。
