## 0. 玩法定义（定稿）

**语义**：**活活塞 = 红石驱动的位移执行器**。本槽活红石信号驱动它推 / 拉容器格子里的物品——
流体系统有活滴水石锥（流体自动化执行件），活塞是**物品世界的对应执行件**。
两种活塞：普通（只推）/ 粘性（推 + 拉）。

**获取**：活塞 / 粘性活塞 + 活按钮（活化无门槛）。

**核心循环（玩家语言 —— 先说这东西玩什么）**：

1. **抢救线**（最「活塞味」的用例）：活岩浆格上的物品**当拍焚毁**——活塞在焚毁前把物品
   推出岩浆格 = 自动抢救线。红石时钟对准岩浆节拍，节奏玩法；
2. **条件位移**：信号来了把物品推走 / 拉回——分拣的执行端（「非法物品推出生产线」）、
   把物品推进活漏斗的取料格（投喂）；
3. **力气玩法 / 取回**：**活塞的堆叠数 = 推的距离**（数量多力气大）——摆几块活塞推几格，
   玩家直接控力（拆堆 = 减力气，合并 = 加力气）；粘性拉把远一格的物品**原样**勾回来
   （取回，不合并）；推把一排物品顶到墙边排列（压实排列，不打包）；
4. **涌现联动**（零新代码）：活塞把活箱子推进漏斗输入面格 ⇒ 漏斗按既有虚拟存储逻辑
   抽其内容——「摆箱」与「抽箱」两个既有行为的组合，基地物流的免费积木。

**规则（草案，违反即 bug）**：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **触发状态机**：读本槽活红石信号（`ContainerRedstoneData.getSignal(本槽)`，**上一拍数据 = 1t 延迟**）；无电→有电且未伸出 ⇒ 伸出（推）；有电→无电且已伸出 ⇒ 收回（粘性拉，普通只收头）；`LivingPistonData(extended)` 组件记账 | 第一个「内部状态 + 状态驱动位移」的红石元件——redstone tech §8 火把坑预警的同款，每拍必 tick、不进稳态跳过 |
| 2 | **头格纯视觉**：伸出的头**不占位**（头格可正常放物品 / 被拉入物品），只做跨槽渲染 | 用户 2026-10-31 定调；渲染走活耕地生长槽大图的跨槽先例 |
| 3 | **推的距离 = 自身堆叠数**：面前连续非空链整体前移 **min(count, 链后自由程)** 格（刚体、保间距、真空留背后）；自由程 0 ⇒ 失败；count 在触发瞬间读取 | 用户 2026-10-31 定调「数量多力气大，推的远」——堆叠数 = 力气，玩家摆几块活塞推几格（拆堆 = 减力气，合并 = 加力气） |
| 4 | **纯位移语义**：推与拉**永不合并**——只改位置、不改任何栈的内容；活活塞是全系统唯一不合并的传输逻辑（漏斗 / 流体推动 / 滴注交付都合并） | 用户 2026-10-31 差异化定调：合并语义已饱和，位移是空白生态位；且原版推方块本就无合并（方块不可堆叠）——把原版语义在堆叠世界里保真 |
| 5 | **拉（粘性）= (X+2) → (X+1) 纯位移**：X+1 必须为空（被占 ⇒ 拉不动），X+2 **整栈**移入；X+2 空 ⇒ 空手收回 | 原版收回的忠实投影（收回移动的正是 X+2→X+1，头缩回腾出的正是 X+1）；v1.0「能堆叠就堆叠」被差异化定调推翻 |
| 6 | **准入：活物品可推**——数据跟组件走（移动 ≠ 破坏，数据不离身），链遇活物品照常推 | 用户 2026-10-31 拍板；原版 BE 不可推是因为 BE 绑位置，我们的组件模型没有这个约束 ⇒ 技术上比原版更安全 |
| 7 | **无漏斗特殊联动**：推的语义对漏斗零特殊（漏斗 = 普通活物品）；**活漏斗不传输活物品**（隔离绝对，无例外）；涌现联动 = 推存储类活物品入输入面格 ⇒ 既有虚拟存储行为抽其内容 | 用户 2026-10-31 终版定调：输入面推入逻辑不变、隔离无例外——联动是组合涌现，不是新机制（设计模板 §三：两个既有行为的组合不抽框架） |
| 8 | **写入必经 TransferPipeline / 容器处理器**（自动 bump 修订），**禁止直写槽位**；位移 = 整栈 extract → insert 空槽（管线无合并路径） | redstone tech §8 教训：原版直写绕过 rev-bump ⇒ 信号场失效 |
| 9 | **无 QC**（网格无头格物理，刻意不做）、**无粘液块**（不映射）、**短脉冲吐方块 = 远期**（需 2t 移动中间态） | QC 来源是头占位；网格没有；短脉冲玩法真机有需求再立项 |
| 10 | **取消活化清空 extended**（机械状态不外流，灯泡同款） | 不存在「伸着头的未活化活塞」 |
| 11 | **跨容器推（方向越界延伸，漏斗 pushToNeighbor 同构）**：链前自由程 0 但推方向上存在**世界相邻容器** ⇒ 链/物品越界进入邻居**接壤格**（纯位移语义不变：整栈、无合并、活物品可推；链可跨边界续走）；无邻居容器 ⇒ 失败（原边缘行为）。**粘性拉跨容器 = v2**（推先行） | 用户 2026-10-31 发起探讨；触发模式对齐漏斗（方向越界 = 跨容器触发条件，§6.1）；邻居解析复用 `CrossContainerTransfer` 既有基建；**不映射**：末影路由（传输语义）、虚拟存储推入（漏斗的活儿）、SlotInteractions（活塞不消费货物——纯位移） |

**能力清单（目标）**：⬜ 触发状态机（信号沿检测 + EXTENDED 组件）· ⬜ 位移（距离 = 堆叠数）·
⬜ 粘性拉（纯位移）· ⬜ 头格跨槽渲染 · ⬜ 准入（活物品可推）·
⬜ 图标（单变体 + 头跨槽）

**验证入口**：§5 拍板后补「规则 → 守卫」表；红石侧复用 `ContainerRedstoneDataTest` 基建
（火把环先例——状态元件的振荡守卫）。

## 1. 原版事实存档（1.21.1 源码，2026-10-31 查证）

`PistonBaseBlock` / `PistonStructureResolver` / `MovingPistonBlock`：

| 机制 | 原版实现 |
|---|---|
| **供电判定**（`getNeighborSignal`） | 六方向（除正面）查信号 + 自身位置查下方信号 + **准连通**：以头顶格为中心再查一圈（`pos.above()` 的邻居供电也算）——QC/BUD 的根源（头占位的物理投影） |
| **伸出解析**（`PistonStructureResolver`） | `MAX_PUSH_DEPTH = 12`：面前连续可推链 + **粘液块黏连**（垂直于推轴的粘连带全拖入，粘液↔蜂蜜互不粘 `canStickTo` 双向同意）；链尾空气 ⇒ 成功；不可推 ⇒ 失败；`PushReaction.DESTROY`（花/火把/庄稼）⇒ 进摧毁列表（`dropResources` 掉落 + 摧毁特效） |
| **不可推清单**（`isPushable`） | 黑曜石族 / 基岩族（destroySpeed=-1）/ `PushReaction.BLOCK` / 伸出的活塞本体 / **`!state.hasBlockEntity()`——一切带 BlockEntity 的方块不可推**（推它会令整次解析失败）；NeoForge：`PushReaction` 是方块的自我声明 |
| **执行** | 被推方块全部变 **MovingPistonBlock**（BE，2 game tick 插值移动）+ 活塞头方块 + 原位清空 + 邻居更新风暴——**2t 移动中间态**是短脉冲玩法的物理前提 |
| **收回** | 普通只收头；**粘性拉 (X+2) → (X+1)**（resolver 的 retract `startPos = pos.relative(dir, 2)`，链遇活塞头阻断）——收回只拉这一个（粘连带可扩展） |
| **短脉冲吐方块**（`TRIGGER_DROP = 2`） | 信号太短（伸出动画 progress < 0.5 时断电）⇒ 粘性**不拉回**，方块吐在原地——0tick 技巧的另一半 |
| **NeoForge 接口** | `BlockPistonExtendEvent` / `BlockPistonRetractEvent`（可监听可取消）；`PushReaction` 自我声明；`handleCauldronDrip` 式官方缝在此处对应事件而非查询 |

**原版玩法生态位**：方块世界唯一位移执行器——门 / 升降机 / 隐藏门 / BUD / 0tick /
推断作物收割 / 刷沙机 / 粘液块飞行器。

## 2. 容器映射

### 2.1 触发状态机（红石联动——新特性 ①）

```
每拍（无稳态跳过）：
  sig = ContainerRedstoneData.getSignal(本槽)     // 上一拍数据（1t 延迟）
  if sig > 0 && !extended:  推（链位移）→ extended = true
  if sig == 0 && extended:  收回（粘性拉 / 普通只收头）→ extended = false
```

- **1t 延迟**：物品函数 tick 在 HasContainerData（红石 BFS，prio 2）**之前** ⇒ 活活塞读到的是
  上一拍信号。原版活塞本就有 tick 延迟（scheduleTick），口径可接受；**不为此建新机制**
  （不做「红石算完后回调」——设计铁律）；
- **§8 火把坑的适用**：活塞是「内部状态 + 状态驱动输出」元件——redstone tech §8 的教训
  （稳态跳过冻死振荡）对它天然适用 ⇒ **每拍必 tick、不进任何稳态跳过**；
- 推走 / 拉来活红石元件 ⇒ 槽位内容变化 ⇒ 信号场下一拍自动重算（既有 rev-bump 机制白拿，
  前提是规则 8：写入必经 TransferPipeline）。

### 2.2 推的算术（位移距离 = 堆叠数——新特性 ②）

```
链     = 从 (X+1) 沿方向连续的非空格
自由程 = 链尾之后的连续空格数（到容器边缘为止——活物品可推后无「不可推物品」截断）
位移量 s = min(count, 自由程)
执行：整链刚体前移 s 格（从链尾向链首，每枚整栈 extract → insert 空槽）：
  s = 0（链顶到边缘）⇒ 推失败，原样不动
推后：链保持间距整体 +s，背后留下 s 格真空
```

**力气算例**（方向 →，count = 3）：

```
推前：│30土│40土│    │    │        （链 = X+1..X+2，自由程 2）
推后：│    │30土│40土│    │        （min(3,2)=2 —— 力气够但顶到墙，走 2 格）
若 X+3、X+4 也空（自由程 4）：整体 +3（min(3,4)=3），背后 3 格真空
```

- **count = 8 推穿整行**：9 列容器自由程最多 8 ⇒ 一块 8 堆叠活塞一信号推完一行；
- **不合并的推**：30 土和 40 土挨着被推，推完还是 30 和 40——活塞是搬运工不是打包工
  （打包是漏斗们的事）；
- **count 在触发瞬间读取**：伸出中拆堆不影响已在伸出的状态，下次触发按新 count
  ——力气跟着堆叠走；
- 12 上限不实现（一行 ≤8 天然满足）——常量留档不设防。

### 2.3 拉的算术（纯位移——新特性 ③）

粘性收回 = **(X+2) → (X+1) 纯位移**（原版收回移动的正是这一格）：

- X+1 空 且 X+2 非空 ⇒ **X+2 整栈移入** X+1（一次整栈转移，无合并）；
- X+1 被占 ⇒ 拉不动（不并入、不覆盖——差异化定调）；
- X+2 空 ⇒ 空手收回（头回缩而已）；
- 拉不做链（原版收回也只拉头前一格；粘连带扩展远期）。

**推 / 拉同语义**：都是纯位移（推多格、拉一格）——粘性活塞 = 可回拉的位移执行器，
与全系统的合并语义彻底切割。

### 2.4 头格渲染（跨槽——新特性 ④）

- 伸出的头画在 **X+1 格**（别人家的槽位）⇒ `IItemDecorator` 只画自己槽 ⇒ 走
  **活耕地生长槽大图的跨槽先例**（`AbstractContainerScreen` 槽位窗口内、邻居关系渲染）；
- 活塞图标本体 = 单变体（伸出与否不换图标，或后续加变体——铜灯模式备案）；
- 头格被玩家放了物品 ⇒ 物品与头重叠渲染（纯视觉，无逻辑冲突——用户定调「没关系」）。

### 2.5 准入（活物品可推——新特性 ⑤，2026-10-31 反转定案）

- **活物品可推**：数据跟组件走（移动 ≠ 破坏，数据不离身）——原版 BE 不可推是因为
  BE 绑定位置，我们的组件模型没有这个约束 ⇒ 技术上比原版更安全；
- 链遇活物品照常推（与普通物品同待遇）——推走活红石元件 ⇒ 信号场下一拍自动重算
  （rev-bump 白拿，联动守卫测试见 §6）；
- **推到容器边缘 = 推不动**（2026-10-31 拍板：自由程 0 ⇒ 失败，纯位移语义下销毁不自然）。

### 2.6 活漏斗联动（涌现行为——无新机制，2026-10-31 终版定调）

**推的语义对漏斗零特殊**：漏斗对推来说是普通活物品（可被链推、可阻挡推）；
**活漏斗不传输活物品**——隔离绝对（本体永不穿过漏斗、永不被漏斗搬运），
无机械投递例外（v1.2~v1.4 的穿管 / 机械投递整套作废）；
**输入面推入逻辑不变** = 向输入面推物品就是一般位移规则（漏斗是普通活物品）。

- **涌现联动**（零新代码，两个既有行为的组合）：活塞把**存储类活物品**（活箱子）推入
  漏斗**输入面格** ⇒ 漏斗按**既有虚拟存储逻辑**抽其内容、从输出面送出（箱子本体不动）
  ——活活塞负责「把箱子摆到位」，漏斗负责「抽箱子」，联动是组合的涌现；
- **非存储活物品**（活海绵 / 活工具等）：推入输入面格 ⇒ 漏斗跳过（隔离），物品原地待着
  ——活海绵的流体不经漏斗（漏斗搬物品不搬流体）；
- **隔离原则无修订**：AGENTS.md / living-hopper-tech 的隔离表述**不需要改**
  （v1.4 曾拟「机械投递例外」，2026-10-31 终版定调撤销——漏斗不传输活物品，
  例外的复杂度买不来自动化收益）；
- **勘误链留痕**：v1.2 穿管 → v1.3/v1.4 机械投递例外 → v1.5 终版（无特殊联动、涌现组合）；
- **实现**：活塞零漏斗感知；漏斗零改动——本节没有需要实现的联动代码。

### 2.7 跨容器推（方向越界延伸——漏斗 pushToNeighbor 同构，2026-10-31 探讨）

**触发**：链前自由程 0（位移被容器边界截断）**且**推方向上存在**世界相邻容器** ⇒
链/物品越界进入邻居容器的**接壤格**（推方向侧的边缘格）；无邻居 ⇒ 失败（原边缘行为）。

- **语义完全不变**：纯位移、整栈、无合并、活物品可推——跨的只是「格子归属哪个容器」，
  边界对位移透明；**链可跨边界续走**（A 侧推入 B 后，B 侧接壤链继续被推——链解析在
  边界处切换到邻居容器接壤格续走，SlotResolver 越界返回 -1 ⇒ 换邻居解析，漏斗同款模式）；
- **复用**（不新建机制）：邻居容器解析 + GUI→世界方向转换（`CrossContainerTransfer` /
  `Pos2D ↔ Direction`，block-facing.md）全是现成基建；覆盖矩阵的口径照抄——**邻居侧
  只有裸 IItemHandler**（活活塞的位移不需要特殊槽位识别：活物品可推、无合并、不消费货物）；
- **原子性**：跨容器推 = A 侧整栈 extract + B 侧空格 insert 的多容器事务——模拟先行
  全程预演、任一跳失败全回滚（`CrossContainerTransfer` 已有跨容器原子先例）；
- **信号场**：物品越界后离开本容器信号场、进入邻居的信号场——两边各自 rev-bump 重算
  （既有机制白拿，守卫测试覆盖「跨边界推红石元件」）；
- **组合性**：跨容器 × 涌现联动 × 堆叠力气全部正交可叠——推活箱子越界落入邻居漏斗
  输入面格（漏斗按既有虚拟存储逻辑抽其内容）、8 堆叠推穿边界接壤链；
- **不映射**（语义归属排除）：末影路由（传输语义）、推入活箱子虚拟存储（= 传输语义，
  漏斗的活儿——活塞纯位移不「消失物品进容器」）、SlotInteractions 槽位交互（活塞不消费
  货物，纯位移）；
- **粘性拉跨容器 = v2**：拉越界（pullFromNeighbor 同构）单列，推先行验证。

## 3. TransferPipeline 复用（设计铁律：不新建机制）

- **推的每一跳 = 一次整栈槽对槽转移**（extract 全栈 → insert **空槽**，与活漏斗同源）；
  链位移 = 从链尾向链首的**串行转移序列**（模拟先行，全程预演通过才落）；
- **拉 = 一次整栈槽对槽转移**（X+2 → 空的 X+1）；
- 位移不走「部分并入」路径 ⇒ 管线的合并分支对活塞关闭（差异化的实现面）；
- **禁止直写槽位**：绕过容器处理器 = 绕过 rev-bump ⇒ 红石信号场失效
  （redstone tech §8 实证教训）——这是「必须走 TransferPipeline」的**正确性理由**，
  不只是风格；
- 活活塞因此是 TransferPipeline 的又一个消费者（漏斗之后），无新增传输原语。

## 6. 坑登记簿 / 远期

- **count 触发瞬间读取**：伸出中堆叠数变化（玩家拆堆 / 合并）不影响已在伸出的状态；
  下一次触发按新 count——**力气跟着堆叠走**（拆堆 = 减力气，合并 = 加力气，玩家直接控力）；
  代价与趣味并存：想要 3 台单格活塞就得拆出 3 格——力气 vs 数量是玩家的真取舍；
- **短脉冲吐方块**（TRIGGER_DROP）：需 2t 移动中间态——活红石 1t 脉冲真实存在（火把环），
  玩法可达；远期立项；
- **粘液块**：不映射（物品无黏连语义；`canStickTo` 双向同意的机制在物品堆叠上无对应物）；
- **红电机械力**（远期愿景）：活塞推铜块 = 机械能的种子——红电文档留过电磁感应口子，
  属愿景层不入本稿；
- **头格视觉与物品重叠**：头格放物品后头与物品叠画（用户定调没关系）——真机若乱，
  头透明度 / 偏移微调即可；
- **推走活红石元件**（活物品可推后成为现实场景）：推走拉杆 / 红石粉 ⇒ 信号场下一拍
  自动重算（rev-bump 白拿）——**必须补联动守卫测试**（推红石元件后信号正确的断言）；
- **隔离原则无修订**：活漏斗不传输活物品（2026-10-31 终版定调）——AGENTS.md /
  living-hopper-tech 无需改动；v1.2~v1.4 的穿管 / 机械投递例外全部作废留痕于 §2.6；
- **性能**：活塞只在「容器里有活活塞」时 tick（分组既有），每拍一次信号读 + 沿检测
  ——微不足道；推链 ≤8 跳 × SlotAccessor 模拟+执行，同漏斗量级；

  已打通），信号场在内层容器独立计算。
