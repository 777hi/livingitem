## 0. 玩法定义（设计规则；代码已落，真机验收范围见§7.8.5）

**语义**：活活塞在同容器网格内把连续物品链前移一格，或通过候选活漏斗入口像挤牙膏一样
压送末端货物。普通活塞推 / 压送，粘性活塞另可把头前一格整栈拉回。

**获取**：原版活塞 / 粘性活塞 + 活按钮（活化无门槛）。

**核心循环**：

1. **条件位移 / 抢救线**：红石控制整链单格推，可配合流体节拍把物品移出危险格，不新增抢救机制。
2. **数量选范围**：活塞数量 N 是普通推链上限，也是压送货物范围；范围内设备可成为货物，
   范围外紧接的一格才可能是接收漏斗。增加数量可能改变设备 / 货物角色，不保证原出口更易成功。
3. **机械定时 / 定量**：锁定漏斗主动取料，将主动权交给活塞；红石决定动作次数 / 时间，
   接收漏斗数量决定每次最多送多少，出口容量再限制实际交付。
4. **设备物流**：可压送活箱子 / 活工具 / 活海绵 / 活漏斗等本体，不展开它们的内部功能。
   借漏斗出口跨容器，末影出口只做玩家末影箱直连推送，不走公共 / 专属路由。
5. **过滤自动化**：漏斗数量变化、普通位移或末端送空改变名单布局；过滤等级可被自动化是接受的
   涌现。漏斗名单链不因此变成物品管道。
6. **原有抽箱行为仍成立**：活箱子放在未锁定漏斗取料格可被抽内容；此主动功能与机械搬箱子
   本体是不同动作，不能混用访问器或全局放开活物品隔离。

**记号**：X 为活塞本槽，X+k 为沿朝向第 k 格；N 为活塞数量；C 为本次末端货物数量；
M 为接收漏斗数量；q 为实际交付量。所有「格」沿用现有容器邻槽口径，不另建几何 / 容器键。

## 2. 容器映射

### 2.1 状态机（成功保持、失败重试）

```text
每拍读取本容器最近一次计算的本槽信号（不再取prev额外延迟）：
  有电且未伸出：按当前N解析 §2.2 / §2.6
    空推或普通推成功，或压送实际q > 0 ⇒ extended=true
  无电且已伸出：粘性按 §2.3 尝试拉，随后extended=false
```

每次尝试读当前count，失败期间修改数量可改变施力范围与候选接收端；已完成动作不追加位移。
成功后即使头格仍有残货，也不再挤，下一次需先收回再通电；不新增红石计算后的回调或调度器。

### 2.2 数量划范围与普通推

```text
N = 活塞当前数量
无同容器X+1 ⇒ 失败
从X+1起按方向检查，范围内不因看到漏斗而提前接管：
  N格以内先遇空槽 ⇒ 链结束，按普通整链单格位移（L可小于N）
  X+1..X+N均非空：检查紧接的X+N+1
    空 ⇒ 普通整链单格位移
    输入面匹配的活漏斗 ⇒ 候选接收端，按 §2.6 判过滤与出口
    其他物品 / 输入面不匹配 / 越界 ⇒ 失败
普通位移：全程能完整抽取 / 插入才从尾到首移动，每栈+1
```

N以内每格按货物解释，漏斗本体也可推；只有X+N+1可作为接收者，不搜索更远处。
候选接收失败不能将其纳入普通链顶走，也不能缩短范围改由前一个漏斗接管。

```text
普通推（N=3）：
前：[活塞×3][土×64][铁×8][活箱子][ 空 ]
后：[活塞×3][ 空 ][土×64][铁×8][活箱子]

空格截断（N=3）：
前：[活塞×3][ 土 ][ 空 ][ 铁 ][ 空 ]
后：[活塞×3][ 空 ][ 土 ][ 铁 ][ 空 ]
```

上限就是N，不加固定12上限，不假定所有容器9列；旧多格冲程 / 压实排列与
`min(count, 自由程)`已作废。增加N可能把原接收漏斗纳入货物范围，是玩家可控制的角色变化。

### 2.3 粘性拉

X+1、X+2均在同容器，X+1空、X+2非空且整栈可移动才拉；其余不搬但收回。
不合并、不拉链、不随N扩大拉取距离，不从漏斗出口 / 玩家末影箱追回刚交付的物品。

### 2.4 三维渲染与执行分离

**模型、挂点与专属动画已实现；修正后的四向最终观感待真机验收。**

- 固定本体在X，头杆朝配置的上 / 下 / 左 / 右伸到X+1并缩回；普通 / 粘性对应各自外观。
- 分部件插值，不只切两张静态图标；伸出态本体与完整收回外观可变化，不受旧单变体限制。
- 服务端可当拍完成位移 / 交付，客户端仅表意；不为视觉动画建世界BE或机械移动中间态。
- 无X+1不画头杆；头与真实物品 / 挤压残货可叠画。被推货物一路滑动未在本轮定案。

短脉冲反向与换容器初始化待 §6，不凭视觉中间态新增吐物品。

### 2.5 两层过滤与本体准入

**接收漏斗货物过滤**与**目标容器槽位准入**是两层检查。过滤通过不代表槽位可放；
普通推拉 / 压送都尊重槽位黑白名单、容量、抽取 / 写入及权限约束。
活物品可作货物，但不能为此全局取消普通漏斗隔离；用本体访问而非箱内存储 / 路由功能访问。

**活水流推动的槽位准入口径另题**：本轮只定活塞与漏斗联动，不修改流体规则、不套用其准入豁免。

### 2.6 活漏斗联动（单接收端挤牙膏，v1.8细化）

#### 2.6.1 接收端定位与漏斗本体

X+1..X+N必须连续非空，货物就是这N格；只有X+N+1为候选接收漏斗，且输入面须匹配。
输入 / 输出按其 `sourceOffset` / `targetOffset` 识别，不能按图标猜；一次仅交付X+N原本的货物。

**漏斗作货物时**：冷却 / 锁定不阻止搬运；自己的数量不是本次剂量，自己的出口不发送后方货物。
**漏斗作接收设备时**：留在原槽，用自己的数量、过滤与真实出口，不与货物漏斗在本槽合堆。

```text
同一布局，向右推动，后一个漏斗左进下出：
[活塞×3 →][A][B×7][漏斗×3 →][漏斗×2 ↓]
           1    2        3            4
          └────货物范围────┘       候选接收端

过滤允许漏斗本体、下方出口可收2时：
[活塞×3 →][A][B×7][漏斗×1 →][漏斗×2 ↓]  → 下方收到漏斗×2
q=2成功；A / B保持原位，货物漏斗剩1；即使货物漏斗送空，A / B也不移动。
```

**N改为2不能据此声称B可通过两漏斗发走**：第三格漏斗成为候选，但它指向第四格活漏斗的
关系是名单传递，不是可交付物品的出口。用户纠正的算例中，漏斗×3将B作为Tag级黑名单
传给漏斗×2；本次没有B的实际交付，q=0、推不动。不是「按3再按2限量直通」。

保留 [活漏斗 §2.4.6](../tech/living-hopper-tech.md) 的名单继承 / 穿透与过滤优先级；
名单中有B不意味着漏斗本体被同样拒绝，N=3时仍须检查本体实际匹配结果。
不新增多段物品管道，不因名称「管道」递归穿漏斗；此项已明确不做，不留待探讨条目。

#### 2.6.2 控制权、剂量与过滤时间

| 维度 | 主动传输（现有机制） | 机械压送（已实现） |
|---|---|---|
| 发起者 | 漏斗tick | 活塞本次尝试 |
| 红石锁定 | 停主动取料与其冷却倒计时 | 仍可压送，非必须锁定；锁定交出主动权 |
| 冷却 | 沿原规则 | 无视且不修改主动冷却，不设机械冷却 |
| 过滤 | 既有名单构建 | 接收者名单过滤货物本体，动作开始时结果固定 |
| 活物品 | 不主动搬本体；存储类可用内部功能 | 可拆数量送本体，组件与内容保全 |
| 剂量 | 原主动规则 | 接收漏斗数量M上限，出口容量再限 |
| 节拍 | 自动运行 | q>0保持伸出，下次先收回再通电 |

正常过滤、源抽取与权限满足时，交付候选为 `min(C, M, 出口可接纳量)`；执行按实际入账
校准q，源净扣减同为q。q>0成功，q=0不伸出可重试；目标未加载、拒收、玩家离线不能假设容量。
出口可按正常规则合并，但不强行合堆、不绕过槽位准入。

**过滤自动化（已接受）**：本次用动作开始时过滤，不在途中反复改判。货物漏斗3→1、普通
位移或末端送空改变布局，既有过滤重建后用于后续动作；等级由Tag→ID等变化是涌现，不阻止。
不为本次动作增加过滤强制刷新挂点，不把等级变化自动化做成另一种新机制。

#### 2.6.3 压送只处理末端栈（送空留空）

```text
部分出料，出口只收2：
前：[活塞×2 →][A×5][B×7][接收漏斗×3]
后：[活塞×2 →][A×5][B×5][接收漏斗×3]  → 收到B×2

末端全部送出，出口足够：
前：[活塞×2 →][A×5][B×2][接收漏斗×3]
后：[活塞×2 →][A×5][ 空 ][接收漏斗×3]  → 收到B×2
两种情况q=2均成功；A始终原位，不移入B腾出的槽。
```

- 单次只交付动作开始时的末端栈，送出多少扣多少；有残余留原槽，送空原槽留空。
- 无论末端是否送空，后方货物都不移动，不借后栈凑满M、不在本次继续出料。
- q>0即成功并保持伸出；q=0失败可重试，成功后持续通电不再出料。
- 送空造成的空隙截断下一次压力；下一轮按普通推 / 空推规则重新解析当前布局，不设特殊修复。
- 直接顶7个货物、接收漏斗3、出口足够，三轮分别送3、3、1。
- **删除留痕（v1.11，用户）**：自动补位对核心定时 / 定量与本体物流收益有限，却增加整段
  准入预演、提交撤销和交付协调；整套删除，不留开关、延后任务或补偿机制。普通整链推不变。

#### 2.6.4 出口范围（末影直连、不做路由）

- 即时出口复用漏斗既有方向、面选择、存储插入与权限；跨容器交付归漏斗，不让活塞续接世界链。
- 普通槽、世界相邻容器、虚拟存储的实际覆盖须依各容器契约实现与核验，不复制物流调度。
- **末影只做直连推送**：通过直连活末影箱实际插入绑定玩家末影箱空间；玩家须在线，
  容量只够部分则部分交付，离线 / 满 / 拒收q=0。只定推入，不放开主动直连提取活物品。
- **公共 / 专属频道不做机械压送**：遇路由目标失败，不登记源指针，不回退主动登记，
  不保存压力请求、货物授权、异步交付或新队列。现有普通主动路由不受影响。
- 玩家末影箱空间可作为转接存放处；如何从另一端取出不属于本轮推送能力，也可使用其他
  模组已有物流能力，不宣称本模组已实现自动无线活物品闭环。

**翻转留痕**：v1.2穿管 → v1.3 / v1.4机械投递 → v1.5 / v1.6无特殊联动 →
v1.7挤牙膏压送 → v1.8数量定角色、名单链不物流直通、直连不路由 →
v1.11删除自动补位，压送只交付原末端栈，送空留空、后方不动。

### 2.7 边界

普通头格、链节、落点全在同容器，无头格不画头杆；普通链尾越界失败、粘性拉越界不拉但收回。
压送的货物范围与候选入口也必须在同容器，接收漏斗输出越界不取消本地头格，出口交付归漏斗。
没有合法入口时世界邻居不改变普通推拉结果；不恢复旧直接跨容器推链与粘性拉v2。
`SlotInteractions`消费交互、名单链物品直通与路由登记均不是实际机械交付。

## 3. 实施复用与正确性（已实现，真机边界待验）

**两种正确性分开**：普通整链位移不能部分完成；压送可部分交付，按实际q扣原末端源。
压送无论是否送空都不移动后方链，不依赖普通推链的整段移动计划完成交付。

容器访问 / 写回更新修订，移动红石元件使信号重算；禁止绕过处理器直写。
主动漏斗管线仍维持活物品隔离 / 功能源展开；机械路径独立使用本体访问器、真实q与中立接收端口，
没有全局放开活物品，也不把单跳模拟称为多槽事务。

工厂的活物品隔离与存储类展开没有全局删除；机械压送不调用 `SlotInteractions` 或
`TransferTargetPolicy`，路由末影由目标访问器返回0。领域通过共享 `MechanicalReceivers`
解耦，piston与hopper保持R3零依赖。

**仍需真机核验**：直连玩家在线 / 部分容量、未锁定主动与压送同拍争货、第三方受限槽；
自动守卫已覆盖普通推拉准入与撤销、部分交付、组件保全、模拟 / 实做差异及世界面选择。
现有移动事务欠账统一见 [TODO.md](../TODO.md)「物品传输」；第三方违约不能承诺绝对无损。
活水流准入是独立口径，本次未改流体代码 / 文档规则。

### 6.1.1 粘性争抢（已定）

后者源空则空手收回；先执行者目标拒收不占货，后者仍可尝试。不同源争一个空目标同理，
后者因目标已占不拉、不合并。两者都收回，无力量比较 / 公平轮换 / 随机或新仲裁器。
实际争抢沿既有执行顺序；不保证左侧、低槽号或某一方优先。核实发现分组首遇顺序与公开
功能排序契约不符，修法归§7.3：恢复既有契约，不新建活塞仲裁。

**两种提交边界不合并**：普通位移整段全有或全无；压送允许部分交付，q真实守恒、后方不动。
压送不再包含第二次整链移动。SIMULATE不修改真实容器，不以临时搬走货物冒充预演。

### 7.4 精确本体移动：编码前契约核验（历史方案）

**已核实**：现有ContainerContext可读槽，但写回没有精确成功量 / 可恢复承诺；
`isItemValid=true`只代表一般准入，不能替代逐请求模拟。链内目标原本被占，普通插入模拟
不知道未来腾空状态；IItemHandlerModifiable能指定槽写入，不证明允许放入或能安全撤销。

**推荐方案**：先定义窄的本体移动边界，由掌握后端的容器层实现，活塞只持动作计划；
不改变旧setItem截断 / 回退语义，不强制所有现有传输使用它，不先建泛型事务框架。

候选契约必须能表达（**行为约束，不是已定方法签名**）：

1. 精确源 / 目标槽及原栈副本；本体读写，不展开存储功能。
2. 全栈可抽取、组件保全、目标空槽与槽级准入 / 容量；计划能反映前一步腾空。
3. 纯检查不修改真实状态；提交时验证当前源 / 目标仍符合计划，不能忽略动态准入。
4. 整段提交或只撤销该段；回滚原槽，不能把货散到其他槽来伪装成功。
5. 显式结果区分不支持、正常拒绝、成功与后端违约；不得把日志告警当成恢复成功。
6. 成功发布槽位脏标记 / revision / runtime失效；该契约只管普通推拉，不再协调压送后补位。

**后端覆盖核验表（不是已支持列表）**：

| 宿主 / 后端 | 已核实形态 | 实施前要证明 |
|---|---|---|
| 世界普通容器 | SimpleContainerContext，可能是Container / 可修改handler / 只读写能力handler | 精确写回、抽取与槽级准入、恢复；不能仅按容器名字判断 |
| 玩家背包 | 复用Simple，装备槽有特殊准入 / 容量分支 | 保留现有装备槽口径，不把handler限制机械套回去；物理槽映射正确 |
| 玩家末影箱宿主 | EnderChestContainerContext继承Simple，原版InvWrapper | 受控后端可优先证明普通位移；不等于放开主动直连提取 |
| 实体容器 | EntityContainerContext继承Simple，马族storageOffset映射 | 逻辑 / 物理槽及准入、读写与撤销都保留offset |
| 物品形态容器 | ItemFormContainerContext继承Simple，接来源提供的handler | 能力取决于真实后端，不因“物品形态”就保证事务或新增内部tick |
| 第三方受限槽 | 正常handler可能隐藏动态规则或重定向插入 | 模拟与实际范围一致、精确恢复；不能强制setter绕过其黑白名单 |
| 只有通用handler，无法精确恢复 | 现有接口不足以保证整链全有或全无 | **待定**显式适配 / 不支持反馈；不偷偷降成仅原版箱子支持 |

核验入口：`container/SimpleContainerContext.java:236–368`；
`container/ItemFormContainerContext.java:26,76–85`；`container/EntityContainerContext.java:101–149`。

**编码阻塞点G1**：定窄契约挂在哪里、特殊槽未来腾空准入怎么表达、无法恢复后端怎样反馈。
推荐先用受控后端的证明性测试收窄问题，再决定是否确需新增公共可选接口。

### 7.5 机械接收与数量返回（编码前方案）

**已核实**：TransferPipeline在hopper领域，源工厂会隔离 / 展开，深层跨容器也有隔离和消费
交互。现有TransferTargetPolicy分发在两侧Accessor与准入之后，不能只注册一条就接受机械货物。

**推荐方案**：薄注册接收边界放共享层，hopper注册实现；活塞不import漏斗 / 末影具体类。
请求只包含本体源、候选接收槽、当前容器与本次tick所需上下文，接收方验证自己与输入关系、
取固定过滤、按M和输出接纳交付，结果回真实q。命名 / 参数 / 对外性尚未定。

```text
源：本体访问（活箱子本体、活工具、活漏斗等）
  → 接收漏斗：入口关系＋本次过滤＋M剂量
  → 目标：功能访问（虚拟存储 / 直连）或普通物品槽 / 世界handler
  → 实际q；q>0成功，末端送空留空、后方不动
```

机械路径不能调用主动tick，不改冷却，不触发SlotInteractions消费，不递归另漏斗，
不调用末影路由登记策略。末影目标现有insert/simulateInsert在非直连返回0，直接使用
实际插入能力即可拒绝路由；不需要另写路由模式。邻居几何复用原候选面与能力查询，但
机械出口插入范围必须与准入逐槽检查一致，不能检查一格却把货送进另一格。

**数量增强候选**：让通用SlotAccessor内核回实际量，旧boolean入口判断量>0并委托；
过滤 / 同步 / 回滚仍复用，原主动调用者不改数量节拍。源 / 目标报告不实的违约不能靠
类型检查解决，须定义失败上报，不给“任意第三方绝对安全”承诺。

**编码阻塞点G2**：接收端口形状、数量返回是否扩现有入口，以及共享包新增契约的对外承诺。
[API契约§1.2](../system-design/api-contract.md)规定container / transfer是对外包，
新类 / 新契约需单独审批；写进蓝图不等于已授权实现API。

### 7.6 执行可见性与同步（接缝修复提案）

- **执行顺序**：修复既有manager稳定顺序契约；不为活塞指定新仲裁 / 特殊最后阶段。
- **旧条目**：先读取当前栈并验功能适用性，相关entry循环也需重验。已知移动槽的旧执行资格
  要失效，不能把被移走设备的旧动作搬到新槽继续执行；不采用对象引用作为通用实例ID。
- **快照**：每次动作取得的过滤结果保持固定；布局改变后，后续容器级计算需要当前槽集合
  和快照，但不重跑已执行功能。具体刷新接缝待回归验证，不用每件货物全局重扫。
- **runtime**：旧失效必须在新状态读取前被消费；机械提交后只作废已知移动槽并同步追踪，
  不迁移伸出态、不因count变化复位。L4消费既有失效队列，L1不反向依赖runtime层。
- **首包 / 删除**：开界面有完整快照；缺失槽与空快照清旧态；物品栏有自己的归属通道。
  客户端用解包后的真实槽索引与当前菜单上下文取数，不从替身容器猜服务端真实位置键。
- **原图与动画**：GUI模型替换 / 抑制与overlay分工，避免两份本体覆盖计数；未知界面、HUD、
  创造包装槽与拖拽预览保留明确回退，不把已有decorator当拥有容器邻槽关系的接口。

核验入口：`client/util/ClientSlotResolve.java:48–60`，
`runtime/LivingItemClientCache.java:39–59`，`client/render/LivingItemTooltip.java:64–89`。
动画时长、光照、深度、scissor与快速反向属于原型；当前没有游戏内验收，不预先填“通过”。
