## 0. 原始需求（用户原话，原样保留）

> 光标持有活物品悬浮在活按钮上时屏蔽这几个键。然后我觉得当前的交互逻辑还有待改进，  
> 能不能加个悬浮框啥的显示信息呢，顺便完善一下交互逻辑。
>
> 还有几个逻辑，我觉得要不干脆一次做了：
>
> 1. 空指针左键长按可以拖动活按钮改变位置，并且记住
> 2. 右键活按钮，活化指针，可以直接点击物品进行活化操作；活指针悬浮在物品上可以通过 wasd 改方向，  
>    显示信息框；可以左键长按框选批量活化操作

## 1. 现状盘点

### 1.1 方向配置：数据层够、输入层缺

| 层       | 能力                                                                                 | 位置                                    |
| ------- | ---------------------------------------------------------------------------------- | ------------------------------------- |
| **数据层** | `Pos2D` 支持 **8 方向**（含四个对角）；`DirectionSlotsData` = `Map<String, Pos2D>` ⇒ **任意槽位数** | `living/model/`                       |
| **输入层** | `keyToDirection` **只有 `W/A/S/D` 四个基本方向**                                           | `client/input/LivingItemInputHandler` |

⇒ **5 个槽位用 4 个方向放不下** —— 任何 5 个互不重叠的位置，必然要动到对角。

### 1.2 现有触发条件（全部满足才处理）

`ScreenEvent.CharacterTyped.Pre` + 容器 GUI + 悬停活按钮 + 光标持活物品 + 输入是 WASD。

> ⚠️ 用的是**字符事件**（`CharacterTyped`）而非按键事件 —— 这决定了 `Q` 的丢弃**拦不住**（见 §3）。

### 1.3 五个痛点

| # | 痛点                      | 证据                                         |
| - | ----------------------- | ------------------------------------------ |
| 1 | 活按钮**无悬停提示**            | `LivingButton` 全类无 `setTooltip`，只有贴图切换     |
| 2 | 方向输入**全程无反馈**           | `LivingItemInputHandler` 只有 `LOGGER.debug` |
| 3 | **不知道有「按 WASD 配方向」这功能** | 无任何入口说明，只能读文档                              |
| 4 | 输入**无法取消**              | 只能等 3 秒超时（`DirectionSession.TIMEOUT_MS`）   |
| 5 | 方向语义不直观                 | 玩家不知道 `WAS` 对应哪个槽位                         |

## 2. 改进方案（三层）

| 层 | 内容                                         | 实现入口                                                           |
| - | ------------------------------------------ | -------------------------------------------------------------- |
| 1 | 活按钮 **tooltip**：按钮作用 + 手持活物品的方向状态 + 操作提示   | `LivingButton`（`setTooltip` / `renderTooltip`）                 |
| 2 | 输入过程 **HUD**：实时显示「已输入 2/5」+ 各槽位当前方向 + 键位提示 | `AbstractContainerScreenMixin.render @TAIL`（**已有叠加入口**，水流渲染在用） |
| 3 | **交互逻辑完善**：`Esc` 取消 · 完成确认 · 无效键提示         | `LivingItemInputHandler`                                       |

⭐ **九宫格与 HUD 必须配套**：光加对角键、不给提示，玩家不知道 `Q/Z/C` 能用 ⇒ 等于白加。

## 3. 方向配置升级为九宫格

**方案**：键位 `Q W E / A S D / Z X C` —— **天然对应九宫格**，一个键 = 一个方向，零歧义。

⚠️ **屏蔽键**：在「光标持活物品 + 悬停活按钮」时屏蔽这几个键 —— 含 `Q` = 原版丢弃键。  
因 GLFW **按键事件先于字符事件**，必须在**按键阶段**（`ScreenEvent.KeyPressed.Pre`）拦截；  
等字符事件时，丢弃已经发生了。

**曾评估「组合键」方案**（`W+A` = 左上）—— **放弃**：  
核心难点是**字符流切分歧义**（`W+A` 是「左上」1 个槽位，还是「上、左」2 个槽位？）。  
三种解法代价都高于九宫格：

| 解法                 | 代价                     |
| ------------------ | ---------------------- |
| 时间窗口（<150ms 视为同时按） | 输入有确认延迟；想快速输两个独立方向会被误判 |
| 分隔符（空格分隔槽位）        | 按键次数翻倍（5 槽 + 4 分隔）     |
| 改模型（先选槽位再输方向）      | 改动大，改变熔炉现有操作习惯         |

### 3.1 拦截判据（2026-10-10 用户补充）

**只在「指针悬停的物品可自定义槽位（`instanceof HasDirection`）」时才拦截键位。**

理由：

- 悬停**普通物品**时，`W/A/S/D` 不该被吞（`Q` 也仍可正常丢弃物品）
- 与现有判据一致 —— 现 `LivingItemInputHandler` 也是先 `findDirectionFunction` 找到 `HasDirection` 才处理

⚠️ **判据要统一**：键位拦截 + 信息框显示用**同一个判据**  
（`screen.getSlotUnderMouse().getItem() instanceof HasDirection`）。

⚠️ **拦截位置有两处**：`ScreenEvent.CharacterTyped.Pre`（字符）与  
`ScreenEvent.KeyPressed.Pre`（按键，为拦 `Q` 等）**两处都要判**。

⭐ **副作用（重要）**：方向配置**不再依赖「手持物品」**，而依赖「悬停槽位物品」  
⇒ 这正是**指针模式的核心价值**（顺带回答了 Q4 的一半）。

### 3.2 两条路的并存形态（Q4 定案，2026-10-10）

**老路保留不动，指针模式作为新增功能** —— 两条路**触发条件不同、互斥**：

| | 老路（现有，不动） | 新路（指针模式，新增） |
|---|---|---|
| 进入 | 无（随时） | 右键活按钮 |
| 触发 | 光标**手持**活物品 + 悬停**活按钮** | 指针悬停**槽位物品**（`instanceof HasDirection`） |
| 配置对象 | **手持物品** | **槽位物品** |
| 拦截判据 | 手持物品 `instanceof HasDirection` | 悬停槽位物品 `instanceof HasDirection` |

⚠️ **实现注意**：`WASD` 拦截有**两套判据**，要保证互斥（同一时刻只有一套生效），
否则会同时拦截、或都不拦。

### 4.1 位置持久化（E1，参考 TrashSlot 1.21.1）

**TrashSlot 的做法**（源码 `libs/src/TrashSlot-1.21.1`）：

| 维度       | 实现                                                                          |
| -------- | --------------------------------------------------------------------------- |
| 存储位置     | `<gameDir>/TrashSlotSaveState.json`（**客户端本地**，Gson 序列化）                     |
| **区分粒度** | **Screen 类名** —— `screen.getClass().getName().replace('.', '/')`            |
| 每项内容     | `slotX/slotY`（坐标）· `anchorX/anchorY`（锚点）· `isEnabled`（显示开关）· `isLocked`（锁定） |
| 默认值      | 由 layout 提供（`getDefaultSlotX/Y`）；支持 `*.default.json` 供整合包预设                 |
| 交互       | 拖动 + **吸附**（拖到 GUI 边缘自动贴靠）+ **碰撞**（不覆盖 GUI 主体）                              |

**⇒ 我们的方案（Q1 定案）**：

- **按 Screen 类名分别保存**（每种界面一个位置）
- 坐标存**相对 GUI 左上角**（`leftPos` / `topPos`）的偏移 —— GUI 位置变化时按钮跟着走
- 存**客户端本地 JSON**（每个玩家自己的 ⇒ 多人服互不影响），路径用 `config/living_item/`（与项目现有客户端配置一致，不用 gameDir）

**✅ 定案（2026-10-10）：吸附 / 碰撞 / 显示开关 —— 三者都不做**（只做拖动 + 位置持久化）。

⚠️ **TrashSlot 是 Architectury / 多加载器项目**（`common/` + `fabric/` + `forge/` + `neoforge/`，依赖 **Balm** 抽象库）  
⇒ **只借鉴思路，不照搬架构**。本项目仅 NeoForge，不需要 common/platform 分层，  
也不需要 accessor mixin（`AbstractContainerScreenAccessor`）——我们的 mixin 本身就能直接访问 `leftPos/topPos`。

### 4.2 框选交互（E2c 细化，2026-10-10 定案）

**渲染**（拖动期间**实时**显示）：

- 半透明**选择框**（覆盖在 GUI 之上、tooltip 之下）
- 框内**槽位实时高亮**
- **命中数量**提示

**命中判据**：以**槽位中心落在选框内**为准（边缘擦到不算）—— 判据稳定，且与高亮预览一致。

**执行时机**：**松开鼠标后**才执行 —— 拖动中**不改任何物品状态**（可随时调整）。

**单击 vs 拖拽**：

- 按下后**几乎没移动**就松开 ⇒ 当作**单击**（切换该物品）
- 按住并**拖过一个小距离** ⇒ 进入框选

**框选语义 = 只活化**（已活化的跳过，不取消）—— 与单击的「切换」**不同**。

**备选（未采）**：以「矩形与槽位相交」为命中判据 —— 更宽松但容易多选，且预览与判据的对应关系不如中心判据直观。

## 5. 待拍板问题（未决）

| #  | 问题                 | 选项                                                                           |
| -- | ------------------ | ---------------------------------------------------------------------------- |
| Q1 | **按钮位置存哪**         | ✅ **定案（2026-10-10，参考 TrashSlot）：按 Screen 类名分别存，客户端本地 JSON**（每个玩家自己的）。详见 §4.1 |
| Q2 | **指针模式怎么进出**       | ✅ **定案（2026-10-10）：右键进入；退出 = 再右键 + 关闭界面自动退出**。`Esc` 不抢（它是关界面的）               |
| Q3 | **取消活化怎么触发**       | ✅ **定案（2026-10-10）：点击 = 切换**（活化 ↔ 取消活化），**与老路语义完全一致** —— 用户原话：「原来是**拿着物品点按钮**，现在是反过来，相当于**拿着按钮点物品**」。✅ **框选 = 只活化**（已活化的跳过，不取消）—— 与单击的「切换」**不同**，见 §4.2                                             |
| Q4 | **方向配置是否完全迁到指针模式** | ✅ **定案（2026-10-10）：两条并存** —— 老路（手持活物品 + 悬停按钮）**保留不动**，指针模式作为**新增功能**。详见 §3.2                                                        |
| Q5 | **框选范围**           | ✅ **定案（2026-10-10）：矩形覆盖即选中** —— 不论槽位在容器区还是玩家背包区，被框到的都算。大箱子两半本就是**同一个 menu**，天然覆盖，不需要额外处理。**不额外过滤**（尊重玩家的选择）                                                               |
| Q6 | **UX 隐患：模式指示**     | ✅ **定案（2026-10-10）：不动鼠标指针**（指针外观无法预料 —— 受玩家材质包影响），改为**活按钮换材质**指示模式（用户单独绘制一张）。⚠️ 按钮若被拖到角落 / 被遮挡时指示会看不到（玩家自己的选择）                           |
