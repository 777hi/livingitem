## 2. 尚未定义的扩展

| 议题 | 当前边界 | 扩展前的判据 |
|---|---|---|
| 子背包菜单的真实宿主反查 | 当前顶层Item/AnotherPlayer可证明；子来源只隔离、不穿透借根位置 | 与tick直接父层语义一致，官方来源能证明真实库存/宿主/槽；没有证据不借viewer |
| 世界门反向发现容器门/容器门配对 | 当前只用原版世界门出口，没有返回原容器保证 | 先定“去哪里”和多门歧义/拆门失效，不为方便搜索提前造永久配对标记 |
| 其他维度/载具 | 当前主世界↔下界、官方门户准入 | 有独立玩法需求再核查官方能力，不从接口能调用推断支持 |
| 更强的货物交付保证 | 当前源交接后交原版，普通失败留源世界，目标注册失败有原版风险 | 若要求失败始终留库存，需要明确改变事件/交付语义；不能删原对象就盲目补库存 |
| 新的组合玩法 | 当前仅活地狱门这一明确围闭点火需求 | 多个实际接入方共同部分主要靠配置时，才讨论通用机制 |
