# 活斧槽内去皮方案

> 状态：设计提案 —— 本文供审阅，不是已生效玩法或执行授权。
> 编写日期：2026-11-10；查证版本：Minecraft 1.21.1 + NeoForge 21.1.219。
> 范围来源：[TODO「活工具·系列扩展」](../TODO.md#活工具--系列扩展2026-10-31-清点登记d-doc-06)。本稿只拆出手动 GUI 去皮，不代表其余工具交互一起实施。

## 1. 建议先确认的玩法

**拿起一把活斧，右键槽里的活木料，将该槽整堆原地变成对应的去皮活木料。**

| 项目 | 本稿建议 | 取舍 |
|---|---|---|
| 变换数量 | 一次整槽 N → N，不拆分、不跨槽放产物 | 对齐现有活锄头的整堆交互；无需引入剩余材料与第二落点 |
| 耐久 | 成功后调用一次原版 `hurtAndBreak(1, …)` | 是一次基础损耗请求，不是保证 Damage 恰好加 1；附魔、不可破坏与模组损坏钩子照常生效 |
| 工具数量 | 光标只接受单件工具；多件先拆分 | 原版工具本就不可堆叠；避免为模组可堆工具新定义「损坏后换下一把」机制 |
| 创造模式 | 材料照样原位变换，只免工具损耗 | 不免工具能力、活标记、槽位权限和真实写入校验 |
| 兼容 | 原版去皮映射 + 声明 `AXE_STRIP` 能力的工具 | 不承诺执行任意模组的方块 override、事件改写或工具自定义右键效果 |
| 反馈 | 悬停显示产物、数量、基础损耗；成功后向操作者播放原版去皮音效 | 无动画状态、无粒子、无新业务网络包 |

整堆 N 件只请求一次基础损耗，**是有意偏离原版逐方块损耗的便利性玩法**，不是性能优化。若希望按木料件数扣耐久，应先改本项设计，不能在实现时自行切换。

**本次不做**：刮铜、脱蜡、铺土径、自动加工、邻槽加工、树皮副产物、世界层辅助、活锄头迁移、通用工具加工框架。

已有活工具「无记忆时不自动影响槽位」的边界继续成立；这里是玩家手动操作，不让工具 tick 自发加工，也不要求先录制记忆。

## 2. 已查清的实现依据

### 2.1 直接调用官方纯转换入口

使用 `AxeItem.getAxeStrippingState(BlockState)`：公开静态、可返回 null，不需要世界坐标，不派发工具修改事件。

本机查证入口：[AxeItem.java](../../libs/src/neoforge-21.1.219-merged/net/minecraft/world/item/AxeItem.java) 的 `getAxeStrippingState` 与 `STRIPPABLES`；依赖源码为本机可选材料，实际版本由 [gradle.properties](../../gradle.properties) 确定。

约束：

- 不维护第二张「原木 → 去皮木」映射，遵守既有 J3 定案。
- 不调用 `useOn`，不构造伪造的 `UseOnContext`，不把玩家脚下或箱子位置冒充木料位置。
- 不用 `getToolModifiedState(..., simulate=true)` 当纯函数：状态层仍派事件；simulate 是协议，不是世界副作用隔离器。
- 官方纯入口只保留轴向 `AXIS`，其余属性来自结果方块默认态；不承诺额外状态全搬过去。
- 返回 null、结果仍为原物品、无物品形态或结果为 AIR，均不构成可执行变换。
- 官方映射本身覆盖原木、全皮木、下界菌柄/菌核和竹块；不只覆盖名字含 `log` 的物品。

这一路不会进入 [LivingToolRecorder.onToolModify](../../src/main/java/com/qiqi/li/living/domain/tools/LivingToolRecorder.java)，因此 GUI 去皮不录制、不覆盖、不清除斧子的既有记忆。

### 2.2 复用现有机制，不新建并行系统

| 需求 | 复用位置 | 本次边界 |
|---|---|---|
| 组合与右键匹配 | `InteractionEntry` / `InteractionRegistry` / `InteractionPredicates` | 新增行为和谓词，不扩规则语法 |
| 注册 | [ToolRegistration](../../src/main/java/com/qiqi/li/living/domain/tools/ToolRegistration.java) | 在工具域注册，不新增 Function 或注册中心 |
| 客户端发包与创造光标 | [GuiInteractionHelper](../../src/main/java/com/qiqi/li/client/input/GuiInteractionHelper.java)、[GuiInteractionPacket](../../src/main/java/com/qiqi/li/network/GuiInteractionPacket.java) | 沿用现有包与光标回传，不走 FakePlayer |
| 菜单槽到真实宿主 | [ContainerContexts](../../src/main/java/com/qiqi/li/living/container/ContainerContexts.java) | 复用解析及逻辑槽映射，不自建容器键 |
| 整槽原位变换 | [ContainerContext.transform](../../src/main/java/com/qiqi/li/living/container/ContainerContext.java) | 使用数量原语，不照抄活锄头的 `targetSlot.set` |
| 悬停提示 | [LivingContainerOverlay](../../src/main/java/com/qiqi/li/client/render/LivingContainerOverlay.java)、现有 `FarmlandPlantHint` 模式 | 在现有 overlay 接入，不新加 Screen Mixin |

注意：现有 `transform` **不负责槽权限校验**，且「没有变化」也返回 true；不能把它的布尔值单独当作「本次成功去皮」的证明。

## 3. 交互与数据规则

### 3.1 准入

| 位置 | 允许 | 必须拒绝 |
|---|---|---|
| 光标 | 单件、已活化、`canPerformAction(ItemAbilities.AXE_STRIP)` 为真 | 空手、普通斧、仅有 `AXE_DIG` 的工具、多件工具；不以 `instanceof AxeItem` 限制模组工具 |
| 目标物品 | 已活化的 BlockItem，官方纯入口能给出不同的有效物品结果 | 普通木料、已去皮木、木板、无转换结果、AIR 结果 |
| 目标槽 | 当前有效菜单中可操作、允许取出与放入结果的真实存储槽 | 输出槽、幽灵槽、禁用槽、无法可靠映射到宿主的槽 |
| 宿主 | 现有上下文能解析、有效逻辑槽、有明确直写能力 | 无上下文、无直写能力；不为单个容器新增专用适配 |

活物品隔离的自动处理规则不变；这里是**显式的活工具对活目标交互**，不是把活物品交给自动设备当耗材。

### 3.2 规则表达与兼容上限

在内置 [interaction_rules.json](../../src/main/resources/assets/living_item/interaction_rules.json) 添加两条规则：

| 建议规则 ID | target | trigger | button / action / predicate |
|---|---|---|---|
| `axe_strip_logs` | `#minecraft:logs` | 省略，交给能力谓词 | `right` / `axe_strip` / `can_strip_with` |
| `axe_strip_bamboo` | `minecraft:bamboo_block` | 省略，交给能力谓词 | 同上 |

两条均在按下时触发。tag 只负责候选集合，最终能否转换必须问官方方法；已去皮木即使在 logs tag 里也不能触发。

兼容分成两关：**规则命中**和**官方转换有结果**。模组木材只有加入相应 tag（或由现有配置另挂 item/tag 规则），且官方映射包含它，才在本版范围内；仅覆盖 `getToolModifiedState` 的木材不支持。省略 trigger 时，谓词必须自行复验双方活标记。

客户端在匹配前后不改变库存；纯判据不成立就让原版右键继续。**已经发包并取消原版点击后，服务端拒绝不能再补演一次原版右键**；此时仅保留或同步真实状态。

### 3.3 数量与组件

- 变换单元是整个目标栈；结果 count 必须与输入相同，不按斧子数量放大，不生成额外物品。
- 产物以新物品默认组件为底，通过原版 `transmuteCopy` 复制源组件补丁，而非 `applyComponents(source.getComponents())` 把旧物品默认值全覆盖过去。
- 自定义名称、说明及普通自定义数据不应因去皮丢失；组件补丁中的显式删除项也不能遗漏。
- 源 `BLOCK_STATE` 先应用于源方块默认态，再询问纯入口；结果只保留转换结果认可的属性。普通无状态木料不额外写默认轴向组件，避免无意义的堆叠差异。
- **不做通用活功能迁移**：源或结果若被其它活功能认领，或木料携带容器载荷/方块实体数据，首版拒绝；不能借去皮清掉隐藏库存或把旧功能状态挪给新物品。这是模组木料的明确支持边界。
- 对上述无附加活功能的木料，活标记随形态变换保留；不取消再活化，不触发无关生命周期。工具自身全部组件保留，仅损耗管线可以改变它们。
- 对未知第三方组件只保留其补丁，不声称理解或迁移其跨物品语义；有特殊语义的木材需独立验收，不能凭「数据还在」宣布完整兼容。

### 3.4 耐久与结算

单件限制来自实际原版行为：整堆工具共用一份 Damage，损坏只 `shrink(1)`，剩余栈的 Damage 不会自动归零。首版不实现耐久轮换或拆工具事务。

服务端确认整堆材料确实变成期望产物后，才对**光标副本**请求一次基础损耗，再经 `menu.setCarried` 提交。创造模式不调用损耗；生存下附魔、不可破坏和模组 `damageItem` 钩子由原版管线处理。单件工具用尽后光标为空，已经完成的木料变换保留。

失败不扣耐久、不播成功音；不预扣耐久再赌产物写得进去。这里不承诺抵御任意第三方损坏钩子的违规副作用，也不为此建立跨物品事务框架。

## 4. 服务端执行与必要接缝

拟新增 `AxeStripHandler`（工具域，待建），将纯转换判据和 `InteractionHandler` 放在同一具体行为类中；客户端谓词、提示与服务端复验共用它，不先抽通用加工器。

顺序：

1. 从当前菜单读取光标和目标的独立快照；校验菜单仍有效、双方准入、结果确实不同。
2. 校验 `Slot.isActive`、`mayPickup(player)`、`mayPlace(result)`；通过 `ContainerContexts.resolve` 取得宿主，再将物理槽号转换为逻辑槽号。
3. 校验逻辑槽有效、后端抽取模拟允许完整输入量、结果 `isItemValid`、宿主声明支持精确写入；目标槽与上下文必须指向同一真实存储位置。
4. 使用 `transform` 整槽替换；变换函数只返回已经准备好的独立结果，不在函数中扣耐久、播音或调用活化时机。提交前重验输入，已变则拒绝。
5. 只有返回成功且最终物品、数量、组件均等于完整期望结果，才进行光标损耗和成功音效；之后使用现有菜单/创造光标同步。

**容量不是空槽插入问题**：木料尚占着目标槽，此时直接 `simulateInsertItem(result)` 会因为异种占位返回 0，不能拿它否决原位变换。也不能先临时清空真实槽来模拟；本操作沿用整槽原语的写入与回读核验，不自算 64 上限，不另开旁边槽位。

### 4.1 在接入前补上的小范围守卫

这两项不是新增框架，而是本功能对既有入口的必要约束：

- **包槽位定位**：`GuiInteractionPacket.resolveSlot` 的索引直查需同时核对请求的 `containerSlot`；回退不能无条件取第一个同号槽，候选不唯一则拒绝。保留正常箱子菜单的索引优先语义，补「箱子和玩家背包都有第 9 槽且内容相同」的测试。创造背包应定位玩家真实库存，不接受创造物品目录作为加工材料。
- **变换快照**：当前 `transform` 的 before 来自 `getItem`，需用独立副本，避免后端 setter 改坏旧引用后回滚失去原值；在原方法里作最小修正并补回归，不增加新原语或改造其它数量操作。

槽位内容相等只能作为一致性检查，**不能证明槽位身份**；大箱顺序、实体装备槽偏移及物品形态库存必须沿现有映射，并由针对性测试/实机验证确认，不能搜索一份相同木料来代替目标槽。

### 4.2 不作出的保证

`supportsExactWrite` 是能力声明，不是写入成功证明；目前具体上下文的旧 `setItem` 还可能在 setter 拒绝时进入抽插回退。方案不把它误写成「绝不会抽插」或「对任意后端原子回滚」。业务层不得自行再加一套抽插或回滚。

先用副本、原引用、no-op、截断、拒写后端验证本次接缝。无直写能力在调用前拒绝；声明可写却拒写的后端不得把降级插入当作本功能的兼容成果。若现有原语不能满足拒写安全性，**先暂停该接入，提出原入口的最小修正供审阅**，不能为赶去皮进度扩大写回框架或假称该容器已支持。

恢复失败沿现有原语留痕，不能承诺「失败时所有第三方库存必然原样」。对正常受支持后端，失败必须不改变木料与工具；违约后端的剩余风险要在验证记录里单列。

## 5. 反馈与生命周期检查

拟新增 `AxeStripHint`（客户端 input，待建），沿用现有纯提示行模式并接入 `LivingContainerOverlay`。

- 可加工时显示「右键去皮：产物名称 × N」「基础耐久消耗 1」；创造模式显示不消耗耐久。
- 多件活斧对可去皮木料显示「先将工具拆成单件」，不吞原版点击。
- 只在当前有效规则实际匹配时提示可加工，避免玩家删除/覆盖规则后仍显示旧提示；槽权限能在客户端判断的部分用于收窄提示，最终资格由服务端复验，不另造客户端交互分发分支。
- 客户端不能证明后端写入成功，不显示成功动画或提前播放音效；成功音由服务端确认后只发给操作者。
- 未匹配的普通物品、普通斧、空手不增加提示；与种植提示、方向 HUD、地图覆盖保持现有优先级。

| 状态 | 存放与粒度 | 移走/换槽 | 取消活化 | 关闭/卸载/重进 |
|---|---|---|---|---|
| 工具耐久、既有记忆 | 工具原有组件，单件 | 跟物品保留 | 仍按既有取消活化行为；本功能不插手 | 跟原物品持久化 |
| 去皮结果和元数据 | 目标槽实际物品 | 跟物品保留 | 依既有活化规则处理 | 依宿主原有持久化 |
| 候选结果与输入快照 | 一次交互局部变量 | 不留运行时状态 | 不适用 | 方法结束即丢弃 |
| 悬停提示 | 当前画面即时计算 | 下帧重算 | 下帧消失 | 不存储 |

不新增 DataComponent、静态运行缓存、容器附件、定时器、扫描器或卸载清理钩子；不读邻槽、不依赖容器列数、不对外报资源量。

## 6. 原版对齐与偏离

| 原版行为 | 本方案 | 理由 |
|---|---|---|
| 由 `AXE_STRIP` 能力识别工具 | 对齐 | 模组工具不必继承原版斧类 |
| 木材转换与轴向保留 | 调用官方纯入口 | 不维护第二份映射 |
| 成功后原版损耗管线 | 对齐，基础请求 1 | 附魔/不可破坏/损坏钩子沿用 |
| 每方块一次操作/损耗 | 改为每槽整堆一次 | GUI 便利性玩法，需用户认可 |
| 方块修改事件与第三方 override | 不触发 | 槽内没有真实方块位置，不伪造世界上下文 |
| 放置新方块、邻居更新、GameEvent、方块使用进度 | 不执行 | 不是世界方块交互 |
| 副手盾牌的使用意图 | 不参与 | GUI 光标操作不等同玩家主手右键世界 |
| 原版去皮音效 | 仅成功后通知操作者 | 不伪造木料所在的世界声源 |
| 自动记忆录制 | 不触发 | GUI 加工不属于记忆射线操作 |

FML 单测不加载 item tags，不能把日志为空或被禁用的 tag 测试算作覆盖：单测可验证规则结构/具体 item 条目与纯判据，`#minecraft:logs` 的真实命中必须进入游戏验证。

后续代码验证按 [unit-testing](../guides/unit-testing.md) 执行局部测试，完整复核用 `./gradlew test --rerun`，再跑项目五门禁；本次只写方案，不重跑全量测试，也不把已有快照当成本方案实机证据。

### 7.3 游戏内验收（不可由单测代替）

- 生存背包、单箱、大箱两半：普通/整堆木料右键，数量不变、只加工所点槽，声音只在成功后出现。
- 下界木料、全皮木、竹块；已经去皮的目标不被重复处理。
- 创造背包与创造开箱分别测试：光标不消失、不复制、背包其它同号槽不被误改；创造目录物品不能当真实库存加工。
- 把相同木料放入箱子第 9 槽与玩家背包第 9 槽，分别点击；实体容器验证装备槽偏移，物品形态容器验证真实宿主保存。
- 工具最后一点耐久、耐久附魔、不可破坏工具；多件工具提示拆分，右键原版分堆仍正常。
- 拿走、换槽、取消活化、关界面、连续右键；普通斧和普通木料的拿起/放置行为不变。
- 原工具已有记忆时做 GUI 去皮，再回世界确认记忆与辅助/自主行为未被改写。
- 改名木料、状态轴向、超大堆叠容器：不截成 64；落盘后重进存档复核实际库存。
- 至少一把模组工具验证能力兼容；仅靠自定义 override 去皮的木材应不触发，而不是宣称支持。
- 回归活锄头耕作、种植/骨粉、活桶倒汲、拉杆/按钮、方向 HUD 与悬停提示。

只承诺验收通过的容器组合；没有启动游戏完成上述检查时，交付必须明确写「实机未验」。
