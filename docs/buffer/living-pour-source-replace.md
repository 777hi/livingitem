# 倒桶路径对齐：A 档 ——「倒桶对任何液体格一律替换」（含 B 档的同向修正）

> **性质**：口径收窄 + 对齐原版的记录文档。用户 2026-10-06 先选 **B**（只补「水浇岩浆源」），
> 随后在看到「为什么异种源格语义要不同」的追问后**改选 A**（对称化、去源/流动分裂）。
> 前置阅读：`living-fluid-tech.md` §3.5（跨流体反应四格场景）、§5（倒/汲语义）、§9（挂起项）。

## §0 🔴 早期误读更正（本文件 §1 的初版结论是错的）

初版把 `LavaFluid.canBeReplacedWith` 的 `getHeight() >= 0.444` 当成**倒桶**规则，据此推出
「原版会拒绝倒进异种**流动**格、也拒绝岩浆倒进水格」。**错在读错了函数**：

| 函数 | 归属 | 含义 |
|---|---|---|
| `Fluid.canBeReplacedWith(state, level, pos, incoming, dir)` | **蔓延**路径（`FlowingFluid`决定能否**流进**这一格） | 0.444 高度门槛在这里 |
| `blockstate.canBeReplaced(fluid)` = `state.canBeReplaced() \|\| !state.isSolid()` | **倒桶**路径（`BucketItem.emptyContents`） | 液体块 `legacySolid=false` ⇒ **一律可替换** |

证据：`BucketItem` 全程**不出现** `canBeReplacedWith`；另一条
`LiquidBlockContainer.canPlaceLiquid` 分支**永不命中**（`LiquidBlock extends Block implements
BucketPickup`，未实现该接口）。

⇒ **原版倒桶对水/岩浆、源/流动一律替换，没有区别对待。**

## §1 原版真实规则与我们的差异（更正后）

| 场景 | 原版 1.21 | A 档（定稿） |
|---|---|---|
| 空格 | 放源 | 诞生源 |
| 任意**流动**格（含同种） | 替换（`setBlock` 成源块） | 直接诞生源（覆盖） |
| **同种源** | 换成同一种块 = 无变化 | 源不变 |
| **异种源**格 | **替换**（水⇄岩浆双向） | 问 `canBeReplacedBy` ⇒ 水/岩浆**对称覆写** ⇒ 双向替换 |

## §2 定稿（A 档）

- **契约**：`canBeReplacedBy(FluidType incoming)` —— **去掉 B 档的 `selfIsSource` 参数**
  （原版没有源/流动之分，0.444 门槛在 2D 也不成立：流动 level 1~3 ⇒ 高度 0.111~0.333）；
- **水与岩浆各自对称覆写**（岩浆：`incoming == WATER`；水：`incoming == LAVA`）；
- **default `false`**：未覆写的流体**保守拒绝**（这是接缝真正的职责 —— 让每个流体自己表态，
  而不是复刻原版「液体一律可替换」的方块规则）；
- **`pour` 简化**：空格/任意流动格 ⇒ 诞生源；同种源 ⇒ 不变；异种源 ⇒ 问一句再决定；
- **客户端不预判**（拒绝时「右键无反应」= 原版倒不进，规则只留一份）。

## §3 B 档 → A 档 的变化

| | B 档 | A 档 |
|---|---|---|
| 接缝签名 | `canBeReplacedBy(incoming, selfIsSource)` | `canBeReplacedBy(incoming)` |
| 水行为 | **不覆写**（水源格不可被替换） | **覆写** `incoming == LAVA`（对称） |
| 异种源格 | 只允许「水→岩浆源」 | 双向（水⇄岩浆） |
| 异种流动格 | 直接覆盖 | 直接覆盖（不变） |

⇒ B 档与 A 档在「异种流动格」上**行为相同**（那本就��原版）；真正被改掉的只有
「岩浆桶倒进水格」：从**拒绝**改成**替换**。

## §4 被否选项

| 选项 | 否掉的理由 |
|---|---|
| A 档的**非对称**版（只有水浇岩浆源） | 原版倒桶无源/流动与方向之别（§0），单向限制纯属自造 |
| C 档（源也不变，只排空桶） | 水桶灭不了火，玩家预期落空 |
| 在 `pour` 里硬编码水/岩浆判断 | 流体知识会漏进交互层；契约化后其它流体可各自表态 |
| 客户端也预判拒绝 | 规则会分裂成两份；服务端权威已足够 |
| 复刻原版「液体一律可替换」为default `true` | 危险默认：将来接入**不可覆写**的流体（如某种不可置换的油）时会静默被冲掉；宁可 default 拒绝 |

## §5 连带影响

- 覆盖是**同键改写**（`generatedSources.put`）⇒ 下一拍 `pruneActual` 移除该格原流体、
  下游失去供给的流体按目标层收敛退走，**不需要额外清理逻辑**；
- 「浇灭岩浆源后回收水」闭环成立（水源被覆盖后可被活空桶汲走）；
- 倒进异种**流动**格仍是覆盖（原版同款），但**不产生任何反应产物** —— 黑曜石/圆石只来自机制五
  （熔岩**蔓延**到水格）；
- 源被覆盖 = 矿脉型资源被玩家主动销毁（原版水桶就能做到，属预期）。

## §7 遗留

- 目标格有物品 ⇒ 客户端不拦截 ⇒ 桶会被放进熔岩格（活的挤没源 / 非活的被焚毁）—— 单列项，未处理。
- DOWN 特例（`LavaFluid.spreadTo` 向下遇水 ⇒ 石头）在 2D 不映射；soul soil + blue ice ⇒ 玄武岩未做。
