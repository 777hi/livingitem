## 0. 玩法定义（草案 —— 待拍板后定稿）

**语义**：**活滴水石锥 = 滴注发射器**。按朝向**发射活水滴**（容器级瞬态投射物），
活水滴沿直线飞过容器格子，命中**流体受体**（活海绵等可存流体的活物品）则交付载荷，
命中不可交付的东西则消失。同时它是**可再生源生成器**：上游是活流体源时，
滴注**复制**语义（源不消耗，滴出的水在落点成源）——原版「滴水石锥 + 炼药锅 = 无本流体」
的容器版等价物（用户 2026-10-29 拍板）。

**获取**：滴水石锥 + 活按钮（活化无门槛）。

**核心循环**：
- **源滴（复制模式）**：活水源摆在上游邻槽 → 锥逐拍发射活水滴 → 滴落进空槽成新源
  （源农场）或命中海绵入库存；
- **海绵泵（消耗模式）**：湿海绵摆在上游邻槽 → 锥逐拍抽海绵发射活水滴 → 送达下游成源 / 入库；
- 活水滴在两堆海绵之间架起**跨格补给线**（射程内直线可达，不再要求相邻）。

**规则（草案，违反即 bug）**：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **发射判定**：逆方向邻槽 = 活流体源 ⇒ **源滴**（源不消耗，复制语义）；= 湿海绵（存量 ≥1000mB）⇒ **泵滴**（海绵均分扣除）；皆非 ⇒ 不发射 | 两种模式按上游类型自然分派，无需轮转拍板；源不消耗 = 原版无本滴注对齐（守恒律修订见 §2.5） |
| 2 | **活水滴 = 容器级瞬态**：不落盘、不进组件，容器重载即在飞滴全部消散（下一发射拍重新开始） | 滴是亚秒级瞬态，落盘 = 存档脏状态；发射器本体**零组件**（桶哲学） |
| 3 | **发射时射线结算**（原版架构，已拍板 ②）：发射时沿 `HasDirection` 按 §2.3 矩阵判定命中格与结果，到达 tick = 距离 × 5t；滴动画 = 客户端本地回放（零逐拍同步）；**到达重验**（目标仍可接收才交付）；射程 8（待拍板 ①） | 用户「射线探测」直觉 = 原版 1504 架构；A 逐格状态滴降为备选 |
| 4 | **命中语义矩阵**（§2.3）：流体受体活物品 = 交付；非活流体容器 = 撞死（**活化资产不外流**，fluid tech §6.1）；已有流体格（源/流动）= 撞死（不覆盖——覆盖是倒桶的显式语义）；空槽 / 普通物品 / 非受体活物品 = 穿过；射程尽头 / 容器边缘 = 消失 | 受体语义 = 活物品间的**投递协议**；撞死非活流体容器 = 滴打水漂（风味 + 对称性红线） |
| 5 | **交付**：目标 = 海绵 ⇒ +1000mB 均分入堆（记账内核第三消费者，§3.1）；目标 = 空槽 ⇒ **源诞生**（`registerGeneratedSource`，复制语义的落点）。受体不可接收（满 / 异种）⇒ 滴消失（泵模式损失 ≤ 一滴，损耗向） | 源诞生有先例（岩浆 SPAWN_SOURCE 即时改写）；满 / 异种拒绝 = 规则 5 同款 |
| 6 | **发射节拍 50t / 滴 + 每发射器在飞 ≤1** | 锚原版 `scheduleTick(50 + 距离)`；射程 8 × 5t = 40t < 50t ⇒ 天然串行，「在飞 ≤1」为调参兜底 |
| 7 | **岩浆滴同机制**（payload 参数化）：岩浆源可被复制滴注、岩浆滴可入海绵 / 空槽成岩浆源 | 原版滴岩浆同款；**岩浆自此可再生**（原版 dripstone+锅+岩浆同款）——经济影响见 §6 |
| 8 | **零组件发射器**：滴水石锥本体无 DataComponent（方向 = `HasDirection`，在飞滴存容器级瞬态） | 桶哲学（搬运不持有）；无落盘、无取消活化清理 |
| 9 | **不跨容器**：飞出容器边缘 = 消失 | 「物品过境水不过境」 |
| 10 | 写入 `generatedSources` ⇒ **下一拍生效** | 与倒桶 / 汲走同层（fluid tech §3.6） |

**能力清单（目标）**：⬜ 活水滴容器级瞬态（发射 / 飞行 / 命中判定 / 消散）·
⬜ 源滴复制 + 泵滴两模式 · ⬜ 交付协议（海绵均分入堆 / 空槽源诞生）·
⬜ 活岩浆滴（payload 参数化）· ⬜ 滴动画（第 5 条渲染通道，§3.2）· ⬜ `HasDirection`

**验证入口**：§5 拍板后补「规则 → 守卫」表；基建复用 `SimpleContainerContext` +
假 `FluidPresence`（活耕地先例）。

## 1. 原版事实存档（1.21.1 源码，2026-10-29 全量查证）

`PointedDripstoneBlock`：11 种方块状态（朝向 × 五段粗细 × waterlogged），钟乳石（朝下）/ 石笋（朝上）成链。

| 机制 | 原版实现 |
|---|---|
| **滴注**（random tick） | 结构：钟乳石**根**（朝下且上方非滴水石锥）正上方是**水源** → 概率水 **0.17578** / 岩浆 **0.05859**（NeoForge patch：模组流体走 `FluidType.getDripInfo().chance()` 声明）→ 从根沿链向下找**尖端**（≤11）→ 从尖端穿「可滴穿」格（空气 / 碰撞不挡中央 4×4 竖柱的非实心块；≤11）找**炼药锅** → `scheduleTick(50 + 距离)` → 锅 **+1 层**（≈333mB）。**水源不消耗 = 无本滴注**。**泥→黏土**特例：根上方是泥块（非下界）⇒ 滴注把泥变黏土 |
| **生长**（random tick，独立结构） | **三明治**：锥根上方是**滴水石块**、滴水石块上方是**水源**（此结构不滴注）→ 概率 0.0114 → 50/50：钟乳石向下长一节 / 给下方石笋长一节（向下探测 ≤10，遇水停）；链长 ≤7 |
| **坠落与伤害** | 钟乳石失去支撑 ⇒ 整条链逐节变下落方块；尖端落地伤害 1.0 × max(距离, 6)，上限 40；石笋摔伤（距离+2）×2；三叉戟高速可击碎 |
| **杂项** | 可 waterlogged；`canDripThrough` = 空气或碰撞不挡中央 4×4 竖柱的非实心块（玻璃挡、台阶穿）；尖端滴水粒子（0.02 / 源下 0.12） |
| **滴粒子**（纯视觉，零逻辑） | **两条生成通道**：①氛围滴（客户端 animateTick：12% 检查，2% 任意流体 / 2–12% 仅可填锅流体）——纯装饰；②真滴广播 `levelEvent(1504)`——服务端 random tick 实际调度转移 / 泥黏土转化时广播，这颗才对应真实转移。**三段生命周期**：悬挂 `DripHangParticle`（尖端底部微颤，lifetime 40t，归零转生）→ 下落 `FallingParticle`（gravity 0.06，落地移除）→ 落地 `DripstoneFallAndLandParticle`（SPLASH 溅射 + 音效）。**零世界效果**（不灭火不湿润不填充）；与转移**完全解耦**：转移走 `scheduleTick(锅, 50+距离)` 服务端链，50+距离 ≈ 落地时间的手工近似 |
| **NeoForge 扩展缝** | `FluidType.getDripInfo()`（`DripstoneDripInfo`：chance + dripParticle）声明「可被滴注」；`handleCauldronDrip`（`CauldronBlock.java:61`）模组流体完全接管锅的接收——与海绵的 `isVaporizedOnPlacement` 同一哲学（官方留缝） |

**原版玩法生态位**：滴石锥 + 锅 = 唯一无本流体收集器（水 / 岩浆都可再生——岩浆锅舀出岩浆桶）；
泥→黏土 = 黏土唯一可再生途径；钟乳石雨 = 伤害装置。

## 2. 容器映射

### 2.1 活水滴本体论（B 架构：发射时结算 + 客户端回放，2026-10-29）

| 维度 | 定案 |
|---|---|
| 服务端 | **只有「已调度的交付事件」**：发射时沿方向射线按 §2.3 矩阵结算命中格与结果 ⇒ 调度一条交付（到达 tick = 距离 × 5t）+ 广播一次滴动画事件；**无逐拍滴状态**（原版 1504 架构，② 已拍板） |
| 客户端 | 一次性广播 ⇒ 本地模拟三段动画（悬挂 40t → 下落 → 溅射，源码同款生命周期）——飞行动画是结算结果的回放 |
| 到达重验 | 到达 tick 检查目标格仍可接收（仍在 / 未满 / 同种）⇒ 交付；否则滴作废（原版 scheduleTick 拆锅同款） |
| 数量 | 每发射器 ≤1 个未结算交付（发射间隔 50t ≥ 到达延迟，天然串行） |
| 发射器本体 | **零组件**（方向 = `HasDirection`；发射判定读容器数据，不持有）——桶哲学；**不落盘**（交付事件随容器瞬态，重载即消散） |

### 2.2 发射模式（按上游类型自然分派，无轮转）

| 模式 | 上游（逆方向邻槽） | 发射时 | 载荷来源 |
|---|---|---|---|
| **源滴（复制）** | 活流体源 | **源不消耗**（复制语义，2026-10-29 用户拍板） | 凭空（对齐原版无本滴注） |
| **泵滴（消耗）** | 湿海绵（存量 ≥1000mB） | 海绵均分扣除 1000mB | 海绵存量 |

- 上游皆非（空 / 普通物品 / 其它）⇒ 不发射；
- v1.0 的「整源搬运」模式**删除**——被源滴复制取代（复制比搬运更强且更贴原版；
  「把源挪走」的场景由海绵吸收承担）。

### 2.3 命中语义矩阵（发射时射线判定 + 到达重验）

| 命中格内容 | 结果 | 理由 |
|---|---|---|
| **活海绵等流体受体活物品**（可接收：未满 / 同种） | **交付** +1000mB（海绵：均分入堆） | 投递协议的第一批受体；「可存流体的活物品」= 用户定调 |
| **流体受体但不可接收**（满 / 异种） | 滴消失（泵模式损失 ≤ 一滴，损耗向） | 不强行覆盖；「穿过去找下一个受体」留给真机反馈再议 |
| **非活流体容器**（桶、模组流体罐物品） | **撞死**（滴消失，传输失败） | **活化资产不外流给非活化载体**（fluid tech §6.1 对称性红线）——滴打水漂是风味 |
| **已有流体格**（源格 / 流动格） | 撞死（待拍板 ⑤） | 覆盖已有资产是倒桶的**显式**语义，滴注是自动行为不覆写 |
| 空槽 | 穿过；**若是射程终点仍无受体** ⇒ 落格**源诞生**（源滴模式：复制语义落点；泵模式同） | 源诞生的容器版落点——「滴进空处成源」 |
| 普通物品 / 非受体活物品（漏斗、红石、另一滴水石锥…） | **穿过**（待拍板 ③） | 对齐原版「滴穿一切非受体」；容器里摆满杂物不应堵死滴注 |
| 容器边缘 / 射程尽头 | 消失 | 不跨容器（规则 9） |

> 待拍板 ③ 的两个选项：穿过（推荐，原版滴穿精神 + 自动化友好）vs 撞死（更「物理」但杂物堵路）。

### 2.4 交付与源诞生

- **入海绵**：+10⁶ mmB 按 count 均分（floor + 零头回收）——**记账内核第三消费者**
  （灯泡充电 / 海绵充放 / 滴注交付，§3.1）；
- **空槽源诞生**：`registerGeneratedSource(槽, fluid)`（倒水同款 API）——「源即时」适用
  （岩浆 SPAWN_SOURCE 先例：直接改写实际层）或下一拍（待实现定，观感无差）；
- **泵滴扣海绵**：均分扣除（ceil 交付口径同 GUI 汲）。

### 2.5 守恒律修订（随源滴复制生效）

fluid tech §0 规则 3「**增长只来自晋升**」修订为：

> **增长来自晋升 + 活滴水石锥滴注复制**（2026-10-29 用户拍板：源是活流体源时，
> 原版无本滴注语义成立）。

**经济影响（有意识接受）**：**岩浆自此可再生**（岩浆源 + 锥 → 岩浆滴 → 空槽成岩浆源；
原版 dripstone+锅+岩浆同款）——岩浆「矿脉型一次性资源」的口径就此改写，
唯一旋钮 = 发射节拍（50t/滴 = 200mB/t，比原版滴锅快约两个数量级，§5④ 附注可调）。
水的可再生原本就有（晋升），滴注是第二种形态（定向、可搬运到晋升够不着的格）。

### 2.6 节拍与时钟

| 项 | 值 | 依据 |
|---|---|---|
| 发射间隔 | 50t / 滴（待拍板 ④） | 原版 `scheduleTick(50 + 距离)` 的 50 |
| 到达延迟 | 距离 × 5t（② 已拍板） | 与水节拍同频；8 格 = 40t ≈ 2s；动画客户端本地模拟（B 架构，零逐拍同步） |
| 发射时钟归类 | 物品自有节拍 | 原版滴注比水流慢一个量级，跟水拍就失去「滴」的意义（活耕地节拍门先例） |
| 命中交付 / 源诞生 | 反应类（当拍） / 下一拍 | 滴命中是显式事件；`registerGeneratedSource` 走既定写入层级 |

## 3. 引擎契合

1. **引擎零改动**：只用 fluid tech §2.3 公开 API —— `registerGeneratedSource`（源诞生）+
   既有查询；发射判定 / 飞行 / 命中全在滴水石锥自己的容器级瞬态里；
2. **宿主是普通 `LivingItemFunction`**：域归 `domain/water/`；海绵交付走
   `LivingSpongeData` 的均分入堆（**记账内核第三消费者**，§3.1 of 活海绵稿）；
3. **活水滴的容器级瞬态存储**：仿 `ContainerFluidData` 的容器键挂法，但**不落盘**
   （对比：流体实层也不落盘，重载重生长——同款取舍）；
4. **对称性合规**：源滴复制 = 活化侧设备复制活化资产（用户拍板）；泵滴 = 活化侧内部转移；
   撞死非活流体容器 = §6.1 对称性红线的执行面。

### 3.1 滴动画的渲染（B 架构已拍板 ②，无通道问题）

B 架构（待拍板 ②）下滴动画 = **发射时一次性小广播**（容器键 / 发射槽 / 方向 / 命中点 /
FluidType）+ 客户端本地模拟三段动画（悬挂 40t → 下落 → 溅射，源码同款生命周期）——
**没有逐拍同步需求**，一个普通 S2C 即可，不触及「渲染态广播」提案
（[buffer/render-state-broadcast.md](render-state-broadcast.md)）的 4 通道收口问题。
> v2.0 初稿曾把活水滴当「第 5 条渲染通道」——那是逐格状态滴（A 案）的代价；
> 改原版架构（B）后该问题溶解，提案回归提案。

## 6. 坑登记簿 / 远期

- **岩浆可再生化**（v2.0 守恒律修订的直接经济后果）：岩浆源 + 锥 = 岩浆农场，
  「矿脉型一次性资源」口径改写——原版同款（dripstone+锅），速率是唯一旋钮，真机盯资源节奏；
- **泥→黏土**（原版滴注转化背书）：滴注路径改写目标格物品——转化表思路的延伸，远期；
- **生长**（三明治结构：水源 / 滴水石块 / 锥根 ⇒ 锥变长 = 射程延长？）：远期，运输闭环后议；
- **投射物框架**：活水滴 / 活岩浆滴是「容器级瞬态投射物」第一族——未来活发射器（弹射物品）、
  活雪球等若出现，按设计模板 §三 抽「瞬态弹」框架（现在只有一族，不抽）；
- **渲染态广播提案**：活水滴是第 5 条通道，v1 独立小包、提案落地后迁移（§3.1）；
- **泵滴撞死的一滴损失**：命中不可接收受体时泵模式损失一滴（≤1000mB，损耗向）——
  真机若观感差，可改「滴在受体前悬停等待」（发射器在飞 ≤1 兜底，不会堆积）；
- **性能**：滴数 = 发射器数 × ≤1，逐格判定 ≤8 格 / 滴——微不足道；
- **嵌套免费**：活潜影箱 / 活背包里——容器级瞬态按容器键隔离，发射判定读内层 ctx；

  成为后一锥的上游）——无需专门机制，级联延迟累加属预期。
