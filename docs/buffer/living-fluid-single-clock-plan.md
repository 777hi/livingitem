## §1 问题：引擎里其实有三个时钟

| 时钟 | 驱动什么 | 现值 |
|---|---|---|
| 每 tick | 目标层 BFS（可达性/拓扑）、挤没、源即时、焚毁、前沿反应、转化 | 1t |
| 每流体节拍 `flowSpeed` | 实际层蔓延 `advanceGrowth` | 水 5t / 岩浆 30t |
| 固定常量 `FLOW_STEP_TICKS = 4` | 物品推动 `pushItems`（**不分流体**） | 4t |

由此产生的**真实错配**：

1. **岩浆 30t 才爬一格，却每 4t 把物品推走一次** —— 黏性最高的流体表现得比水还像传送带；
2. **水 5t 长一格，却 4t 推一次** —— 推动抢在生长前面；
3. **晋升在目标层每 tick 判定** ⇒ 三连源中间源被汲走后**下一 tick 就补回**，
   与「实际层的水有没有真的流到那格」无关（与 §3.6 定稿的「拓扑层即时」一致，但与
   「一切随流体节拍」的新原则冲突）。

## §2 定稿：划界 —— 生长类上时钟，反应类保持当拍

**上时钟（是"流动"本身的组成部分）**

| 逻辑 | 改动 |
|---|---|
| 蔓延 `advanceGrowth` | 已是每流体节拍；本批**让它回报本拍推进过的流体集合** |
| **晋升** | 从目标层收敛循环搬到**实际层**，在该流体**推进之后**判定；输入 = 实际层四邻中已是源的个数；升格当拍改写实际层为源（源即时） |
| **推动 `pushItems`** | 按流体分组，并入该流体的推进拍，**排在蔓延之后**（物品跟着刚长出的前沿走，不抢跑） |

**保持当拍（是对"外界状态变化"的反应）**

- 挤没（活物品进源格）、源即时、移除即时 —— 外部投放立刻生效才对得上玩家的手；
- **焚毁**（物品进岩浆格）：挂 30t 时钟 ⇒「丢进去 1.5s 才烧」，不可接受；
- **前沿反应**（两种流体接触）：接触时点由**先到的那个流体**决定（水 5t 贴上来就当拍凝固）；
- **转化**（源格泡物品）：外部投放的反应；§6 已定「转化即时，无节拍」。

一句话口径：**流动的事按流体节拍走；外界引起的事当拍生效。**

## §3 被否掉的选项及理由

| 选项 | 否掉的理由 |
|---|---|
| 全部逻辑（含焚毁/反应/转化）一律上时钟 | 外部输入会有最长 30t 的延迟，手感差且难解释；「等 1.5s 才烧掉」说不过去 |
| 晋升仍留目标层、但只在该流体节拍判定 | 目标层是**拓扑**（水还没到的格也在里面），用它判晋升等于「预见式升源」，与原版 `getNewLiquid`（**本格得有流体**）不符 |
| 保留晋升收敛循环（升格后同拍重跑 BFS） | 实际层本来就逐拍生长，同拍重跑无意义 ⇒ 删掉，`computeTargets` 退化为纯 BFS |
| 推动与蔓延同拍但**先推后长** | 物品会先被推进尚未长水的格 ⇒ 顺序定「先蔓延后推动」 |
| 晋升做成「即时例外」（源消失当拍补回，其余走时钟） | 破坏一致性，且正是本次要消除的错配来源 |

## §4 连带影响与守卫生效点

| 影响 | 说明 |
|---|---|
| **三连源再生 1t ⇒ ≤1 个节拍（水 ≤5t）** | 用户已确认接受（一致性优先；要高供水速率靠**多源并行**，不靠 1t 再生）。管道抽取（§10）的供水上限随之下降 |
| 岩浆**不受影响** | 永不晋升（`shouldPromote` 默认 false） |
| 推动节拍 | 水 4t → **5t**（几乎无感）；岩浆 4t → **30t**（黏性终于对上了） |
| `FLOW_STEP_TICKS` 常量 | 失去使用者 ⇒ **删除**（不留死常量） |

**测试守卫**

| # | 守卫 |
|---|---|
| C1 | 晋升只在**该流体的推进拍**发生：flowSpeed=5 的水，汲走后第 1~4 tick **不**补回，第 5 tick 补回 |
| C2 | **等价性守卫**（最重要）：同一场景在「晋升上时钟」下跑够拍数，终态与旧行为（目标层即时晋升）**相同**（晋升只是变慢，不改变终态） |
| C3 | 推动按流体节拍：flowSpeed=10 的岩浆，物品在第 10 tick 前**不动**，第 10 tick 动一次（不再 4t 一次） |
| C4 | 挤没自愈仍成立（活物品压源 ⇒ 源销毁；移走 ⇒ 下一推进拍重新派生） |
| C5 | 反应类仍当拍：焚毁 / 前沿反应 / 转化在**非节拍 tick** 也生效（防止有人后来把它们也塞进时钟） |
