# 活红石 · 活潜影箱 · 活铜块 —— 实施规划

> **文档版本**: 2026.08 v2
> **最后更新**: 2026-08-16
> **适用版本**: Minecraft 1.21.1

---

## 0. 总览

三大系统的关系：

```
活红石 ──→ 逻辑层（信号 0-15，门电路，时序电路）
活铜块 ──→ 电力层（功率 FE/t，发电，输电，储电）
活避雷针 ──→ 传输层（红电波共振，跨容器/跨维度）
活潜影箱 ──→ 封装层（芯片，层次化设计）

活红石 + 活铜块 = 电气系统（逻辑 + 电力，电磁感应耦合）
活铜块 + 活避雷针 = 无线电力网络（局域电力 + 全局共振）
活红石 + 活潜影箱 = 可封装的逻辑 = 芯片
三者合一 = 信息时代（计算 + 电力 + 封装 + 无线传输）
```

**核心设计**：活红石管逻辑，活铜块管电力，两者通过**电磁感应**自然耦合——相邻即感应，无需转换器。

实施顺序：**活红石 → 活铜块 → 活潜影箱**。前两者各自可用，组合后产生质变。

## 1. Phase 1：活红石（容器内红石系统）

### 1.1 目标

在 2D 容器网格（9×6 背包 / 9×3 活潜影箱）中实现原版红石信号传播的等价逻辑。

### 1.2 核心数据结构

#### ContainerRedstoneData（容器级红石信号数据）

```java
public class ContainerRedstoneData {
    // 每个槽位的当前信号强度 (0-15)
    private int[] signalStrength;
    // 每个槽位的信号来源方向（防止回传）
    private Pos2D[] signalSource;
    // 是否需要重新计算
    private boolean dirty;
    // 传播计数器（每 2 tick 传播一次）
    private int tickCounter;
}
```

与 `ContainerFluidData`、`ContainerStressData` 并列，作为容器级数据在 `TickContext` 中持有。

#### LivingRedstoneData（物品级数据组件）

```java
public record LivingRedstoneData(
    int signalStrength,    // 当前信号强度 0-15
    boolean isPowered,     // 是否被信号激活
    Pos2D outputDirection  // 信号输出方向（活中继器/比较器用）
) implements TooltipProvider {}
```

### 1.3 活红石物品清单

| 优先级 | 物品 | 功能 | 对应原版 | DataComponent |
|--------|------|------|---------|---------------|
| P0 | **活红石粉** | 信号传播介质，每格 -1 | `RedstoneWireBlock` | `LivingRedstoneData` |
| P0 | **活红石火把** | 信号源(15) + 反相器 | `RedstoneTorchBlock` | `LivingRedstoneTorchData` |
| P1 | **活按钮** | 脉冲信号源（右键触发） | `ButtonBlock` | `LivingButtonData` |
| P1 | **活拉杆** | 持续信号源（开关切换） | `LeverBlock` | `LivingLeverData` |
| P1 | **活红石灯** | 信号消费者（亮/灭） | `RedstoneLampBlock` | `LivingRedstoneLampData` |
| P2 | **活中继器** | 延迟 + 单向 + 可调增益 | `RepeaterBlock` | `LivingRepeaterData` |
| P2 | **活比较器** | 信号比较（A>B? A:0） | `ComparatorBlock` | `LivingComparatorData` |
| P3 | **活活塞** | 推/拉相邻物品 | `PistonBlock` | `LivingPistonData` |
| P3 | **活门** | 开/关 | `DoorBlock` | `LivingDoorData` |

### 1.4 信号传播算法

```
每 2 tick 执行一次：

1. 标记所有信号源（活火把=15，活按钮/拉杆=按下时15）
2. BFS 从信号源出发：
   a. 对每个活红石粉槽位，取所有邻居的最大信号强度 - 1
   b. 对活中继器：延迟 N tick 后输出输入信号
   c. 对活比较器：比较两侧信号
3. 更新所有消费者的状态（活灯亮/灭，活活塞推/拉）
4. 同步 DataComponent 到客户端
```

**连接判定**：活红石粉只向相邻的活红石组件传播，不穿过普通物品。判定条件：
- 目标槽位的物品是活红石组件（活红石粉、活火把、活中继器...）
- 或目标槽位是活潜影箱（信号穿透边界，见 Phase 2）

### 1.5 与现有架构集成

```
ContainerLivingItemHandler.processContext()
  │
  ├─ 扫描活物品，按功能分组
  │   ├─ LivingRedstoneFunction.tick()        ← 新增
  │   ├─ LivingRedstoneTorchFunction.tick()   ← 新增
  │   ├─ LivingButtonFunction.tick()          ← 新增
  │   ├─ LivingCopperBlockFunction.tick()     ← 新增（Phase 3）
  │   ├─ ...
  │
  ├─ 容器级数据计算
  │   ├─ ContainerFluidData.calculate()
  │   ├─ ContainerStressData.calculate()
  │   ├─ ContainerRedstoneData.calculate()    ← 新增
  │   └─ ContainerPowerData.calculate()       ← 新增（Phase 3）
  │
  ├─ 电磁感应耦合                            ← 新增（Phase 3）
  │   ├─ 源型红石 → 铜块发电（signal²→FE/t）
  │   └─ 铜块功率 → 感型红石传感（√FE/t→signal）
  │
  └─ 后同步
      ├─ LivingWaterBucketFunction.postTickSync()
      ├─ LivingWaterWheelFunction.postTickSync()
      ├─ LivingRedstoneFunction.postTickSync()  ← 新增
      └─ LivingCopperBlockFunction.postTickSync() ← 新增（Phase 3）
```

### 1.6 交互设计

- **活按钮**：GUI 中右键点击 → 触发脉冲信号（20 tick 持续时间）
- **活拉杆**：右键点击 → 切换开/关状态
- **活中继器**：右键点击 → 调整延迟（1/2/3/4 tick）
- **活比较器**：右键点击 → 切换比较/减法模式
- **活红石粉**：自动连接相邻组件，无需手动配置

### 1.7 渲染

- 活红石粉：根据信号强度渲染颜色渐变（暗红→亮红，与原版一致）
- 活红石火把：根据是否点亮渲染不同图标
- 活按钮/拉杆：根据是否激活渲染不同状态
- 活红石灯：根据是否被信号激活渲染亮/灭

### 1.8 与活水车的联动

- 活水车产生应力 → 活比较器可读取应力强度 → 转换为红石信号
- 活红石信号 → 控制活水车是否运转（通过活活塞推拉齿轮）
- 实现 **机械 ↔ 逻辑** 双向控制

> 注：活水车不参与活铜块电力系统。电力系统的输出面向科技模组（IEnergyStorage）。

### 1.9 实施步骤

```
Step 1：ContainerRedstoneData + 信号传播核心算法
Step 2：LivingRedstoneFunction（活红石粉）
Step 3：LivingRedstoneTorchFunction（活红石火把）
Step 4：LivingButtonFunction + LivingLeverFunction（信号源）
Step 5：LivingRedstoneLampFunction（信号消费者，可视化验证）
Step 6：LivingRepeaterFunction + LivingComparatorFunction
Step 7：LivingPistonFunction + LivingDoorFunction
Step 8：渲染层（颜色渐变、状态图标）
```

## 2. Phase 2：活潜影箱（封装 + 边界连续性）

### 2.1 目标

实现活潜影箱的**边界连续性**——多个活潜影箱在容器中排列时，内部槽位在逻辑上连续，物品和信号可以跨边界传输。

### 2.2 边界连续性规则

```
容器 C 中：
  槽位 1：活潜影箱 a（内部 9×3 = 27 槽位）
  槽位 2：活潜影箱 b（内部 9×3 = 27 槽位）

逻辑空间：a 和 b 水平相邻 → 18×3 = 54 个连续槽位

a 的右边界（内部槽位 8, 17, 26）←→ b 的左边界（内部槽位 0, 9, 18）
```

**4 个活潜影箱 2×2 排列 → 18×6 的逻辑空间**。

### 2.3 跨边界传输

#### 物品传输（活漏斗）

```
活潜影箱 a 内部的活漏斗 c：
  c 的输出方向 = 右
  c 所在槽位 = a 的内部槽位 17（右边界中间）

  → c 的输出目标 = a 的右边界之外
  → a 的右边是活潜影箱 b
  → c 输出到 b 的内部槽位 9（左边界中间）
```

#### 信号传输（活红石）

```
活潜影箱 a 内部槽位 8（右边界）信号强度 = 12
  → 穿透边界 → 活潜影箱 b 内部槽位 0（左边界）信号强度 = 11

衰减规则：边界穿透 -1（与红石粉每格衰减一致）
```

#### 外部 ↔ 内部传输

```
容器 C 中：
  槽位 5：活红石粉（信号 12）
  槽位 6：活潜影箱 S

  S 的左边界 = S 内部槽位 0, 9, 18
  信号从槽位 5 → S 的左边界 → S 内部传播

  S 的右边界 = S 内部槽位 8, 17, 26
  信号从 S 右边界 → 容器 C 槽位 7
```

### 2.4 封装 = 芯片

活潜影箱的边界连续性 + 活红石的信号传播 = **芯片封装**。

```
引脚映射：
  活潜影箱 9×3 网格的边界槽位 = 引脚
  上边界 9 个 + 下边界 9 个 + 左边界 3 个 + 右边界 3 个 = 24 个引脚

封装层级：
  Level 0：离散元件（活红石粉、活火把...）= 面包板
  Level 1：活潜影箱封装 Level 0 = IC 芯片
  Level 2：活潜影箱封装 Level 1 = PCB
  Level 3：活潜影箱封装 Level 2 = 系统模块
  ...
```

### 2.5 技术挑战

#### 递归 tick 性能

```
容器 tick
  → 活潜影箱 A tick
    → A 内部活潜影箱 B tick
      → B 内部活潜影箱 C tick
```

应对策略：
- **最大嵌套深度限制**：4 层
- **脏标记优化**：边界信号不变 → 跳过内部 tick
- **缓存**：内部信号稳定后缓存输出，直到输入变化

#### 信号延迟

深层嵌套导致信号衰减为 0。应对：
- **活中继器**在边界处刷新信号强度
- 或：边界穿透**不衰减**（边界是"导线"不是"红石粉"）

#### 并发一致性

同一 tick 内多个活潜影箱输入同时变化。应对：
- 先收集所有边界信号，再统一更新内部（类原版 BFS 拓扑排序）

### 2.6 可视化

- **Tooltip**：显示各引脚信号强度
- **物品渲染**：图标边缘颜色编码（红=高信号，灰=无信号）
- **引脚标签**：给引脚命名（如 "CLK"、"D0"、"Q3"）

### 2.7 实施步骤

```
Step 1：LivingShulkerBoxFunction（内部活物品 tick）
Step 2：边界连续性（物品跨边界传输）
Step 3：信号跨边界传播（活红石 + 活潜影箱联动）
Step 4：脏标记优化 + 嵌套深度限制
Step 5：引脚可视化（Tooltip + 渲染）
```

## 3. Phase 3：活铜块（容器内电力系统）

### 3.1 目标

在容器内实现电力传输系统。活铜块专注于**电力层**（发电、输电、储电），与活红石的**逻辑层**通过电磁感应自然耦合。产出的电力通过 `IEnergyStorage` 输出给科技模组，作为容器内的一种发电方式。

**定位**：活铜块是**发电侧**，用电侧活物品暂未设计（TBD）。

### 3.2 电磁感应耦合

活红石和活铜块相邻时自动产生电磁耦合，**无需任何转换器物品**。

```
现实：变化的磁场 → 感应电动势（法拉第定律 EMF = -dΦ/dt）
映射：变化的活红石信号 → 活铜块感应发电
      恒定的活红石信号 → 不发电（恒定磁场不产生电动势）
```

#### 堆叠倍增

活红石的堆叠数决定信号强度上限，平方增长（类比互感耦合：N个紧密耦合线圈的总电感 ∝ N²）：

```
effectiveSignal = signalStrength × stackCount²
```

| 堆叠数 | effectiveSignal 上限 | 物理类比 |
|--------|---------------------|---------|
| 1 | 15 | 单匝线圈 |
| 2 | 60 | 2匝互感 |
| 4 | 240 | 4匝互感 |
| 8 | 960 | 8匝互感 |
| 16 | 3840 | 16匝互感 |
| 32 | 15360 | 32匝互感 |
| 64 | 61440 | 64匝满组互感 |

**天然平衡**：64堆叠发电需要64堆叠铜块传输才能不浪费，成本与产出同步增长，不超模。

#### 正向耦合：活红石 → 活铜块（法拉第感应发电）

**只有信号变化才发电**，恒定信号不发电。

```
源型活红石 ──相邻──→ 活铜块
  → 铜块所在电路获得功率 += |Δ(effectiveSignal)|
  
  Δ(effectiveSignal) = effectiveSignal_now - effectiveSignal_prev
```

| 场景 | 堆叠 | Δ(effectiveSignal) | 发电功率 | 类比 |
|------|------|-------------------|---------|------|
| 活红石火把(恒定亮) | 1 | 0 | **0 FE/t** | 恒定磁场不感应 |
| 活红石火把(亮起瞬间) | 1 | 15 | 15 FE/t | 磁场建立瞬间 |
| 活按钮(按下) | 1 | 15 | 15 FE/t | 脉冲发电机 |
| 活按钮(按下) | 64 | 61440 | 61440 FE/t | 大功率脉冲发电机 |
| 活拉杆(切换) | 1 | 15 | 15 FE/t | 开关瞬间发电 |
| 活中继器振荡(每周期2沿) | 1 | 15×2 | 30 FE/t | 交流发电机 |
| 活中继器振荡 | 64 | 61440×2 | 122880 FE/t | 大功率交流发电机 |

**持续发电需要持续振荡**——活中继器环形振荡器是最基本的持续发电方式。涂蜡铜块可以将脉冲储能后慢放，实现"按一下按钮，持续供电数秒"。

#### 反向耦合：活铜块 → 活红石（传感）

```
活铜块(功率P) ──相邻──→ 感型活红石
  → 红石获得信号 = min(15 × stackCount², ⌊√P⌋)
```

堆叠越多，能读取的功率范围越大：

| 铜块功率 | 1堆叠感型红石 | 64堆叠感型红石 |
|---------|-------------|--------------|
| 25 FE/t | 5 | 5 |
| 225 FE/t | 15（饱和） | 15 |
| 960 FE/t | 15（饱和） | 30 |
| 61440 FE/t | 15（饱和） | 247 |

#### 源/感分离（防止反馈爆炸）

**关键规则**：只有**源型活红石**驱动铜块，铜块只驱动**感型活红石**。感型红石的信号不回传给铜块，避免正反馈循环。

| 活红石 | 角色 | 驱动铜块？ | 被铜块驱动？ |
|--------|------|-----------|-------------|
| 活红石火把 | 源 | ✅ | ✗ |
| 活按钮 | 源 | ✅ | ✗ |
| 活拉杆 | 源 | ✅ | ✗ |
| 活中继器(输出侧) | 源 | ✅ | ✗ |
| 活比较器(输出侧) | 源 | ✅ | ✗ |
| 活红石粉 | 感 | ✗ | ✅ |
| 活红石灯 | 感 | ✗ | ✅ |
| 活活塞 | 感 | ✗ | ✗ |
| 活门 | 感 | ✗ | ✅ |

### 3.3 电路 = 氧化状态

铜块的氧化状态决定所属电路，不同电路绝缘，同电路导通。

| 氧化状态 | 电路 | 典型用途 |
|---------|------|---------|
| 未锈蚀 | A | 主电源线（大功率负载） |
| 斑驳 | B | 辅助电源线（传感器/控制器） |
| 风化 | C | 备用/充电线 |
| 氧化 | D | 低功率信号电源 |

**总线模型**：同电路的所有铜块共享一个功率值，不逐节点模拟电流。

```
电路 A 总线：
  发电1 ──→ [铜块A] ──→ [铜块A] ──→ IEnergyStorage输出
                                    │
                                    └──→ [铜块A] ──→ 涂蜡铜块(储能)

总线功率 = Σ(发电) - Σ(储能充电)
```

### 3.4 活铜块变种

#### 铜块 = 电缆

全向连接同电路邻居，零损耗传输。电力网络的默认连接件。

```
     ┌──→ 邻居(同电路)
     │
邻居 ←── [铜块] ──→ 邻居(同电路)
     │
     └──→ 邻居(同电路)
```

#### 雕文铜块 = 跨线器（Crossover）

解决 2D 网格中不同电路交叉走线的问题。水平方向透传一条电路，垂直方向透传另一条，交叉点绝缘。

```
    电路A ──→ ┃          ┃ ──→ 电路A（水平直通）
               ┃ 雕文铜块 ┃
    电路B ──→ ┃    ╳    ┃ ──→ 电路B（垂直直通）
               ┃          ┃
               A与B交叉但绝缘
```

#### 切制铜块 = 母线（Bus Bar）

定向高容量电力传输。只沿条纹方向导通，垂直方向绝缘。右键旋转条纹方向。

```
    ──→ 电力传输（沿条纹，2×容量）
    │
    ✗ 垂直方向绝缘
```

| | 铜块（电缆） | 切制铜块（母线） |
|---|------------|----------------|
| 方向 | 全向 | 单向（可旋转） |
| 容量 | 标准 | 2× |
| 用途 | 通用连接 | 主干线/防回流 |

#### 铜格栅 = 跨路器（变压器）

连接两侧不同电路，功率从高压侧流向低压侧，实现跨电路功率均衡。

```
电路A(100 FE/t) ──→ [格栅] ──→ 电路B(20 FE/t)

transfer = max(0, (powerA - powerB) / 2) = 40 FE/t
转移后：A = 60, B = 60（均衡）
```

### 3.5 涂蜡 = 储能（电容/电池）

涂蜡 = 密封 = 能量不泄漏 = 储能。

```
有剩余功率时充电：energy += surplus（不超过容量上限）
功率不足时放电：  energy -= deficit（不低于0）
```

| 涂蜡变种 | 容量 | 放电率 | 角色 |
|---------|------|-------|------|
| 涂蜡未锈蚀 | 160 FE | 10 FE/t | 去耦电容（平滑瞬态波动） |
| 涂蜡斑驳 | 640 FE | 5 FE/t | 缓冲电容（脉冲展宽） |
| 涂蜡风化 | 2560 FE | 2 FE/t | 深循环电池（持续供电） |
| 涂蜡氧化 | 10240 FE | 0.5 FE/t | UPS 电池（应急后备） |

涂蜡 × 变种组合：

| 组合 | 角色 |
|------|------|
| 涂蜡铜块 | 通用电容（全向充放电） |
| 涂蜡雕文铜块 | 双电路电容（交叉点两侧各自独立储能） |
| 涂蜡切制铜块 | 定向电容（只沿条纹方向充放电，防倒灌） |
| 涂蜡铜格栅 | 密封变压器（变比不变，两侧各带储能） |

### 3.6 核心数据结构

```java
public class ContainerPowerData {
    int[] circuitPower = new int[4];   // 电路A/B/C/D的净功率(FE/t)
    int[] circuitEnergy = new int[4];  // 涂蜡铜块储存的能量(FE)
}
```

与 `ContainerFluidData`、`ContainerStressData`、`ContainerRedstoneData` 并列，作为容器级数据在 `TickContext` 中持有。

### 3.7 用电侧（TBD）

用电侧活物品暂未设计。当前电力系统的输出方式是通过 `IEnergyStorage` 对外暴露给科技模组。

未来可能的用电侧设计方向：
- 活铜电致块：电力 → 红石信号（反向电磁感应的显式物品）
- 活铜马达：电力 → 机械能（驱动活活塞/活门）
- 活铜加热器：电力 → 热能（冶炼/烹饪）

### 3.8 Tick 流程

```
processContext() 每tick：

1. 清零 ContainerPowerData.circuitPower[0..3]
2. 扫描所有活铜块，统计每条电路的发电量：
   对每个活铜块，查4邻居：
     有源型活红石且信号变化 → circuitPower[circuit] += |Δ(effectiveSignal)|
3. 铜格栅跨路均衡：
   对每个铜格栅，连接两侧电路A和B：
     transfer = max(0, (powerA - powerB) / 2)
     powerA -= transfer; powerB += transfer
4. 涂蜡铜块充放电
5. IEnergyStorage 输出（剩余功率输出给科技模组）
6. 反向耦合：活铜块有功率 → 相邻感型活红石获得信号
7. 活避雷针共振（见 §3.12）：
   a. 收集阶段：遍历所有容器，避雷针输入端有铜块 → 贡献到频道共振
   b. 桥接阶段：避雷针输出端从频道共振取净值 → 注入铜块电路
```

**总复杂度**：O(槽位数) ≈ O(54)，每tick一次。活避雷针遍历 O(全局避雷针数)，通常 < 100。

### 3.9 与科技模组兼容

**这是当前电力系统的主要输出方式**——容器作为一个整体对外暴露 NeoForge `IEnergyStorage`，内部通过铜块网络汇总发电功率后输出。

```
容器内活红石振荡 → 电磁感应 → 铜块电力总线 → IEnergyStorage → 外部科技模组

```

### 3.12 活避雷针（红电波共振）

活避雷针是电力系统从**局域**走向**全局**的关键。
电磁感应管容器内（相邻槽位），活避雷针管跨容器（通过频道共振）。

```
局域：活红石 ──法拉第感应──→ 活铜块(4电路) ──→ IEnergyStorage
全局：活铜块 ──→ 活避雷针 ──→ 频道共振 ──→ 活避雷针 ──→ 活铜块
```

#### 物品

活避雷针只有一种，没有氧化/涂蜡变体。
堆叠数 = 频道，64个独立频道。

#### 方向性 I/O

活避雷针一头大（输入端）一头小（输出端），参考活漏斗的方向性设计。
4 个朝向（上下左右）+ 输入/输出分离，在 2D 网格中实现灵活拓扑：

```
        输入端(大头)
          ↑
    ┌─────┴─────┐
    │ 活避雷针   │  ← 朝向 = 上（输入在上，输出在下）
    └─────┬─────┘
          ↓
        输出端(小头)

4 种朝向：
  上：输入=上邻居，输出=下邻居
  下：输入=下邻居，输出=上邻居
  左：输入=左邻居，输出=右邻居
  右：输入=右邻居，输出=左邻居
```

右键旋转朝向。

#### 共振模型

所有同堆叠数的避雷针共享同一个频道共振状态，**不区分发射/接收**。
共振是双向等权的——每个避雷针既是贡献者也是感受者。

```
频道5共振 = 150 FE/t

容器A：铜块(100FE) → 避雷针(输入) → 贡献100到频道5
容器B：铜块(50FE)  → 避雷针(输入) → 贡献50到频道5
容器C：频道5 → 避雷针(输出) → 铜块获得 150-0=150
容器A：频道5 → 避雷针(输出) → 铜块获得 150-100=50（净值）
```

#### 净值扣除防自激

每个避雷针从共振中拿到的 = 频道共振总和 - 自己贡献的。

```
containerRodContribution[容器ID][频道] = 输入端贡献值

输出端获得 = channelResonance[频道] - containerRodContribution[容器ID][频道]
```

#### 四种拓扑模式

| 模式 | 输入接铜块 | 输出接铜块 | 效果 |
|------|----------|----------|------|
| **纯贡献** | ✅ | ✗ | 只贡献到频道，不从频道取 |
| **纯感受** | ✗ | ✅ | 只从频道取，不贡献 |
| **双向桥接** | ✅ | ✅ | 贡献+感受，输入输出可不同电路 |
| **空闲** | ✗ | ✗ | 不参与共振 |

#### 跨电路桥接

避雷针不绑定电路——它读取输入端铜块的电路，注入输出端铜块的电路。
输入和输出可以是不同电路，实现跨电路传输：

```
[铜块A(电路A)] → 避雷针(输入) → 频道共振 → 避雷针(输出) → [铜块C(电路C)]

电路A → 频道 → 电路C 的跨电路桥接
```

#### 跨维度无衰减

红电波是概念频道，共振不分维度。主世界的频道5和地狱的频道5是同一个频道5，状态完全同步。

#### 全局注册表

```java
public class RedElectricWaveRegistry {
    // 频道 → 该频道共振功率总和
    Int2IntMap channelResonance;  // channelId → totalPower(FE/t)

    // 容器ID → 频道 → 该容器贡献值（用于净值扣除）
    Map<UUID, Int2IntMap> containerContribution;
}
```

#### 每 tick 流程

```
1. 清零 channelResonance[1..64] 和 containerContribution

2. 收集阶段：遍历所有容器中所有活避雷针
   → 输入端有铜块？
   → 读取该铜块电路功率 = power
   → channelResonance[频道] += power
   → containerContribution[容器][频道] += power

3. 桥接阶段：遍历所有容器中所有活避雷针
   → 输出端有铜块？
   → 净值 = channelResonance[频道] - containerContribution[容器][频道]
   → 注入该铜块电路 power += 净值
```

#### 典型应用

```
1. 跨容器输电：
   容器A：活红石振荡 → 铜块A → 避雷针(stack=8, 朝右) → 频道8
   容器B：频道8 → 避雷针(stack=8, 朝左) → 铜块A → IEnergyStorage

2. 跨维度供电：
   主世界：发电机 → 铜块A → 避雷针(stack=1) → 频道1
   地狱：频道1 → 避雷针(stack=1) → 铜块A → 用电

3. 多频道分工：
   频道1：低功率控制信号
   频道8：主电源
   频道16：辅助电源

4. 跨电路桥接：
   铜块A(电路A) → 避雷针(输入) → 频道 → 避雷针(输出) → 铜块B(电路B)
   实现电路A和电路B的功率互通
```

#### 与 EnderChannelRegistry 的关系

红电波频道和末影珍珠频道是两套独立系统：

| | 末影珍珠频道 | 红电波频道 |
|---|------------|-----------|
| 传输内容 | 物品/实体 | 功率(FE/t) |
| 频道数 | 按珍珠ID | 64（堆叠数） |
| 跨维度 | ✅ | ✅（无衰减） |
| 模型 | 发布/订阅 | **共振（共享状态）** |

## 6. 技术风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 信号传播性能（BFS 每 2 tick） | 大量活红石粉时可能卡顿 | 脏标记 + 增量更新 + 传播深度限制 |
| 递归 tick（活潜影箱嵌套） | 深层嵌套性能爆炸 | 最大嵌套深度 4 层 + 脏标记缓存 |
| 电磁感应反馈爆炸 | 源/感不分导致正反馈循环 | 源/感分离 + 法拉第感应（恒定信号不发电） |
| 共振自激 | 避雷针输出端功率回灌到自身输入端 | 净值扣除（自身贡献不参与输出端计算） |
| 科技模组兼容性 | 不同模组能量单位不同 | 统一通过 NeoForge IEnergyStorage |
| 信号穿透衰减 | 深层嵌套信号为 0 | 活中继器刷新 / 边界穿透不衰减 |
