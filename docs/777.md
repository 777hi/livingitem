# 活红石 · 活潜影箱 · 红电转换 —— 实施规划

> **文档版本**: 2026.08 v1
> **最后更新**: 2026-08-11
> **适用版本**: Minecraft 1.21.1

---

## 0. 总览

三大系统的关系：

```
活红石 ──→ 计算能力（逻辑门、时序电路）
活潜影箱 ──→ 封装能力（芯片、层次化设计）
红电转换 ──→ 通信能力（电力、红电波、跨容器/跨维度）

活红石 + 活潜影箱 = 可封装的逻辑 = 芯片
活红石 + 红电转换 = 有线/无线电路
三者合一 = 信息时代（计算 + 通信 + 存储）
```

实施顺序：**活红石 → 活潜影箱 → 红电转换**。前两者各自可用，组合后产生质变。

## 1. Phase 1：活红石（容器内红石系统）

### 1.1 目标

在 2D 容器网格（9×6 背包 / 9×3 活潜影箱）中实现原版红石信号传播的等价逻辑。

### 1.2 核心数据结构

#### ContainerRedstoneData（容器级红石信号数据）

```java
public class ContainerRedstoneData {
    // 每个槽位的当前信号强度 (0-15)
    private int[] signalStrength;
    // 每个槽位的信号来源方向（防止回传）
    private Pos2D[] signalSource;
    // 是否需要重新计算
    private boolean dirty;
    // 传播计数器（每 2 tick 传播一次）
    private int tickCounter;
}
```

与 `ContainerFluidData`、`ContainerStressData` 并列，作为容器级数据在 `TickContext` 中持有。

#### LivingRedstoneData（物品级数据组件）

```java
public record LivingRedstoneData(
    int signalStrength,    // 当前信号强度 0-15
    boolean isPowered,     // 是否被信号激活
    Pos2D outputDirection  // 信号输出方向（活中继器/比较器用）
) implements TooltipProvider {}
```

### 1.3 活红石物品清单

| 优先级 | 物品 | 功能 | 对应原版 | DataComponent |
|--------|------|------|---------|---------------|
| P0 | **活红石粉** | 信号传播介质，每格 -1 | `RedstoneWireBlock` | `LivingRedstoneData` |
| P0 | **活红石火把** | 信号源(15) + 反相器 | `RedstoneTorchBlock` | `LivingRedstoneTorchData` |
| P1 | **活按钮** | 脉冲信号源（右键触发） | `ButtonBlock` | `LivingButtonData` |
| P1 | **活拉杆** | 持续信号源（开关切换） | `LeverBlock` | `LivingLeverData` |
| P1 | **活红石灯** | 信号消费者（亮/灭） | `RedstoneLampBlock` | `LivingRedstoneLampData` |
| P2 | **活中继器** | 延迟 + 单向 + 可调增益 | `RepeaterBlock` | `LivingRepeaterData` |
| P2 | **活比较器** | 信号比较（A>B? A:0） | `ComparatorBlock` | `LivingComparatorData` |
| P3 | **活活塞** | 推/拉相邻物品 | `PistonBlock` | `LivingPistonData` |
| P3 | **活门** | 开/关 | `DoorBlock` | `LivingDoorData` |

### 1.4 信号传播算法

```
每 2 tick 执行一次：

1. 标记所有信号源（活火把=15，活按钮/拉杆=按下时15）
2. BFS 从信号源出发：
   a. 对每个活红石粉槽位，取所有邻居的最大信号强度 - 1
   b. 对活中继器：延迟 N tick 后输出输入信号
   c. 对活比较器：比较两侧信号
3. 更新所有消费者的状态（活灯亮/灭，活活塞推/拉）
4. 同步 DataComponent 到客户端
```

**连接判定**：活红石粉只向相邻的活红石组件传播，不穿过普通物品。判定条件：
- 目标槽位的物品是活红石组件（活红石粉、活火把、活中继器...）
- 或目标槽位是活潜影箱（信号穿透边界，见 Phase 2）

### 1.5 与现有架构集成

```
ContainerLivingItemHandler.processContext()
  │
  ├─ 扫描活物品，按功能分组
  │   ├─ LivingRedstoneFunction.tick()        ← 新增
  │   ├─ LivingRedstoneTorchFunction.tick()   ← 新增
  │   ├─ LivingButtonFunction.tick()          ← 新增
  │   ├─ ...
  │
  ├─ 容器级数据计算
  │   ├─ ContainerFluidData.calculate()
  │   ├─ ContainerStressData.calculate()
  │   └─ ContainerRedstoneData.calculate()    ← 新增
  │
  └─ 后同步
      ├─ LivingWaterBucketFunction.postTickSync()
      ├─ LivingWaterWheelFunction.postTickSync()
      └─ LivingRedstoneFunction.postTickSync()  ← 新增
```

### 1.6 交互设计

- **活按钮**：GUI 中右键点击 → 触发脉冲信号（20 tick 持续时间）
- **活拉杆**：右键点击 → 切换开/关状态
- **活中继器**：右键点击 → 调整延迟（1/2/3/4 tick）
- **活比较器**：右键点击 → 切换比较/减法模式
- **活红石粉**：自动连接相邻组件，无需手动配置

### 1.7 渲染

- 活红石粉：根据信号强度渲染颜色渐变（暗红→亮红，与原版一致）
- 活红石火把：根据是否点亮渲染不同图标
- 活按钮/拉杆：根据是否激活渲染不同状态
- 活红石灯：根据是否被信号激活渲染亮/灭

### 1.8 与活水车的联动

- 活水车产生应力 → 活比较器可读取应力强度 → 转换为红石信号
- 活红石信号 → 控制活水车是否运转（通过活活塞推拉齿轮）
- 实现 **机械 ↔ 电气** 双向转换

### 1.9 实施步骤

```
Step 1：ContainerRedstoneData + 信号传播核心算法
Step 2：LivingRedstoneFunction（活红石粉）
Step 3：LivingRedstoneTorchFunction（活红石火把）
Step 4：LivingButtonFunction + LivingLeverFunction（信号源）
Step 5：LivingRedstoneLampFunction（信号消费者，可视化验证）
Step 6：LivingRepeaterFunction + LivingComparatorFunction
Step 7：LivingPistonFunction + LivingDoorFunction
Step 8：渲染层（颜色渐变、状态图标）
```

## 2. Phase 2：活潜影箱（封装 + 边界连续性）

### 2.1 目标

实现活潜影箱的**边界连续性**——多个活潜影箱在容器中排列时，内部槽位在逻辑上连续，物品和信号可以跨边界传输。

### 2.2 边界连续性规则

```
容器 C 中：
  槽位 1：活潜影箱 a（内部 9×3 = 27 槽位）
  槽位 2：活潜影箱 b（内部 9×3 = 27 槽位）

逻辑空间：a 和 b 水平相邻 → 18×3 = 54 个连续槽位

a 的右边界（内部槽位 8, 17, 26）←→ b 的左边界（内部槽位 0, 9, 18）
```

**4 个活潜影箱 2×2 排列 → 18×6 的逻辑空间**。

### 2.3 跨边界传输

#### 物品传输（活漏斗）

```
活潜影箱 a 内部的活漏斗 c：
  c 的输出方向 = 右
  c 所在槽位 = a 的内部槽位 17（右边界中间）

  → c 的输出目标 = a 的右边界之外
  → a 的右边是活潜影箱 b
  → c 输出到 b 的内部槽位 9（左边界中间）
```

#### 信号传输（活红石）

```
活潜影箱 a 内部槽位 8（右边界）信号强度 = 12
  → 穿透边界 → 活潜影箱 b 内部槽位 0（左边界）信号强度 = 11

衰减规则：边界穿透 -1（与红石粉每格衰减一致）
```

#### 外部 ↔ 内部传输

```
容器 C 中：
  槽位 5：活红石粉（信号 12）
  槽位 6：活潜影箱 S

  S 的左边界 = S 内部槽位 0, 9, 18
  信号从槽位 5 → S 的左边界 → S 内部传播

  S 的右边界 = S 内部槽位 8, 17, 26
  信号从 S 右边界 → 容器 C 槽位 7
```

### 2.4 封装 = 芯片

活潜影箱的边界连续性 + 活红石的信号传播 = **芯片封装**。

```
引脚映射：
  活潜影箱 9×3 网格的边界槽位 = 引脚
  上边界 9 个 + 下边界 9 个 + 左边界 3 个 + 右边界 3 个 = 24 个引脚

封装层级：
  Level 0：离散元件（活红石粉、活火把...）= 面包板
  Level 1：活潜影箱封装 Level 0 = IC 芯片
  Level 2：活潜影箱封装 Level 1 = PCB
  Level 3：活潜影箱封装 Level 2 = 系统模块
  ...
```

### 2.5 技术挑战

#### 递归 tick 性能

```
容器 tick
  → 活潜影箱 A tick
    → A 内部活潜影箱 B tick
      → B 内部活潜影箱 C tick
```

应对策略：
- **最大嵌套深度限制**：4 层
- **脏标记优化**：边界信号不变 → 跳过内部 tick
- **缓存**：内部信号稳定后缓存输出，直到输入变化

#### 信号延迟

深层嵌套导致信号衰减为 0。应对：
- **活中继器**在边界处刷新信号强度
- 或：边界穿透**不衰减**（边界是"导线"不是"红石粉"）

#### 并发一致性

同一 tick 内多个活潜影箱输入同时变化。应对：
- 先收集所有边界信号，再统一更新内部（类原版 BFS 拓扑排序）

### 2.6 可视化

- **Tooltip**：显示各引脚信号强度
- **物品渲染**：图标边缘颜色编码（红=高信号，灰=无信号）
- **引脚标签**：给引脚命名（如 "CLK"、"D0"、"Q3"）

### 2.7 实施步骤

```
Step 1：LivingShulkerBoxFunction（内部活物品 tick）
Step 2：边界连续性（物品跨边界传输）
Step 3：信号跨边界传播（活红石 + 活潜影箱联动）
Step 4：脏标记优化 + 嵌套深度限制
Step 5：引脚可视化（Tooltip + 渲染）
```

## 3. Phase 3：红电转换（电力 + 红电波）

### 3.1 目标

实现红石信号与电力的双向转换，兼容科技模组；实现红电波无线传输。

### 3.2 红电转换

#### 物理模型：类光电效应

```
红石信号强度 (0-15) → 红电转换器 → 电力输出

功率 = k × signal²    （P = V²/R，信号强度类比电压）
```

#### 活铜块清单

| 优先级 | 物品 | 功能 | 现实对应 |
|--------|------|------|---------|
| P0 | **活铜导线** | 信号/电力传输，**无衰减** | 铜导线 |
| P0 | **活铜光电块** | 红→电转换 | 光电效应 |
| P0 | **活铜电致块** | 电→红转换 | 电致发光 |
| P1 | **活铜电容** | 储能，平滑脉冲 | 电容器 |
| P1 | **活铜线圈** | 产生红电波 | LC 振荡电路 |
| P1 | **活铜天线** | 发射/接收红电波 | 天线 |
| P2 | **活铜变压器** | 升压/降压 | 变压器 |

#### 与科技模组兼容

```
活铜光电块 ──→ Create: Stress Units (SU)
            ──→ Mekanism: Joules (J)
            ──→ Immersive Engineering: IF
            ──→ 通用: NeoForge Energy (FE)
```

通过 NeoForge `EnergyStorage` capability 天然兼容所有能源模组。

#### 活铜导线 vs 活红石粉

| | 活红石粉 | 活铜导线 |
|---|---------|---------|
| 信号衰减 | 每格 -1 | **无衰减** |
| 传输内容 | 红石信号 (0-15) | 红石信号 + 电力 |
| 连接判定 | 只连接红石组件 | 连接所有电气组件 |
| 类比 | 半导体（掺杂硅） | 超导体 |

### 3.3 红电波

#### 物理模型

```
活铜线圈（振荡电路）
  ├─ 红石信号以频率 f 振荡
  ├─ 产生红电波：频率 = f，振幅 = 信号强度
  └─ 空间传播（3D 世界）

活铜天线（调谐到频率 f）→ 接收 → 输出红石信号
```

#### 红电波参数

| 参数 | 红石对应 | 现实对应 |
|------|---------|---------|
| 频率 | 信号振荡速率（tick/周期） | Hz |
| 振幅 | 信号强度（0-15） | V |
| 波长 | 传播速度 / 频率 | m |
| 衰减 | 距离平方反比 | 自由空间损耗 |

#### 频率复用 = 信道复用

```
同一空间同时传输多路信号：

  天线 A：发射 f₁ = 2 tick/周期 → "传感器数据"
  天线 B：发射 f₂ = 4 tick/周期 → "控制指令"
  天线 C：发射 f₃ = 8 tick/周期 → "状态反馈"

  接收端：
  天线 R₁（调谐 f₁）→ 只收到"传感器数据"
  天线 R₂（调谐 f₂）→ 只收到"控制指令"
  天线 R₃（调谐 f₃）→ 只收到"状态反馈"
```

**这打破了 2D 网格的信道限制**——物理空间 54 槽位，频率维度无限。

#### 调制方式

| 方式 | 编码 | 用途 |
|------|------|------|
| OOK | 有信号=1，无信号=0 | 简单数字传输 |
| AM | 信号强度 = 数据值 | 模拟信号传输 |
| FSK | f₁=0，f₂=1 | 抗噪数字传输 |

### 3.4 跨容器/跨维度通信

#### 跨容器

红电波穿透容器边界，在不同箱子/背包间传播。

```
箱子 A ──红电波──→ 箱子 B ──红电波──→ 箱子 CA
```

#### 跨维度

利用活末影珍珠的跨维度通道：

```
主世界节点 ←──红电波──→ 末影通道 ←──红电波──→ 地狱节点

末影通道 = 光纤骨干网
红电波 = WiFi 局域网
```

### 3.5 实施步骤

```
Step 1：LivingCopperWireFunction（活铜导线，无衰减传输）
Step 2：LivingPhotoelectricFunction（红→电转换 + FE 输出）
Step 3：LivingElectroluminescentFunction（电→红转换 + FE 输入）
Step 4：LivingCapacitorFunction（活铜电容，储能）
Step 5：LivingCoilFunction（活铜线圈，振荡电路）
Step 6：LivingAntennaFunction（活铜天线，发射/接收）
Step 7：频率调谐 + 信道复用
Step 8：跨容器红电波传播
Step 9：跨维度通道桥接（与活末影珍珠通道联动）
```

## 4. Phase 4：信息时代（计算 + 通信 + 存储）

### 4.1 冯·诺依曼架构映射

| 计算机组件 | 活物品实现 |
|-----------|----------|
| **CPU** | 活潜影箱封装的 ALU + 控制器 |
| **RAM** | 活红石 RS 锁存器阵列 |
| **ROM** | 活拉杆阵列（只读） |
| **总线** | 活铜导线 + 红电波 |
| **I/O** | 活铜天线 + 活按钮/灯 |
| **时钟** | 活红石中继器环形振荡器 |

### 4.2 时序逻辑（Phase 1 后期或 Phase 4 前置）

| 电路 | 实现 | 用途 |
|------|------|------|
| RS 锁存器 | 活红石火把交叉连接 | 1 bit 存储 |
| D 触发器 | RS 锁存器 + 时钟门控 | 同步 1 bit 存储 |
| T 触发器 | D 触发器 + XOR 反馈 | 计数器 |
| 寄存器 | D 触发器阵列 + 活潜影箱封装 | 多 bit 存储 |

### 4.3 通信协议栈

```
Layer 3：应用层 —— 活物品间协作协议
Layer 2：传输层 —— 红电波数据包（源地址 + 目标地址 + 数据 + 校验）
Layer 1：链路层 —— FSK/OOK 调制 + 频率复用
Layer 0：物理层 —— 红电波传播
```

### 4.4 杀手级应用

1. **自动化工厂**：传感器 → 红电波 → 控制器 → 执行器（全无线）
2. **跨容器通信网络**：矿场 → 工厂 → 仓库
3. **分布式计算**：多 CPU 通过红电波组网
4. **红电波雷达**：发射 → 反射 → 接收 → 距离/速度
5. **跨维度互联网**：末影通道 = 光纤骨干，红电波 = WiFi

### 4.5 实施步骤

```
Step 1：时序逻辑（RS 锁存器、D 触发器）
Step 2：基本计算单元（ALU、寄存器）封装为芯片
Step 3：数据包协议（地址 + 数据 + 校验）
Step 4：可编程控制器（简化 CPU）
Step 5：分布式协作网络
```

## 6. 技术风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 信号传播性能（BFS 每 2 tick） | 大量活红石粉时可能卡顿 | 脏标记 + 增量更新 + 传播深度限制 |
| 递归 tick（活潜影箱嵌套） | 深层嵌套性能爆炸 | 最大嵌套深度 4 层 + 脏标记缓存 |
| 红电波跨容器传播 | 需要容器间引用/通信机制 | 复用 ContainerSnapshot / 容器身份系统 |
| 科技模组兼容性 | 不同模组能量单位不同 | 统一通过 NeoForge Energy capability |
| 信号穿透衰减 | 深层嵌套信号为 0 | 活中继器刷新 / 边界穿透不衰减 |
