## Mixin 兼容性全面分析

### Mixin 注入类型风险等级

| 注入类型 | 兼容性风险 | 说明 |
|---------|-----------|------|
| `@Inject(HEAD, cancellable)` | 🟢 低 | 只在方法开头注入，其他模组可以同时注入，互不干扰 |
| `@Inject(TAIL)` | 🟢 低 | 只在方法末尾注入，不影响原版逻辑 |
| `@Inject(RETURN)` | 🟢 低 | 在每个返回点注入 |
| `@Redirect` | 🔴 **高** | **替换原版方法调用**，同一目标只能有一个 Redirect，多个模组冲突直接崩溃 |
| `@ModifyArg` / `@ModifyReturnValue` | 🟡 中 | 修改参数/返回值，多个模组可以链式修改，但语义可能冲突 |
| `@Mixin(Interface)` | 🟢 低 | 给类添加接口实现，不修改行为 |
| `@Shadow @Mutable @Final` | 🟡 中 | 修改 final 字段，可能与其他模组的 @Shadow 冲突 |

#### 2. `MapItemUpdateMixin` — `@Mixin(MapItem.class)` ⚠️⚠️⚠️

```

@Redirect(method = "update", at = INVOKE("LevelChunk;isEmpty"))
```

| 维度 | 评价 |
|------|------|
| 注入类型 | 🔴 **`@Redirect` × 2** — 最高风险！ |
| 目标类 | `MapItem` — **核心类**，很多模组会 Mixin |
| 目标方法 | `update()` — 原版地图更新的核心方法 |

- 如果暮色森林有自己的 `MapItem` 子类且**重写**了 `update()`，Redirect 不会匹配（安全）

- **但**如果暮色森林的 `update` 实现中对 `getChunk` 有不同的调用模式，Redirect 可能匹配不到或匹配到错误位置

**建议**：改用 `@Inject` + `@ModifyVariable` 或完全重构为不依赖 Redirect 的方式。

**`MapItemUpdateMixin`（最紧急）**：

3. **改用事件/接口**：注册 `MapItemUpdateEvent`，在事件中修改行为

### 2. `MapItemUpdateMixin` — `@Mixin(MapItem.class)` — 地图更新跳过未加载区块 ⚠️⚠️⚠️

| 维度 | 评估 |
|------|------|
| **必要性** | ❓ **存疑** — 目的是防止活地图 `update` 触发区块加载，但 `getChunkNow` 返回 null 后整个区块被跳过，地图上会出现空白 |
| **NeoForge 替代** | ❌ 无 — NeoForge 没有地图更新事件 |
| **替代思路 1** | **完全删除** — 活地图的 `update` 本来就是原版逻辑，让原版正常加载区块填充地图颜色。活地图只是创建位置远，手持时 `update` 会正常填充周围区块 |
| **替代思路 2** | 改用 `@Inject(HEAD)` + 条件跳过 — 在 `update` 方法开头注入，如果玩家不在地图附近就 `return`，不 Redirect 内部调用 |
| **替代思路 3** | 用 `@WrapOperation`（Mixin 新 API）替代 `@Redirect`，允许多模组链式包装 |

**深入分析**：这个 Mixin 的原始目的是什么？

- 活地图创建在远处，`MapItem.update` 在玩家手持时每 tick 调用，会尝试 `getChunk` 获取地图范围内的区块
- 如果地图范围很远，`getChunk` 会**同步加载区块**，造成卡顿
- Redirect 改为 `getChunkNow`（不触发加载），未加载的区块返回 null 被跳过

**但问题是**：
- 活地图创建时已经调用了 `renderBiomePreviewMap` 预渲染了水域轮廓
- 玩家手持时 `update` 只会填充玩家**附近**的区块（`update` 的扫描范围是基于玩家位置，不是地图中心）
- 所以 `update` 中的 `getChunk` 加载的区块是**玩家附近的区块**，不是远处的！
- **这意味着这个 Redirect 可能根本不需要！** 玩家附近的区块本来就应该被加载

**结论**：🔴 **可能非必要** — `MapItem.update` 的 `getChunk` 加载的是玩家附近区块（不是地图中心），正常情况下这些区块已经加载。建议**先删除测试**，如果活地图手持时没有卡顿，就不需要这个 Mixin。

### 9. `ItemRendererWaterWheelMixin` — `@Mixin(ItemRenderer.class)` — 水车旋转渲染 ⚠️

## 总结：优先级排序

| 优先级 | Mixin | 行动 | 原因 |
|--------|-------|------|------|
| 🔴 **P0** | `MapItemUpdateMixin` | **先删除测试** | 2个 `@Redirect` 风险极高，可能根本不需要 |
| 🔴 **P0** | `BlockEntityMixin` | **改用 AttachmentType** | NeoForge 官方 API，完全消除 Mixin |
| 🟠 **P1** | `AbstractContainerScreenMixin` | **改用 ContainerScreenEvent** | NeoForge 官方 API，消除 Mixin |
| 🟠 **P1** | `RecipeBookComponentMixin` | **消除 3 个 Redirect** | 改用 `@Inject` + 条件控制 |
| 🟠 **P1** | `ItemRendererWaterWheelMixin` | **消除 Redirect** | 改用自定义 BakedModel 或 `@Inject` |
| 🟡 **P2** | `MapItemMixin` | **改用 PlayerInteractEvent** | 需验证时序 |
| 🟡 **P2** | `ItemStackMixin` | **优化 Data Components 设计** | 长期重构 |
| 🟡 **P2** | `CreativeModeInventoryScreenMixin` | **部分改用 ScreenEvent** | 鼠标事件可替代 |
| 🟢 **P3** | `SpriteIconButtonMixin` | **评估是否需要** | 可能用原版双态机制替代 |
| 🟢 **保留** | 其余所有 | 保留 | `@Inject` 兼容性好，无更好替代 |

你想从哪个开始喵？我建议先从 **P0 的 `MapItemUpdateMixin`** 开始——直接删除测试，确认活地图手持时是否真的需要跳过区块加载。
