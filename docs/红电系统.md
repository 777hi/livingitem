# 活红石 · 活潜影箱 · 活铜块 —— 实施规划

> **文档版本**: 2026.09 v17.7
> **最后更新**: 2026-09-01
> **适用版本**: Minecraft 1.21.1
>
> **v17.7 修订**：铜块网络传播——移除旧感应耦合与方向映射，改为按网络组件遍历（锚点 BFS + copyFrom 共享）
> 同氧化等级铜块网络检测边信号。不同锈蚀等级形成独立网络，发电机仅接收其所在
> 网络内的相位事件。公式更新为 v3：`eff_δ_sum = Σ√|Δ_i|`，`合因子 = (eff_δ_sum)^(1+u)`，
> √|Δ| 求和替代 log₂|Δ| × n。每 tick 每发电机一次入账。
>
> **v17.6 修订**：公式 v2——信号幅度改用 log₂ 压缩，解锁度重定义为
> `调谐效率 × (n / 偏好周期)`，移除规律度因子。新公式：
> `eff_δ = log₂(|Δ|)`，`合因子 = (eff_δ × n)^(1+u)`，`单次跳变能量(RE) = 合因子 × P`。
> 高堆叠数的完美信号输入将非常富有挑战性，挑战失败无收益，挑战成功收益丰厚。
> 旧约束（规律度等）全部移除，玩家自由选择挑战难度。
>
> **v17.5 修订**：储能模型重构——**无容器池**，发电直存铜灯（按剩余容量比例分配，
> 无铜灯则弃），涂蜡铜灯 = **纯容器**
> （无充放限率，电量按盏存 DataComponent → 拆分/合并/搬运天然守恒），
> 容器方块能力**双向**：对外取电 + 接受外部电源充电（充入铜灯）。
> 发电是唯一的**内部**能量来源；外部充电是合法的**跨系统**能量转换，等量无套利；
> 容量涌现为线性「每盏 C × count」（平方容量在拆分时坍缩毁电，弃用），
> 放电率概念退役（限流归用电侧）。池常态为空 → 无需容器级持久化。
>
> **v17.4 修订**：规律度并入合因子——`合因子 = n^(1+解锁度)`，
> 解锁度 = 调谐效率 × 波形规律度。规律度从乘法因子变为平方奖励的第二把钥匙，
> ×2 硬天花板消失；因子数 3 → 2（幅度、相位质量）。满配上限相应减半，由 K 吸收。
>
> **v17.3 修订**：移除形态倍率——形态退位为**感应拓扑（线圈分组）**：
铜块 1 组×4 向（全叠加）、雕文 1 组×1 向（定向 WASD 输入/输出双方向）、
切制 2 组（H/V 隔离，各自计算相加）、格栅 1 组×4 向+频率过滤（待定）。
功率差异由通道数与 n 自然产生；按通道叠加波形，异周期杂讯会污染规律度。
因子数 4 → 3（幅度、相位共振、规律）。
>
> **v17.2 修订**：相位与共振合并为一个因子——`合因子 = n^(1+效率)`：
> 效率 0（失谐/宽带）退化为线性 n，效率 1（完美调谐）解锁平方 n²。
> 硬常数天花板（×4）消失，「平方」成为完美调谐的奖品；
> 因子数 5 → 4（幅度、相位共振、形态、规律）。
>
> **v17.1 修订**：取消「集群」实体——发电机改为**本地感应**：相邻块经锈蚀管径
> 逐跳共享输入路数与信号（共享感知、分别发电），路 = 物理信号路径
> （n ≤ min(路径数, P)），发电逐块独立、多块线性叠加；
> 删除周长公式与 √块数衰减。单块直连 ≤4 路，满相（相数 = P）需块间协作。
> 另修正谐振链转发规则：下游分频（周期 ×2）后再发射，阶梯配方才成立。
>
> **v17 重大修订**：电力层改为「调谐 + 感应耦合」模型（涌现化重构）——
> 偏好周期改由**发电机堆叠数**决定（stack，2~64t 全整数周期覆盖），
> 锈蚀改为**感应耦合强度**（管径），发电机堆叠数不再做倍率增益；
> 新增**波形规律度**因子与**跳变即能量事件**记账（能量 ∝ 周期 P，
> 平均功率对频率中性）；旧「锈蚀阶梯」由硬设定改为可发现的谐振链配方。
>
> **v15 修订**：发电因子完善——相位倍率改为平方数列（1/4/9/16），
> 基础幅度修正（|Δsignal| 已含 stackCount²，不再重复乘）。
>
> **v14 重大修订**：Phase 3（活铜块）整章重写。
> 从「电磁感应耦合双系统」改为「信号同源 + 三轴正交」模型，
> 避雷针改为守恒的供需分配。
>
> **注意**：本文档为规划架构概览，具体实现细节请参阅 [活红石技术文档](tech/living-redstone-tech.md)。

## 0. 总览

三大系统的关系：

```
活红石   ──→ 逻辑层（信号 0-15，门电路，时序电路）
活铜块   ──→ 信号层（未涂蜡：频道隔离 + 5 种拓扑）
             电力层（涂蜡：感应发电 + 储能）
活避雷针 ──→ 传输层（红电波频道，跨容器/跨维度）
活潜影箱 ──→ 封装层（芯片，层次化设计）

活红石 + 活铜块 = 电气系统（信号同源，涂蜡分层）
活铜块 + 活避雷针 = 无线电力网络（局域发电 + 全局供需分配）
活红石 + 活潜影箱 = 可封装的逻辑 = 芯片
三者合一 = 信息时代（计算 + 电力 + 封装 + 无线传输）
```

**核心设计**：红石信号与红电信号**本质同源**，只是在不同介质中的叫法不同——
无需任何转换器物品。铜块**涂蜡与否**决定它工作在信号层还是电力层。

实施顺序：**活红石 → 活铜块 → 活潜影箱**。前两者各自可用，组合后产生质变。

## 1. Phase 1：活红石（容器内红石系统）

### 1.1 目标

在 2D 容器网格（9×6 背包 / 9×3 活潜影箱）中实现原版红石信号传播的等价逻辑。

### 1.2 核心数据结构

#### ContainerRedstoneData（容器级红石信号数据）

```java
public class ContainerRedstoneData {
    // 每个槽位的当前信号强度 (0-15)
    private int[] signalStrength;
    // 每个槽位的信号来源方向（防止回传）
    private Pos2D[] signalSource;
    // 是否需要重新计算
    private boolean dirty;
}
```

与 `ContainerFluidData`、`ContainerStressData` 并列，作为容器级数据在 `TickContext` 中持有。

### 1.4 信号传播算法（四阶段）

```
每 game tick 执行一次（时间分辨率 = 1 tick），拆分为 4 个 Phase：

Phase 0 — 倒计时 + 断电检测（用 prevSignalStrength）：
  - 中继器：被锁定则跳过倒计时；检测输入端是否仍有信号，断电则立即归零
  - 按钮：递减 pulseTimer，到期自动弹起

Phase 1 — 收集信号源：
  - 火把（点亮）→ 输出 cap = getSignalCap(count)
  - 按钮（按下）→ 输出 cap = getSignalCap(count)
  - 拉杆（激活）→ 输出 cap = getSignalCap(count)
  - 中继器（powered && delayTimer == 0）→ 输出 cap = getSignalCap(count)
  - 比较器（output > 0）→ 输出 output
  - 红石块（始终）→ 输出 cap = getSignalCap(count)，四向

Phase 2 — 统一迭代传播：
  - 单一 BFS 队列，根据槽位类型自动切换传播规则：
    - 红石粉：四方向传播，每格 -1，上限受 getSignalCap 约束
    - 中继器/比较器：只向 outDir 方向传播，第一跳不衰减
    - 火把：跳过输入端（防止向输入端泄露）
  - 无 visited 数组：通过 signalStrength[neighbor] 比较决定是否继续
  - 红石粉始终向所有方向边写入信号（v10 变更），非红石组件（活漏斗等）可读取边信号

Phase 3 — 充能导体（先于 Phase 4 执行）：
  - 所有信号源（红石粉/火把/按钮/拉杆/红石块/中继器/比较器）向相邻导电活物品充能
  - 导体所有边写入信号，触发第二波 BFS 传播
  - 仅活物品可被充能（LivingItemManager.isLivingItem），复用原版 isRedstoneConductor 判定导电性

Phase 4 — 重新检测输入（级联效应）：
  - 中继器：被锁定则跳过状态转移；锁定检测：检查侧面是否有已输出状态的中继器
  - 中继器：重新检测 signalStrength[inputSlot]，级联上电（此时导体信号已就绪）
  - 比较器：重新计算 output，更新 powered

Phase 5 — 更新显示状态：
  - 火把：反相器逻辑（有输入→熄灭，无输入→点亮）
  - 红石粉：更新 signalStrength + isPowered
  - 红石灯：检查邻居有无信号，更新 lit

Phase 6 — 容器内外红石交互（面信号模型）：
  - 在 Phase 0 之前执行 injectExternalInputs()
  - 输入：遍历容器**所有关联方块位置**（大箱子遍历两个半箱），读取外部红石信号
  - 通过 CrossContainerTransfer.worldToGrid() 将世界方向映射为内部网格方向
  - 外部信号存入 faceInput[4]（不写入 edgeGrid），方向性元件通过 getEffectiveInput() 读取
  - 方向性元件（火把/中继器/比较器）可读取 faceInput
  - 无方向性元件（红石粉/红石灯/铜块/铜格栅/铜灯）仅接收内部邻居信号
  - 输出：Phase 5 后 computeFaceOutput() 扫描 edgeGrid 边界边（跳过铜槽位，红电信号不参与跨容器传输）→ faceOutput[4]
  - Mixin BlockStateBase.getSignal() → getBoundarySignal() → faceOutput[dir]（弱信号，红石粉可读）
  - Mixin BlockStateBase.getDirectSignal() → getBoundarySignal() → faceOutput[dir]（强信号，中继器/比较器/火把可读）
  - 连接：Mixin RedStoneWireBlock.getConnectingSide() 强制返回 SIDE，让红石粉连接容器
  - 方向映射复用 CrossContainerTransfer（已内置容器朝向旋转处理）

  反馈循环防护（面信号模型天然优势）：
  - faceInput[4] 不写入 edgeGrid，仅通过 getEffectiveInput() 供定向元件读取
  - faceOutput[4] 仅扫描 edgeGrid（纯内部）得出，不受外部信号影响
  - 输入/输出通道完全分离，EdgeGrid 回归静态纯内部类
  - 非定向元件（红石粉/灯/铜块）的 inputAt() 在边界处返回 0，不参与跨容器信号传播

  跨容器直读机制（超限信号传输）：
  - injectExternalInputs 检测邻居方块是否为容器，若是则直接读取其 ContainerRedstoneData.faceOutput
  - 通过 ContainerLivingItemHandler.getRedstoneDataByPos() 获取邻居容器数据
  - 使用 worldDir.getOpposite() 翻转方向，正确读取邻居对面那个面的 faceOutput
  - 绕过原版 level.getSignal() 的 0-15 截断，支持超限信号（>15）跨容器传输
  - 非容器邻居仍走原版 level.getSignal() 路径（0-15）

  相邻容器边界信号隔离：
  - 非定向元件（红石粉/灯）在容器边界不接收外部信号，inputAt() 返回 0
  - 定向元件（中继器/比较器/火把）在容器边界可通过 getEffectiveInput() 读取外部信号
  - 所有红石元件在容器边界都能输出信号到外部（computeFaceOutput 扫描 edgeGrid 边界边）
  - 铜块（红电信号）不参与跨容器传输，computeFaceOutput 跳过铜槽位边界边
  - 边界红石粉不会因相邻容器输出而产生衰减反馈环，彻底消除循环风险

  大箱子支持：
  - injectExternalInputs 遍历 getAssociatedBlockPositions() 所有半箱
  - notifyBoundaryChange 通知所有关联方块位置的邻居
  - ContainerIdentity 新增 getAssociatedBlockPositions() 方法

  信号变化通知：
  - notifyBoundaryChange 对比 faceOutput 与 prevFaceOutput
  - 仅在边界输出信号实际变化时触发 updateNeighborsAt()，避免闪烁

Phase 7 — 活漏斗红石信号控制（v10 新增）：
  - 活漏斗在 LivingHopperFunction.tick() 中通过 ContainerRedstoneData.getSignal(slot) 检测边信号
  - 任意边信号 > 0 → 漏斗被禁用（跳过传输和冷却倒计时），tooltip 显示红色警告 ⚠
  - 信号消失 → 自动恢复传输
  - 依赖 Phase 2 的边写入解耦：红石粉始终向所有方向边写入信号，非红石组件可直接读取
```

**设计要点**：

- `prevSignalStrength` 保存上一帧信号，Phase 0 用于断电检测，避免"先算新信号再判断断电"的时序问题

## 2. Phase 2：活潜影箱（封装 + 边界连续性）

### 2.1 目标

实现活潜影箱的**边界连续性**——多个活潜影箱在容器中排列时，内部槽位在逻辑上连续，物品和信号可以跨边界传输。

### 2.2 边界连续性规则

```
容器 C 中：
  槽位 1：活潜影箱 a（内部 9×3 = 27 槽位）
  槽位 2：活潜影箱 b（内部 9×3 = 27 槽位）

逻辑空间：a 和 b 水平相邻 → 18×3 = 54 个连续槽位

a 的右边界（内部槽位 8, 17, 26）←→ b 的左边界（内部槽位 0, 9, 18）
```

**4 个活潜影箱 2×2 排列 → 18×6 的逻辑空间**。

### 2.3 跨边界传输

#### 物品传输（活漏斗）

```
活潜影箱 a 内部的活漏斗 c：
  c 的输出方向 = 右
  c 所在槽位 = a 的内部槽位 17（右边界中间）

  → c 的输出目标 = a 的右边界之外
  → a 的右边是活潜影箱 b
  → c 输出到 b 的内部槽位 9（左边界中间）
```

#### 信号传输（活红石）

```
活潜影箱 a 内部槽位 8（右边界）信号强度 = 12
  → 穿透边界 → 活潜影箱 b 内部槽位 0（左边界）信号强度 = 11

衰减规则：边界穿透 -1（与红石粉每格衰减一致）
```

#### 外部 ↔ 内部传输

```
容器 C 中：
  槽位 5：活红石粉（信号 12）
  槽位 6：活潜影箱 S

  S 的左边界 = S 内部槽位 0, 9, 18
  信号从槽位 5 → S 的左边界 → S 内部传播

  S 的右边界 = S 内部槽位 8, 17, 26
  信号从 S 右边界 → 容器 C 槽位 7
```

### 2.4 封装 = 芯片

活潜影箱的边界连续性 + 活红石的信号传播 = **芯片封装**。

```
引脚映射：
  活潜影箱 9×3 网格的边界槽位 = 引脚
  上边界 9 个 + 下边界 9 个 + 左边界 3 个 + 右边界 3 个 = 24 个引脚

封装层级：
  Level 0：离散元件（活红石粉、活火把...）= 面包板
  Level 1：活潜影箱封装 Level 0 = IC 芯片
  Level 2：活潜影箱封装 Level 1 = PCB
  Level 3：活潜影箱封装 Level 2 = 系统模块
  ...
```

### 2.5 技术挑战

#### 递归 tick 性能

```
容器 tick
  → 活潜影箱 A tick
    → A 内部活潜影箱 B tick
      → B 内部活潜影箱 C tick
```

应对策略：

- **最大嵌套深度限制**：4 层
- **脏标记优化**：边界信号不变 → 跳过内部 tick
- **缓存**：内部信号稳定后缓存输出，直到输入变化

#### 信号延迟

深层嵌套导致信号衰减为 0。应对：

- **活中继器**在边界处刷新信号强度
- 或：边界穿透**不衰减**（边界是"导线"不是"红石粉"）

#### 并发一致性

同一 tick 内多个活潜影箱输入同时变化。应对：

- 先收集所有边界信号，再统一更新内部（类原版 BFS 拓扑排序）

### 2.6 可视化

- **Tooltip**：显示各引脚信号强度
- **物品渲染**：图标边缘颜色编码（红=高信号，灰=无信号）
- **引脚标签**：给引脚命名（如 "CLK"、"D0"、"Q3"）

### 2.7 实施步骤

```
Step 1：LivingShulkerBoxFunction（内部活物品 tick）
Step 2：边界连续性（物品跨边界传输）
Step 3：信号跨边界传播（活红石 + 活潜影箱联动）
Step 4：脏标记优化 + 嵌套深度限制
Step 5：引脚可视化（Tooltip + 渲染）
```

## 3. Phase 3：活铜块（信号介质 + 电力系统）

### 3.1 核心概念：红石信号与红电信号同源

**红石信号和红电信号本质是同一种信号，只是在不同介质中的叫法不同。**

```
信号在活红石元件中传播  → 称为「红石信号」
信号在活铜块家族中传播  → 称为「红电信号」

两者自由互转，无需任何转换器物品：
  活红石粉 → 活铜块   ：红石信号变为红电信号
  活铜块 → 活红石粉   ：红电信号变为红石信号
```

活铜块家族的传播行为与活红石粉一致（BFS，每格衰减 -1），
区别在于**铜块提供了红石粉没有的拓扑能力**（见 §3.3）。

### 3.2 三轴正交模型

原版铜块相关物品有 5 种形态 × 4 档锈蚀 × 2 种涂蜡 = 40 件。
若逐个设计机制则无人能记住，因此采用**三轴正交**：每个轴只管一件事。

| 轴        | 控制               | 取值                     |
| -------- | ---------------- | ---------------------- |
| **基础形态** | 拓扑（信号怎么流 / 感应什么） | 铜块 / 雕文 / 切制 / 格栅 / 铜灯 |
| **锈蚀状态** | 分档（信号层=频道，电力层=共振声部） | 未锈蚀 / 斑驳 / 风化 / 氧化     |
| **涂蜡**   | 层次（信号层 / 电力层）    | 未涂蜡 = 导电传信号，涂蜡 = 绝缘产电力 |

玩家只需掌握 **5 + 4 + 2 = 11 个概念**，即可推断全部 40 件物品的行为。

> 例：`涂蜡风化切制铜块` 堆叠 8 = 电力层 + 第 3 声部 + 十字拓扑（两轴感应）
> → 偏好周期 = 8 tick（= 堆叠数），读取两个轴向的相位差发电。看名字即知拓扑，堆叠数即知谐振点。

#### 锈蚀 = 分档（两层各有含义）

锈蚀在两层都表示「第几档」，但档位的**含义**随层次而变：

| 层次 | 锈蚀的含义 | 未锈蚀 → 氧化 |
| -- | ----- | --------- |
| 信号层（未涂蜡） | **频道**：不同档位互不导通 | A / B / C / D 四条独立线路 |
| 电力层（涂蜡） | **共振声部**：跨锈蚟级和声的对象 | 第 1 / 2 / 3 / 4 声部 |

两层的档位序号一致，只是一个管「跟谁连」（频道），一个管「跟谁共振」（声部）——
都是「第几档 / 第几路」的寻址语义，区别只在于被寻址的对象是信号还是网络。
之所以能这样分工，是因为**涂蜡铜块本来就不导通**——
既然它不参与连线，「频道」对它就没有意义，档位自然腾出来表达别的东西。

> ⚠️ **旧版（v17.1）曾把电力层锈蚟定义为「耦合强度管径 1.0 / 0.7 / 0.5 / 0.35」**，
> 该设计已在 v17.7 移除（`PowerMath` 与 `LivingWaxedCopperFunction` 中不存在任何
> 氧化级系数）。电力层锈蚟现在是**二值网络隔离 + 跨级共振**，
> 氧化级高**不会**降低发电效率，只会让你处在另一个网络（另一个声部）里。

##### 信号层：锈蚀 = 频道隔离

不同锈蚀状态的活铜块之间**不传递红电信号**，等同于不同颜色的电线。

```
[未锈蚀铜块] ─✅→ [未锈蚀铜块]     同频道，导通
[未锈蚀铜块] ─✗→ [斑驳铜块]       不同频道，绝缘
[活红石粉]   ─✅→ [任意锈蚀铜块]   红石粉可注入任意频道
```

**这是 2D 布线的核心价值**：9×6 网格中，4 种锈蚀铜块 + 活红石粉
可以走 5 路互不干扰的独立信号。原版红石粉相邻必然串信号，
在 2D 平面上几乎无法布线。

##### 电力层：锈蚀 = 共振声部（网络隔离 + 跨级和声）

见 [§3.5 铜块网络传播](#35-铜块网络传播信号的路由) 与
[§3.6.1 网络级共振](#361-网络级共振)。
发电机通过按网络组件遍历同氧化等级铜块网络检测边信号（每组件仅锚点跑一次 BFS，其余 copyFrom 共享相位历史）。
不同锈蚀等级（新鲜/暴露/锈蚀/氧化）形成 4 个独立网络，互不连通。

**隔离只是手段，和声才是目的**：每个锈蚟级是一个「声部」，多个锈蚟级同时发电时
按**出力平衡度**互相感应（共振）——出力越接近、声部越多，总发电量越高
（满配 ×16）。只建一种锈蚟级 = 只有一个声部 = 没有共振加成。

声部单位是**锈蚟级**而非 BFS 连通块：同锈蚟级的多个互不相连的连通块出力直接相加。
这既是简化，也是共振倍率上限被封死在 4 的结构性前提（否则拆簇即可刷倍率）。

#### 涂蜡 = 层次切换

蜡是绝缘体，因此**涂蜡铜块不传导信号**——但它能通过同氧化等级网络传播相位事件。

```
未涂蜡：导电 → 传播红电信号（信号层）
涂蜡  ：绝缘 → 通过网络传播相位事件并发电（电力层）
```

### 3.3 信号层：五种形态的拓扑能力

未涂蜡的活铜块家族在信号层工作，每种形态提供一种红石粉做不到的拓扑能力。

#### 铜块 = 电缆

全向连接同频道邻居，行为等同活红石粉，但**受锈蚀频道隔离**。
电力网络与信号网络的默认连接件。

```
     ┌──→ 邻居(同锈蚀)
     │
邻居 ←── [铜块] ──→ 邻居(同锈蚀)
     │
     └──→ 邻居(同锈蚀)
```

#### 切制铜块 = 立交桥（Crossover）

解决 2D 网格中两路信号交叉的问题。**水平轴与垂直轴完全独立**，交叉点互不干扰。

```
    信号A ──→ ┃          ┃ ──→ 信号A（水平直通）
               ┃ 切制铜块 ┃
    信号B ──→ ┃    ╳    ┃ ──→ 信号B（垂直直通）
               ┃          ┃
              A 与 B 交叉但绝缘
```

配合锈蚀频道，这是 2D 布线的最后一块拼图：
即使同频道的两路信号也能交叉而不串扰。

> 实现提示：现有 `EdgeGrid` 将信号存在**边**上（`hEdges` / `vEdges`），
> 水平边与垂直边天然分离，切制铜块的立交桥语义可直接落地。

#### 雕文铜块 = 二极管（输入/输出双方向）

输入/输出方向独立设置，信号仅从输入方向接收、仅向输出方向转发。通过 WASD 2 键配置：第 1 键设输入方向，第 2 键设输出方向。默认输入=↓ 输出=↑（下传上）。

```
    输入=↓ 输出=↑  →  下传上（默认）
    输入=← 输出=→  →  左传右
    输入=← 输出=↑  →  左传上（拐角导通）
    输入=↓ 输出=→  →  下传右（拐角导通）
```

原版中"防止信号回流"由中继器承担，但中继器占格子且有 2 tick 延迟。
雕文铜块提供**零延迟定向导通**，且支持拐角，是 2D 布线的关键器件。

| <br /> | 活中继器     | 雕文铜块       |
| ------ | -------- | ---------- |
| 单向     | ✅        | ✅          |
| 拐角     | ❌        | ✅          |
| 延迟     | 2-8 tick | **0 tick** |
| 信号刷新   | ✅ 恢复到 15 | ✗ 继续衰减     |
| 用途     | 延迟 + 整形  | 纯防回流 + 拐角  |

#### 铜格栅 = 红石→红电桥接加法器

格栅有孔 = 红石信号穿过孔洞汇入铜网络。所有输入边的红石信号**相加**，
结果向四周同锈蚀状态的铜原件输出。

```
红石信号A ──→ ┐
              ├── [铜格栅] ──→ 铜电缆（同锈蚀）
红石信号B ──→ ┘
        sumSignal = min(A + B, signalCap)
```

- **输入**：只接收红石信号（红石粉、红石块、火把等），不接收铜电缆信号
- **求和**：4条边的红石信号相加，受 signalCap 上限
- **输出**：向4方向输出到同锈蚀状态的铜原件
- **隔离**：铜→格栅方向阻断，防止铜信号回灌

用途：将红石电路的信号桥接到铜电缆网络，同时实现多路信号合并。

#### 铜灯 = 信号记忆（记录/清除）

活铜灯收到红石信号上升沿时记录该信号强度，再次收到上升沿时熄灭清除记录。
记录的信号强度可被活比较器的比较模式读取。

```
收到上升沿 → 若未记录：记录输入信号强度
           → 若已记录：熄灭清除
无输入     → 保持当前记录
```

这是 Phase 4「信息时代」的地基：信号强度存储、锁存器、寄存器全靠它。
没有记忆单元，容器内只能实现组合逻辑，无法实现时序逻辑。

#### 信号层能力对照

| 形态 | 拓扑能力       | 对应原版/电子学        |
| -- | ---------- | --------------- |
| 铜块 | 全向传导（频道隔离） | 电缆              |
| 切制 | 双轴独立交叉     | 立交桥 / Crossover |
| 雕文 | 输入/输出双方向   | 二极管（可拐角）       |
| 格栅 | 红石→红电桥接加法 | 加法器             |
| 铜灯 | 信号记忆       | 记录/清除单元         |

### 3.4 电力层：感应发电模型（双因子）

**设计立意**：其它模组烧资源发电，红电系统**烧脑子**发电。
玩家通过搭建精密的信号线路来提升产量，而非投入更多燃料。
设计哲学：**构造几条规则，剩下的交给涌现**——
系统里没有需要查表的硬设定，只有可推理的机制。

涂蜡铜块对周围红电信号的**变化**产生感应，从而在内部产生红电（FE）。
单次跳变产生的能量由以下公式决定：

```
eff_δ_sum        = Σ√|Δ_i|                        // 各边信号 |Δ| 的 √ 求和
解锁度 u         = 调谐效率 × (n / 偏好周期)       // [0, 1]
调谐效率         = (1 + cos θ) / 2，θ = (tick误差 / 偏好周期) × 2π
合因子           = (eff_δ_sum)^(1+u)               // 不含 P
单次跳变能量(RE) = 合因子 × P
FE               = RE × K，K = 1/16
```

- **eff_δ_sum**：各不同偏移的 |Δ| 分别取 √ 后求和，替代了旧公式的 `log₂|Δ| × n`。
  √ 压缩让 |Δ| 从 4~4096 变为 2~64，信号大小不再是发电效益的主导因素；
  求和方式确保多路输入各算各的贡献，不丢失信息。
- **P** = 输入波形的周期（tick）。`合因子 × P` 是**频率中性化**：
  快时钟跳变密、慢时钟单次多，两边打平——低周期不是捷径，而是更多的选择。
- 记账方式为**跳变即能量事件**：每 tick 每发电机从最佳域入账一次（见 §3.10），
  对外显示用 EMA 平滑（示波器式反馈）。

两个因子各管一件事，每一步都是**正向增长**（只有奖励，没有惩罚）：
幅度看信号源（经 log₂ 压缩），相位质量看布局（n）与调谐（u 由 eff × n/pref 决定）。

**发电机堆叠数 = 偏好周期 = stackCount（2 ~ 64 tick，堆 1 叠 = 宽带态，见因子二）**，
是调谐的旋钮；**信号源堆叠数决定幅度**（信号值 = 源 stackCount²）。

#### 为什么要有 ×P（乘法的部分）

目的是频率中性化。方波周期 P，每周期跳 2 次，即每 tick 跳 2/P 次：

```
平均功率 = 单次能量 × 每tick跳变数
        = (合因子 × P) × (2/P)
        = 2 × 合因子      ← P 被完全消掉
```

**×P 是用来抵消「快时钟跳得密」的**。用 RE 自然单位看得最清楚：

```
平均功率(RE/t) = 单次能量 × 每 tick 跳变数
              = (合因子 × P) × (2/P)
              = 2 × 合因子        ← P 被完全消掉，且没有任何常数
```

2t 时钟每 tick 跳 1 次、单次 ×2 RE；64t 时钟每 32 tick 跳 1 次、单次 ×64 RE——
乘起来平均产出完全相同（2×合因子 RE/t）。如果没有 ×P，快时钟平均功率
碾压慢时钟 32 倍；如果除以 P（即不加 P 因子），等于没中性化。所以 P 必须乘回去。

#### 为什么要乘 K = 1/16

K 是**边界换算常量**，只出现在电池 / IEnergyStorage 输出处：

```
FE = RE × K，K = 1/16
```

P=16 时 `K=1/16` 让 FE 数值与旧公式一致（旧公式用 `(P/16)` 做频率中性化）。
16 是 16t 分析窗口的标准长度，也是旧公式的「1 刻度」。K 对**所有发电机
一视同仁地缩放**，不改变任何相对强弱。

> **实现注（v17.2）：自然单位制**——内部记账改用
> **红电单位 RE**：`每跳能量(RE) = 合因子 × P`（全部是涌现量）；
> K 放在电池 / IEnergyStorage 输出处，结合电池容量实现时一次性标定。
> 不要把 K 绑到最大周期等设计旋钮上——那会让改动堆叠数隐式重标定整个能源经济。

两个因子各管一件事，每一步都是**正向增长**（只有奖励，没有惩罚）：
幅度看信号源（经 log₂ 压缩），相位质量看多路布局与调谐。

**发电机堆叠数 = 偏好周期 = stackCount（2 ~ 64 tick，堆 1 叠为特殊态，见因子二）**，
是调谐的旋钮；**信号源堆叠数决定幅度**（信号值 = 源 stackCount²）。

#### 因子一：基础幅度（门槛）

**只有交变信号才发电**，恒定信号不发电。

```
基础幅度 = 直连幅度（来自 edgeGrid vs prevEdgeGrid）

直连幅度 = |signal_now - signal_prev|
```

| 场景       | signal_now | signal_prev | |Δsignal| | 产出            |
| -------- | ---------- | ----------- | --------- | ------------- |
| 恒定亮的红石火把 | 4096 | 4096 | 0 | **0** — 直流不发电 |
| 中继器环形振荡器 | 4096 | 0 | 4096 | 持续产出          |
| 按钮按下     | 4096 | 0 | 4096 | 一次性脉冲         |

> 信号值在铜块网络中 = signalStackCount²，最大 4096（信号源 stackCount=64）。
> 因此 |Δsignal| 上限为 4096（信号从 4096→0），**已包含信号源 stackCount²**。

玩家的第一课：**必须搭振荡器**。最简形式是中继器环形回路，占 3-4 格，产出很低。

> ⚠️ **`signal_prev`** **必须按槽位存储，不能存在物品的 DataComponent 上。**
> 否则玩家拖动涂蜡铜块到不同信号环境的槽位就能凭空制造 Δ，形成永动机。
> 现有 `ContainerRedstoneData.prevEdgeGrid` 双缓冲已提供按槽位的历史值，直接复用即可。

#### 因子二：相位质量（布局 × 调谐，平方奖励）

多路输入的相位错开数 n，与解锁度 u 一起决定平方奖励：

```
合因子 = (eff_δ_sum)^(1 + u)
解锁度 u = 调谐效率 × (n / 偏好周期)    // [0, 1]
调谐效率 = (1 + cos θ) / 2，θ = (tick误差 / 偏好周期) × 2π
eff_δ_sum = Σ√|Δ_i|    // 各不同偏移的 |Δ| 分别 √ 后求和
偏好周期 P_pref = 发电机堆叠数（2 ~ 64 tick，全整数覆盖）
```

**发电机堆叠数决定偏好周期**：往发电机堆里加减铜块，就是在物理地"旋转调谐旋钮"，
任何周期 ≥2 的时钟都能找到自己的谐振点。

**新公式要点**：

- 解锁度 u 不再包含规律度，因为实际信号几乎都是规律的，规律度永远接近 1。
- u 与相数 n 成正比：更多相数意味着更高的解锁度——但同时也更难建造。
- 合因子使用 `eff_δ_sum` 作为底数：√ 压缩让 |Δ| 从 4~4096 变为 2~64，
  信号大小不再是发电效益的主导因素，相数 n 的影响相对更大。
- `合因子 = (eff_δ_sum)^(1+u)`：u=0（失谐/宽带）→ 线性 eff_δ_sum（保底）；
  u=1（完美调谐 + n=偏好周期）→ 平方 (eff_δ_sum)²（天花板）。

> **堆 1 叠 = 宽带接收器（效率固定 0）**——合因子退化为线性 eff_δ×n，不挑频率。
> 定位：**入门档**（不懂调谐也有产出）+ **杂讯收割**（工厂混合周期环境下
> 专用发电机吃不满，宽带来者不拒）。

| 输入路数 | 相位差  | 满配合因子 | 数学 | 现实对应     |
| ---- | ---- | ---- | --- | -------- |
| 1 路  | —    | ×eff_δ_sum | (eff_δ_sum)¹=eff_δ_sum | 单相脉动（调谐无感） |
| 2 路  | 180° | ×4×eff_δ_sum² | (eff_δ_sum)² | 两相推挽     |
| 3 路  | 120° | ×9×eff_δ_sum² | (eff_δ_sum)² | **三相交流** |
| 4 路  | 90°  | ×16×eff_δ_sum² | (eff_δ_sum)² | 四相整流     |

> 以 |Δ|=4096（√=64）为例：单路 eff_δ_sum=64，合因子=64；四路满配每路 √=64，
> eff_δ_sum=4×64=256，合因子=256。高堆叠数下 n 可以更大，但建造难度也急剧上升。

> 同相输入合并计数（不奖励也不惩罚），**不是归零**——玩家最直觉的搭法
> （两个相同振荡器并排）应当有产出，否则会误以为系统故障。

> **小知识 · 集群涌现多相**：相数 n 统计的是「网络里被充能的边数」，不是你接的红石路数。
> 涂蜡铜块网络越大，参与相位的边越多——少数红石输入经网络传播，会自然涌现成多相
> （实测 4 路输入可涌现 n=7）。单个孤立铜块只有 4 条边，n 硬上限就是 4；**多相是集群的特权**。
> 注意：若多条边同步上升（同相位），会被合并为 1 相而无增益——真正的多相要靠网络拓扑
> 天然错开相位（红石传播有延迟）。
> 单路（n=1）恒为 eff_δ：调谐的奖励与多相绑定，精通路径与进阶路径在此汇合。

**「错开」的精确定义**：

- **相位只在同周期路径之间比较**——输入自动按周期分成若干「相位域」，
  每个域独立去重计相数；不同域之间没有相位差概念，**相数不跨域累加**；
- **相位 = 波形在周期内的整数 tick 偏移**（以参考路上升沿为 0 点），
  偏移 ≥1 tick 才算两相——整数 tick 既是分辨率下限，也是「相数上限 ≤ P」的来源；
- **同相（位模式完全重合）合并为一组**，n = 去重后的相组数，倍率 = n²；
- 表中 180°/120°/90° 是**标准满相配置**（均匀错开的经典摆法）而非判定条件，
  任意错开 ≥1 tick 的不同相组都按 n² 计。

**这是「精密」的主要来源**：三相 120° 意味着周期 6 tick，
三路振荡器分别延迟 0 / 2 / 4 tick，需要真正理解时序才能搭出来。



#### 本地感应：共享感知，分别发电

不引入「集群」实体，也不统计周长路数。规则一句话：

**相邻的块共享输入路数和信号（经锈蚀管径逐跳转发），发电计算逐块独立。**

- **共享发生在「路」的粒度**：块 B 的输入路 = 自己的邻居信号边
  + 相邻发电机转发的每一路输入（幅度 × 管径 c，波形与相位随路一起共享）。
  内部块不聋——振荡场沿块群逐跳传播，离信号源越远衰减越多（c 的跳数幂）；
- **路 = 物理信号路径**：直连边与共享来的每条线各算一路（不按邻居方向折叠，
  否则共享来的多相会在单方向里混叠失效），
  **n ≤ min(路径数, P)**——每条相线都要真实建造，槽位是自然的约束；
- **相位**：在本块全部输入路中按周期域去重计相（同相合并）；
- **发电独立**：双因子（含堆叠调谐）逐块各算各的，N 块 = N 份线性叠加——
  铜块是成本而非放大器，无需 √N 衰减之类的防膨胀规则；
- **满相协作门槛**：k 块直排提供 2k+2 个外部边位，吃满 P 相需要
  **2k+2 ≥ P 且块间连通**（P=5 双块起步，P=8 需 1×3 或 2×2 起步）——
  「低频多相要塞满容器」以精确公式回来了。

> 为什么共享要经过铜块网络而不是无衰减共享：无衰减的「全组共享」会让
> 锈蚀失去意义、切制/雕文的方向检测失效——

形状通过**铜块网络**表达：块与块谁挨着谁、氧化等级怎么配，决定网络怎么连通（见 §3.5）。

#### 检测结果与 Tooltip 显示（仪表盘进 tooltip）

检测系统的全部中间量本来就是事件驱动算出来的，顺手写回物品数据组件
（参照 `LivingGrateData.sumSignal` 的模式）即可让 **每台发电机自带仪表盘**：

| Tooltip 字段 | 来源 | 用途 |
|---|---|---|
| 检测周期 P / 偏好周期 P_pref | 事件间隔 / 堆叠数 | 调谐指引：差几 tick 一眼可见 |
| 相位域数、各域相数 n | 相位分组结果 | 多相布局调参 |
| 解锁度 u% | eff × n / pref | 平方奖励解锁进度 |
| 合因子 / log₂|Δ| 各因子 | 计算 | 「为什么产量低」逐项归因 |
| 最近跳变能量 / EMA 功率 | 记账 | 产出读数 |
| 起振进度 | 事件样本数（2~3 周期） | 低频档的「检测中…」状态 |

> 同步路径：服务端检测值 → 写回该槽位物品的小型 DataComponent →
> `syncSlotToClients` → 客户端 tooltip 读取。只在数值变化时同步，无额外开销。

> 2 tick 周期依赖容器内 **1 game tick 的时间分辨率**（红石传播每 tick 执行一次）。
> 早期实现每 2 tick 才传播，最快只能到 4 tick 周期，该档位形同虚设。

#### 调谐敏感性（自然涌现）

同样差 1 tick，在不同偏好周期下的严重程度天差地别：

| 偏好周期    | 差 1 tick 的相位误差 | 效率                  |
| ------- | -------------- | ------------------- |
| 64 tick  | 5.6°          | **~99.5%** — 几乎无损  |
| 16 tick | 22.5°          | **96%** — 几乎无损      |
| 8 tick  | 45°            | 85% — 轻微损失          |
| 4 tick  | 90°            | 50% — 平方奖励折半        |
| 2 tick  | **180°**       | **0%** — 退化为线性（信号反相） |

从 `(1+cosθ)/2` 这一个公式自然长出来：
新手把发电机堆到 64 叠（偏好周期 64t）随便对齐都能拿满平方；
想玩 2 tick 高频时，必须精确到单 tick——而且失谐的最坏结果只是
「平方退化为线性」，不再是颗粒无收，悬崖反而更温和了。

#### 频率中性化（没有捷径）

配合记账规则 `单次跳变能量(RE) = 合因子 × P`，平均功率对周期中性：
2t 时钟跳得密、64t 时钟单次多，两边打平。
**低周期不是捷径，而是更多的选择**——
频率选择完全由「你造得出什么时钟」和「匹配得多准」决定。

#### 相数上限（第二重取舍）

整数 tick 偏移决定了周期能容纳的最大相数（最多 P 相）：

| 偏好周期    | 最大相数 | 原因                  |
| ------- | ---- | ------------------- |
| 2 tick  | 2 相  | 只有 tick 0/1 两个可区分位置 |
| 4 tick  | 4 相  | <br />              |
| 8 tick  | 8 相  | <br />              |
| 16 tick | 16 相 | 但槽位不够放              |

**高频物理上做不了多相**。于是形成真正的取舍：

- **高频少相** — 省槽位，零容错，适合老手
- **低频多相** — 容错高，但要塞满整个容器
- **中频中相** — 需要计算才知道哪个划算

没有唯一最优解。这个取舍不是人为设定的，而是从"整数 tick"这一约束推导出来的。

#### 形态 = 线圈分组（不再是倍率）

涂蜡形态决定**把哪些方向合成一路波形来检测**（线圈分组），
功率差异由 n 自然产生，没有任何数值倍率：

| 形态 | 线圈分组 | 功率特性 |
|---|---|---|
| 涂蜡铜块 | **1 组 × 4 向**（全叠加） | n 上限最高（满配 ×16），但一锅烩——一根异周期杂讯线污染全部 |
| 涂蜡切制 | **2 组**（水平/垂直各自独立） | 每组独立计算、功率相加；隔离两组信号，脏不了对方 |
| 涂蜡雕文 | **1 组 × 1 向**（输入/输出双方向 WASD 配置） | 只收输入方向信号，只向输出方向传播；零延迟定向导通，支持拐角 |
| 涂蜡格栅 | **1 组 × 4 向 + 频率过滤**（待定） | 自动滤掉失谐杂讯，只收匹配周期的路 |

- **按通道叠加**：同周期的多路叠加依然干净（n 照常去重计数）；
  混入异周期杂讯会把该通道的波形搅浑，相数 n 会被拉低——
  这就是"拒绝听某个方向"的真实收益；
- **干净布线时铜块最强，环境脏时切制/雕文反超**——取舍是情境的，不是数值的；
- 物理对应：电机绕组接法（分槽/隔离绕组），不是绕组品质等级。

#### 因子互斥约束

两个因子并非全部可以同时取到最大值，存在以下互斥：

**相位 ⊗ 调谐**：解锁度 u = 调谐效率 × (n / 偏好周期)——
偏科即打折，不存在「相位吃满、调谐白给」的组合。

> 单块直连 ≤ 4 路，**第 5 相起必须块间协作**（相邻共享，每条相线都要真实建造）；
> n ≤ min(路径数, P)，平方增长受建造槽位自然约束，是否额外设上限待实测。

**拓扑 × 相位**：形态的线圈分组限制了各通道的输入路数——
铜块单通道最多 4 相（×16），雕文每通道最多 2 相（每通道 ×4，两通道相加），
切制单通道 1 相（×1）。这不是因子惩罚，是**拓扑事实**：想多相就用全向形态，
想隔离就接受通道变窄。

**实际选择**：没有唯一最优解，每种流派有各自的适用场景：

| 流派 | 相数 n | 合因子 | 适合 |
|------|------|------|------|
| 极简 | 1 | ×1（调谐无感） | 新手 |
| 双相 | 2 | ×4 | 进阶 |
| 四相 | 4 | ×16 | 高手 |
| 铜块网络规模化 | 网络内多路 | 随网络规模增长 | 规模化 |
| 抗干扰 | 1（切制单通道） | ×1 | 布线紧张 / 杂讯环境 |

#### 玩家成长路径

| 阶段  | 关注因子        | 典型行为                   |
| --- | ----------- | ---------------------- |
| 入门  | 基础幅度        | 搭出第一个振荡器，发现恒定信号不发电     |
| 进阶  | 相位错开        | 搭两路 180°，再挑战三路 120°    |
| 精通  | 解锁度        | 调谐 + 多相布局，把平方奖励拿满  |
| 优化  | 线圈分组        | 换形态控制听什么、不听什么，隔离杂讯保住 n |
| 布局  | **铜块网络**    | 搭建同氧化等级铜块网络，接入更多振荡器（见 §3.5） |
| 规模化 | **网络拓扑**  | 规划氧化等级网络隔离，实现多路信号并行输入 |

#### 设计原则：让玩家「算」，不让玩家「查」

| 机制            | 判定   | 理由                       |
| ------------- | ---- | ------------------------ |
| 相位差 120°      | ✅ 采纳 | 玩家能算：周期 6，延迟 0/2/4       |
| 共振匹配偏好周期      | ✅ 采纳 | 玩家能算：周期 6 的时钟，堆 6 叠恰好谐振  |
| 氧化等级网络隔离     | ✅ 采纳 | 玩家能算：不同氧化等级独立网络，互不干扰        |
| 铜块网络传播（按组件遍历） | ✅ 采纳 | 玩家能记：同氧化等级铜块连通，铜灯不导电        |
| 谐振频率 = 电路铜块总数 | ❌ 否决 | 多铺一根电缆就破坏谐振，不可预测         |
| 起振时间 / Q 值    | ❌ 否决 | 不可观测，且拉长调试反馈周期           |
| 阻抗匹配          | ❌ 否决 | 用电侧是外部模组机器，玩家只能查表        |

### 3.5 铜块网络传播：信号的路由

涂蜡铜块是绝缘的，但**同氧化等级的相邻铜块之间可以传播相位事件**。
发电机通过遍历同氧化等级铜块网络来检测振荡器信号，不同锈蚀等级形成彼此隔离的网络。

#### 核心规则

```
每 tick，按网络组件遍历（每组件仅锚点跑一次 BFS，其余 copyFrom 共享）：
  ① 按组件遍历：同 (TopoKey, rep) 发电机归一组，锚点（最小槽位 rep）从自身出发 BFS 遍历同氧化等级铜块
     - 四个方向检查：铜块（同氧化等级）→ 入队继续
     - 铜灯（泡）→ 跳过（不导电，仅作储能）
     - 非铜块物品 → 跳过
  ② 对每个遍历到的铜块槽位，检查 4 条边的 edgeGrid 信号变化
     - 读 getEdgeValue(slot, dir) vs getPrevEdgeValue(slot, dir)
     - 无变化 → 跳过（稳态开销 O(1)）
     - 上升沿 → SignalTracker 更新 → 周期已知 → PhaseEvent → ChannelState
  ③ 域内去重计 n，eff_δ_sum = Σ√|Δ_i|
  ④ 取最佳域合因子 → 能量入账
```

#### 氧化等级网络隔离

| 氧化等级 | 物品 | 网络 |
|---------|------|------|
| 0（新鲜） | `waxed_copper_block` | 只连通新鲜铜块 |
| 1（暴露） | `waxed_exposed_copper` | 只连通暴露铜块 |
| 2（锈蚀） | `waxed_weathered_copper` | 只连通锈蚀铜块 |
| 3（氧化） | `waxed_oxidized_copper` | 只连通氧化铜块 |

- 不同氧化等级**不互通**，必须用同种铜块搭建网络
- 涂蜡铜块雕刻/切制/格栅按相同氧化等级计入网络
- 铜灯（泡）**不参与网络传播**，仅作为储能

#### 设计意义

1. **>4 相输入**：振荡器不需要直接放在发电机旁边，通过铜块网络延伸到远处
   接入更多振荡器即可实现 >4 相输入
2. **布线需求**：不同氧化等级的网络隔离，需要规划网络拓扑
3. **建造复杂度**：网络越长，需要铺设的铜块越多，形成自然约束
4. **无距离衰减**：铜块网络内传播无距离约束（不用距离衰减），
   但不同氧化等级之间的隔离是硬约束

### 3.6 储能：铜灯 = 唯一储存，容器 = 铜灯的架子（v17.5）

**无容器池**：发电机产生的电**直接按剩余容量比例存入各铜灯堆**；
**没有用电侧、也没有铜灯时，电凭空消失**——发电必须被消费或储存，
这是电力层的即时性压力，也是涂蜡铜灯存在意义的根基。

**涂蜡铜灯 = 纯粹的容器**：无充电限率、无放电率——只管装。
限流职责归用电侧自己（机器抽多快是机器的事），电池只回答「能装多少」。

```
每容器 tick：
  1. 本 tick 发电量（RE）→ 按 K 折算 FE → 按各铜灯堆剩余容量比例直存（充电不限率）
  2. 无铜灯 → 电凭空消失（显性浪费，tooltip 可见）
外部用电侧（IEnergyStorage）：
  取电：请求 X → 按槽位顺序逐堆扣铜灯（每盏等量，向下取整，零头保守丢弃）→ 返回实际供给
  充电：外部电源推电进容器 → 按剩余容量比例充入各铜灯堆（受每盏容量 C 上限）
```

#### 容量涌现：堆叠数 × 单位容量（线性）

```
每盏容量 = C（单位容量标定常数，与 K 并列，全 mod 第二个也是最后一个硬数）
铜灯堆容量 = count × C
电量按「每盏」存（DataComponent 记 q = 每盏电量），堆叠总电量 = count × q
```

- **电量按盏存是防刷电的根基**：拆分时组件被复制——若存「每堆总量」
  则两堆各得一份（刷电）；按盏存则 64×q 拆成 54+10 各带 q，天然守恒；
- **合并由原版语义免费保护**：1.20.5+ 堆叠要求组件相同——
  电量不同的两堆铜灯不自动合并（如同不同耐久的工具），同电量合并天然守恒；
- **容量必须线性**：平方容量（count²×C）在拆分时容量坍缩（64 堆拆散剩 1/64），
  满堆拆一次毁掉 98% 的电——不可接受。线性下 q ≤ C 永远装得下，
  任何拆分/搬运/合并都严格守恒；
- **堆叠的价值 = 格位效率**：64 盏一条格子 vs 占 64 格；
- **锈蚀对铜灯 v1 无作用**（铜灯不是发电机，不参与共振声部——四种锈蚀的涂蜡铜灯
  储电能力完全相同，锈蚀只是外观差异）；
- 充电分配/放电扣取均按比例摊（各堆均匀进化，无排序逻辑）；
- 池常态为空（每 tick 结算清空）→ **无需容器级持久化**，
  电全部住在铜灯 DataComponent 里随 NBT 走——持久化问题自动消失。

> 满溢语义：电池满后跳变照常计算但能量弃掉，tooltip 显示「电池已满」——
> 玩法信号（该上用电侧或加大电池），比静默溢出好。
> 「充电宝物流」免费涌现：充满的铜灯拔下来插到别的容器接着用（多容器各自独立池，
> 跨容器批量输电仍是活避雷针的职责）。

#### 铜灯物品 = 通用电池（双向）

铜灯物品注册 `EnergyStorage.ITEM` 能力，**双向开放**：

- **电池槽（放电）**：机器从灯里抽取（每盏等量扣）✅
- **充能槽（充电）**：外部电源给灯充能（每盏等量加，受每盏容量 C 限制）✅
  —— 跨系统能量**等量转换**（外部 100 FE 进灯 ↔ 红电侧取 100 FE），守恒无套利

**无出身论**：外部充的电与红电发的电在灯里混为一个 q、不分来源——
外部充的电可被红电用电侧取用，红电发的电也可被外部系统抽走。
电池里的电没有出身论，这正是「通用电池物品」的语义。

> 注意：**容器方块级接口同样双向**（canReceive=true）——外部电源可对容器充电，
> 电按剩余容量比例充入各铜灯堆（整 FE 量化，守恒无套利）。
> 外部充能进灯 → 灯回到容器 → 其电量自然供红电用电侧取用（无出身论）。

### 3.6.1 网络级共振（不同锈蚀级之间的「和声」）

> 技术细节与公式推导见 [living-power-tech.md §3.7](tech/living-power-tech.md)。本节只给规划层结论。

**核心思路**：把对象从「单个涂蜡铜块」抬到「锈蚀级发电网络」这一维度。
同锈蚀级的若干连通块出力**直接相加**（声部单位 = 锈蚀级，不是 BFS 连通块），
不同锈蚀级之间按**出力平衡度**互相感应（共振）。不需要物理接触——
所有电都是容器级的，声部之间天然共处同一容器。

**收益**：更高的总发电量。满配 4 声部且出力完全平衡时，总发电 ×16。

#### 公式（单遍前馈，无反馈）

设 `Aₖ` = 第 k 个锈蚀级本 tick 的**基础**发电量（同锈蚀级连通块已相加），仅统计 `Aₖ > 0` 的声部：

```
平衡度 s = GM/AM = (Π Aₖ)^(1/N) ÷ (Σ Aₖ / N)      // AM-GM 不等式，s ∈ [0, 1]，与规模无关
共振因子 R = 1 + (N − 1) · s                        // R ∈ [1, N] ⊆ [1, 4]
增益 gain   = R ^ 2                                 // RESONANCE_EXPONENT = 2

容器本 tick 总发电 = (Σ baseRe[k]) × gain
```

- `N` = 活跃声部数，结构性封顶 `OXIDATION_LEVELS = 4`（锈蚀级只有 4 种，故 `R ≤ 4`）。
- 只建 1 种锈蚀级 → `N = 1` → `R = 1` → `gain = 1`（无加成）。
- `s` 用 GM/AM 而非方差：规模无关——「3 声部各 100」与「3 声部各 10000」平衡度相同，
  逼玩家去追求**规模相近**而非单纯堆量；凑弱网稀释平衡度只会亏（见下表）。

#### 三条铁律（安全红线，详见技术文档）

1. **只读基础值、单遍前馈**：共振只采样本 tick 乘增益前的 `baseRe[k]`，增益绝不回灌——
   杜绝「A 增益↑ → A 出力↑ → A 增益再↑」的永动机。
2. **EMA 只跟踪基础出力**：每锈蚀级维护指数滑动平均，但只喂 `baseRe[k]`，不喂增益后值。
3. **EMA 必须截断归零**：指数衰减永不真正到 0，设 `EMA_EPSILON = 1e-6`，
   低于阈值强制置 0，否则停发的声部会永远顶着「活跃」名分把 `s` 永久压死、共振再无自愈。

#### 每 tick 流程

```
1. 遍历本容器所有涂蜡铜发电机 → 按锈蚀级累加 baseReByOx[k]
2. powerData.updateOxidationEma(baseReByOx)   // 推进每级 EMA（含归零截断）
3. gain = powerData.resonanceGain()           // 只读 EMA（基础值）算 R²
4. generatedRe = powerData.drainGeneratedRe()
   if (gain > 1.0 && generatedRe > 0) generatedRe = round(generatedRe * gain)
5. 按原逻辑把 generatedRe 分配给各铜灯储能
```

#### 场景对照（验证用，详见技术文档测试 `NetworkResonanceTest`）

| 配置 | 基础总发电 | 平衡度 s | R | gain | 实际总发电 |
| --- | --- | --- | --- | --- | --- |
| 单声部 ×2700 | 2700 | 1.0 | 1 | 1 | 2700 |
| 2 声部各 2700 | 5400 | 1.0 | 2 | 4 | 21600 |
| 3 声部各 2700 | 8100 | 1.0 | 3 | 9 | 72900 |
| 4 声部各 2700 | 10800 | 1.0 | 4 | 16 | 172800 |
| 3 声部 2700 + 1 弱网 270 | 10800 | ↓ | ↓ | ↓ | < 72900（凑弱网不划算） |

> **进阶成本匹配奖励**：4 色共振是进阶目标。获取 4 种不同锈蚀程度的涂蜡铜块物品
> 需养蜂取蜜蜡 + 逐级风化 + 每级单独涂蜡，是一条渐进式进度门槛；
> ×16 的超线性回报匹配这条超线性获取成本，不会失衡。

### 3.7 完整物品矩阵

| 形态     | 未涂蜡（信号层）       | 涂蜡（电力层）     |
| ------ | -------------- | ----------- |
| **铜块** | 电缆，全向传导        | 发电机，1 线圈 × 4 向全叠加 |
| **雕文** | 二极管，输入/输出双方向  | 发电机，2 线圈（H/V 隔离） |
| **切制** | 立交桥，双轴绝缘       | 发电机，1 线圈 × 1 向（无干扰） |
| **格栅** | 红石→红电桥接加法器     | 发电机，1 线圈 × 4 向 + 频率过滤（待定） |
| **铜灯** | 信号记忆，记录/清除    | 电池          |

× 4 档锈蚀 = 4 条独立频道（信号层）/ 4 个氧化等级网络（电力层）

> 铜门 / 铜活门暂不设计，留待后期作为「信号闸门 = 晶体管」。

#### 锈蚀在两层的含义

锈蚀在信号层是「频道隔离」，在电力层是「氧化等级网络隔离」。
两层都是「第几档」，但一个管**跟谁连**，一个管**网络连通性**。

之所以能这样分工：涂蜡铜块本来就不导通，「频道」对它没有意义，
档位自然腾出来表达别的东西。谐振点的选择交给了堆叠数调谐（§3.4 因子三）。

### 3.8 核心数据结构（事件驱动）

```java
public class ContainerPowerData {
    /** 发电机状态：slot → GeneratorState */
    Map<Integer, GeneratorState> generators;

    /** 边信号跟踪器：edgeKey = (slot << 2) | dir → SignalTracker（跨 tick 持久） */
    Map<Long, SignalTracker> edgeTrackers;

    /** 本 tick 发电量（RE），tick 末由 glue 分配入铜灯 */
    long generatedReThisTick;

    /** EMA 平滑后的功率读数（RE/t） */
    double emaPowerRe;
}

public class GeneratorState {
    /** 偏好周期 = 堆叠数 */
    int preferredPeriod;

    /** 单通道接收事件 */
    ChannelState channel;
}

public class ChannelState {
    /** 相位域：period → PhaseDomain */
    Map<Integer, PhaseDomain> domains;

    void onPhaseEvent(PhaseEvent event, int preferredPeriod);
    double bestFactor(int preferredPeriod);
    int bestPeriod(int preferredPeriod);
    void tickCleanup(long now, int preferredPeriod);
}

public class PhaseDomain {
    int period;
    Set<Integer> offsets;        // 已观察到的不同偏移量（去重 = 相数 n）
    Map<Integer, Integer> deltaByOffset; // offset → |Δ|（用于 √|Δ| 求和）
    long lastEventTick;
}

public record PhaseEvent(
    long sourceId,     // edgeKey = (slot << 2) | dir
    int period,        // 周期（tick）
    int offset,        // 相位偏移
    int delta,         // 跳变幅度 |Δ|
    long tick          // 事件 tick
) {}
```

> 全部为事件驱动增量更新，无密集历史环。
> `signal_prev` 不额外存储——直接复用 `ContainerRedstoneData.prevEdgeGrid`。

### 3.10 Tick 流程（事件驱动 + 铜块网络传播）

```
processContext() 每 tick（在红石传播之后，priority = 3）：

1. 收集发电机槽位（铜灯跳过）

2. 按网络组件遍历（每组件仅锚点跑一次 BFS，其余 copyFrom 共享）：
   a. 锚点从自身出发，四个方向遍历同氧化等级铜块
      - 同氧化等级铜块 → 入队
      - 铜灯 → 跳过（不导电）
      - 非铜块 → 跳过
   b. 对每个遍历到的铜块槽位，检查 4 条边：
      - 读 edgeGrid[slot][dir] vs prevEdgeGrid[slot][dir]
      - 无变化 → 跳过
      - 上升沿 → SignalTracker.onRisingEdge()
      - 周期已知 → 创建 PhaseEvent → ChannelState.onPhaseEvent()

3. tickCleanup：清理 >128 tick 无事件的过期域

4. 能量入账：
   bestFactor = channel.bestFactor(pref)
   bestPeriod = channel.bestPeriod(pref)
   if factor > 0 && period > 0:
      re = PowerMath.eventEnergyRe(factor, period)
      powerData.onEventEnergy(re)

5. EMA 更新 totalPower（对外显示与读数）

6. 发电直存（tick 末）：
   本 tick 发电量 → 折算 FE → 按剩余容量比例直存入各涂蜡铜灯堆（充电不限率）
   → 无铜灯则弃（显性浪费）

7. IEnergyStorage 输出：
   请求 X → 直接从各铜灯堆按存量比例扣 → 返回实际供给

8. 活避雷针供需分配（见 §3.14）：
   a. 收集阶段：遍历所有容器，累加各频道的 supply 与 demand
   b. 分配阶段：各输出端按 min(1, supply/demand) 比例获得功率
```

**总复杂度**：O(槽位数) 稳态 + O(铜块网络大小) 有信号时。
按网络组件遍历铜块网络，无信号时同组件只跑一次 BFS（O(1) 感知开销）。

> ⚠️ **`getPriority()`** **必须 > 红石的 2**（红石与红石火把均为 2），
> 因为电力计算依赖红石已算完的 `edgeGrid`。当前占用：
> 水桶 0、水车 1、红石 2 → **电力用 3**。

> ⚠️ **感应分配必须先算完所有直连、再统一分配**（单趟两阶段），
> 不能边算边读下游的中间值，否则会引入遍历顺序依赖。

### 3.14 活避雷针（红电波频道）

活避雷针是电力系统从**局域**走向**全局**的关键。
涂蜡铜块管容器内发电，活避雷针管跨容器输电。

```
局域：活红石振荡 → 铜块信号网络 → 涂蜡铜块发电 → totalPower → IEnergyStorage
全局：totalPower → 活避雷针 → 红电波频道 → 活避雷针 → 其它容器
```

#### 物品

活避雷针只有一种，没有氧化/涂蜡变体。
堆叠数 = 频道，64个独立频道。

#### 方向性 I/O

活避雷针一头大（输入端）一头小（输出端），参考活漏斗的方向性设计。
4 个朝向（上下左右）+ 输入/输出分离，在 2D 网格中实现灵活拓扑：

```
        输入端(大头)
          ↑
    ┌─────┴─────┐
    │ 活避雷针   │  ← 朝向 = 上（输入在上，输出在下）
    └─────┬─────┘
          ↓
        输出端(小头)

4 种朝向：
  上：输入=上邻居，输出=下邻居
  下：输入=下邻居，输出=上邻居
  左：输入=左邻居，输出=右邻居
  右：输入=右邻居，输出=左邻居
```

右键旋转朝向。

#### 供需分配模型（能量守恒）

活避雷针按朝向区分**输入端**（供给）和**输出端**（需求），
采用标准电网供需模型，保证能量守恒。

```
channelSupply[频道] = Σ(所有输入端贡献的功率)
channelDemand[频道] = Σ(所有输出端请求的功率)

每个输出端实际获得 = request × min(1, supply / demand)
```

```
频道 5：
  容器A：铜块总线(100 FE/t) → 避雷针输入端 → supply += 100
  容器B：铜块总线(50 FE/t)  → 避雷针输入端 → supply += 50
  supply = 150

  容器C：避雷针输出端 → request 200 → demand += 200
  容器D：避雷针输出端 → request 100 → demand += 100
  demand = 300

  分配比例 = min(1, 150/300) = 0.5
  容器C 获得 200 × 0.5 = 100
  容器D 获得 100 × 0.5 = 50
  总输出 150 = 总输入 150   ✅ 守恒
```

> ⚠️ **为什么不用「共振 + 净值扣除」**
>
> 早期方案是「频道共振总和广播给每个避雷针，扣除自身贡献」。
> 该模型能挡住单容器自环，但**两个容器可以互相刷**：
>
> ```
> 容器A 贡献 100，容器B 贡献 100，共振 = 200
> 容器A 获得 200 - 100 = 100（拿到 B 的）
> 容器B 获得 200 - 100 = 100（拿到 A 的）
> 总输入 200 → 总输出 400，能量翻倍
> ```
>
> N 个容器互联时按 N×(N-1) 放大，10 个容器就是 90 倍。
> 「共振」概念上很浪漫，但**能量守恒是硬约束**。
> 现改为供需分配，保留跨维度无衰减的特性，玩家感知不到区别。
>
> 该思路与 `EnderChannelRegistry` 的轮询公平调度一致——
> 同样是多对多的资源分配问题。

#### 四种拓扑模式

| 模式       | 输入接铜块 | 输出接铜块 | 效果                |
| -------- | ----- | ----- | ----------------- |
| **纯供给**  | ✅     | ✗     | 只向频道供电（发电站）       |
| **纯需求**  | ✗     | ✅     | 只从频道取电（用电端）       |
| **双向桥接** | ✅     | ✅     | 同时供给与需求，可用于频道间转运  |
| **空闲**   | ✗     | ✗     | 不参与分配             |

#### 与容器电力的关系

避雷针不绑定锈蚀档位——它的输入端从**容器的 `totalPower`** 取电注入红电波频道，
输出端从频道取电补充**容器的池与铜灯**：

```
容器A: 涂蜡铜块发电 → totalPower → 避雷针(输入) → 红电波频道 5
                                                      ↓
容器B: 铜灯 ← 避雷针(输出) ←──────────────────┘
```

避雷针的频道由**堆叠数**决定（1~64 共 64 个独立频道），与锈蚀无关。
一个避雷针可以是纯供给、纯需求，或两端都接以实现频道间转运。

> 早期设计里避雷针在「4 条电力总线」之间桥接。
> 现在电力就地产生并汇总为单一 `totalPower`，容器内已无总线可桥，
> 避雷针的唯一职责就是**跨容器输电**。这比原设计更简单，玩家也更好理解：
> 「容器内不需要电线，容器间用避雷针」。

#### 跨维度无衰减

红电波是概念频道，不分维度。主世界的频道 5 和下界的频道 5 是同一个频道，状态完全同步。

#### 全局注册表

```java
public class RedElectricWaveRegistry {
    /** 频道 → 本 tick 的供给总量(FE/t) */
    Int2IntMap channelSupply;

    /** 频道 → 本 tick 的需求总量(FE/t) */
    Int2IntMap channelDemand;
}
```

> ⚠️ **必须在** **`ServerStoppedEvent`** **中清空**。
> 这是进程级静态表，单人游戏「退出存档 → 进入另一个存档」不会重启 JVM，
> 不清理会把上一个世界的频道状态带入新世界。
> 参考 [LivingItem.onServerStopped](../src/main/java/com/qiqi/li/LivingItem.java) 的现有处理。

#### 每 tick 流程

```
1. 清零 channelSupply[1..64] 和 channelDemand[1..64]

2. 收集阶段：遍历所有容器中所有活避雷针
   → 输入端有铜块？ channelSupply[频道] += 该铜块所属总线功率
   → 输出端有铜块？ channelDemand[频道] += 该铜块所属总线的需求量

3. 分配阶段：遍历所有容器中所有活避雷针
   → 输出端有铜块？
   → ratio = min(1.0, channelSupply[频道] / channelDemand[频道])
   → 注入功率 = 该端 request × ratio

4. 扣减供给侧：各输入端按同一 ratio 实际输出，未被消耗的功率留在本地总线
```

**复杂度**：O(全局避雷针数)，通常 < 100，每 tick 两趟遍历。

#### 典型应用

```
1. 跨容器输电：
   容器A：活红石振荡 → 铜块A → 避雷针(stack=8, 朝右) → 频道8
   容器B：频道8 → 避雷针(stack=8, 朝左) → 铜块A → IEnergyStorage

2. 跨维度供电：
   主世界：发电机 → 铜块A → 避雷针(stack=1) → 频道1
   地狱：频道1 → 避雷针(stack=1) → 铜块A → 用电

3. 多频道分工：
   频道1：低功率控制信号
   频道8：主电源
   频道16：辅助电源

4. 跨频道桥接：
   铜块(未锈蚀) → 避雷针(输入) → 红电波频道 → 避雷针(输出) → 铜块(斑驳)
   实现未锈蚀总线和斑驳总线的功率互通
```

#### 与 EnderChannelRegistry 的关系

红电波频道和末影珍珠频道是两套独立系统：

| <br /> | 末影珍珠频道 | 红电波频道    |
| ------ | ------ | -------- |
| 传输内容   | 物品/实体  | 功率(FE/t) |
| 频道数    | 按珍珠ID  | 64（堆叠数）  |
| 跨维度    | ✅      | ✅（无衰减）   |
| 模型     | 发布/订阅  | **供需分配** |

## 6. 技术风险与应对

| 风险                   | 影响                       | 应对                                  |
| -------------------- | ------------------------ | ----------------------------------- |
| 信号传播性能（BFS 每 tick）   | 大量活红石粉时可能卡顿              | 已做槽位位图去装箱（实测满载 54 格约 4.9μs）；如仍不足可加脏标记 |
| 递归 tick（活潜影箱嵌套）      | 深层嵌套性能爆炸                 | 最大嵌套深度 4 层 + 脏标记缓存                  |
| **拖动发电机刷电**          | 移动涂蜡铜块凭空产生 Δ = 永动机       | `prev` **按槽位存储**，不存物品 DataComponent |
| **低周期无脑最优**          | 快时钟跳变密导致平均功率碾压慢时钟        | 频率中性化：单次跳变能量(RE) = 合因子 × P，平均功率与周期无关  |
| **多容器共谋刷电**          | 共振模型下 N 容器互联放大 N×(N-1) 倍 | 改用**供需分配模型**，保证能量守恒                 |
| 检测性能                 | 每台发电机多路波形分析              | 事件驱动 O(1) 增量更新，稳态仅整数比较              |
| **n² 相位平方逃逸**         | 多相路径数大时收益平方增长              | ⚠️ 有界：n ≤ min(路径数, P)，相线需逐条建造；是否设上限待实测 |
| 低频调谐反馈慢             | 64t 周期需 2~3 周期才建立评级      | 玩法侧「起振观测期」，tooltip 显示检测进度            |
| 科技模组兼容性              | 不同模组能量单位不同               | 统一通过 NeoForge IEnergyStorage        |
| 静态表跨存档残留             | 频道状态带入新世界                | `ServerStoppedEvent` 统一清理           |
| 信号穿透衰减               | 深层嵌套信号为 0                | 活中继器刷新 / 边界穿透不衰减                    |
