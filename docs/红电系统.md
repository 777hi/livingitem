## 0. 总览

三大系统的关系：

```
活红石   ──→ 逻辑层（信号 0-15，门电路，时序电路）
活铜块   ──→ 信号层（未涂蜡：频道隔离 + 5 种拓扑）
             电力层（涂蜡：感应发电 + 储能）
活避雷针 ──→ 传输层（红电波频道，跨容器/跨维度）
活潜影箱 ──→ 封装层（芯片，层次化设计）

活红石 + 活铜块 = 电气系统（信号同源，涂蜡分层）
活铜块 + 活避雷针 = 无线电力网络（局域发电 + 全局供需分配）
活红石 + 活潜影箱 = 可封装的逻辑 = 芯片
三者合一 = 信息时代（计算 + 电力 + 封装 + 无线传输）
```

**核心设计**：红石信号与红电信号**本质同源**，只是在不同介质中的叫法不同——
无需任何转换器物品。铜块**涂蜡与否**决定它工作在信号层还是电力层。

实施顺序：**活红石 → 活铜块 → 活潜影箱**。前两者各自可用，组合后产生质变。

## 1. Phase 1：活红石（容器内红石系统）

### 1.1 目标

在 2D 容器网格（9×6 背包 / 9×3 活潜影箱）中实现原版红石信号传播的等价逻辑。

### 1.2 核心数据结构

#### ContainerRedstoneData（容器级红石信号数据）

```java
public class ContainerRedstoneData {
    // 每个槽位的当前信号强度 (0-15)
    private int[] signalStrength;
    // 每个槽位的信号来源方向（防止回传）
    private Pos2D[] signalSource;
    // 是否需要重新计算
    private boolean dirty;
}
```

与 `ContainerFluidData`、`ContainerStressData` 并列，作为容器级数据在 `TickContext` 中持有。

#### LivingRedstoneData（物品级数据组件，每个红石物品有独立组件）

```java

### 1.4 信号传播算法（四阶段）

```
每 game tick 执行一次（时间分辨率 = 1 tick），拆分为 4 个 Phase：

Phase 0 — 倒计时 + 断电检测（用 prevSignalStrength）：
  - 中继器：被锁定则跳过倒计时；检测输入端是否仍有信号，断电则立即归零
  - 按钮：递减 pulseTimer，到期自动弹起

Phase 1 — 收集信号源：
  - 火把（点亮）→ 输出 cap = getSignalCap(count)
  - 按钮（按下）→ 输出 cap = getSignalCap(count)
  - 拉杆（激活）→ 输出 cap = getSignalCap(count)
  - 中继器（powered && delayTimer == 0）→ 输出 cap = getSignalCap(count)
  - 比较器（output > 0）→ 输出 output
  - 红石块（始终）→ 输出 cap = getSignalCap(count)，四向

Phase 2 — 统一迭代传播：
  - 单一 BFS 队列，根据槽位类型自动切换传播规则：
    - 红石粉：四方向传播，每格 -1，上限受 getSignalCap 约束
    - 中继器/比较器：只向 outDir 方向传播，第一跳不衰减
    - 火把：跳过输入端（防止向输入端泄露）
  - 无 visited 数组：通过 signalStrength[neighbor] 比较决定是否继续
  - 红石粉始终向所有方向边写入信号（v10 变更），非红石组件（活漏斗等）可读取边信号

Phase 3 — 充能导体（先于 Phase 4 执行）：
  - 所有信号源（红石粉/火把/按钮/拉杆/红石块/中继器/比较器）向相邻导电活物品充能
  - 导体所有边写入信号，触发第二波 BFS 传播
  - 仅活物品可被充能（LivingItemManager.isLivingItem），复用原版 isRedstoneConductor 判定导电性

Phase 4 — 重新检测输入（级联效应）：
  - 中继器：被锁定则跳过状态转移；锁定检测：检查侧面是否有已输出状态的中继器
  - 中继器：重新检测 signalStrength[inputSlot]，级联上电（此时导体信号已就绪）
  - 比较器：重新计算 output，更新 powered

Phase 5 — 更新显示状态：
  - 火把：反相器逻辑（有输入→熄灭，无输入→点亮）
  - 红石粉：更新 signalStrength + isPowered
  - 红石灯：检查邻居有无信号，更新 lit

Phase 6 — 容器内外红石交互（面信号模型）：
  - 在 Phase 0 之前执行 injectExternalInputs()
  - 输入：遍历容器**所有关联方块位置**（大箱子遍历两个半箱），读取外部红石信号
  - 通过 CrossContainerTransfer.worldToGrid() 将世界方向映射为内部网格方向
  - 外部信号存入 faceInput[4]（不写入 edgeGrid），方向性元件通过 getEffectiveInput() 读取
  - 方向性元件（火把/中继器/比较器）可读取 faceInput
  - 无方向性元件（红石粉/红石灯/铜块/铜格栅/铜灯）仅接收内部邻居信号
  - 输出：Phase 5 后 computeFaceOutput() 扫描 edgeGrid 边界边 → faceOutput[4]
  - Mixin BlockStateBase.getSignal() → getBoundarySignal() → faceOutput[dir]（弱信号，红石粉可读）
  - Mixin BlockStateBase.getDirectSignal() → getBoundarySignal() → faceOutput[dir]（强信号，中继器/比较器/火把可读）
  - 连接：Mixin RedStoneWireBlock.getConnectingSide() 强制返回 SIDE，让红石粉连接容器
  - 方向映射复用 CrossContainerTransfer（已内置容器朝向旋转处理）

  反馈循环防护（面信号模型天然优势）：
  - faceInput[4] 仅用于 BFS 传播，不写入 edgeGrid
  - faceOutput[4] 仅扫描 edgeGrid（纯内部）得出，不受外部信号影响
  - 输入/输出通道完全分离，EdgeGrid 回归静态纯内部类

  跨容器直读机制（超限信号传输）：
  - injectExternalInputs 检测邻居方块是否为容器，若是则直接读取其 ContainerRedstoneData.faceOutput
  - 通过 ContainerLivingItemHandler.getRedstoneDataByPos() 获取邻居容器数据
  - 使用 worldDir.getOpposite() 翻转方向，正确读取邻居对面那个面的 faceOutput
  - 绕过原版 level.getSignal() 的 0-15 截断，支持超限信号（>15）跨容器传输
  - 非容器邻居仍走原版 level.getSignal() 路径（0-15）

  相邻容器边界反馈环特性：
  - 两个相邻容器的相邻边界上都有活红石粉时，信号每 tick 衰减 1
  - 原因：面信号互传形成衰减反馈环（A 输出 → B 输入 → B 衰减输出 → A 输入 → A 衰减输出...）
  - 保留为特性：实际使用中相邻边界通常不会同时放红石粉，信号自然衰减至 0 无死循环

  大箱子支持：
  - injectExternalInputs 遍历 getAssociatedBlockPositions() 所有半箱
  - notifyBoundaryChange 通知所有关联方块位置的邻居
  - ContainerIdentity 新增 getAssociatedBlockPositions() 方法

  信号变化通知：
  - notifyBoundaryChange 对比 faceOutput 与 prevFaceOutput
  - 仅在边界输出信号实际变化时触发 updateNeighborsAt()，避免闪烁

Phase 7 — 活漏斗红石信号控制（v10 新增）：
  - 活漏斗在 LivingHopperFunction.tick() 中通过 ContainerRedstoneData.getSignal(slot) 检测边信号
  - 任意边信号 > 0 → 漏斗被禁用（跳过传输和冷却倒计时），tooltip 显示红色警告 ⚠
  - 信号消失 → 自动恢复传输
  - 依赖 Phase 2 的边写入解耦：红石粉始终向所有方向边写入信号，非红石组件可直接读取
```

**设计要点**：

- `prevSignalStrength` 保存上一帧信号，Phase 0 用于断电检测，避免"先算新信号再判断断电"的时序问题
- 所有组件统一在 Phase 2 的单次 BFS 中传播，中继器间信号可自然接收
- `calculate()` 拆分为 5 个私有方法，每个 Phase 一个，新增组件只需在对应 Phase 方法中加循环

**信号强度公式**：`getSignalCap(count) = count == 1 ? 15 : count * count`

\| 堆叠数 | 1 | 2 | 3 | 4 | 5 | 8 | 16 | 32 | 64 |
\|--------|---|---|---|---|---|---|---|----|----|-----|-----|
\| 信号上限 | 15 | 4 | 9 | 16 | 25 | 64 | 256 | 1024 | 4096 |

**连接判定**：活红石粉只向相邻的活红石组件传播，不穿过普通物品。判定条件：

- 目标槽位的物品是活红石组件（活红石粉、活火把、活中继器...）
- 或目标槽位是活潜影箱（信号穿透边界，见 Phase 2）

## 2. Phase 2：活潜影箱（封装 + 边界连续性）

### 2.1 目标

实现活潜影箱的**边界连续性**——多个活潜影箱在容器中排列时，内部槽位在逻辑上连续，物品和信号可以跨边界传输。

### 2.2 边界连续性规则

```
容器 C 中：
  槽位 1：活潜影箱 a（内部 9×3 = 27 槽位）
  槽位 2：活潜影箱 b（内部 9×3 = 27 槽位）

逻辑空间：a 和 b 水平相邻 → 18×3 = 54 个连续槽位

a 的右边界（内部槽位 8, 17, 26）←→ b 的左边界（内部槽位 0, 9, 18）
```

**4 个活潜影箱 2×2 排列 → 18×6 的逻辑空间**。

### 2.3 跨边界传输

#### 物品传输（活漏斗）

```
活潜影箱 a 内部的活漏斗 c：
  c 的输出方向 = 右
  c 所在槽位 = a 的内部槽位 17（右边界中间）

  → c 的输出目标 = a 的右边界之外
  → a 的右边是活潜影箱 b
  → c 输出到 b 的内部槽位 9（左边界中间）
```

#### 信号传输（活红石）

```
活潜影箱 a 内部槽位 8（右边界）信号强度 = 12
  → 穿透边界 → 活潜影箱 b 内部槽位 0（左边界）信号强度 = 11

衰减规则：边界穿透 -1（与红石粉每格衰减一致）
```

#### 外部 ↔ 内部传输

```
容器 C 中：
  槽位 5：活红石粉（信号 12）
  槽位 6：活潜影箱 S

  S 的左边界 = S 内部槽位 0, 9, 18
  信号从槽位 5 → S 的左边界 → S 内部传播

  S 的右边界 = S 内部槽位 8, 17, 26
  信号从 S 右边界 → 容器 C 槽位 7
```

### 2.4 封装 = 芯片

活潜影箱的边界连续性 + 活红石的信号传播 = **芯片封装**。

```
引脚映射：
  活潜影箱 9×3 网格的边界槽位 = 引脚
  上边界 9 个 + 下边界 9 个 + 左边界 3 个 + 右边界 3 个 = 24 个引脚

封装层级：
  Level 0：离散元件（活红石粉、活火把...）= 面包板
  Level 1：活潜影箱封装 Level 0 = IC 芯片
  Level 2：活潜影箱封装 Level 1 = PCB
  Level 3：活潜影箱封装 Level 2 = 系统模块
  ...
```

### 2.5 技术挑战

#### 递归 tick 性能

```
容器 tick
  → 活潜影箱 A tick
    → A 内部活潜影箱 B tick
      → B 内部活潜影箱 C tick
```

应对策略：

- **最大嵌套深度限制**：4 层
- **脏标记优化**：边界信号不变 → 跳过内部 tick
- **缓存**：内部信号稳定后缓存输出，直到输入变化

#### 信号延迟

深层嵌套导致信号衰减为 0。应对：

- **活中继器**在边界处刷新信号强度
- 或：边界穿透**不衰减**（边界是"导线"不是"红石粉"）

#### 并发一致性

同一 tick 内多个活潜影箱输入同时变化。应对：

- 先收集所有边界信号，再统一更新内部（类原版 BFS 拓扑排序）

### 2.6 可视化

## 3. Phase 3：活铜块（信号介质 + 电力系统）

### 3.1 核心概念：红石信号与红电信号同源

**红石信号和红电信号本质是同一种信号，只是在不同介质中的叫法不同。**

```
信号在活红石元件中传播  → 称为「红石信号」
信号在活铜块家族中传播  → 称为「红电信号」

两者自由互转，无需任何转换器物品：
  活红石粉 → 活铜块   ：红石信号变为红电信号
  活铜块 → 活红石粉   ：红电信号变为红石信号
```

活铜块家族的传播行为与活红石粉一致（BFS，每格衰减 -1），
区别在于**铜块提供了红石粉没有的拓扑能力**（见 §3.3）。

### 3.2 三轴正交模型

原版铜块相关物品有 5 种形态 × 4 档锈蚀 × 2 种涂蜡 = 40 件。
若逐个设计机制则无人能记住，因此采用**三轴正交**：每个轴只管一件事。

| 轴        | 控制               | 取值                     |
| -------- | ---------------- | ---------------------- |
| **基础形态** | 拓扑（信号怎么流 / 感应什么） | 铜块 / 雕文 / 切制 / 格栅 / 铜灯 |
| **锈蚀状态** | 分档（信号层=频道，电力层=耦合） | 未锈蚀 / 斑驳 / 风化 / 氧化     |
| **涂蜡**   | 层次（信号层 / 电力层）    | 未涂蜡 = 导电传信号，涂蜡 = 绝缘产电力 |

玩家只需掌握 **5 + 4 + 2 = 11 个概念**，即可推断全部 40 件物品的行为。

> 例：`涂蜡风化雕文铜块` 堆叠 8 = 电力层 + 弱耦合管径 + 十字拓扑（两轴感应）
> → 偏好周期 = 2×8 = 16 tick，读取两个轴向的相位差发电。看名字即知拓扑，堆叠数即知谐振点。

#### 锈蚀 = 分档（两层各有含义）

锈蚀在两层都表示「第几档」，但档位的**含义**随层次而变：

| 层次 | 锈蚀的含义 | 未锈蚀 → 氧化 |
| -- | ----- | --------- |
| 信号层（未涂蜡） | **频道**：不同档位互不导通 | A / B / C / D 四条独立线路 |
| 电力层（涂蜡） | **耦合强度**：感应传能的「管径」 | 强 → 弱（1.0 / 0.7 / 0.5 / 0.35） |

两层的档位序号一致，只是一个管「跟谁连」（频道），一个管「传多少能量」（耦合）。
之所以能这样分工，是因为**涂蜡铜块本来就不导通**——
既然它不参与连线，「频道」对它就没有意义，档位自然腾出来表达别的东西。

##### 信号层：锈蚀 = 频道隔离

不同锈蚀状态的活铜块之间**不传递红电信号**，等同于不同颜色的电线。

```
[未锈蚀铜块] ─✅→ [未锈蚀铜块]     同频道，导通
[未锈蚀铜块] ─✗→ [斑驳铜块]       不同频道，绝缘
[活红石粉]   ─✅→ [任意锈蚀铜块]   红石粉可注入任意频道
```

**这是 2D 布线的核心价值**：9×6 网格中，4 种锈蚀铜块 + 活红石粉
可以走 5 路互不干扰的独立信号。原版红石粉相邻必然串信号，
在 2D 平面上几乎无法布线。

##### 电力层：锈蚀 = 感应耦合强度

见 [§3.5 感应耦合与谐振链](#35-感应耦合与谐振链相邻发电机的能量路由)。
发电机之间的振荡能量按耦合强度分配：锈蚀越深「管径」越细，
分到的感应份额越少（1.0 → 0.35）。深锈蚀不是更差的块，
而是**隔离、节流与终端封口**的路由材料。

#### 涂蜡 = 层次切换

蜡是绝缘体，因此**涂蜡铜块不传导信号**——它只能通过感应工作。

```
未涂蜡：导电 → 传播红电信号（信号层）
涂蜡  ：绝缘 → 感应邻居信号变化并发电（电力层）
```

> ⚠️ 涂蜡铜块的角色类似**变压器**（感应耦合），不是导线。
> 这一点在 [§3.5 感应耦合与谐振链](#35-感应耦合与谐振链相邻发电机的能量路由) 中还会进一步展开——
> 变压器之间也能感应耦合，这正是谐振链分频的物理依据。

### 3.3 信号层：五种形态的拓扑能力

未涂蜡的活铜块家族在信号层工作，每种形态提供一种红石粉做不到的拓扑能力。

#### 铜块 = 电缆

全向连接同频道邻居，行为等同活红石粉，但**受锈蚀频道隔离**。
电力网络与信号网络的默认连接件。

```
     ┌──→ 邻居(同锈蚀)
     │
邻居 ←── [铜块] ──→ 邻居(同锈蚀)
     │
     └──→ 邻居(同锈蚀)
```

#### 雕文铜块 = 二极管（输入/输出双方向）

输入/输出方向独立设置，信号仅从输入方向接收、仅向输出方向转发。通过 WASD 2 键配置：第 1 键设输入方向，第 2 键设输出方向。默认输入=↓ 输出=↑（下传上）。

```
    输入=↓ 输出=↑  →  下传上（默认）
    输入=← 输出=→  →  左传右
    输入=← 输出=↑  →  左传上（拐角导通）
    输入=↓ 输出=→  →  下传右（拐角导通）
```

原版中"防止信号回流"由中继器承担，但中继器占格子且有 2 tick 延迟。
雕文铜块提供**零延迟定向导通**，且支持拐角，是 2D 布线的关键器件。

| <br /> | 活中继器     | 雕文铜块       |
| ------ | -------- | ---------- |
| 单向     | ✅        | ✅          |
| 拐角     | ❌        | ✅          |
| 延迟     | 2-8 tick | **0 tick** |
| 信号刷新   | ✅ 恢复到 15 | ✗ 继续衰减     |
| 用途     | 延迟 + 整形  | 纯防回流 + 拐角  |

#### 切制铜块 = 立交桥（Crossover）

解决 2D 网格中两路信号交叉的问题。**水平轴与垂直轴完全独立**，交叉点互不干扰。

```
    信号A ──→ ┃          ┃ ──→ 信号A（水平直通）
               ┃ 切制铜块 ┃
    信号B ──→ ┃    ╳    ┃ ──→ 信号B（垂直直通）
               ┃          ┃
              A 与 B 交叉但绝缘
```

配合锈蚀频道，这是 2D 布线的最后一块拼图：
即使同频道的两路信号也能交叉而不串扰。

> 实现提示：现有 `EdgeGrid` 将信号存在**边**上（`hEdges` / `vEdges`），
> 水平边与垂直边天然分离，切制铜块的立交桥语义可直接落地。

#### 铜格栅 = 红石→红电桥接加法器

格栅有孔 = 红石信号穿过孔洞汇入铜网络。所有输入边的红石信号**相加**，
结果向四周同锈蚀状态的铜原件输出。

```
红石信号A ──→ ┐
              ├── [铜格栅] ──→ 铜电缆（同锈蚀）
红石信号B ──→ ┘
        sumSignal = min(A + B, signalCap)
```

- **输入**：只接收红石信号（红石粉、红石块、火把等），不接收铜电缆信号
- **求和**：4条边的红石信号相加，受 signalCap 上限
- **输出**：向4方向输出到同锈蚀状态的铜原件
- **隔离**：铜→格栅方向阻断，防止铜信号回灌

用途：将红石电路的信号桥接到铜电缆网络，同时实现多路信号合并。

#### 铜灯 = 信号记忆（记录/清除）

活铜灯收到红石信号上升沿时记录该信号强度，再次收到上升沿时熄灭清除记录。
记录的信号强度可被活比较器的比较模式读取。

```
收到上升沿 → 若未记录：记录输入信号强度
           → 若已记录：熄灭清除
无输入     → 保持当前记录
```

这是 Phase 4「信息时代」的地基：信号强度存储、锁存器、寄存器全靠它。
没有记忆单元，容器内只能实现组合逻辑，无法实现时序逻辑。

#### 信号层能力对照

| 形态 | 拓扑能力       | 对应原版/电子学        |
| -- | ---------- | --------------- |
| 铜块 | 全向传导（频道隔离） | 电缆              |
| 雕文 | 输入/输出双方向   | 二极管（可拐角）       |
| 切制 | 双轴独立交叉     | 立交桥 / Crossover |
| 格栅 | 红石→红电桥接加法 | 加法器             |
| 铜灯 | 信号记忆       | 记录/清除单元         |

### 3.4 电力层：感应发电模型（五因子 + 调谐）

**设计立意**：其它模组烧资源发电，红电系统**烧脑子**发电。
玩家通过搭建精密的信号线路来提升产量，而非投入更多燃料。
设计哲学：**构造几条规则，剩下的交给涌现**——
系统里没有需要查表的硬设定，只有可推理的机制。

涂蜡铜块对周围红电信号的**变化**产生感应，从而在内部产生红电（FE）。
单次跳变产生的能量由五个**互相独立**的因子相乘决定：

```
单次跳变能量 = |Δsignal| × 相位倍率 × 共振倍率 × 形态倍率 × 规律倍率 × (P / 16)
```

- **P** = 输入波形的周期（tick）。`× P/16` 是**频率中性化**：
  快时钟跳变密、慢时钟单次多，两边打平——低周期不是捷径，而是更多的选择。
- 记账方式为**跳变即能量事件**：每次跳变直接入账电池（见 §3.10），
  对外显示用 EMA 平滑（示波器式反馈）。
- 长期平均功率 ≈ |Δsignal| × 倍率乘积 ÷ 8，与周期无关。

五个因子各管一件事，每一步都是**正向增长**（只有奖励，没有惩罚）：
幅度看信号源、相位看多路布局、共振看调谐功力、形态看选材、规律度看时钟质量。

**发电机堆叠数 = 偏好周期 = 2 × stackCount（2 ~ 128 tick）**，
是共振因子的调谐旋钮（见因子三）；**信号源堆叠数决定幅度**（信号值 = 源 stackCount²）。

#### 因子一：基础幅度（门槛）

**只有交变信号才发电**，恒定信号不发电。

```
基础幅度 = 直连幅度 + 感应幅度

直连幅度 = |signal_now - signal_prev|        （来自 edgeGrid vs prevEdgeGrid）
感应幅度 = 上游发电机经耦合分配传入的振荡幅度  （见 §3.5 感应耦合）
```

| 场景       | signal_now | signal_prev | |Δsignal| | 产出            |
| -------- | ---------- | ----------- | --------- | ------------- |
| 恒定亮的红石火把 | 4096 | 4096 | 0 | **0** — 直流不发电 |
| 中继器环形振荡器 | 4096 | 0 | 4096 | 持续产出          |
| 按钮按下     | 4096 | 0 | 4096 | 一次性脉冲         |

> 信号值在铜块网络中 = signalStackCount²，最大 4096（信号源 stackCount=64）。
> 因此 |Δsignal| 上限为 4096（信号从 4096→0），**已包含信号源 stackCount²**。

玩家的第一课：**必须搭振荡器**。最简形式是中继器环形回路，占 3-4 格，产出很低。

> ⚠️ **`signal_prev`** **必须按槽位存储，不能存在物品的 DataComponent 上。**
> 否则玩家拖动涂蜡铜块到不同信号环境的槽位就能凭空制造 Δ，形成永动机。
> 现有 `ContainerRedstoneData.prevEdgeGrid` 双缓冲已提供按槽位的历史值，直接复用即可。

#### 因子二：相位倍率（进阶）

一个涂蜡铜块可以有多路邻居输入。系统检测这些输入之间的**相位关系**——
越是错开，倍率越高（对应现实的多相交流电）。

| 输入路数 | 相位差  | 原始倍率 | 数学 | 现实对应     |
| ---- | ---- | ---- | --- | -------- |
| 1 路  | —    | ×1   | 1² | 单相脉动     |
| 2 路  | 180° | ×4   | 2² | 两相推挽     |
| 3 路  | 120° | ×9   | 3² | **三相交流** |
| 4 路  | 90°  | ×16  | 4² | 四相整流     |

> 倍率遵循平方数列（n²），让多相的回报更陡峭——从单路到双路直接翻 4 倍，
> 正反馈极强。同相输入 = ×1（等同单路，不奖励也不惩罚），**不是归零**。
> 玩家最直觉的搭法（两个相同振荡器并排）应当有产出，否则会误以为系统故障。

**这是「精密」的主要来源**：三相 120° 意味着周期 6 tick，
三路振荡器分别延迟 0 / 2 / 4 tick，需要真正理解时序才能搭出来。

#### 集群共享路数（突破 4 路物理限制）

单个涂蜡铜块最多 4 个邻居 = 4 路输入。但**相邻的同类型涂蜡铜块形成集群**
（锈蚀可混编，锈蚀差异通过耦合管径影响集群内的能量分配，见 §3.5），
集群内所有外部输入汇聚，作为一个整体计算相位倍率，突破单块 4 路上限。

**集群外部输入路数** = 2(宽 + 高)（矩形集群的周长边数）：

| 集群形状 | 块数 | 外部路数 E | 每块平均路数 |
|---------|------|----------|-----------|
| 1×1 | 1 | 4 | 4.0 |
| 1×2 | 2 | 6 | 3.0 |
| 2×2 | 4 | 8 | 2.0 |
| 1×4 | 4 | 10 | 2.5 |
| 2×4 | 8 | 12 | 1.5 |
| 4×4 | 16 | 16 | 1.0 |

集群越大，每块平均路数越少（内部连接被消耗），但**总路数更多**。

**E > 周期相数时**，多出的路与已有路同相，同时跳变，**叠加基础幅度**：

```
每相路数 = E / 周期相数
同相叠加的相对幅度 = 每相路数（以单路 |Δ| 为 1）
```

**集群衰减**：防止无限堆叠，按 √块数 衰减：

```
集群衰减 = 1 / √块数
有效功率 = 原始功率 × 集群衰减
```

**方形集群不赚**——衰减恰好抵消基础幅度增长：

```
N×N 方形: E = 4N, 每相路数 = N, 相对幅度 = N, 衰减 = 1/N
乘积 = N × (1/N) = 1  ← 恒定，与 1×1 相同
```

**长条形集群赚**——更高的周长面积比，更多外部面暴露给振荡器：

（幅度以 1 路输入的 |Δ| 为单位，相对值；满共振、满相位、满规律）

| 集群 | 块数 | E | 每相路数 | 相对幅度 | 相位倍率 | 衰减 | **相对功率** |
|------|------|---|---------|---------|--------|------|-------------|
| 1×1 | 1 | 4 | 1 | 1 | ×16 | 1.0 | **16** |
| 1×2 | 2 | 6 | 1.5 | 1.5 | ×16 | 0.707 | **17** |
| 2×2 | 4 | 8 | 2 | 2 | ×16 | 0.5 | **16** |
| 1×4 | 4 | 10 | 2.5 | 2.5 | ×16 | 0.5 | **20** |
| 1×8 | 8 | 18 | 4.5 | 4.5 | ×16 | 0.354 | **25.5** |

> 物理直觉：现实中发电机定子越细长，散热面越大；
> 紧凑的方形电机效率受限。涂蜡铜块集群同理——
> 长条形让更多面暴露给振荡器，方形则把面浪费在内部连接上。

**最优配置**（9×4 = 36 槽箱子，同周期满配对比）：

| 方案 | 集群 | 振荡器 | 总占用 | 相对功率 |
|------|------|--------|--------|----------|
| 基准 | 1×1 (1块) | 4 | 5 | 16 |
| 长条 | 1×4 (4块) | 10 | 14 | **20** |
| 长条 | 1×8 (8块) | 18 | 26 | **25.5** |
| 方形 | 2×2 (4块) | 8 | 12 | 16（不赚） |

集群共享比单块提升约 59%，增长温和，不超模。

#### 因子三：共振倍率（精通）—— 堆叠数 = 调谐旋钮

**发电机堆叠数决定偏好周期：`P_pref = 2 × stackCount`（2 ~ 128 tick，64 档连续可调）。**
往发电机堆里加减铜块，就是在物理地"旋转调谐旋钮"。
没有固定的档位表——任何周期的时钟都能找到自己的谐振点。

> 2 tick 周期依赖容器内 **1 game tick 的时间分辨率**（红石传播每 tick 执行一次）。
> 早期实现每 2 tick 才传播，最快只能到 4 tick 周期，该档位形同虚设。

匹配度用**相位角**衡量，而非 tick 数：

```
相位误差(度) = (tick误差 / 偏好周期) × 360°
效率 = (1 + cos θ) / 2
共振倍率 = 1 + 3 × 效率        // 完美匹配 ×4，完全失配 ×1
```

#### 调谐敏感性（自然涌现）

同样差 1 tick，在不同偏好周期下的严重程度天差地别：

| 偏好周期    | 差 1 tick 的相位误差 | 效率                  |
| ------- | -------------- | ------------------- |
| 128 tick | 2.8°          | **~100%** — 几乎无感    |
| 16 tick | 22.5°          | **96%** — 几乎无感      |
| 8 tick  | 45°            | 85% — 轻微惩罚          |
| 4 tick  | 90°            | 50% — 腰斩            |
| 2 tick  | **180°**       | **0%** — 完全失效（信号反相） |

从 `(1+cosθ)/2` 这一个公式自然长出来：
新手把发电机堆到 64 叠（偏好周期 128t）随便对齐都能发电；
想玩 2 tick 高频时，必须精确到单 tick。

#### 频率中性化（没有捷径）

配合记账规则 `单次跳变能量 × (P/16)`，平均功率对周期中性：
2t 时钟跳得密、128t 时钟单次多，两边打平。
**低周期不是捷径，而是更多的选择**——
频率选择完全由「你造得出什么时钟」和「匹配得多准」决定。

#### 相数上限（第二重取舍）

整数 tick 偏移决定了周期能容纳的最大相数（最多 P 相）：

| 偏好周期    | 最大相数 | 原因                  |
| ------- | ---- | ------------------- |
| 2 tick  | 2 相  | 只有 tick 0/1 两个可区分位置 |
| 4 tick  | 4 相  | <br />              |
| 8 tick  | 8 相  | <br />              |
| 16 tick | 16 相 | 但槽位不够放              |

**高频物理上做不了多相**。于是形成真正的取舍：

- **高频少相** — 省槽位，零容错，适合老手
- **低频多相** — 容错高，但要塞满整个容器
- **中频中相** — 需要计算才知道哪个划算

没有唯一最优解。这个取舍不是人为设定的，而是从"整数 tick"这一约束推导出来的。

#### 因子四：形态倍率

涂蜡后，基础形态决定**感应模式**：

| 涂蜡变种     | 感应模式        | 倍率    | 定位             |
| -------- | ----------- | ----- | -------------- |
| 涂蜡**铜块** | 四邻居全向拾取     | ×1    | 通用发电机，入门首选     |
| 涂蜡**雕文** | 水平/垂直两轴独立读取 | ×1.5  | **天生的两相发电机**   |
| 涂蜡**切制** | 只沿条纹方向读取    | ×2    | 抗干扰，垂直方向噪声进不来  |
| 涂蜡**格栅** | 带频率选择性      | ×3\~4 | **共振器**，要求精确匹配 |

每个变种都有不可替代的用途，不是单纯的数值差异。

#### 因子互斥约束

五个因子并非全部可以同时取到最大值，存在以下互斥：

**相位 × 共振**：整数 tick 约束下，偏好周期 P 最多 P 相；
高频（小 P）做不了多相，多相只能在中低频实现。

> 集群共享路数可突破单块 4 路上限（见上方「集群共享路数」章节），
> 但受 √块数 衰减约束，长条形集群最优，方形集群不赚。

**相位 × 形态**：形态的感应方向数限制了输入路数。

| 形态 | 最大感应方向 | 最大相数 | 原始形态 | 原始相位 | 乘积 |
|------|------------|---------|---------|---------|------|
| 铜块 | 4 | 4 相 | ×1 | ×16 | 16 |
| 雕文 | 2 | 2 相 | ×1.5 | ×4 | 6 |
| 切制 | 1 | 1 相 | ×2 | ×1 | 2 |
| 格栅 | 待定 | 待定 | ×3~4 | 待定 | — |

切制铜块 ×2 × 1 相 = 2，不如铜块 ×1 × 2 相 = 4。
切制不是"比铜块更强的发电机"，而是"抗干扰的单相发电机"——
旁边有噪声信号时，切制只读条纹方向，把噪声排除在外。

**感应 × 相位**：感应传入的是单路波形，下游相位倍率只有 ×1。
想同时吃感应转移和多相，必须额外搭直连输入，但槽位有限。

**实际选择**：没有唯一最优解，每种流派有各自的适用场景：

| 流派 | 形态 | 相位 | 共振 | 乘积 | 适合 |
|------|------|------|------|------|------|
| 极简 | 铜块 | 1 路 | ×4 | 4 | 新手 |
| 双相 | 铜块 | 2 路 | ×4 | 16 | 进阶 |
| 双相雕文 | 雕文 | 2 路 | ×4 | 24 | 进阶优化 |
| 四相 | 铜块 | 4 路 | ×4 | 64 | 高手 |
| 集群长条 | 铜块1×4 | 10路共享 | ×4 | 100+ | 高手规模化 |
| 抗干扰 | 切制 | 1 路 | ×4 | 8 | 布线紧张时 |
| 感应链 | 铜块 | 感应(1路) | ×4 | 4 | 省槽位 |

#### 因子五：规律度（波形质量）

**混乱的跳变不算数，有规律的波形才发得好电。** 这是「烧脑子」立意的收口：
把杂乱脉冲整流成稳定时钟，本身就该有回报。

```
规律度 r = 周期自一致率
        = 最近两个周期窗口逐 tick 对比的重合度（信号数值级，非 0/1）
规律倍率 = 1 + r          （×1 混乱波形 ~ ×2 完美周期）
```

涌现效果（可预言）：

- 手搓按钮乱按 → 无周期 → ×1；稳定时钟 → ×2：电厂需要专业「时钟房」
- 两路不同周期混进同一根线 → 复合波形不再重复 → 规律度崩掉：
  **信号层的布线纪律（频道隔离/立交桥）直接变成发电收益**
- 谐振链下游周期改变但依然规律 → 规律度沿链保真传递（变压器不失真）
- 比较器读熔炉/漏斗产生的周期信号，节奏稳定即可吃满规律倍率：**工厂节奏即发电机**

> 实现注：检测为**事件驱动**——周期 = 同向跳变间隔，规律度 = 最近几次间隔的一致性，
> 均为 O(1) 增量更新，无密集历史环（见 §3.8）。

#### 玩家成长路径

| 阶段  | 关注因子        | 典型行为                   |
| --- | ----------- | ---------------------- |
| 入门  | 基础幅度        | 搭出第一个振荡器，发现恒定信号不发电     |
| 进阶  | 相位倍率        | 搭两路 180°，再挑战三路 120°    |
| 精通  | 共振倍率        | 增减发电机堆叠调谐，让偏好周期精确对上时钟  |
| 优化  | 形态倍率        | 从涂蜡铜块换到涂蜡格栅，接受更严格的匹配要求 |
| 波形  | **规律度**     | 把杂乱脉冲整流成稳定时钟，布线纪律开始值钱  |
| 布局  | **感应耦合**    | 发现谐振链配方与混合锈蚀的能量路由（见 §3.5） |
| 集群化 | **集群共享路数**  | 把涂蜡铜块排成长条，共享外部输入突破 4 路上限 |

#### 设计原则：让玩家「算」，不让玩家「查」

| 机制            | 判定   | 理由                       |
| ------------- | ---- | ------------------------ |
| 相位差 120°      | ✅ 采纳 | 玩家能算：周期 6，延迟 0/2/4       |
| 共振匹配偏好周期      | ✅ 采纳 | 玩家能算：周期 6 的时钟，堆 3 叠恰好谐振  |
| 感应耦合按锈蚀衰减     | ✅ 采纳 | 玩家能算：深一档管径更细，份额更少        |
| 谐振链 2:4:8:16  | ✅ 采纳 | 玩家能记：堆叠数翻倍排开就是分频链        |
| 谐振频率 = 电路铜块总数 | ❌ 否决 | 多铺一根电缆就破坏谐振，不可预测         |
| 起振时间 / Q 值    | ❌ 否决 | 不可观测，且拉长调试反馈周期           |
| 阻抗匹配          | ❌ 否决 | 用电侧是外部模组机器，玩家只能查表        |

### 3.5 感应耦合与谐振链：相邻发电机的能量路由

涂蜡铜块是绝缘的，发电机之间传的**不是信号，而是感应耦合**——
上游的振荡按耦合强度分配给相邻发电机，现实中的变压器/谐振腔正是如此。
这是电力层最主要的进阶技巧：**锈蚀是路由材料，布局即电路**。

#### 耦合强度 = 锈蚀档位（管径）

```
未锈蚀 c=1.0 ＞ 斑驳 c≈0.7 ＞ 风化 c≈0.5 ＞ 氧化 c≈0.35
```

**分叉守恒（加权版）**：上游辐射的能量在所有下游之间按耦合权重分配：

```
下游 i 分到的感应幅度 = 上游幅度 × c_i / Σ c_j      （总量守恒）
```

例：A（|Δ|=4096）的下游为 B（未锈蚀 1.0）与 C（氧化 0.35）：
B 分到 4096×1.0/1.35 = 3034，C 分到 4096×0.35/1.35 = 1062，总量仍 4096。
**摆放什么锈蚀的邻居 = 调节能量往哪边倒**：

- 未锈蚀 = 粗管：全力传动（链式传输的主力）
- 氧化 = 细管：隔离、节流、终端封口
- 深锈蚀**不是更差的块**——注意耦合只影响发电机之间的转移，
  每台发电机靠自己直连信号产生的发电量完全不受锈蚀影响；
  配合频率中性化，锈蚀档位与产量高低完全脱钩。

#### 谐振再发射：下游以自身偏好周期转发

下游发电机把感应到的振荡**以自己的偏好周期再发射**（谐振腔行为，不是无源转发）。
于是「堆叠 1 / 2 / 4 / 8 的发电机排成一列」就构成一条 2:1 逐级分频的**谐振链**：

```
[2t 振荡器] → [堆叠1(2t)] → [堆叠2(4t)] → [堆叠4(8t)] → [堆叠8(16t)]
                ✅共振       ✅共振        ✅共振        ✅共振
```

一个振荡器 + 一列调好堆叠的发电机 = 全部完美共振。
**旧的「锈蚀阶梯」没有消失，而是从硬设定变成了玩家可发现的配方。**

#### 防环与防扇出（结构性，非补丁）

- **无环**：感应幅度只来自上游的**直连 |Δ|**，每 tick 一次单向分配
  （先算完所有直连，再统一分配，见 §3.10），不存在再辐射放大回路；
- **无扇出刷电**：加权守恒保证上游辐射总量恒等于其幅度，
  下游越多每份越少，堆砌铜块无利可图。

> 这与 [§3.14 活避雷针](#314-活避雷针红电波频道) 的供需分配是**同一个模型**：
> 有限的供给在多个需求之间按比例分配。玩家不需要切换心智模型。

#### 涌现的两条流派

| <br />   | 谐振链                     | 独立驱动             |
| ------- | ------------------------ | ---------------- |
| 布局      | 1 振荡器 + 一列调谐发电机          | 每台自配振荡器          |
| 相对产出    | 逐级共振、全链满配                | 各自满配             |
| 故障模式    | 振荡器一停，**整链全停**           | 坏一个不影响其它         |
| 定位      | 前期省槽位，中期主力               | 后期规模化            |

取舍点在**槽位总量**与**单点故障风险**，而不是简单的数值高低。
前期槽位紧张时谐振链明显更划算。

#### 与相位倍率的交互

感应传入的是**单路波形**，所以下游的相位倍率只有 ×1。
想同时吃到感应转移与多相加成，必须在链外**额外接入直连输入**：

```
[2t 振荡器 A] ──→ [堆叠1] ──感应──→ [堆叠2] ←── [4t 振荡器 B]
                                    ↑
                              两路输入，可吃相位倍率
```

感应与多相**可以叠加**，但要额外花槽位。
于是「省槽位的感应链」和「费槽位的多相」构成一个连续的权衡空间，
而不是二选一。

### 3.6 储能：涂蜡铜灯 = 电池

**涂蜡铜块专职发电，涂蜡铜灯专职储能**，职责分离。

铜灯是容器形状（装东西）且原版自带状态保持语义，作为电池最贴切。
锈蚀四档对应容量四档：

| 涂蜡铜灯 | 容量       | 放电率      | 角色           |
| ---- | -------- | -------- | ------------ |
| 未锈蚀  | 160 FE   | 10 FE/t  | 去耦电容（平滑瞬态波动） |
| 斑驳   | 640 FE   | 5 FE/t   | 缓冲电容（脉冲展宽）   |
| 风化   | 2560 FE  | 2 FE/t   | 深循环电池（持续供电）  |
| 氧化   | 10240 FE | 0.5 FE/t | UPS 电池（应急后备） |

```
有剩余功率时充电：energy += surplus（不超过容量上限）
功率不足时放电：  energy -= deficit（不低于 0）
```

储能不分频道——所有涂蜡铜灯共同构成容器的单一电池组，
容量与放电率各自累加。锈蚀在此只决定这块铜灯的**规格**，
与信号层的频道、发电层的频率都无关。

> 铜灯的锈蚀是第三种含义（容量档位）。这是三处含义中唯一没有物理类比的，
> 但因为铜灯本身就是独立部件（专职储能，不参与信号也不发电），
> 玩家不会把它和另外两处混淆。

### 3.7 完整物品矩阵

| 形态     | 未涂蜡（信号层）       | 涂蜡（电力层）     |
| ------ | -------------- | ----------- |
| **铜块** | 电缆，全向传导        | 通用发电机 ×1    |
| **雕文** | 二极管，输入/输出双方向  | 两相发电机 ×1.5  |
| **切制** | 立交桥，双轴绝缘       | 抗干扰发电机 ×2   |
| **格栅** | 红石→红电桥接加法器     | 共振发电机 ×3\~4 |
| **铜灯** | 信号记忆，记录/清除    | 电池          |

× 4 档锈蚀 = 4 条独立频道（信号层）/ 4 档耦合管径（电力层）

> 铜门 / 铜活门暂不设计，留待后期作为「信号闸门 = 晶体管」。

#### 锈蚀在两层的含义

锈蚀在信号层是「频道隔离」，在电力层是「耦合管径」。
两层都是「第几档」，但一个管**跟谁连**，一个管**传多少能量**。

之所以能这样分工：涂蜡铜块本来就不导通，「频道」对它没有意义，
档位自然腾出来表达别的东西。谐振点的选择交给了堆叠数调谐（§3.4 因子三），
分频关系由谐振链配方涌现（§3.5）。

### 3.8 核心数据结构（事件驱动）

```java
public class ContainerPowerData {
    /** 容器总功率(FE/t)，EMA 平滑，即对外(IEnergyStorage/避雷针)读数 */
    double totalPower;

    /** 储能(FE)，由涂蜡铜灯提供容量 */
    int storedEnergy;

    /**
     * 每台发电机每路的跳变事件历史（时间戳 + 幅度，最近 ~8 次）。
     * 周期 = 同向跳变间隔；规律度 = 间隔一致性；相位 = 各路事件时间差。
     * 全部 O(1) 增量更新，事件驱动，无密集历史环。
     */
    Map<Integer, PathEventHistory> eventHistory;

    /**
     * 每台发电机本 tick 的辐射幅度，供感应耦合的下游读取。
     * 先算所有直连幅度，再统一单向分配，一次遍历完成，无环无迭代。
     */
    Map<Integer, Integer> radiateAmplitude;
}
```

> **为什么没有「电力总线」**：电力由信号变化就地产生，
> 直接计入容器总量，不需要像其它模组那样铺线缆——
> 信号本身的传输已经很完善，传输电力用传输信号代替即可。
> 跨容器输电由 [§3.14 活避雷针](#314-活避雷针红电波频道) 负责。

与 `ContainerFluidData`、`ContainerStressData`、`ContainerRedstoneData` 并列，
作为容器级数据在 `TickContext` 中持有。

#### 检测的实现要点（事件驱动，O(1) 增量）

```
每 tick：对每台发电机的 4 路，比较 edgeGrid vs prevEdgeGrid（|Δ| 本来就要算）
  → 无跳变：什么都不做（稳态开销 = 几次整数比较）
  → 有跳变：记录事件，O(1) 更新周期估计（同向跳变间隔）、
    规律度（最近几次间隔的一致性）、相位（各路事件时间差）
```

**为什么不用固定深度历史环**：偏好周期可达 128t，
密集环形缓冲需要 256 深才能比较相邻两个周期；
事件驱动只存最近几次跳变的时间戳，周期多长都不怕，
代价仅为低频时钟需要 2~3 个周期建立评级（玩法侧的「起振观测期」）。

`signal_prev` 不额外存储——直接复用 `ContainerRedstoneData.prevEdgeGrid`：

```java
// ContainerRedstoneData 已有双缓冲，暴露一个读取方法即可
public int getPrevSignal(int slot) {
    return prevEdgeGrid == null ? 0 : prevEdgeGrid.maxOfSlot(slot);
}
```

### 3.10 Tick 流程（事件驱动）

```
processContext() 每 tick（在红石传播之后，priority = 3）：

1. 清零 radiateAmplitude

2. 直连检测（每台发电机）：
   a. 按形态确定要读取的邻居方向集合
   b. 对每路比较 edgeGrid vs prevEdgeGrid
      → 无变化：仅 O(1) 跳过
      → 有跳变：|Δ| = 直连幅度；记录事件，
        O(1) 更新周期估计 / 规律度 / 相位评级

3. 感应分配（每台发电机，单趟两阶段）：
   上游辐射总幅度 = 本块直连幅度
   各下游分到 = 辐射幅度 × c_i / Σ c_j（加权守恒，锈蚀 = 耦合管径）
   下游把感应输入并入本 tick 判断（先直连后分配，无环无迭代）

4. 能量入账（仅跳变帧）：
   能量 = |Δ| × 相位 × 共振 × 形态 × 规律 × (P / 16)
   → storedEnergy += 能量（电池容量上限内）

5. EMA 更新 totalPower（对外显示与读数）

6. 涂蜡铜灯充放电：
   surplus > 0 → storedEnergy += min(surplus, 剩余容量)
   deficit > 0 → storedEnergy -= min(deficit, 放电率)

7. IEnergyStorage 输出（剩余功率输出给科技模组）

8. 活避雷针供需分配（见 §3.14）：
   a. 收集阶段：遍历所有容器，累加各频道的 supply 与 demand
   b. 分配阶段：各输出端按 min(1, supply/demand) 比例获得功率
```

**总复杂度**：O(槽位数) 稳态 + O(事件数) 跳变帧。
稳态 = 每台发电机 4 次整数比较（亚微秒级）；检测与入账只在跳变帧发生，
且均为 O(1) 增量操作。低频发电机（最长 128t 周期）每 2~3 个周期才建立一次评级。

> ⚠️ **`getPriority()`** **必须 > 红石的 2**（红石与红石火把均为 2），
> 因为电力计算依赖红石已算完的 `edgeGrid`。当前占用：
> 水桶 0、水车 1、红石 2 → **电力用 3**。

> ⚠️ **感应分配必须先算完所有直连、再统一分配**（单趟两阶段），
> 不能边算边读下游的中间值，否则会引入遍历顺序依赖。

### 3.14 活避雷针（红电波频道）

活避雷针是电力系统从**局域**走向**全局**的关键。
涂蜡铜块管容器内发电，活避雷针管跨容器输电。

```
局域：活红石振荡 → 铜块信号网络 → 涂蜡铜块发电 → totalPower → IEnergyStorage
全局：totalPower → 活避雷针 → 红电波频道 → 活避雷针 → 其它容器
```

#### 物品

活避雷针只有一种，没有氧化/涂蜡变体。
堆叠数 = 频道，64个独立频道。

#### 方向性 I/O

活避雷针一头大（输入端）一头小（输出端），参考活漏斗的方向性设计。
4 个朝向（上下左右）+ 输入/输出分离，在 2D 网格中实现灵活拓扑：

```
        输入端(大头)
          ↑
    ┌─────┴─────┐
    │ 活避雷针   │  ← 朝向 = 上（输入在上，输出在下）
    └─────┬─────┘
          ↓
        输出端(小头)

4 种朝向：
  上：输入=上邻居，输出=下邻居
  下：输入=下邻居，输出=上邻居
  左：输入=左邻居，输出=右邻居
  右：输入=右邻居，输出=左邻居
```

右键旋转朝向。

#### 供需分配模型（能量守恒）

活避雷针按朝向区分**输入端**（供给）和**输出端**（需求），
采用标准电网供需模型，保证能量守恒。

```
channelSupply[频道] = Σ(所有输入端贡献的功率)
channelDemand[频道] = Σ(所有输出端请求的功率)

每个输出端实际获得 = request × min(1, supply / demand)
```

```
频道 5：
  容器A：铜块总线(100 FE/t) → 避雷针输入端 → supply += 100
  容器B：铜块总线(50 FE/t)  → 避雷针输入端 → supply += 50
  supply = 150

  容器C：避雷针输出端 → request 200 → demand += 200
  容器D：避雷针输出端 → request 100 → demand += 100
  demand = 300

  分配比例 = min(1, 150/300) = 0.5
  容器C 获得 200 × 0.5 = 100
  容器D 获得 100 × 0.5 = 50
  总输出 150 = 总输入 150   ✅ 守恒
```

> ⚠️ **为什么不用「共振 + 净值扣除」**
>
> 早期方案是「频道共振总和广播给每个避雷针，扣除自身贡献」。
> 该模型能挡住单容器自环，但**两个容器可以互相刷**：
>
> ```
> 容器A 贡献 100，容器B 贡献 100，共振 = 200
> 容器A 获得 200 - 100 = 100（拿到 B 的）
> 容器B 获得 200 - 100 = 100（拿到 A 的）
> 总输入 200 → 总输出 400，能量翻倍
> ```
>
> N 个容器互联时按 N×(N-1) 放大，10 个容器就是 90 倍。
> 「共振」概念上很浪漫，但**能量守恒是硬约束**。
> 现改为供需分配，保留跨维度无衰减的特性，玩家感知不到区别。
>
> 该思路与 `EnderChannelRegistry` 的轮询公平调度一致——
> 同样是多对多的资源分配问题。

#### 四种拓扑模式

| 模式       | 输入接铜块 | 输出接铜块 | 效果                |
| -------- | ----- | ----- | ----------------- |
| **纯供给**  | ✅     | ✗     | 只向频道供电（发电站）       |
| **纯需求**  | ✗     | ✅     | 只从频道取电（用电端）       |
| **双向桥接** | ✅     | ✅     | 同时供给与需求，可用于频道间转运  |
| **空闲**   | ✗     | ✗     | 不参与分配             |

#### 与容器电力的关系

避雷针不绑定锈蚀档位——它的输入端从**容器的 `totalPower`** 取电注入红电波频道，
输出端从频道取电补充**容器的 `storedEnergy`**：

```
容器A: 涂蜡铜块发电 → totalPower → 避雷针(输入) → 红电波频道 5
                                                      ↓
容器B: storedEnergy ← 避雷针(输出) ←──────────────────┘
```

避雷针的频道由**堆叠数**决定（1~64 共 64 个独立频道），与锈蚀无关。
一个避雷针可以是纯供给、纯需求，或两端都接以实现频道间转运。

> 早期设计里避雷针在「4 条电力总线」之间桥接。
> 现在电力就地产生并汇总为单一 `totalPower`，容器内已无总线可桥，
> 避雷针的唯一职责就是**跨容器输电**。这比原设计更简单，玩家也更好理解：
> 「容器内不需要电线，容器间用避雷针」。

#### 跨维度无衰减

红电波是概念频道，不分维度。主世界的频道 5 和下界的频道 5 是同一个频道，状态完全同步。

#### 全局注册表

```java
public class RedElectricWaveRegistry {
    /** 频道 → 本 tick 的供给总量(FE/t) */
    Int2IntMap channelSupply;

    /** 频道 → 本 tick 的需求总量(FE/t) */
    Int2IntMap channelDemand;
}
```

> ⚠️ **必须在** **`ServerStoppedEvent`** **中清空**。
> 这是进程级静态表，单人游戏「退出存档 → 进入另一个存档」不会重启 JVM，
> 不清理会把上一个世界的频道状态带入新世界。
> 参考 [LivingItem.onServerStopped](../src/main/java/com/qiqi/li/LivingItem.java) 的现有处理。

#### 每 tick 流程

```
1. 清零 channelSupply[1..64] 和 channelDemand[1..64]

2. 收集阶段：遍历所有容器中所有活避雷针
   → 输入端有铜块？ channelSupply[频道] += 该铜块所属总线功率
   → 输出端有铜块？ channelDemand[频道] += 该铜块所属总线的需求量

3. 分配阶段：遍历所有容器中所有活避雷针
   → 输出端有铜块？
   → ratio = min(1.0, channelSupply[频道] / channelDemand[频道])
   → 注入功率 = 该端 request × ratio

4. 扣减供给侧：各输入端按同一 ratio 实际输出，未被消耗的功率留在本地总线
```

**复杂度**：O(全局避雷针数)，通常 < 100，每 tick 两趟遍历。

#### 典型应用

```
1. 跨容器输电：
   容器A：活红石振荡 → 铜块A → 避雷针(stack=8, 朝右) → 频道8
   容器B：频道8 → 避雷针(stack=8, 朝左) → 铜块A → IEnergyStorage

2. 跨维度供电：
   主世界：发电机 → 铜块A → 避雷针(stack=1) → 频道1
   地狱：频道1 → 避雷针(stack=1) → 铜块A → 用电

3. 多频道分工：
   频道1：低功率控制信号
   频道8：主电源
   频道16：辅助电源

4. 跨频道桥接：
   铜块(未锈蚀) → 避雷针(输入) → 红电波频道 → 避雷针(输出) → 铜块(斑驳)
   实现未锈蚀总线和斑驳总线的功率互通
```

#### 与 EnderChannelRegistry 的关系

红电波频道和末影珍珠频道是两套独立系统：

| <br /> | 末影珍珠频道 | 红电波频道    |
| ------ | ------ | -------- |
| 传输内容   | 物品/实体  | 功率(FE/t) |
| 频道数    | 按珍珠ID  | 64（堆叠数）  |
| 跨维度    | ✅      | ✅（无衰减）   |
| 模型     | 发布/订阅  | **供需分配** |

  里程碑：活红石与执行端联动，容器内实现完整自动化流水线
```

**总预估：13-19 周**

## 6. 技术风险与应对

| 风险                   | 影响                       | 应对                                  |
| -------------------- | ------------------------ | ----------------------------------- |
| 信号传播性能（BFS 每 tick）   | 大量活红石粉时可能卡顿              | 已做槽位位图去装箱（实测满载 54 格约 4.9μs）；如仍不足可加脏标记 |
| 递归 tick（活潜影箱嵌套）      | 深层嵌套性能爆炸                 | 最大嵌套深度 4 层 + 脏标记缓存                  |
| **拖动发电机刷电**          | 移动涂蜡铜块凭空产生 Δ = 永动机       | `prev` **按槽位存储**，不存物品 DataComponent |
| **感应成环刷电**           | 若发电机互相感应可闭环自激放大          | 单向分配：先算完所有直连再统一分配，无再辐射回路        |
| **感应扇出刷电**           | 一块带 N 个下游若各给满则总量放大 N 倍   | 加权守恒：按 c_i/Σc_j 分配，辐射总量恒等于上游幅度  |
| **低周期无脑最优**          | 快时钟跳变密导致平均功率碾压慢时钟        | 频率中性化：单次跳变能量 ×(P/16)，平均功率与周期无关  |
| **多容器共谋刷电**          | 共振模型下 N 容器互联放大 N×(N-1) 倍 | 改用**供需分配模型**，保证能量守恒                 |
| 检测性能                 | 每台发电机多路波形分析              | 事件驱动 O(1) 增量更新，稳态仅整数比较              |
| 低频调谐反馈慢             | 128t 周期需 2~3 周期才建立评级     | 玩法侧「起振观测期」，tooltip 显示检测进度            |
| 科技模组兼容性              | 不同模组能量单位不同               | 统一通过 NeoForge IEnergyStorage        |
| 静态表跨存档残留             | 频道状态带入新世界                | `ServerStoppedEvent` 统一清理           |
| 信号穿透衰减               | 深层嵌套信号为 0                | 活中继器刷新 / 边界穿透不衰减                    |
