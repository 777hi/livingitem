**`FilterData` 是唯一的跨领域数据类型**——它被活漏斗、活末影箱、活箱子、传输基础设施 4 个领域引用。

但仔细看引用关系：

```
FilterData 的使用者：
  ├── domain/hopper/     ← 活漏斗（过滤链构建 + 传输过滤）
  ├── domain/ender/      ← 活末影箱（路由过滤）
  ├── domain/chest/      ← 活箱子（Accessor 过滤）
  ├── transfer/          ← FilteredSlotAccessor, SlotAccessorFactory
  └── container/         ← CrossContainerTransfer, ContainerSnapshot
```

`FilterData` 本质上是**传输基础设施的一部分**——它定义了"什么物品可以被传输"的规则，被 `FilteredSlotAccessor` 使用。活漏斗、活末影箱、活箱子都只是**配置**了 FilterData，不是**定义**了它。

所以 `FilterData` 应该去 **`transfer/`**——和 `FilteredSlotAccessor` 在一起。

## 为什么 `FilterData` 去 `transfer/` 而不是 `data/`？

```
判断标准：这个数据类型属于谁？

FilterData 的语义："传输过滤规则"
  - 它不描述活漏斗的状态（LivingHopperData 才是）
  - 它不描述活末影箱的状态（LivingEnderChestData 才是）
  - 它描述的是"一次传输操作中，什么物品可以通过"
  - 它的唯一消费者是 FilteredSlotAccessor（传输基础设施）

所以 FilterData 是传输领域的概念，不是某个活物品的概念。
```

## `LivingItemManager` 怎么办？

迁入后 import 变成：

```java
// 之前
import com.qiqi.li.living.data.LivingHopperData;

// 之后
import com.qiqi.li.living.domain.hopper.LivingHopperData;
```

路径变长了，但 `LivingItemManager` 本身就是跨领域的注册中心，引用各领域的 Data 类型是合理的。如果觉得路径太长，可以在 `api/` 里加一个 `DataComponentTypes` 常量类集中暴露所有 DataComponent 类型引用，但这是锦上添花，不是必须的。
