# 活地狱门（Living Nether Portal）技术文档

> 适用：Minecraft 1.21.1 + NeoForge 21.1.x。
> 核心代码与自动守卫已接入，用户实测功能逻辑基本正常；创造模式玩家背包显示修复及活黑曜石图标仍待复测，其他未逐项验收边界见 §5。

## §0 玩法定义

**语义**：活地狱门是**容器级组合结构玩法**。活黑曜石提供边界，活打火石提供点火，独立门面属于容器；不是每块黑曜石携带的功能。

**获取**：将黑曜石和打火石活化。门面由活黑曜石在同一真实容器网格中围闭后点燃，没有单独的传送门物品。

**核心循环**：摆出四邻封闭区域 → 活打火石右键内部空槽 → 紫色动态半透明门面 → 空光标右键传玩家 / 普通货物进入门面自动交接 → 破坏条件触发熄灭 → 清障后重新点火。

**规则**（违反即 bug）：

| 编号 | 规则 | 守卫/判据 |
|---|---|---|
| P1 | 四邻围闭支持四块围一槽、非矩形、多门及共享边；容器外沿不算墙，不跨真实容器拼门 | `PortalStructureTest` |
| P2 | 候选区域全部无物品、无任何实际流体或即时源，且有可用位置才允许点火 | `PortalStructureTest`、`LivingPortalFunctionTest`；GUI见 §5 |
| P3 | 点火成功才建立门面；未点火结构不自动亮，重复点亮不重复扣损耗 | `PortalInteractHandlers`；真实光标/耐久见 §5 |
| P4 | 必要边界失效、区域内任何活物品或活流体出现，整扇对应门熄灭；无可用位置也熄灭 | `LivingPortalFunctionTest`、`PortalStructureTest` |
| P5 | 灭门只删门面及点燃状态，保留槽内物品和流体；修复结构/位置或重开配置不自动复燃，不自动扩大、合并或拆分门 | `LivingPortalFunctionTest`、`PortalDataMigrationTest` |
| P6 | 门用自身真实位置；物品形态仅在 `host_anchor.portal` 允许时借真实外层宿主位置，不使用操作者/viewer兜底 | `PortalPositionResolverTest`、`SophisticatedBackpackSourceTest` |
| P7 | 空光标右键有效门面即时尝试主世界↔下界传送，不消耗珍珠，保留官方门户权限/冷却 | `PortalPlayerTeleportTest`；真实出口见 §5 |
| P8 | 非活化普通货物每门面槽每次容器tick交接一批；数量与组件按真实扣量，活物品不作货物 | `PortalItemTransferTest`、`LivingPortalFunctionTest` |
| P9 | 源世界掉落物注册成功即交给原版；随后过门被拒可留源世界，不按null/removed或合并回填库存 | `PortalItemTransferTest`；官方注册取消边界见 §3 |
| P10 | 点燃状态按容器保存；背包借谁的位置不改变自己的UUID归属；卸载暂停不等于无位置，回填先验状态 | `PortalDataAccessTest`、`PortalDataMigrationTest` |

**边界**：不建立容器门配对或世界门反向搜索容器门；不添加跨世界事务、自动补货、持续重试、额外燃料或随机坏门。仅主世界/下界点火与传送；骑乘准入沿官方 `canUsePortal(false)`，没有独立载具兼容层。

**能力清单**：✅ 自由围闭与脆弱维护 · ✅ 点火/玩家GUI交互代码 · ✅ 容器持久化与交接 · ✅ 宿主位置配置消费 · ✅ 原版掉落物过门接入 · ✅ 动态门户纹理覆盖 · ✅ 权威菜单映射与空快照。✅ 表示已接代码，不替代 §5 游戏内验收。

**实现入口**：`living/domain/portal/`，注册 `PortalRegistration`；客户端 `ContainerPortalOverlay` / `PortalMenuSlots`。查询源码用 `python tools/gen_code_map.py --query LivingPortalFunction`，不维护文件清单。

## 1. 构造、维护与反馈

围闭从点火目标沿四邻搜索。`ContainerContext.resolveNeighbor` 的 -1 是外泄，不是跳过；普通物品不充当框。各已点燃区域保存逻辑槽集合和布局宽度，布局或边界失效整区域删除。框材仅认活黑曜石占位，不记录物品身份，不按 count 增加门数/吞吐。

门面与物品是不同层：普通货物可共存，活物品和活流体触发灭门。流体判据由 `FluidPresence` 与 `FluidSourceLedger` 联合提供，包含刚倒桶尚未进入实际flow表的源。GUI点火/使用同样重验，倒桶动作完成后维护已有门；不让视觉同步延迟成为可趁机传送的窗口。

`LivingPortalFunction` 不匹配单件物品，使用静态自维持与 `HasContainerData`，priority=4，在流体/其他容器数据之后维护。先校验并清失效门，再处理剩余有效门面的实际货物。没有框材也能清失效状态。各货物提交前再次维护并重取位置，不使用初始旧来源点授权后续槽。

门面绘制使用 NeoForge Foreground事件、原版block atlas `block/nether_portal` 动态sprite，18px槽面拼接、透明度0.55。位姿重置后Z=400，遵循已有自绘叠加层约束。动画本地推进，门范围/存在是服务端权威。完整视觉、数量可辨与资源包重载待实机。

活黑曜石使用现有活物品方块图标样式：专用GUI平面模型、原版黑曜石材质；不增加框材功能或状态，普通及非GUI回退沿图标系统。

**玩家背包重开同步约束**：门面非空时沿活流体模式每tick向查看者下发快照，不以相同包去重。客户端关界面会清缓存，单独重开玩家背包没有可靠Open事件，不能依赖门状态变化才能恢复画面。正常tick只在写回阶段同步一次；点火、倒桶后及Open的即时同步保留。空门仍廉价返回，灭门只发必要空包，菜单/容器映射和创造目录过滤不变。

此次修复针对确定的缓存恢复缺口；未认定创造界面不发Foreground或虚拟菜单ID为1（已查源码均不支持这些前提）。创造背包是否完全恢复显示仍需复测。

## 2. 位置、保存与GUI身份

自身 `getAnchor()` 优先；否则 `portalUsesHostAnchor()` 开启才读取 `getHostAnchor()`。方块取中心，实体/玩家取实际当前位置与世界；无有效 `ServerLevel+Vec3` 不允许点火/传送，权威维护清门。此开关默认false，只控制物品形态借位，不限制本来有位置的方块/实体。

玩家物品栏自身的玩家位置与“活背包内部借玩家位置”不同：后者需要配置。末影箱内容没有唯一世界位置，不使用其owner位置兜底。

门数据走类型化key `portal`、共同热store、UUID SavedData或宿主附件；Player自身库存使用按容器键保存的附件。无UUID内容保留容器迁移独立物品快照，有UUID移交身份；双箱拆半清旧双箱门key，防立即补箱复燃，其他领域值不受影响。

GUI复用 `ItemFormContainers.Source` 的明确菜单context入口。当前精妙顶层Item/AnotherPlayer来源通过官方context类型、真实owner inventory唯一UUID及实际槽核验后提供宿主。所有子来源仅安全隔离：不以父BE冒充自身、不穿透多层借最外层位置，暂无宿主证明时拒绝门交互。顶层Block继续走真实BE。

`isItemContentMenu` 独立于Handle成功与否，防UUID/handler失效时回落错误父容器。旧Handle兼容仍在原末端，外来GUI不会用玩家唯一背包猜宿主。

**尚未承诺的范围**：活背包在方块/实体外层tick时可借真实宿主；但其子菜单真实位置反查当前未完整开放，因此不能把“内部tick有锚点”等同“任意子菜单可点火/使用”。见 §5。

交互包的门action携带原菜单ID与双槽号，不回退同号异库存。创造模式仅真实inventory wrapper参与，不把分类/搜索目录或销毁槽当门槽。服务端重验门面，不以内容相同证明槽身份。

快照按菜单ID、容器key和菜单槽→逻辑槽映射发送。显示与命中同源；失效映射、关菜单、灭门清空旧快照，不让幽灵门持续吞右键。客户端不会解析服务器空间几何猜owner。

## 3. 货物与玩家传送边界

### 3.1 货物

每槽每次处理上限 `min(99, 货物正常最大堆叠数, 实际数量, 可抽取量)`。大堆剩余留源；99来自当前ItemStack保存CODEC边界，不是对源库存强截64。载荷由独立源快照复制组件，只交付实际确认扣量。

流程是源快照 → STANDARD抽取/精确写校验 → consume/回读 → 源世界真实ItemEntity → 短拾取延迟/零初速度 → addFreshEntity → 一次标记原版NETHER_PORTAL。正常实体tick完成首次过门尝试，可能与交接同一服务器拍，不手动tick、不额外changeDimension、不持续重标记。

源注册明确拒绝、尚未交付且源仍严格匹配扣后状态，才用既有rollbackSlot条件恢复并回读。consume/rollback和实际参与的回退均保留独立快照，不建立receipt/事务架构。注册回调异常时交付不明不盲目回填，异常和恢复失败留ERROR。

**官方原版的已知风险**：`addDuringTeleport` 不返回目标注册结果，`ItemEntity.changeDimension` 随后可能合并；非null返回不证明交付，removed也可能表示成功合并。采用原版路线不等于无损跨世界事务。普通目的地失败/旅行取消往往留源掉落物，源已删除后的目标注册取消仍可能损失。真实事件拒绝行为必须实机验证；不会自动补回造成复制。

### 3.2 玩家

世界出口计算沿公开 DimensionType比例、WorldBorder、PortalForcer找/建门、BlockUtil目标矩形、PortalShape避碰与原版出口组合。虚拟源无世界门几何，固定默认X轴与中心偏移；不把GUI门尺寸映射成真实门框，也不先移动玩家。

同源世界、官方准入、目标启用与冷却通过后受理，设置官方冷却；目的地求取后关闭旧菜单再调用真实玩家changeDimension，官方旅行事件只触发一次。声音与ticket由原版回调完成。受理后目的地失败/事件取消仍有本次冷却；已建世界门不随取消自动撤销。

只使用原版世界门出口。世界门POI不会认识容器门面，回程是原版世界门网络或另一个容器门，不保证回到原箱子。

## 4. 接入回归与不可误改约束

- 门无数据是廉价no-op，不能要求其他领域mock提供PlayerList才运行；空门不每拍写Player附件，不覆盖流体账本。
- GUI只精确接管门action，普通放置/分堆保留；旧动作的目标准入没有全局放宽。
- 公共流体视图可以从对应ctx回填持久源，GUI不用触发全套tick hooks也能查询即时/保存的流体。
- 宿主借位不改变背包身份；明确的物品内容菜单即使Handle失败也禁止错落parentBE。
- 两槽移动的undo与本次源出生失败的单槽条件恢复不可混用，不因实体removed填货。

自动守卫范围见[测试索引](../reference/test-map.md)。全量执行与门禁口径见[单元测试指南](../guides/unit-testing.md)与[项目入口](../../AGENTS.md)。

## 5. 游戏内验收与未验证事项

**用户实测确认“功能逻辑基本正常”**，不是下列所有边界逐项通过。创造模式单独玩家背包曾不显示门面；持续快照修复与活黑曜石专用图标尚待复测。自动测试不能替代以下真实链路：

- 原版箱子、创造inventory页、多人菜单与第三方GUI的紫色动画、透明度/数量、绘制Z、资源包重载。
- 源实体首次tick、同服务器拍顺序、箱内失败掉落/拾取、下界/主世界POI搜索与建门、负坐标/世界边界。
- 官方旅行取消、目标注册取消、目标物品合并及数量总账。
- 倒水/倒熔岩、自动流入、放入无功能活物品/活黑曜石整门熄灭，货物/流体保留，清障重新点火。
- 玩家活背包开关、换槽/实际宿主移动、另一个玩家菜单来源、关开配置不复燃。
- 子菜单/远程库存拒绝，不冒用父容器；未来扩展真实宿主反查须独立证据。
- 退出重进、UUID/无UUID完整交接、玩家附件、双箱爆炸拆半立即补回不复燃。

发现实际行为与本节规则不符按bug处理；对尚未支持的第三方来源，不用viewer位置兜底或放宽原准入。
