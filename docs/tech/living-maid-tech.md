# 活魂符与女仆背包联动

> **实现状态**：首版已由用户实测确认；2026-11-08补不裁剪、四向身体与有限头部追光标，代码/我方测试通过，新增展示实机待验。
> **范围**：Minecraft 1.21.1、NeoForge 21.1.219，编译对接TLM 1.5.3-neoforge+mc1.21.1。
> **设计与否决留痕**：[活魂符设计稿](../buffer/活魂符-design.md)。

## §0 玩法定义

**语义**：活魂符是存有具体女仆的魂符的活物品形态，在容器内自行换槽，在容器界面显示所存女仆。
女仆实体背包兼容是独立的宿主接入：允许放入的活物品在该库存里运行，不要求背包接纳每一种活物品。

**获取**：空魂符收存已有女仆得到`smart_slab_has_maid`，再经活按钮活化。
初始赠送的INIT魂符尚无具体女仆快照，本功能不把它当已有女仆；可先释放、再收存。

**核心循环**：读取魂符所存女仆的饱食度H和背包容量C → 均匀排期 → 到点从合法空邻槽随机选目标 →
正式提交下一次计时并移动自身。开关GUI不参与服务端判断。

**规则**（违反即bug）：
1. C是所存女仆的背包可用容量，不是当前宿主大小或空格数；H是原`maid_hunger`饱食度属性，
   不读取默认0的`MaidHunger`整数替代。原属性省略默认实例时使用原默认，显式0停走。
2. C分钟内均匀安排H次迈步机会；时间按服务端game tick，间隔公式与数值例子见§1。
   低H低频，0停，不把默认饱食度当上限。
3. 每枚每tick至多一步；目标只选同宿主有效、空、允许插入且可抽取源的四邻，等概率随机。
   不合并、不交换、不跨容器、不进入非存储槽；异常多件魂符不拆分。
4. 到点无路则跳过，不积攒补走；计时随物品换槽。同一时间基准内手动换槽/换箱不重排，
   输入改变/跨维度/过期恢复重排，不兑现离线历史步数。
5. TLM快照只读：不因步行消耗饱食度，不额外喂食、更新好感、执行任务或递归运行快照背包。
   取消活化清我方clock，不删除女仆快照；原主人校验及释放行为保持。
6. 女仆实体背包按当前装备类型开放的范围运行，普通区六列；隐藏、装备、饰品、机器等区域不冒领。
   原准入/黑名单/拾取/穿脱/死亡处理不改，活魂符仍可能被原背包规则拒收。
7. 模型/简单待机音仅在容器界面演出，临时预览女仆不入世界、不完整tick。
   每枚独立，移槽匹配只排除clock；同数据有歧义重置演出，不共享实体。
8. 模型准备或绘制失败保留/恢复原图；HUD手持/掉落/carried保持原样。
   关闭界面、物品离开、重载或换世界明确停声并释放实例。

9. 槽位只作为模型的站立锚点，不按槽位矩形裁剪；模型可伸到邻槽，不扩大点击区域或增加实际占槽。
10. 身体初始正面，随最后迈步方向转向：上背面、下正面、左朝左、右朝右；停步不自动回正。
    头部在相对身体的范围内追踪光标，不让身体跟着光标转，不在背面强行扭头180度。

**已接入能力**：女仆背包宿主选择/范围与反馈过滤；活魂符均匀随机走位；槽位图标替换、
原模型预览/步行动画与待机语音，四向身体和有限光标追踪。首版动画/语音用户已确认，新增展示状态见§4。
**明确不做**：放宽女仆背包准入、INIT原地生成、饱食度消费/喂食、任务回放、槽位物品寻路、
手持女仆模型、另造库存操作或同步协议。
**验证入口**：§3的我方守卫与§4的实机清单，不以构建绿灯代替实际模型/库存行为。

## §1 数据与均匀计时

- `TlmSoulData`从`maid_info`只选模型标识、attributes和背包类型，不每tick复制整份背包NBT。
  饱食度沿原AttributeSupplier/AttributeInstance恢复保存的base及持久修饰符；损坏字段不冒充默认值。
  未保存的临时修饰符不可由快照还原。
- C从原BackpackManager查快照背包类型，合法未知类型遵从原空背包回退，不维护本模组容量表。
- 间隔为`max(1,1200*C/H)` game tick；H=20/C=6为360tick一次，连续且有路时7200tick中20次。
  分数余量保留，避免取整累积漂移；极大H受每tick一步上限约束。
- `LivingSoulSlabClock`为本功能自有持久/同步组件，保存时间scope、排期与余量及输入；
  普通tick只读，到点/重排才经`commitItemComponents`写回，成功后`move`携带新clock到目标。
  无writer/旧值改变时不继续位移，不把副本修改当宿主完成。
- `canApply`按Item与活标记认领，逐枚数据校验留tick。框架缓存按Item，不能以首枚快照决定整类资格。

## §2 宿主与客户端接缝

**实体宿主**：`EntityContainers.Provider`收敛认领、构造和菜单物理槽判据。
TLM提供者复用可写范围库存与EntityContainerContext，六列从`getLiveColumns()`进入共同布局链。
菜单级实体身份不等于该菜单全部槽归此实体；GUI反查、脏槽同步、tooltip与流体映射核对真实存储handler。
原实体白名单/能力面双闸仍保留；新入口不把所有生物装备栏升级成运行宿主。

**均匀排期**：现有runtime按槽位作废，不能承担随魂符迁移的计时，因此clock属于物品。
到点先确认clock提交、再移动；移动失败不复制物品，失败跳过只影响该机会。

**客户端**：独立窄Mixin接NeoForge `renderSlotContents`的两处图标调用，准备成功才替换；
Foreground仅画当帧登记项，数量/耐久/高亮/点击保持原链。
原渲染器直接分派模型，不改变dispatcher阴影或玩家选项，不full load/tick所存女仆。
多枚实例按宿主/物理槽独立，只有稳定快照唯一一对一时插值；计时组件不参与视觉身份比较。

### 2.1 展示朝向与光标（2026-11-08）

首版固定Y旋转且身体默认0，用户实测背对玩家；原生摆臂、尾巴、迈步和语音实际正常，
不需要启动完整女仆AI补动画。现去掉固定Y角，身体以原渲染器读取的角度表示：
初始/下180°、上0°、左270°、右90°，最短角度平滑转向，停步保留。

光标位置由Foreground现成事件传入，头部参考点以当前插值位置和保存的绘制矩阵变换到GUI坐标。
`SoulSlabPreviewFacing`分别维护身体与相对头角，左右限45°、俯仰限20°；
侧向略向观察者倾头、背向反转左右投影，不解算必须盯住鼠标的完整3D目标。
原renderer读body/head/pitch前后值插值，骨骼动作仍由模型决定，独立眼球响应不作跨模型承诺。

取消额外槽矩形scissor，保留界面原有scissor及异常恢复；模型仍以槽底为锚点。
原数量/耐久预留、冷却反馈回原图和真实点击链不变。此次不产生气泡、跳跃或舞蹈。

## §4 验证状态与已知边界

**已验证**：首版用户实测反馈“全都正常”，随后明确确认原生手臂/尾巴待机、走路和待机语音存在。
构建和我方全量测试通过；**本次新增的无槽裁剪、身体四向、光标追踪尚未实机验收**，不以旧版通过代替。

**新增展示待验**：
- [ ] 初始正面、上/下/左/右身体正确且停步保持；快速连续转向不绕远路。
- [ ] 正面/侧面/背面有限追踪光标，身体不随光标变方向；走动时参考点随当前显示位置移动。
- [ ] 大模型、尾巴/翅膀可越槽，界面自身边界保留；数量、耐久、高亮和邻槽点击不受影响。

**专项/组合覆盖（用户未逐项说明的仍需核对）**：
- [ ] 原女仆背包各类型容量内活熔炉/漏斗/流体实际运行，隐藏/装备/饰品不串位。
- [ ] HAS_MAID活化后槽位原图被女仆替换，标准/Gecko/YSM模型、待机音、步行动画和数量/耐久/高亮正确。
- [ ] H=20/C=6连续每18秒一拍，关闭GUI仍走；换箱不因当前容量重排，受堵不补走。
- [ ] 显式属性0停，缺默认项20；不修改原饱食度、好感与内部库存。
- [ ] 同快照多枚、拖放、取走、取消活化、原释放、重载和换世界无残留模型/声音。
- [ ] 有/无TLM实际客户端/专用服务器启动组合。
- [ ] 女仆收存/释放时实体附件型流体/电力数据的原保存交接，不以物品NBT保留冒充附件全保留。

**边界**：
- 原HAS_MAID不能进入某些容器（含女仆背包），此限制保持。测试魂符走位应使用原来允许存放的宿主。
- 末影背包另显示玩家末影箱，现有非玩家runtime/流体客户端缓存是单目标；
  本轮仅保证女仆普通存储区反馈，独立末影区域不误读女仆快照，不承诺多宿主同时完整反馈。
  实体菜单首包只发送主实体与玩家背包，不让附加末影箱首包覆盖主实体（`LivingItemMenuRuntimeTest`）。
- 绕过父`renderSlotContents`的第三方自绘screen当前保留原图，不擅自叠女仆。
- 冷却反馈期间客户端暂透传原图；数量/耐久区域预留避免重复装饰派发，视觉仍须实机核对。
