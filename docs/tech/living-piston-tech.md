## §0 玩法定义（定稿）

> **性质**：本节「规则」是**契约**（违反即 bug），不是实现细节。
> **关键拍板（用户）**：「数量解歧义」（N 划货物 / 设备边界，2026-11-02）·
> 「名单链是名单链，不是物品管道」（2026-11-03 纠正算例）·
> 「删除压送自动补位，送空留空、后方不动」（v1.11，2026-11-03）·
> 「末影只做直连推送，公共 / 专属路由不做」（2026-11-02）·
> 「伸出态放服务端运行时，不写物品组件」（v1.9）。

**语义**：活活塞在同容器网格内把连续物品链前移一格，或通过候选活漏斗入口像挤牙膏一样
压送末端货物。普通活塞推 / 压送，粘性活塞另可把头前一格整栈拉回。

**获取**：原版活塞 / 粘性活塞 + 活按钮（活化无门槛）。

**核心循环**：

1. **条件位移 / 抢救线**：红石控制整链单格推，可配合流体节拍把物品移出危险格，不新增抢救机制。
2. **数量选范围**：活塞数量 N 是普通推链上限，也是压送货物范围；范围内设备可成为货物，
   范围外紧接的一格才可能是接收漏斗。增加数量可能改变设备 / 货物角色，不保证原出口更易成功。
3. **机械定时 / 定量**：锁定漏斗主动取料，将主动权交给活塞；红石决定动作次数 / 时间，
   接收漏斗数量决定每次最多送多少，出口容量再限制实际交付。
4. **设备物流**：可压送活箱子 / 活工具 / 活海绵 / 活漏斗等本体，不展开它们的内部功能。
   借漏斗出口跨容器，末影出口只做玩家末影箱直连推送，不走公共 / 专属路由。
5. **过滤自动化**：漏斗数量变化、普通位移或末端送空改变名单布局；过滤等级可被自动化是接受的
   涌现。漏斗名单链不因此变成物品管道。
6. **原有抽箱行为仍成立**：活箱子放在未锁定漏斗取料格可被抽内容；此主动功能与机械搬箱子
   本体是不同动作，不能混用访问器或全局放开活物品隔离。

**记号**：X 为活塞本槽，X+k 为沿朝向第 k 格；N 为活塞数量；C 为本次末端货物数量；
M 为接收漏斗数量；q 为实际交付量。所有「格」沿用现有容器邻槽口径，不另建几何 / 容器键。

**规则（定稿，违反即 bug）**：

| # | 规则 | 定案依据 / 边界 |
|---|---|---|
| 1 | **状态驱动**：有电且未伸出尝试动作，无电且已伸出收回；成功后保持伸出，持续通电不重复推 / 挤。extended 放服务端运行时，不写物品组件 | 方向配置随物品；读取本容器最近一次计算的信号，每拍必 tick；运行时失效后的新工作起点允许有电重试，不承诺全服统一 1t 快照 |
| 2 | **头格纯视觉**：不占位，可与残货共格；动画不参与机械判定 | 2026-10-31 头格定案 + 渲染分离 |
| 3 | **数量划范围**：普通链长 L ≤ N；压送要求 X+1..X+N 连续非空，X+N+1 才是候选接收端。范围内每个非空槽算一节，包括活漏斗，不提前接管；不越范围继续搜入口 | 用户提出数量解歧义；空格截断链 / 压力 |
| 4 | **普通推 / 拉整栈、不合并、不覆盖**，每栈只前移一格；只有入口压送可拆数量，出口按正常插入规则合并 | 定量交付例外不推广到链内位移 |
| 5 | **粘性拉 X+2 → X+1**：同容器、X+1 空且可接纳整栈才拉；无货 / 被占 / 越界 / 拒收均照样收回，不拉链、不反向追回出口货物 | 拉失败也收回 |
| 6 | **货物可以是活物品本体**，组件 / 内部数据保全；货物漏斗冷却 / 锁定不使它不可推，自己的输出 / 过滤不代替接收端配置 | 本体移动与功能使用分开；活塞伸出态不跟物品迁移，配置保留 |
| 7 | **候选接收漏斗须输入面匹配**，交付沿它的既有输出语义；设备本体不动，不作为缓存；接收失败不回退为推走它 | 范围内漏斗仍按货物；输入面匹配不等于出口可交付 |
| 8 | **实际交付守恒**：q = 源净扣减量 = 目标实际入量，不丢、不复制；普通位移不可部分完成；通过容器访问 / 写回更新修订 | 模拟不是事务保证；实现边界见 §9 |
| 9 | **不做** QC、粘液 / 蜂蜜黏连；v1 不做短脉冲吐物品的机械中间态 | 不能依据视觉进度跳过拉取 |
| 10 | **取消活化清空 extended**，停止专属伸缩渲染 | 机械状态不外流 |
| 11 | **活塞不直接跨容器**：头格越界不推、不伸出、不画头杆；普通链尾越界失败；压力链与入口在同容器，跨容器出口归漏斗 | 不恢复旧接壤链方案 |
| 12 | **空推成功、失败重试**：有头格且面前空则伸出；普通推失败或 q = 0 不伸出，持续通电可重试；q > 0 成功，残余不连续挤 | 红石决定尝试时刻；出口堵住时不保证准时送达 |
| 13 | **漏斗红石锁定只停主动传输，仍允许机械压送**；压送不要求必须锁定；主动隔离保留 | 解锁同拍争货顺序仍待核验 |
| 14 | **压送无视且不修改主动冷却**，保留接收漏斗过滤；检查末端货物本体，M 限单次剂量 | 不增加机械专属冷却、不全局删主动冷却 |
| 15 | **单次只挤动作开始时的末端栈**，数量受 C、M、出口实际接纳量限制；能收 2 就送 2，不凑满 M、不借后方栈补额度 | 源抽取、权限等正常访问限制仍有效 |
| 16 | **压送不移动后方链节**：末端部分交付则残余留原槽；末端送空则原槽留空，后方始终原位不动。q > 0 即成功，送空不继续出料 | v1.11 用户删除自动补位；不保留补位预演、任务或补偿机制 |
| 17 | **名单链仍是名单链**：不新增多段物品管道；接收漏斗输出到另一个活漏斗不表示货物可递归直通 | 用户纠正：名单传播 ≠ 本体物流 |
| 18 | **本次过滤结果固定**：动作开始时取过滤结果；数量 / 位移 / 送空后的布局在既有重建时生效，用于后续动作，不在本次反复改判 | 用户接受过滤等级自动化涌现；不新增重建挂点 |
| 19 | **末影只做直连推送**：绑定玩家在线且实际能接纳才交付；公共 / 专属频道拒绝机械压送，不登记路由，不回退主动登记 | 用户定案；不自动放开从玩家末影箱主动提取活物品 |
| 20 | **普通推拉与压送出口都尊重槽位准入**，包括槽位黑白名单、容量及正常访问限制 | 与接收漏斗货物过滤是两层检查；活水流准入口径另题 |
| 21 | **运行时生命周期**：原槽原方向保持伸出；改朝向使旧态失效且不补拉；移走 / 取消活化不补拉；新位置或缓存回收 / 重启从未伸出开始。同槽只改数量不清伸出态 | 接受复位后仍有电可再执行，不保存机械历史；复用现有清理，不引入物品 UUID 识别同类交换 |
| 22 | **同拍粘性争抢**：按既有实际执行顺序，先成功者拉走整栈；后者检查更新后的源 / 目标，源空或目标被占则不拉但收回。前者失败不占货 | 不拆分拉取、不新增公平 / 随机仲裁；不承诺某一方优先 |

**能力清单（全部已实现 ✅）**：普通推拉（N 链 / 空推 / 失败重试）· 粘性单栈拉 ·
三维伸缩渲染（2D blit 全平面）· 数量定位接收端 · 单次定量压送（`min(C,M,出口)`）·
末影直连推送 · WASD 朝向配置 · 取消活化清机械态。

## §1 原版事实存档（Minecraft 1.21.1）

| 机制 | 查证结论 |
|---|---|
| 供电 / QC | 六方向除正面、自身下方及头顶周边查询；QC 是供电规则，不是头占位造成 |
| 推链 | 固定上限 12，连续可推链；粘液 / 蜂蜜可扩展黏连带，二者互不粘 |
| 不可推 | 部分硬方块、BLOCK 推反应、伸出活塞本体、带 BE 方块；容器模型采用组件跟物品走，不照搬 BE 限制 |
| 触发 | `PistonBaseBlock.checkIfExtend` 经 `level.blockEvent` 派发；不是 `scheduleTick`；活塞读本容器最近计算信号，非原版精确时序或全服统一 1t 快照 |
| 移动 | `PistonMovingBlockEntity` 每 tick 进度 +0.5，`getProgress(partialTick)` 插值；世界中存在机械移动态 |
| 收回 / 短脉冲 | 粘性尝试 X+2→X+1，不能拉也收回；短脉冲吐出有专门事件与机械状态条件，仅动画不能复现 |
| 渲染 | `PistonHeadRenderer` 分开画固定伸出态本体与移动头杆，按进度切 SHORT，普通 / 粘性按 PistonType 区分 |

查证以 `gradle.properties` 的 `neo_version` 对应 merged 源码为准；核对 `libs/src/neoforge-21.1.219-merged/`。

## §2 机制：状态机 / 数量划范围 / 粘性拉

### 2.1 状态机（成功保持、失败重试）

```text
每拍读取本容器最近一次计算的本槽信号（不取 prev 额外延迟）：
  有电且未伸出：按当前 N 解析 §2.2 / §3
    空推或普通推成功，或压送实际 q > 0 ⇒ extended=true
  无电且已伸出：粘性按 §2.3 尝试拉，随后 extended=false
```

每次尝试读当前 count，失败期间修改数量可改变施力范围与候选接收端；已完成动作不追加位移。
成功后即使头格仍有残货，也不再挤，下一次需先收回再通电；不新增红石计算后的回调或调度器。

### 2.2 数量划范围与普通推

```text
N = 活塞当前数量
无同容器 X+1 ⇒ 失败
从 X+1 起按方向检查，范围内不因看到漏斗而提前接管：
  N 格以内先遇空槽 ⇒ 链结束，按普通整链单格位移（L 可小于 N）
  X+1..X+N 均非空：检查紧接的 X+N+1
    空 ⇒ 普通整链单格位移
    输入面匹配的活漏斗 ⇒ 候选接收端，按 §3 判过滤与出口
    其他物品 / 输入面不匹配 / 越界 ⇒ 失败
普通位移：全程能完整抽取 / 插入才从尾到首移动，每栈 +1
```

N 以内每格按货物解释，漏斗本体也可推；只有 X+N+1 可作为接收者，不搜索更远处。
候选接收失败不能将其纳入普通链顶走，也不能缩短范围改由前一个漏斗接管。

```text
普通推（N=3）：
前：[活塞×3][土×64][铁×8][活箱子][ 空 ]
后：[活塞×3][ 空 ][土×64][铁×8][活箱子]

空格截断（N=3）：
前：[活塞×3][ 土 ][ 空 ][ 铁 ][ 空 ]
后：[活塞×3][ 空 ][ 土 ][ 铁 ][ 空 ]
```

上限就是 N，不加固定 12 上限，不假定所有容器 9 列；旧多格冲程 / 压实排列与
`min(count, 自由程)` 已作废（[设计历程 §5①](../archive/活活塞-design.md)）。

### 2.3 粘性拉

X+1、X+2 均在同容器，X+1 空、X+2 非空且整栈可移动才拉；其余不搬但收回。
不合并、不拉链、不随 N 扩大拉取距离，不从漏斗出口 / 玩家末影箱追回刚交付的物品。

## §3 机械压送（活漏斗联动，单接收端挤牙膏）

### 3.1 接收端定位与漏斗本体

X+1..X+N 必须连续非空，货物就是这 N 格；只有 X+N+1 为候选接收漏斗，且输入面须匹配。
输入 / 输出按其 `sourceOffset` / `targetOffset` 识别，不能按图标猜；一次仅交付 X+N 原本的货物。

**漏斗作货物时**：冷却 / 锁定不阻止搬运；自己的数量不是本次剂量，自己的出口不发送后方货物。
**漏斗作接收设备时**：留在原槽，用自己的数量、过滤与真实出口，不与货物漏斗在本槽合堆。

```text
同一布局，向右推动，后一个漏斗左进下出：
[活塞×3 →][A][B×7][漏斗×3 →][漏斗×2 ↓]
           1    2        3            4
          └────货物范围────┘       候选接收端

过滤允许漏斗本体、下方出口可收 2 时：
[活塞×3 →][A][B×7][漏斗×1 →][漏斗×2 ↓]  → 下方收到漏斗×2
q=2 成功；A / B 保持原位，货物漏斗剩 1；即使货物漏斗送空，A / B 也不移动。
```

**名单链 ≠ 物品管道**（用户纠正的算例）：N=3 时第三格漏斗成为候选，但它指向第四格活漏斗的
关系是名单传递，不是可交付物品的出口——漏斗×3 将 B 作为 Tag 级黑名单传给漏斗×2 时，
本次没有 B 的实际交付，q=0、推不动，不是「按 3 再按 2 限量直通」。
保留 [活漏斗 §2.4.6](living-hopper-tech.md) 的名单继承 / 穿透与过滤优先级；名单中有 B
不意味着漏斗本体被同样拒绝，N=3 时仍须检查本体实际匹配结果。不新增多段物品管道。

### 3.2 控制权、剂量与过滤时间

| 维度 | 主动传输（现有机制） | 机械压送 |
|---|---|---|
| 发起者 | 漏斗 tick | 活塞本次尝试 |
| 红石锁定 | 停主动取料与其冷却倒计时 | 仍可压送，非必须锁定；锁定交出主动权 |
| 冷却 | 沿原规则 | 无视且不修改主动冷却，不设机械冷却 |
| 过滤 | 既有名单构建 | 接收者名单过滤货物本体，动作开始时结果固定 |
| 活物品 | 不主动搬本体；存储类可用内部功能 | 可拆数量送本体，组件与内容保全 |
| 剂量 | 原主动规则 | 接收漏斗数量 M 上限，出口容量再限 |
| 节拍 | 自动运行 | q>0 保持伸出，下次先收回再通电 |

正常过滤、源抽取与权限满足时，交付候选为 `min(C, M, 出口可接纳量)`；执行按实际入账
校准 q，源净扣减同为 q。q>0 成功，q=0 不伸出可重试；目标未加载、拒收、玩家离线不能假设容量。
出口可按正常规则合并，但不强行合堆、不绕过槽位准入。

**过滤自动化（已接受）**：本次用动作开始时过滤，不在途中反复改判。货物漏斗 3→1、普通
位移或末端送空改变布局，既有过滤重建后用于后续动作；等级由 Tag→ID 等变化是涌现，不阻止。
不为本次动作增加过滤强制刷新挂点，不把等级变化自动化做成另一种新机制。

### 3.3 压送只处理末端栈（送空留空）

```text
部分出料，出口只收 2：
前：[活塞×2 →][A×5][B×7][接收漏斗×3]
后：[活塞×2 →][A×5][B×5][接收漏斗×3]  → 收到 B×2

末端全部送出，出口足够：
前：[活塞×2 →][A×5][B×2][接收漏斗×3]
后：[活塞×2 →][A×5][ 空 ][接收漏斗×3]  → 收到 B×2
两种情况 q=2 均成功；A 始终原位，不移入 B 腾出的槽。
```

- 单次只交付动作开始时的末端栈，送出多少扣多少；有残余留原槽，送空原槽留空。
- 无论末端是否送空，后方货物都不移动，不借后栈凑满 M、不在本次继续出料。
- q>0 即成功并保持伸出；q=0 失败可重试，成功后持续通电不再出料。
- 送空造成的空隙截断下一次压力；下一轮按普通推 / 空推规则重新解析当前布局，不设特殊修复。
- 直接顶 7 个货物、接收漏斗 3、出口足够，三轮分别送 3、3、1。
- **自动补位已删除**（v1.11 用户拍板）：对核心定时 / 定量与本体物流收益有限，却增加整段
  准入预演、提交撤销和交付协调；整套删除，不留开关、延后任务或补偿机制。普通整链推不变。

### 3.4 出口范围（末影直连、不做路由）

- 即时出口复用漏斗既有方向、面选择、存储插入与权限；跨容器交付归漏斗，不让活塞续接世界链。
- **末影只做直连推送**：通过直连活末影箱实际插入绑定玩家末影箱空间；玩家须在线，
  容量只够部分则部分交付，离线 / 满 / 拒收 q=0。只定推入，不放开主动直连提取活物品。
- **公共 / 专属频道不做机械压送**：遇路由目标失败，不登记源指针，不回退主动登记，
  不保存压力请求、货物授权、异步交付或新队列。现有普通主动路由不受影响。
- 玩家末影箱空间可作为转接存放处；如何从另一端取出不属于本轮推送能力。

### 3.5 两层过滤与本体准入

**接收漏斗货物过滤**与**目标容器槽位准入**是两层检查。过滤通过不代表槽位可放；
普通推拉 / 压送都尊重槽位黑白名单、容量、抽取 / 写入及权限约束。
活物品可作货物，但不能为此全局取消普通漏斗隔离；用本体访问而非箱内存储 / 路由功能访问。
活水流推动的槽位准入口径另题：只定活塞与漏斗联动，不修改流体规则、不套用其准入豁免。

## §4 渲染（图标 + 伸缩叠加层，2D blit 全平面方案）

### 4.1 分工与几何

| 层 | 内容 | 实现 |
|---|---|---|
| 图标（机身） | 纯机身剖面 16×12×16（UV [0,4,16,16] 1:1 无拉伸，**无 display 变换 = 16px 原版尺寸**），板缘 4px 行不烘进贴图 | `item/living_piston.json`，普通 / 粘性双 spec 共用（侧视同貌），`directional()` 挂家族旋转 |
| 板（叠加层） | piston_side 顶 4 行板缘剖面 16×4，占 x∈[−8,+8] × y∈[−8−t, −4−t]——静止贴机身前缘 = 朝向指示；滑出后原位只剩机身 | `LivingPistonOverlay` blit，⚠️ x=−8 起笔（左上角锚点，见 §10） |
| 杆（叠加层） | piston_side 顶 4 行剖面（原版 `template_piston_head` 杆侧面 UV [16,4,0,0] 同区——原版杆与板缘本就同一块贴图），4px 宽居中 x∈[−2,+2]，从机身前缘长到板内缘 | travel > 0 才画；先杆后板 ⇒ 板盖杆顶 |
| 行程 | **travel = 一个槽距 18px（`SLOT_PITCH`，含边框）**：静止板外缘缩进本格边框 1px（−8，格边 −9）；全伸外缘缩进邻格远端边框 1px（−26，格边 −27）——「头块原样挪了一格」 | `headOffsetUnits(progress) × SLOT_PITCH`，单常数一行可调 |
| 位姿 | translate(cx, cy, 175) → Rz(rotationOf(direction))；z 夹在物品(150)与数量文字(200)之间 | `DirectionalLivingModel.rotationOf` 家族约定（§4.2） |

动画时长 100ms（原版活塞 2gt，`DURATION_MS` 可调）；进度纯逻辑在 `PistonRenderState`
（伸出 / 收回插值与端点钳制、中途翻转续接、方向变化吸附、键独立、活跃键每帧剪枝——免挂点清理）。

### 4.2 旋转约定（家族角度）

`DirectionalLivingModel.rotationOf(Pos2D)` = **GUI 视觉角**（UP=0 / RIGHT=90 / DOWN=180 / LEFT=−90，
基准 = 图标内容朝上，屏面 y 向下 ⇒ 正角视觉顺时针）。两个使用方：

- **叠加层**（GuiGraphics 直绘，无翻转）直接使用 `rotationOf`；
- **物品模型管线**（`DirectionalLivingModel.applyTransform`）在 `applyTransform` 之后
  含 y 翻转（`GuiGraphics.renderItem` 的 `scale(16,-16,16)` 在前）⇒ 施加**相反数**
  （与既有火把家族实机验证值 UP=0/RIGHT=−90/DOWN=180/LEFT=90 逐项一致）。

### 4.3 数据源与边界

- 朝向读物品组件 `LivingPistonData`（随同步包下发）；伸出态读 `LivingItemClientCache`
  的 runtime 片段（`PistonSegment`），进度键 = `C/P + getContainerSlot()` 前缀防同号互串。
- 静止（收回完成）也画板 = 朝向指示；仅无 runtime 片段（从未伸出过）才不画。
- **HUD 代价**：HUD / 快捷栏只有纯机身图标（无板无朝向，前景事件只覆盖容器界面）。
- 已知边界：第三方滚动容器裁剪状态不可知；创造包装槽 `getContainerSlot()` 可能返回菜单号；
  无 X+1 不画头杆；头与真实物品 / 挤压残货可叠画。手持 / 掉落原版 3D（ContextAware 回退）。

## §5 生命周期

| 状态 | 存放意图 | 移动 / 换槽 / 改方向 | 取消活化 | 卸载 / 恢复 |
|---|---|---|---|---|
| extended | 服务端容器+槽位运行时，不写物品组件 | 原位原朝向有效；移动 / 改方向失效，不补做旧方向拉取；仅 count 改变不复位 | 作废且不补拉 | 运行时确被回收 / 重启后默认未伸出；有电可重新尝试，接受动作不跨回收连续 |
| 朝向 | 既有 HasDirection 物品配置 | 配置跟物品；改向开启新工作起点，不维护旧方向机械历史 | 沿现有配置契约 | 保留配置，不保留伸出记录 |
| 视觉进度 | 客户端临时态（PistonRenderState） | 按有效机械态展示，不串旧槽 | 停专属渲染 | 重开初始化；短脉冲反向方案不属 v1 |
| 漏斗本体冷却与派生过滤 | 沿既有运行时 / 派生口径 | 新布局重建过滤，机械压送不改主动冷却 | 沿主动功能契约 | 不建压送持久状态 |

复用现有失效机制，**同类物品原地交换不全量识别**，不加物品 UUID、不追踪拆合来源。
朝向可存一份运行时有效性戳，仅用于发现配置变化、丢弃 extended，不是随物品保存的旧方向。
缓存不是保证卸载瞬间清空；以既有清理与有效性检查的实际时机为准。

**同拍粘性争抢（已定）**：两个活粘性活塞断电拉同一栈，按实际执行顺序、检查当前真实槽位：
先成功者整栈拉走，后者源空则空手收回；先执行者目标拒收不占货，后者仍可尝试。不同源争一个
空目标同理，后者因目标已占不拉、不合并。两者都收回，无力量比较 / 公平轮换 / 随机或新仲裁器。

## §9 实现要点与框架接缝

**两种正确性分开**：普通整链位移不能部分完成（moveStack 尾到首提交、undo 逆序撤销）；
压送可部分交付，按实际 q 扣原末端源，无论是否送空都不移动后方链。

- **共享扩展（非 piston 专属）**：`MechanicalReceivers` 中立机械接收端口——提供原始本体源
  （不展开活箱子 / 末影功能）与真实 q，首个 matches 独占，返回 0 不回退普通推；
  `SlotAccessor.transferAmount` 以 insert 后栈余量为权威 q（不信任 insert 报告），boolean 旧入口
  委托 `q>0`；`BodySlotAccessor` 本体精确写违约恢复并回读。领域经共享端口解耦，piston 与 hopper
  保持 R3 零依赖；接收端候选经中立注册表发现（不写死漏斗类型）。
- **`HopperMechanicalReceiver`**（漏斗域）：权威重验 N+1 输入面、按动作开始时快照过滤本体、
  剂量 `min(C,M,A)`；不读写 cooldown/disabled；同容器目标走既有 Accessor（活箱子虚拟存储 /
  末影直连，路由返回 0）；另一活漏斗目标返回 0，不形成多段物品管道。
- **世界邻居出口** `CrossContainerTransfer.pushMechanicalToNeighbor`：复用面候选与能力查询，
  不走主动隔离 / 施肥 / 路由；无 facing 安全返回 0，多方块 `Container.canPlaceItem` 只在槽位体系
  一致时咨询。
- **G3 四缝收口**（全局启用前必修，详见 [API契约](../system-design/api-contract.md)）：
  执行顺序按 manager 稳定排序契约；旧 SlotEntry 执行前重读当前栈 / 验功能准入；
  tick 内快照按 revision 重建；runtime 失效消费前移 + 首包 / 空快照清态。
  活活塞是这组接缝的第一个消费者，回归守卫随件落地。
- 容器访问 / 写回更新修订，移动红石元件使信号重算；禁止绕过处理器直写。主动漏斗管线仍维持
  活物品隔离 / 功能源展开；机械路径独立使用本体访问器、真实 q 与中立接收端口，没有全局放开
  活物品，也不把单跳模拟称为多槽事务。

## §10 踩坑实录

1. **单位空间错（[0,16]→[0,1]，审查抓出）**：渲染原型把 16px 槽距的位移量写进了 [0,1] 模型
   单位空间（16 倍偏差）。**教训**：位姿计算前先明确当前矩阵的坐标空间；测试用独立 JOML 矩阵
   复算投影而非手抄符号。
2. **投影角手算反**：`Rx(30)·Ry(225)` 后模型 +X 的 GUI 投影角实为 `-153.4349488°`，原实现与
   测试一起错（同一手算源头）。**修**：JOML 独立矩阵回归守四向，「目标屏面角 − 投影角」定表。
3. **图标大一圈**：`living_piston.json` 残留第一版「铺满 18px 整槽」的 `display.gui.scale=1.125`
   （16×1.125=18px）。**教训**：模型 JSON 里调试用 display 变换要在定稿时删净，别靠覆盖掩盖。
4. **板位 −4 vs −8（「静止空条」＋「杆短 4px」同源）**：板画进机身内部 4px，机身前缘上方空
   一条且板压住杆顶。**修**：板占 y∈[−8−t, −4−t]。
5. **blit 左上角锚点（「T」变「7」，2026-11-05）**：`GuiGraphics.blit(x, y, …)` 的 (x, y) 是
   四边形**左上角**——16 宽的板 `blit(x=0,…)` 从轴心向右铺 [0,+16]，与居中的杆构成「7」。
   **修**：板 `blit(x=−8,…)` 居中。**教训**：GUI 绘制原语的锚点语义（blit 左上 / 旋转绕原点 /
   translate 系）要在写第一笔时写进注释。
6. **y 翻转与旋转角的组合**：物品模型管线在 `applyTransform` **之后**做 y 翻转 ⇒ 视觉角 =
   施加角的相反数；叠加层（GuiGraphics 直绘）无翻转 ⇒ 直接用视觉角。同一个角度约定在两条
   管线里符号相反——`rotationOf` 统一定义视觉角、管线侧取相反数，测试钉死两边。
7. **undo 失败继续尝试（原「停止」是权宜之计）**：`undo` 自带「状态不符即拒绝、不覆盖」后，
   某格撤销失败应继续尝试剩余步骤——继续只会多恢复、不会多破坏；中途停止反而留下半恢复态。
8. **测试基建**：E2E FakeHandler 的 `extractItem` 必须有真实抽取语义（`moveStack` 的
   `simulateExtractItem` 依赖它做抽取权限检查）；未全局注册的功能不得加进共享测试的全局注册
   清单来"验证清理"（会污染其它测试并掩盖未启用边界）；`ComponentOwnershipTest` 的 BeforeAll
   注册曾与未启用守卫冲突——独立验证归属声明。
